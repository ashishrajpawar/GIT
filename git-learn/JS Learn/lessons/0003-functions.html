Lesson 3

Functions

Foundations ~20 min read Beginner
Why this matters for your app

In your WhatsApp clone, every single user action calls a function. Tap Send — a function runs. Open a chat — a function runs. Mark messages as read — a function runs. Functions are the engine of every app: they are reusable packages of code you write once and can trigger as many times as you need. Without functions, you'd copy and paste the same code everywhere and your app would be impossible to maintain. This is the most important concept in the entire course.

What is a function?

A function is a named block of code that does a specific job. You write the code once, give it a name, and then call that name whenever you want the job done.

Think of it like a recipe. You write down the steps for making tea once. Then whenever you want tea, you don't write the steps again — you just say "make tea". In JavaScript, writing the steps is called defining a function. Saying "make tea" is called calling it.

Defining a function

Use the function keyword, give it a name, add parentheses, and put the code inside curly braces:

function showWelcome() {
  console.log("Welcome to ChatApp!");
  console.log("Loading your messages...");
}

At this point, nothing has happened yet. You've only written the recipe. The code inside does not run until you call the function.

Calling a function

To actually run the code, you write the function's name followed by parentheses:

showWelcome();   // Runs the function — prints both lines

You can call it as many times as you like:

showWelcome();   // Prints the welcome messages
showWelcome();   // Prints them again
showWelcome();   // And again

The code inside runs fresh each time. That is the whole point of functions — write once, use many times.

Common mistake: defining vs calling

Writing function showWelcome() { ... } does not run anything. It only prepares the function. You must write showWelcome() — with the parentheses — to actually execute it. Forgetting the parentheses is one of the most common beginner errors.

In your WhatsApp clone

React Native uses functions for almost everything. Every screen in your app will be a function. Every button will call a function when tapped. The very first line of your app will call a function to start it up.

Parameters and arguments — passing data in

A function that always does the exact same thing is useful, but a function that can work with different data each time is far more powerful. You pass data in using parameters.

A parameter is a named slot you define inside the parentheses when you write the function. An argument is the actual value you provide when you call it.

// "username" is the parameter — a named slot
function greetUser(username) {
  console.log(`Hello, ${username}! Welcome back.`);
}

// "Ashish" and "Sara" are arguments — the real values
greetUser("Ashish");   // Hello, Ashish! Welcome back.
greetUser("Sara");     // Hello, Sara! Welcome back.
greetUser("Ravi");     // Hello, Ravi! Welcome back.

One function, three different results — because the data changed each time. The function's job stayed the same; only the input changed.

Multiple parameters

You can define as many parameters as you need, separated by commas:

function showMessagePreview(senderName, messageText) {
  console.log(`${senderName}: ${messageText}`);
}

showMessagePreview("Ali",  "Hey, are you free tonight?");
showMessagePreview("Sara", "Call me when you can.");
showMessagePreview("Ravi", "On my way!");

This is exactly the kind of function you'd write to build the chat list screen — for each conversation, you show the contact's name and their last message.

Arguments must match the order of parameters

The first argument fills the first parameter, the second fills the second, and so on. Order matters. If you write showMessagePreview("Hey, are you free?", "Ali") the name and text will be swapped — JavaScript won't warn you, it will just produce the wrong output.

In your WhatsApp clone

When a new message arrives from Firebase, your app will call a function like displayMessage(senderName, text, timestamp) with the real values from the database. Parameters are what let one function handle every incoming message, no matter who sent it.

Return values — getting data back out

So far, functions have been doing things — printing to the console, for example. But often you want a function to compute something and hand the result back to you so you can use it elsewhere.

You do that with the return keyword. When JavaScript hits return, it immediately exits the function and sends the value back to whoever called it.

function addUnread(currentCount, newMessages) {
  return currentCount + newMessages;
}

const total = addUnread(3, 2);
console.log(total);   // 5

The function computed 3 + 2 and returned 5. That 5 was stored in total. Now you can use total anywhere — show it on a badge, compare it to a limit, log it, whatever you need.

Using the return value directly

You don't have to store the return value in a variable first. You can use it directly:

console.log(addUnread(10, 4));   // 14

Return exits the function immediately

Any code written after a return statement in the same block will never run:

function checkOnlineStatus(isOnline) {
  if (isOnline) {
    return "Online";
  }
  return "Last seen recently";
  // Nothing below here can ever be reached in this function
}
Common mistake: forgetting the return keyword

If you forget return, the function runs its code but sends back undefined instead of your computed value. This is a very common bug. If you write a function that should produce a value and instead you're getting undefined, the first thing to check is whether you have a return statement.

function broken(a, b) {
  a + b;   // Computed the answer but never returned it!
}

console.log(broken(3, 4));   // undefined  ← forgot return
In your WhatsApp clone

You'll write dozens of functions that return values: a function that formats a timestamp and returns "10:32 AM", a function that counts unread messages and returns a number, a function that builds a message object and returns it. Return values are what let functions feed data into each other.

Arrow functions — the modern shorthand

JavaScript has a second, more compact way to write functions called an arrow function. It uses => (an equals sign followed by a greater-than sign, which looks like an arrow). You'll see this syntax constantly in React Native code.

Here is the same function written both ways — they do the same thing:

// Traditional function syntax
function greetUser(username) {
  return `Hello, ${username}!`;
}

// Arrow function syntax
const greetUser = (username) => {
  return `Hello, ${username}!`;
};

The differences to notice: the function keyword is gone, the name moves to a const declaration on the left, and => sits between the parameters and the body.

The short form — implicit return

When an arrow function has just one expression to return, you can drop the curly braces and the return keyword. JavaScript returns the expression automatically. This is called an implicit return:

// Full arrow function
const addUnread = (current, newMessages) => {
  return current + newMessages;
};

// Shorter — implicit return (no braces, no return keyword)
const addUnread = (current, newMessages) => current + newMessages;

console.log(addUnread(3, 2));   // 5

Single parameter — parentheses optional

If your function takes exactly one parameter, you can leave out the parentheses around it:

const shout = message => message.toUpperCase();

console.log(shout("hello"));   // HELLO

No parameters — empty parentheses required

If the function takes no parameters at all, you must still include empty parentheses:

const getTimestamp = () => new Date().toISOString();

console.log(getTimestamp());   // Something like "2025-06-14T10:32:00.000Z"
One subtle difference from traditional functions

Arrow functions handle the this keyword differently from traditional functions. You won't need to worry about this for a while, but it's worth knowing this difference exists. For most everyday use in React Native — event handlers, array methods, small utility functions — arrow functions are exactly what you'll reach for.

In your WhatsApp clone

React Native code is written almost entirely with arrow functions. Every component you build will look like const ChatScreen = () => { ... }. Every button's onPress handler will be an arrow function. The sooner this syntax feels natural, the smoother your React Native code will read.

Functions using strings, arrays, and objects

Now that you know functions and the data types from Lesson 2, you can start combining them. Functions become genuinely useful when they work with real data structures.

Working with strings

const formatSenderName = (firstName, lastName) => {
  return `${firstName} ${lastName}`;
};

console.log(formatSenderName("Ashish", "Pawar"));   // Ashish Pawar

Working with arrays

const countUnread = (messages) => {
  let count = 0;
  for (const msg of messages) {
    if (!msg.isRead) {
      count = count + 1;
    }
  }
  return count;
};

const chatMessages = [
  { text: "Hey!",        isRead: true  },
  { text: "You free?",   isRead: false },
  { text: "Call me.",    isRead: false }
];

console.log(countUnread(chatMessages));   // 2

Working with objects

const getUserDisplayName = (user) => {
  if (user.nickname) {
    return user.nickname;
  }
  return user.name;
};

const contact1 = { name: "Ashish Pawar",  nickname: "Ash" };
const contact2 = { name: "Sara Khan",     nickname: null  };

console.log(getUserDisplayName(contact1));   // Ash
console.log(getUserDisplayName(contact2));   // Sara Khan
In your WhatsApp clone

This is the exact pattern your app will use throughout. A function receives an object (a message, a user, a chat) and does something useful with it — formats it, filters it, counts something about it. The data types from Lesson 2 are the raw material; functions are what you do with that material.

A real WhatsApp example

Let's put it all together. Here are two functions that would genuinely appear in a chat app. Read through them carefully — every technique from this lesson appears somewhere here.

sendMessage() — creating a message object

When a user taps Send, your app needs to create a structured message object to save and display. Here is a function that does that job:

// Takes the sender's name and the message text.
// Returns a complete message object ready to save to the database.
const sendMessage = (sender, text) => {
  const message = {
    sender: sender,
    text: text,
    timestamp: new Date().toISOString(),
    isRead: false,
    id: Date.now()   // Simple unique ID based on current time
  };
  return message;
};

const newMsg = sendMessage("Ashish", "On my way, five minutes!");

console.log(newMsg.sender);      // Ashish
console.log(newMsg.text);        // On my way, five minutes!
console.log(newMsg.isRead);      // false
console.log(newMsg.timestamp);   // e.g. "2025-06-14T10:32:00.000Z"

Notice what this function does: it takes two simple values (a name and some text), builds a richer object from them, and returns that object. The caller doesn't need to know how the object is built — they just call the function and get a ready-to-use message back.

formatNotification() — building a notification string

When a message arrives and the app is in the background, the phone shows a push notification. Here is a function that builds that notification text:

// Takes a message object (like the one sendMessage returns).
// Returns a formatted notification string.
const formatNotification = (message) => {
  const MAX_LENGTH = 40;

  // Trim long messages so the notification doesn't overflow
  const preview = message.text.length > MAX_LENGTH
    ? message.text.slice(0, MAX_LENGTH) + "..."
    : message.text;

  return `${message.sender}: ${preview}`;
};

const msg1 = sendMessage("Sara", "Are you coming to the meeting today at 3pm?");
const msg2 = sendMessage("Ravi", "Hi!");

console.log(formatNotification(msg1));
// Sara: Are you coming to the meeting today at...

console.log(formatNotification(msg2));
// Ravi: Hi!

These two functions work together: sendMessage() creates the object, formatNotification() reads it and produces a string. Each function has one clear job. That is good design — and it is how professional apps are built.

In your WhatsApp clone

In your real React Native app, sendMessage() won't just build a local object — it will also call Firebase to save the message to the database and trigger a push notification to the other person's phone. But the local shape of the function will look almost exactly like this. The fundamentals you're writing now will carry through directly.

Common mistake: using a function's result before it returns

Functions that return objects (like sendMessage() above) must complete and return before you can read the result. If you try to access newMsg.sender before calling sendMessage(), you'll get a ReferenceError because newMsg doesn't exist yet. Always call the function first, then use the result.

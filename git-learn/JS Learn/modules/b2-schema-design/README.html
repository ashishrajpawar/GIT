Track B

Schema Design

3 lessons Phase 2 — Backend Core
Module goal

Design Token's complete database schema — users, tokens, access rules, conversations, and messages. Then set up a migration system so the schema can evolve safely over time without losing data.

Lessons

  1. Token Schema — users, tokens, access_rules, redemption_events, constraints, indexes
  2. Messaging Schema — conversations, messages, read receipts, revocation triggers
  3. Migrations — versioned schema changes, migration runner, safe patterns for production

After this module

You'll have:

  • A production-ready schema with 6 tables and proper constraints
  • Database-level enforcement of Token's business rules (revocation, max uses, valid status transitions)
  • Triggers that propagate revocation to conversations automatically
  • A migration system that tracks applied changes and runs safely in production
  • The api/migrations/ folder in your Token repo with real migration files

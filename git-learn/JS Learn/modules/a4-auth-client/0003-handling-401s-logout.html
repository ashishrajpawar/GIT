Handling 401s & Logout

A4 — Lesson 3 of 3 ~45 min
Why this matters for Token

The access token expires every 15 minutes. When it does, the next API call returns 401. The app must silently refresh the token and retry the original request — without the user noticing. If the refresh also fails (token revoked, logged out elsewhere), the app must redirect to login. This is the invisible plumbing that makes auth feel seamless.

The silent refresh flow

  1. User is browsing the token list — access token expired 30 seconds ago
  2. App calls GET /api/tokens → server returns 401
  3. API client intercepts the 401 before the component sees it
  4. Client calls POST /api/auth/refresh with the stored refresh token
  5. Server returns a new access token (+ rotated refresh token)
  6. Client stores new tokens and retries the original request
  7. User sees their token list — they never knew the token expired

Implementing the refresh interceptor

// app/src/api/client.ts
import { createApiClient } from '@token/shared/api-client';
import {
  getAccessToken, setAccessToken, getRefreshToken, setRefreshToken, clearTokens
} from '../auth/store';

let refreshPromise: Promise<boolean> | null = null;

async function attemptRefresh(): Promise<boolean> {
  const refreshToken = await getRefreshToken();
  if (!refreshToken) return false;

  try {
    const res = await fetch('http://localhost:3000/api/auth/refresh', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ refreshToken }),
    });

    if (!res.ok) {
      await clearTokens();
      return false;
    }

    const json = await res.json();
    setAccessToken(json.data.accessToken);
    await setRefreshToken(json.data.refreshToken);
    return true;
  } catch {
    return false;
  }
}

// Deduplicate concurrent refresh attempts
function refresh(): Promise<boolean> {
  if (!refreshPromise) {
    refreshPromise = attemptRefresh().finally(() => {
      refreshPromise = null;
    });
  }
  return refreshPromise;
}

let onForceLogout: (() => void) | null = null;
export function setForceLogoutHandler(fn: () => void) {
  onForceLogout = fn;
}

export const client = createApiClient({
  baseUrl: __DEV__ ? 'http://localhost:3000/api' : 'https://api.tokn.app/api',
  getAccessToken,
  onUnauthorized: async () => {
    const success = await refresh();
    if (!success && onForceLogout) {
      onForceLogout();
    }
  },
});

Retry after refresh

The onUnauthorized callback alone isn't enough — we need the original request to retry. Enhance the API client:

// Enhanced createApiClient with retry-on-401
export function createApiClientWithRefresh(config: ApiClientConfig & { refresh: () => Promise<boolean> }) {
  async function request<T>(method: HttpMethod, path: string, body?: unknown): Promise<T> {
    let response = await rawFetch(method, path, body, config.getAccessToken());

    if (response.status === 401) {
      // Attempt silent refresh
      const refreshed = await config.refresh();

      if (refreshed) {
        // Retry with new access token
        response = await rawFetch(method, path, body, config.getAccessToken());
      } else {
        // Refresh failed — force logout
        config.onUnauthorized();
        throw new ApiError(401, 'Session expired. Please log in again.');
      }
    }

    if (response.status === 204) return null as T;

    const json = await response.json();
    if (!response.ok) throw new ApiError(response.status, json.error);
    return json as T;
  }

  // ... return { get, post, patch, delete }
}

async function rawFetch(method: string, path: string, body: unknown, token: string | null) {
  const headers: Record<string, string> = { 'Accept': 'application/json' };
  if (token) headers['Authorization'] = `Bearer ${token}`;
  if (body) headers['Content-Type'] = 'application/json';

  return fetch(path, {
    method,
    headers,
    body: body ? JSON.stringify(body) : undefined,
  });
}

Preventing duplicate refresh calls

If 5 API calls return 401 simultaneously, you don't want 5 refresh requests. The deduplication pattern:

let refreshPromise: Promise<boolean> | null = null;

function refresh(): Promise<boolean> {
  if (!refreshPromise) {
    // First caller creates the promise
    refreshPromise = attemptRefresh().finally(() => {
      refreshPromise = null;  // reset for next time
    });
  }
  // All callers await the same promise
  return refreshPromise;
}

The first request that gets 401 triggers the refresh. All subsequent 401s in that window share the same promise and wait for the same result. Once refreshed, all retry with the new token.

Connecting to AuthContext

// app/src/auth/AuthContext.tsx — add the force-logout handler
import { setForceLogoutHandler } from '../api/client';

export function AuthProvider({ children }) {
  // ... existing state and functions

  useEffect(() => {
    // When the API client can't refresh, force logout
    setForceLogoutHandler(() => {
      clearTokens();
      setUser(null);
    });
  }, []);

  // ... rest of provider
}

Logout — what to clean up

async function logout() {
  // 1. Tell the server (best-effort — don't block on failure)
  try {
    await client.post('/auth/logout');
  } catch {}

  // 2. Clear all local state
  await clearTokens();            // SecureStore + in-memory
  setUser(null);                  // triggers navigation to Login

  // 3. The conditional navigator swaps to auth screens automatically
}

Edge cases to handle

Logged out on another device

If the user logs out on their tablet, the server revokes all refresh tokens. The phone's next API call gets 401, tries to refresh, refresh returns 401, force-logout triggers. The user sees the login screen.

Token revoked by server (admin action)

Same flow — any 401 that can't be fixed by refresh leads to logout.

Network offline during refresh

// In attemptRefresh:
} catch (err) {
  // Network error — don't clear tokens!
  // The refresh token might still be valid

Important: don't clear tokens on network errors. The user might just be in a tunnel. Only clear on a definitive 401 from the refresh endpoint (server explicitly rejected the token).

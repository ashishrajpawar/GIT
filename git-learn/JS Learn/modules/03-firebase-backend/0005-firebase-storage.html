Firebase Storage — Image Sending

ref · uploadBytesResumable · getDownloadURL · Image messages · Avatar upload ~50 min Hands-on
Why this matters for your WhatsApp clone

WhatsApp's most-used feature after text messages is sending photos. A user picks an image from their gallery, taps Send, and a few seconds later it appears in the conversation on both devices — full resolution, permanently stored, still there when either device is offline. Firebase Storage handles the file hosting. This lesson wires the ImagePicker from Lesson 11 to Firebase Storage, adds upload progress, stores the download URL as a message in Firestore, and displays image messages in the thread. It also completes the profile photo flow from Lesson 11.

1. How Firebase Storage works

Firebase Storage stores files in a folder-like hierarchy called a bucket. Each file has a path (like a file path on disk) and a permanent download URL once uploaded.

// Storage paths for your WhatsApp clone:
avatars/{userId}/profile.jpg          ← user profile photos
chats/{chatId}/images/{timestamp}.jpg ← images sent in a specific chat

The workflow for sending an image is always the same three steps:

  1. Pick — user selects an image with expo-image-picker (Lesson 11)
  2. Upload — send the file bytes to Firebase Storage, get a download URL
  3. Store — save the download URL in a Firestore message document (Lesson 4 pattern)

2. Converting a local URI to uploadable bytes

ImagePicker gives you a local file:// URI. Firebase Storage needs a Blob (binary data). The conversion requires fetch:

async function uriToBlob(uri) {
  const response = await fetch(uri);
  const blob     = await response.blob();
  return blob;
}
Why fetch works on a local file URI

React Native's fetch can read local file:// URIs in addition to HTTP URLs. Calling response.blob() reads the raw bytes. This is the standard pattern — no third-party library needed.

3. Uploading with uploadBytesResumable — with progress

uploadBytesResumable uploads a file and lets you track progress. Use it instead of plain uploadBytes so you can show a progress bar.

import { ref, uploadBytesResumable, getDownloadURL } from 'firebase/storage';
import { storage } from './firebase';

async function uploadImage(uri, path, onProgress) {
  // 1. Convert local URI to Blob
  const blob = await uriToBlob(uri);

  // 2. Create a storage reference at the given path
  const storageRef = ref(storage, path);
  //  e.g. path = 'chats/abc123/images/1720000000000.jpg'

  // 3. Start the upload
  const uploadTask = uploadBytesResumable(storageRef, blob);

  // 4. Return a Promise that resolves with the download URL
  return new Promise((resolve, reject) => {
    uploadTask.on(
      'state_changed',
      (snapshot) => {
        // Progress 0–1
        const progress = snapshot.bytesTransferred / snapshot.totalBytes;
        onProgress?.(progress);   // optional callback — update your progress bar
      },
      (error) => reject(error),   // upload failed
      async () => {
        // Upload complete — get the permanent download URL
        const downloadURL = await getDownloadURL(uploadTask.snapshot.ref);
        resolve(downloadURL);
      }
    );
  });
}

The downloadURL is a permanent HTTPS URL that anyone with the link can load in an <Image> component. Store it in Firestore — it never changes.

4. Sending an image message

An image message is just a Firestore message document with an imageUrl field instead of (or in addition to) text.

import { collection, addDoc, doc, updateDoc, serverTimestamp, increment } from 'firebase/firestore';
import { db, auth } from './firebase';

async function sendImageMessage(chatId, members, localUri) {
  const myUid    = auth.currentUser.uid;
  const filename = `${Date.now()}.jpg`;
  const path     = `chats/${chatId}/images/${filename}`;

  // 1. Upload to Storage
  const downloadURL = await uploadImage(localUri, path, (progress) => {
    setUploadProgress(progress);   // 0.0 → 1.0 — drives your progress bar
  });

  // 2. Write the message document (same pattern as Lesson 4)
  await addDoc(collection(db, 'chats', chatId, 'messages'), {
    text:      '',             // empty — this is an image message
    imageUrl:  downloadURL,    // permanent Storage URL
    senderId:  myUid,
    createdAt: serverTimestamp(),
    read:      false,
  });

  // 3. Update the chat preview
  const unreadUpdates = {};
  members.forEach(uid => {
    if (uid !== myUid) unreadUpdates[`unreadCounts.${uid}`] = increment(1);
  });
  await updateDoc(doc(db, 'chats', chatId), {
    lastMessage:   '📷 Photo',
    lastMessageAt: serverTimestamp(),
    lastSenderId:  myUid,
    ...unreadUpdates,
  });

  setUploadProgress(0);   // reset progress bar
}

5. Displaying image messages in the thread

Update MessageBubble to render an image when imageUrl is present.

function MessageBubble({ message }) {
  const myUid = auth.currentUser?.uid;
  const isMe  = message.senderId === myUid;

  return (
    <View style={[styles.bubbleRow, isMe ? styles.rowRight : styles.rowLeft]}>
      <View style={[styles.bubble, isMe ? styles.bubbleMe : styles.bubbleThem]}>

        {/* Image message */}
        {message.imageUrl ? (
          <Image
            source={{ uri: message.imageUrl }}
            style={styles.messageImage}
            resizeMode="cover"
          />
        ) : (
          // Text message
          <Text style={styles.bubbleText}>{message.text}</Text>
        )}

        <View style={styles.bubbleMeta}>
          <Text style={styles.bubbleTime}>{formatTime(message.createdAt)}</Text>
          {isMe && (
            <Text style={[styles.ticks, message.read && styles.ticksRead]}>
              {message.read ? '✓✓' : '✓'}
            </Text>
          )}
        </View>
      </View>
    </View>
  );
}

7. Uploading a profile photo

This completes the profile photo flow from Lesson 11. After the user picks a photo, upload it to Storage and save the download URL on the Firebase user profile with updateProfile.

import { updateProfile } from 'firebase/auth';
import { ref, uploadBytesResumable, getDownloadURL } from 'firebase/storage';
import { auth, storage } from './firebase';

async function uploadProfilePhoto(localUri) {
  const myUid = auth.currentUser.uid;
  const path  = `avatars/${myUid}/profile.jpg`;

  // Upload — overwrites any previous profile photo at the same path
  const downloadURL = await uploadImage(localUri, path, setUploadProgress);

  // Save to Firebase Auth user profile
  await updateProfile(auth.currentUser, { photoURL: downloadURL });

  // Also save to Firestore user document (for showing in chat lists)
  // await updateDoc(doc(db, 'users', myUid), { photoURL: downloadURL });

  return downloadURL;
}
One path per user — old photo is overwritten

Using avatars/{userId}/profile.jpg (a fixed path per user) means uploading a new photo automatically overwrites the old one. No cleanup needed. If you used a timestamped path each time, old photos would accumulate in Storage and cost money. For profile photos, a fixed path is correct.

8. Storage Security Rules

In the Firebase console: Storage → Rules. Replace the test-mode rules with:

rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {

    // Profile avatars — only the owner can write, anyone authenticated can read
    match /avatars/{userId}/{allPaths=**} {
      allow read:  if request.auth != null;
      allow write: if request.auth != null && request.auth.uid == userId;
    }

    // Chat images — any authenticated user can read and write
    // (in production you'd also check they're a member of the chat)
    match /chats/{chatId}/{allPaths=**} {
      allow read:  if request.auth != null;
      allow write: if request.auth != null;
    }
  }
}

Click Publish.

9. Full working example — MessageThreadScreen with image sending

This extends the MessageThreadScreen from Lesson 4 with image picking, upload progress, and image bubble rendering. Only the additions are shown — merge these into your existing screen.

// Add these imports to your MessageThreadScreen file
import { Image } from 'react-native';
import * as ImagePicker from 'expo-image-picker';
import { ref, uploadBytesResumable, getDownloadURL } from 'firebase/storage';
import { storage } from './firebase';

// ── Inside MessageThreadScreen component ──────────────────────────────────────

const [uploadProgress, setUploadProgress] = useState(0);
const [uploading,      setUploading]      = useState(false);

const [mediaPermission, requestMediaPermission] =
  ImagePicker.useMediaLibraryPermissions();

// Convert local URI to Blob
async function uriToBlob(uri) {
  const response = await fetch(uri);
  return response.blob();
}

// Upload file to Storage, return download URL
async function uploadToStorage(uri, path) {
  const blob        = await uriToBlob(uri);
  const storageRef  = ref(storage, path);
  const uploadTask  = uploadBytesResumable(storageRef, blob);

  return new Promise((resolve, reject) => {
    uploadTask.on('state_changed',
      (snap) => setUploadProgress(snap.bytesTransferred / snap.totalBytes),
      reject,
      async () => resolve(await getDownloadURL(uploadTask.snapshot.ref))
    );
  });
}

// Pick image and send it
async function handlePickAndSend() {
  // Check permission
  if (mediaPermission?.status !== 'granted') {
    const result = await requestMediaPermission();
    if (result.status !== 'granted') return;
  }

  const picked = await ImagePicker.launchImageLibraryAsync({
    mediaTypes: ['images'],
    quality: 0.7,
  });
  if (picked.canceled) return;

  const localUri = picked.assets[0].uri;
  const filename = `${Date.now()}.jpg`;
  const path     = `chats/${chatId}/images/${filename}`;

  setUploading(true);
  setUploadProgress(0);

  try {
    const downloadURL = await uploadToStorage(localUri, path);

    // Write image message to Firestore
    await addDoc(collection(db, 'chats', chatId, 'messages'), {
      text:      '',
      imageUrl:  downloadURL,
      senderId:  myUid,
      createdAt: serverTimestamp(),
      read:      false,
    });

    // Update chat preview
    const unreadUpdates = {};
    members.forEach(uid => {
      if (uid !== myUid) unreadUpdates[`unreadCounts.${uid}`] = increment(1);
    });
    await updateDoc(doc(db, 'chats', chatId), {
      lastMessage:   '📷 Photo',
      lastMessageAt: serverTimestamp(),
      lastSenderId:  myUid,
      ...unreadUpdates,
    });

  } catch (e) {
    console.error('Image send failed:', e.message);
    Alert.alert('Upload failed', 'Could not send the image. Try again.');
  } finally {
    setUploading(false);
    setUploadProgress(0);
  }
}

Anything unclear? Ask your teacher. Common issues: (1) storage/unauthorized — your Storage Security Rules are still in test mode and have expired, or the rules don't allow the current user to write to that path; re-publish the rules from Section 8. (2) Progress stays at 0 then jumps to 100 — this is normal for small images on a fast connection; the progress callback fires once when done. (3) Image doesn't show in the other user's thread — check that imageUrl is stored in the Firestore message document and that MessageBubble checks message.imageUrl before message.text. (4) fetch of local URI fails on Android — make sure you're using the URI from result.assets[0].uri exactly as ImagePicker returns it; don't modify it.

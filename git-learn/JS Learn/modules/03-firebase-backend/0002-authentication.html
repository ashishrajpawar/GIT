Authentication — Sign Up, Log In, Log Out

createUserWithEmailAndPassword · signInWithEmailAndPassword · onAuthStateChanged · signOut ~45 min Hands-on
Why this matters for your WhatsApp clone

In Module 2 you built Login and Register screens that faked the network delay with setTimeout and always succeeded. Now you replace those two lines with real Firebase Auth calls. After this lesson, users can create real accounts, log in on any device, and stay logged in across app restarts — Firebase remembers the session automatically. You also get a unique user ID (uid) for every account, which becomes the key that links each user to their chats and messages in Firestore.

1. The three Firebase Auth functions you need

FunctionWhen to call itReturns
createUserWithEmailAndPassword(auth, email, password)Register screen — new userPromise → UserCredential
signInWithEmailAndPassword(auth, email, password)Login screen — existing userPromise → UserCredential
signOut(auth)Settings screen — log out buttonPromise → void

All three are async — they talk to Firebase servers and return a Promise. Always await them inside a try/catch.

2. Registering a new user

This replaces the await new Promise(r => setTimeout(r, 1200)) fake delay in your RegisterScreen from Lesson 10.

import { createUserWithEmailAndPassword, updateProfile } from 'firebase/auth';
import { auth } from './firebase';

async function handleRegister() {
  const errors = validate({ name, email, password, isRegister: true });
  if (Object.keys(errors).length > 0) { setFormErrors(errors); return; }

  setLoading(true);
  try {
    // 1. Create the account — Firebase stores email + hashed password
    const credential = await createUserWithEmailAndPassword(auth, email, password);

    // 2. Save the display name on the Firebase user profile
    await updateProfile(credential.user, { displayName: name });

    // 3. Navigate into the app — replace so back doesn't return to Register
    navigation.replace('Main');

  } catch (err) {
    setFormErrors({ general: friendlyAuthError(err.code) });
  } finally {
    setLoading(false);
  }
}

credential.user is the newly created Firebase user object. It has a uid (unique ID), email, and after updateProfile, a displayName. You'll store the uid in Firestore documents in Lesson 3.

3. Logging in an existing user

This replaces the fake delay in your LoginScreen.

import { signInWithEmailAndPassword } from 'firebase/auth';
import { auth } from './firebase';

async function handleLogin() {
  const errors = validate({ email, password, isRegister: false });
  if (Object.keys(errors).length > 0) { setFormErrors(errors); return; }

  setLoading(true);
  try {
    await signInWithEmailAndPassword(auth, email, password);
    // On success, auth.currentUser is now set — navigate to main app
    navigation.replace('Main');

  } catch (err) {
    setFormErrors({ general: friendlyAuthError(err.code) });
  } finally {
    setLoading(false);
  }
}
You don't need to store the user yourself

After a successful signInWithEmailAndPassword, Firebase stores the session on the device automatically. auth.currentUser is set immediately and stays set across app restarts — until the user signs out. You don't need AsyncStorage or any manual session management.

4. Handling Firebase Auth error codes

When a Firebase Auth call fails, err.code is a string like 'auth/wrong-password'. Map these to friendly messages — never show the raw Firebase error string to users.

function friendlyAuthError(code) {
  switch (code) {
    case 'auth/email-already-in-use':
      return 'An account with this email already exists. Try logging in instead.';
    case 'auth/invalid-email':
      return 'That email address is not valid.';
    case 'auth/weak-password':
      return 'Password must be at least 6 characters.';
    case 'auth/user-not-found':
    case 'auth/wrong-password':
    case 'auth/invalid-credential':
      // Combine these — never tell an attacker which one was wrong
      return 'Incorrect email or password. Please try again.';
    case 'auth/too-many-requests':
      return 'Too many failed attempts. Please wait a moment and try again.';
    case 'auth/network-request-failed':
      return 'No internet connection. Check your network and try again.';
    default:
      return 'Something went wrong. Please try again.';
  }
}
Never distinguish "user not found" from "wrong password"

Telling a user "no account with that email" is a security risk — it lets attackers enumerate which email addresses have accounts. Always return the same message for both auth/user-not-found and auth/wrong-password: "Incorrect email or password."

5. Staying logged in — onAuthStateChanged

The most important Firebase Auth feature: onAuthStateChanged fires every time the user's authentication state changes — when they log in, when they log out, and when the app starts if they were previously logged in.

This is how you implement "stay logged in" — the app checks the auth state on startup and skips the Login screen if there's already an active session.

import { onAuthStateChanged } from 'firebase/auth';
import { auth } from './firebase';

// In your root App component
export default function App() {
  const [user,          setUser]          = useState(null);
  const [authChecked,   setAuthChecked]   = useState(false);
  //                                        ↑ true once we know if logged in or not

  useEffect(() => {
    // Subscribe — fires immediately with current state, then on every change
    const unsubscribe = onAuthStateChanged(auth, (firebaseUser) => {
      setUser(firebaseUser);       // null = logged out, object = logged in
      setAuthChecked(true);        // we now know the auth state
    });

    return unsubscribe;            // unsubscribe when App unmounts (cleanup)
  }, []);

  // Show nothing while Firebase checks the session — avoids a login flash
  if (!authChecked) return null;

  return (
    <NavigationContainer>
      <Stack.Navigator screenOptions={{ headerShown: false }}>
        {user ? (
          // Logged in — go straight to main app
          <Stack.Screen name="Main" component={MainTabs} />
        ) : (
          // Logged out — show auth screens
          <>
            <Stack.Screen name="Login"    component={LoginScreen} />
            <Stack.Screen name="Register" component={RegisterScreen} />
          </>
        )}
      </Stack.Navigator>
    </NavigationContainer>
  );
}
Conditional navigator — the right way to handle auth state

Rather than calling navigation.navigate from inside the login handler, you let the navigator itself react to user state. When user becomes non-null (login succeeds), the navigator automatically shows MainTabs. When user becomes null (sign out), it automatically shows LoginScreen. No navigation.replace needed — the screens switch by themselves. This is the pattern recommended by React Navigation for auth flows.

6. Reading the current user anywhere in the app

Once logged in, you can read the current user from auth.currentUser anywhere. The most useful fields:

import { auth } from './firebase';

const user = auth.currentUser;

user.uid          // "abc123xyz..." — unique ID, used as Firestore document key
user.email        // "priya@example.com"
user.displayName  // "Priya Sharma" — set via updateProfile
user.photoURL     // profile photo URL — set via updateProfile or Storage upload

You'll use user.uid constantly in Lesson 3 — it's how you query "only this user's chats" from Firestore.

7. Signing out

import { signOut } from 'firebase/auth';
import { auth } from './firebase';

async function handleSignOut() {
  try {
    await signOut(auth);
    // onAuthStateChanged fires with null — navigator switches to Login automatically
  } catch (err) {
    Alert.alert('Sign out failed', 'Please try again.');
  }
}

Because the onAuthStateChanged pattern is in place, you don't call navigation.navigate('Login') after signing out. Setting user to null via the listener causes the navigator to swap screens automatically.

// ── Auth error helper ─────────────────────────────────────────────────────────
function friendlyAuthError(code) {
  switch (code) {
    case 'auth/email-already-in-use':  return 'An account with this email already exists.';
    case 'auth/invalid-email':         return 'That email address is not valid.';
    case 'auth/weak-password':         return 'Password must be at least 6 characters.';
    case 'auth/user-not-found':
    case 'auth/wrong-password':
    case 'auth/invalid-credential':    return 'Incorrect email or password. Please try again.';
    case 'auth/too-many-requests':     return 'Too many attempts. Please wait and try again.';
    case 'auth/network-request-failed':return 'No internet connection. Check your network.';
    default:                           return 'Something went wrong. Please try again.';
  }
}

// ── Validation (same as Lesson 10) ────────────────────────────────────────────
function validate({ name = '', email, password, isRegister }) {
  const errors = {};
  if (isRegister && name.trim().length < 2)
    errors.name = 'Name must be at least 2 characters';
  const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  if (!email.trim())                     errors.email    = 'Email is required';
  else if (!emailRegex.test(email.trim()))errors.email   = 'Enter a valid email address';
  if (!password)                         errors.password = 'Password is required';
  else if (password.length < 6)          errors.password = 'Password must be at least 6 characters';
  return errors;
}

// ── Screen: Login ─────────────────────────────────────────────────────────────
function LoginScreen({ navigation }) {

    if (Object.keys(errors).length > 0) { setFormErrors(errors); return; }

      // onAuthStateChanged fires → navigator switches to MainTabs automatically

      setLoading(false);

      <ScrollView contentContainerStyle={styles.formScroll} keyboardShouldPersistTaps="handled">
        <View style={styles.logoArea}>

          <Text style={styles.appName}>WhatsApp</Text>
        </View>
        <Text style={styles.formTitle}>Log in to your account</Text>
        {formErrors.general ? (
          <View style={styles.generalError}>
            <Text style={styles.generalErrorText}>{formErrors.general}</Text>
          </View>
        ) : null}
        <Text style={styles.label}>Email</Text>
        <TextInput style={[styles.input, formErrors.email && styles.inputError]}
          value={email} onChangeText={t => { setEmail(t); clearError('email'); }}
          placeholder="you@example.com" placeholderTextColor="#aaa"
          keyboardType="email-address" autoCapitalize="none" autoCorrect={false}
          returnKeyType="next"
        />
        {formErrors.email ? <Text style={styles.errorText}>{formErrors.email}</Text> : null}
        <Text style={styles.label}>Password</Text>

// ── Root App — conditional navigator based on auth state ──────────────────────
export default function App() {
  const [user,        setUser]        = useState(undefined);
  //                                    ↑ undefined = not checked yet
  //                                      null      = checked, logged out
  //                                      object    = checked, logged in

  useEffect(() => {
    const unsubscribe = onAuthStateChanged(auth, (firebaseUser) => {
      setUser(firebaseUser ?? null);
    });
    return unsubscribe;   // cleanup listener when App unmounts
  }, []);

  // Blank screen while Firebase checks the persisted session
  // Prevents a flash of the Login screen for already-logged-in users
  if (user === undefined) return <View style={[styles.flex, styles.splash]} />;

  return (
    <NavigationContainer>
      <Stack.Navigator screenOptions={{ headerShown: false }}>
        {user ? (
          <Stack.Screen name="Main" component={MainTabs} />
        ) : (
          <>
            <Stack.Screen name="Login"    component={LoginScreen} />
            <Stack.Screen name="Register" component={RegisterScreen} />
          </>
        )}
      </Stack.Navigator>
    </NavigationContainer>
  );
}

Common issues: (1) auth/invalid-credential on correct password — this is the new Firebase error code that replaces the old auth/wrong-password; the friendlyAuthError function already handles it. (2) App always shows Login even after registering — check that onAuthStateChanged is subscribed in App.js and that user starts as undefined (not null), so the splash shows while Firebase checks the session.

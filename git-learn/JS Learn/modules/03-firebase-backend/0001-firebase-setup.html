Firebase · Lesson 1

Firebase Project Setup & Connecting to Expo

Firebase console · SDK install · firebaseConfig · Auth & Firestore enable ~40 min Setup + Hands-on
Why this matters for your WhatsApp clone

Right now your app's data is hardcoded — the chat list never changes and messages disappear when you close the app. Firebase is the backend that fixes all of this. It stores your users, their messages, and their profile photos on Google's servers, syncs data across devices in real time, and handles authentication so users can log in securely. This lesson sets up Firebase and connects it to your Expo app — one config file is all you need, and every lesson in Module 3 builds on it.

1. What Firebase gives your app

Firebase is a suite of backend services from Google. Your WhatsApp clone will use three of them:

ServiceWhat it does for your appLesson
AuthenticationSign up / log in / log out with email + password. Gives every user a unique UID.Lesson 2
FirestoreReal-time database. Stores chat conversations and messages. Syncs across devices instantly.Lessons 3 & 4
StorageFile hosting for profile photos and images sent in chats.Lesson 5

All three are configured in one place — the Firebase project you create in this lesson.

2. Creating a Firebase project

Go to console.firebase.google.com and follow these steps:

  1. Click Add project
  2. Name it whatsapp-clone (or any name you like)
  3. Google Analytics — disable it (you don't need it)
  4. Click Create project — takes about 30 seconds

You now have a Firebase project. Next, register your app inside it.

3. Registering your app and getting firebaseConfig

Firebase needs to know your app exists before it will accept connections from it. Register a Web app — this gives you a config object that works for both Expo Go and EAS Build.

  1. On the project overview page, click the </> (Web) icon
  2. Give the app a nickname: whatsapp-clone-expo
  3. Do NOT check "Also set up Firebase Hosting" — you don't need it
  4. Click Register app
  5. Firebase shows you a firebaseConfig object — copy it

The config looks like this (your values will be different):

const firebaseConfig = {
  apiKey:            "AIzaSyB...",
  authDomain:        "whatsapp-clone-xxxxx.firebaseapp.com",
  projectId:         "whatsapp-clone-xxxxx",
  storageBucket:     "whatsapp-clone-xxxxx.appspot.com",
  messagingSenderId: "123456789012",
  appId:             "1:123456789012:web:abcdef123456",
};
Keep firebaseConfig out of git

The apiKey in firebaseConfig is not a secret in the traditional sense — it identifies your project but does not grant access. Access is controlled by Firestore Security Rules (covered later). However, you should still avoid committing it to a public repository. Add .env to your .gitignore and store the values there if you plan to make your repo public.

4. Enabling Authentication

  1. In the Firebase console left sidebar, click Build → Authentication
  2. Click Get started
  3. Under Sign-in method, click Email/Password
  4. Toggle Enable to on
  5. Click Save

That's it. Firebase Auth is now ready to create users and verify passwords.

5. Enabling Firestore

  1. In the left sidebar, click Build → Firestore Database
  2. Click Create database
  3. Choose Start in test mode — this allows all reads and writes for 30 days while you build. You'll lock it down with Security Rules in Lesson 3.
  4. Choose a region — pick the one closest to you (e.g. asia-south1 for India, europe-west for Europe)
  5. Click Enable
Test mode expires in 30 days

Test mode's open security rules expire after 30 days. Before you ship the app, you must replace them with real Security Rules. This is covered in Lesson 3. For now, test mode lets you build without worrying about permissions.

6. Enabling Firebase Storage

  1. In the left sidebar, click Build → Storage
  2. Click Get started
  3. Choose Start in test mode
  4. Select the same region as your Firestore
  5. Click Done

7. Installing the Firebase SDK in your Expo project

In your terminal, inside the whatsapp-clone project folder:

npx expo install firebase

Use npx expo install (not plain npm install) so Expo picks the version of the Firebase SDK that is compatible with your current Expo SDK version.

No native code — Firebase JS SDK works in Expo Go

The Firebase JavaScript SDK (firebase package) is pure JavaScript — it has no native C++/Java code. This means it works in plain Expo Go, no EAS Build required. You only need EAS Build for packages with native code (like react-native-webrtc in Module 5). For Modules 3 and 4, Expo Go is fine.

8. Creating the firebase.js config file

Create a single file at the root of your project: firebase.js. Every other file in your app imports from here — if you ever change Firebase projects, you only update one file.

// firebase.js — at the root of your whatsapp-clone project
import { initializeApp } from 'firebase/app';
import { getAuth }       from 'firebase/auth';
import { getFirestore }  from 'firebase/firestore';
import { getStorage }    from 'firebase/storage';

const firebaseConfig = {
  apiKey:            "AIzaSyB...",          // ← paste your values here
  authDomain:        "whatsapp-clone-xxxxx.firebaseapp.com",
  projectId:         "whatsapp-clone-xxxxx",
  storageBucket:     "whatsapp-clone-xxxxx.appspot.com",
  messagingSenderId: "123456789012",
  appId:             "1:123456789012:web:abcdef123456",
};

// Initialize Firebase — only call initializeApp once in the entire app
const app = initializeApp(firebaseConfig);

// Export the services your app needs
export const auth    = getAuth(app);
export const db      = getFirestore(app);
export const storage = getStorage(app);

You now have three named exports: auth, db, and storage. Every screen that needs Firebase imports exactly what it needs:

// In LoginScreen.js
import { auth } from './firebase';

// In ChatListScreen.js
import { db } from './firebase';

// In ProfileScreen.js
import { storage } from './firebase';

9. Verifying the connection

Before building the full auth flow in Lesson 2, verify the connection works with a quick test. Add this temporarily to App.js and check the console:

import { useEffect } from 'react';
import { auth } from './firebase';

export default function App() {
  useEffect(() => {
    // If Firebase is connected, currentUser is null (no one logged in yet)
    // If there's an error, initializeApp threw when the app loaded
    console.log('Firebase connected. Current user:', auth.currentUser);
  }, []);

  return (
    // ... your existing app
  );
}

Open Expo Go, check the terminal output. You should see:

Firebase connected. Current user: null

null is correct — nobody is logged in yet. If you see an error instead, the most common causes are listed in the troubleshooting section below.

10. Project file structure after this lesson

Your project should now look like this:

whatsapp-clone/
  App.js              ← your React Native app
  firebase.js         ← NEW — Firebase config and exports
  package.json
  node_modules/
    firebase/         ← NEW — Firebase SDK
  assets/
  ...
One app initialisation, many imports

initializeApp(firebaseConfig) must only be called once. By putting it in firebase.js and importing the resulting auth, db, and storage from that file, you guarantee this. If you called initializeApp in multiple files, Firebase would throw a "duplicate app" error.

Anything unclear? Ask your teacher. Common issues: (1) Firebase: No Firebase App '[DEFAULT]' has been created — you imported auth or db before firebase.js ran; make sure firebase.js is imported (or the exports used) before any Firebase call. (2) auth/invalid-api-key — you pasted the config incorrectly; double-check each value against the Firebase console. (3) FirebaseError: Failed to get document because the client is offline — the device has no internet; this is expected if you're on a simulator with no network. (4) duplicate-app error — you called initializeApp more than once; make sure it only lives in firebase.js.

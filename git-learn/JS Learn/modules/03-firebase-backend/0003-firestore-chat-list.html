Firestore — Real-Time Chat List

Data model · addDoc · onSnapshot · orderBy · Security Rules ~50 min Hands-on
Why this matters for your WhatsApp clone

The chat list you built in Lesson 13 uses hardcoded data — it never changes and is the same for every user. Firestore replaces that with a real database: chats are stored in the cloud, every user sees only their own conversations, and the list updates instantly when a new message arrives — without the user needing to pull to refresh. This lesson sets up the Firestore data model, reads it with a real-time listener, and locks it down with Security Rules so users can only see their own data.

1. Firestore concepts — documents and collections

Firestore stores data as documents inside collections. Think of a collection as a folder and a document as a JSON file inside it.

// A Firestore path looks like: collection/documentId
// You can nest further: collection/documentId/subCollection/subDocumentId

chats/                        ← collection
  abc123/                     ← document (one chat conversation)
    members: ['uid1', 'uid2']
    lastMessage: 'See you then!'
    lastMessageAt: Timestamp
    unreadCounts: { uid1: 0, uid2: 2 }

    messages/                 ← sub-collection (inside the chat document)
      msg001/                 ← one message document
        text: 'Hey!'
        senderId: 'uid1'
        createdAt: Timestamp
        read: false

Your WhatsApp clone uses two levels:

  • /chats/{chatId} — one document per conversation, stores metadata (last message, members, unread counts)
  • /chats/{chatId}/messages/{messageId} — sub-collection of all messages in that chat (covered in Lesson 4)

2. The chat document shape

Every document in the chats collection looks like this:

{
  // Who is in this chat
  members:       ['uid_ashish', 'uid_priya'],   // array of user UIDs
  memberNames:   { uid_ashish: 'Ashish', uid_priya: 'Priya Sharma' },
  memberColors:  { uid_ashish: '#075E54', uid_priya: '#128C7E' },

  // Last message preview (shown in the chat list)
  lastMessage:   'Perfect, see you then!',
  lastMessageAt: Timestamp,   // Firebase server timestamp — used for ordering
  lastSenderId:  'uid_priya',

  // Unread counts per user
  unreadCounts:  { uid_ashish: 2, uid_priya: 0 },

  // Group chat support
  isGroup:       false,
  groupName:     null,        // only set for group chats
}

The members array is the key to querying — you ask Firestore for "all chats where members contains my uid".

3. Creating a chat document — addDoc

To start a new chat between two users, add a document to the chats collection. Firestore generates a unique ID automatically.

import { collection, addDoc, serverTimestamp } from 'firebase/firestore';
import { db, auth } from './firebase';

async function startChat(otherUserId, otherUserName) {
  const myUid  = auth.currentUser.uid;
  const myName = auth.currentUser.displayName;

  const newChat = {
    members:       [myUid, otherUserId],
    memberNames:   { [myUid]: myName,  [otherUserId]: otherUserName },
    memberColors:  { [myUid]: '#075E54', [otherUserId]: '#128C7E' },
    lastMessage:   '',
    lastMessageAt: serverTimestamp(),   // Firebase server time — never use new Date()
    lastSenderId:  null,
    unreadCounts:  { [myUid]: 0, [otherUserId]: 0 },
    isGroup:       false,
    groupName:     null,
  };

  const docRef = await addDoc(collection(db, 'chats'), newChat);
  console.log('New chat ID:', docRef.id);
  return docRef.id;
}
Always use serverTimestamp() for time fields

serverTimestamp() uses Firebase's server clock, not the device clock. This matters because different phones have different times — a phone that is 5 minutes ahead would make its messages appear at the top of the list. Server timestamps are consistent regardless of where the message was sent from.

4. Reading chats once — getDocs

Use getDocs to fetch the chat list once — good for initial load or manual refresh. This is the "snapshot at a point in time" approach.

import { collection, query, where, orderBy, getDocs } from 'firebase/firestore';
import { db, auth } from './firebase';

async function loadChats() {
  const myUid = auth.currentUser.uid;

  // Query: chats where I am a member, sorted newest first
  const q = query(
    collection(db, 'chats'),
    where('members', 'array-contains', myUid),   // only MY chats
    orderBy('lastMessageAt', 'desc')             // newest at top
  );

  const snapshot = await getDocs(q);

  const chats = snapshot.docs.map(doc => ({
    id:           doc.id,                        // Firestore document ID
    ...doc.data(),                               // all the fields
    // Build display fields from the raw data:
    name:         doc.data().isGroup
                    ? doc.data().groupName
                    : doc.data().memberNames[otherMember(doc.data().members, myUid)],
    unread:       doc.data().unreadCounts?.[myUid] ?? 0,
    time:         formatTimestamp(doc.data().lastMessageAt),
  }));

  return chats;
}

// Get the other person's uid from the members array
function otherMember(members, myUid) {
  return members.find(uid => uid !== myUid);
}

// Convert a Firestore Timestamp to a display string
function formatTimestamp(ts) {
  if (!ts) return '';
  const date = ts.toDate();                      // Timestamp → JS Date
  const now  = new Date();
  const diff = now - date;
  const oneDay = 86400000;
  if (diff < oneDay)   return date.toLocaleTimeString([], { hour: '2-digit', minute: '2-digit' });
  if (diff < oneDay*2) return 'Yesterday';
  return date.toLocaleDateString([], { weekday: 'short' });
}

5. Real-time updates — onSnapshot

onSnapshot is the key difference between Firestore and a regular REST API. It sets up a live listener — whenever any chat document that matches your query changes (new message, unread count update), Firestore pushes the update to your app instantly. No polling, no pull-to-refresh needed.

import { collection, query, where, orderBy, onSnapshot } from 'firebase/firestore';
import { db, auth } from './firebase';

useEffect(() => {
  const myUid = auth.currentUser?.uid;
  if (!myUid) return;

  setLoading(true);

  const q = query(
    collection(db, 'chats'),
    where('members', 'array-contains', myUid),
    orderBy('lastMessageAt', 'desc')
  );

  // Subscribe — fires immediately with current data, then on every change
  const unsubscribe = onSnapshot(q,
    (snapshot) => {
      const chats = snapshot.docs.map(doc => ({
        id:     doc.id,
        ...doc.data(),
        name:   doc.data().isGroup
                  ? doc.data().groupName
                  : doc.data().memberNames?.[otherMember(doc.data().members, myUid)] ?? 'Unknown',
        unread: doc.data().unreadCounts?.[myUid] ?? 0,
        time:   formatTimestamp(doc.data().lastMessageAt),
      }));
      setAllChats(chats);
      setLoading(false);
      setError(null);
    },
    (err) => {
      console.error('Firestore error:', err);
      setError('Could not load chats. Check your connection.');
      setLoading(false);
    }
  );

  return unsubscribe;   // crucial — unsubscribes when the component unmounts
}, []);
Always return the unsubscribe function from useEffect

If you forget return unsubscribe, the Firestore listener keeps running even after the component unmounts — listening forever, updating state on an unmounted component, causing memory leaks and console warnings. The return is the cleanup function that React calls when the component unmounts.

6. Firestore Security Rules — locking down your data

Right now your Firestore is in test mode — anyone can read and write anything. Before you ship, replace those rules with ones that require authentication and ownership checks.

In the Firebase console: Firestore Database → Rules. Replace the existing rules with:

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Chats collection
    match /chats/{chatId} {
      // Only authenticated users who are members of this chat can read it
      allow read: if request.auth != null
                  && request.auth.uid in resource.data.members;

      // Only authenticated members can update (e.g. mark as read, update lastMessage)
      allow update: if request.auth != null
                    && request.auth.uid in resource.data.members;

      // Only authenticated users can create a new chat
      // and they must include themselves in the members array
      allow create: if request.auth != null
                    && request.auth.uid in request.resource.data.members;

      // Messages sub-collection
      match /messages/{messageId} {
        // Any member of the parent chat can read messages
        allow read: if request.auth != null
                    && request.auth.uid in get(/databases/$(database)/documents/chats/$(chatId)).data.members;

        // Only members can write messages
        allow create: if request.auth != null
                      && request.auth.uid in get(/databases/$(database)/documents/chats/$(chatId)).data.members
                      && request.resource.data.senderId == request.auth.uid;
      }
    }
  }
}

Click Publish. These rules mean:

  • You must be logged in to do anything
  • You can only read chats you are a member of
  • You can only send messages in chats you belong to
  • You can only send messages as yourself (senderId == request.auth.uid)
Composite index required for the chat list query

The query where('members', 'array-contains', uid) + orderBy('lastMessageAt', 'desc') uses two fields — Firestore requires a composite index for this. The first time you run the query, Firestore throws an error with a link in the console. Click that link — it takes you directly to the Firebase console to create the index with one click. The index takes about a minute to build.

7. Seeding test data from the app

Before you build a contact-picker screen, seed some test chats directly from the app so the chat list shows real data. Add a temporary button to your Settings screen:

import { collection, addDoc, serverTimestamp } from 'firebase/firestore';
import { db, auth } from './firebase';

async function seedTestChats() {
  const myUid  = auth.currentUser.uid;
  const myName = auth.currentUser.displayName ?? 'Me';

  const testChats = [
    { otherUid: 'fake_uid_priya',  otherName: 'Priya Sharma',  lastMsg: 'Perfect, see you then!' },
    { otherUid: 'fake_uid_rahul',  otherName: 'Rahul Mehta',   lastMsg: 'I\'ll send the file now.' },
    { otherUid: 'fake_uid_family', otherName: 'Family Group',  lastMsg: 'Mom: Dinner at 7!', isGroup: true },
  ];

  for (const chat of testChats) {
    await addDoc(collection(db, 'chats'), {
      members:       [myUid, chat.otherUid],
      memberNames:   { [myUid]: myName, [chat.otherUid]: chat.otherName },
      memberColors:  { [myUid]: '#075E54', [chat.otherUid]: '#128C7E' },
      lastMessage:   chat.lastMsg,
      lastMessageAt: serverTimestamp(),
      lastSenderId:  chat.otherUid,
      unreadCounts:  { [myUid]: Math.floor(Math.random() * 4), [chat.otherUid]: 0 },
      isGroup:       chat.isGroup ?? false,
      groupName:     chat.isGroup ? chat.otherName : null,
    });
  }
  Alert.alert('Done', '3 test chats created!');
}

8. Full working example — ChatListScreen with live Firestore data

This replaces the SAMPLE_CHATS array in your ChatListScreen from Lesson 13 with a live Firestore listener. Everything else — the UI, search, skeletons, error states — stays identical. Only the data source changes.

function otherMember(members, myUid) {
  return members.find(uid => uid !== myUid) ?? '';
}

function formatTimestamp(ts) {
  if (!ts) return '';
  const date = ts.toDate();
  const now  = new Date();
  const diff = now - date;
  const day  = 86400000;
  if (diff < day)   return date.toLocaleTimeString([], { hour: '2-digit', minute: '2-digit' });
  if (diff < day*2) return 'Yesterday';

}

// ── Skeleton (same as Lesson 13) ──────────────────────────────────────────────
function SkeletonBlock({ width, height, borderRadius, style }) {
  const opacity = useRef(new Animated.Value(0.4)).current;
  useEffect(() => {
    Animated.loop(
      Animated.sequence([
        Animated.timing(opacity, { toValue: 1,   duration: 700, useNativeDriver: true }),
        Animated.timing(opacity, { toValue: 0.4, duration: 700, useNativeDriver: true }),
      ])
    ).start();
  }, []);
  return (
    <Animated.View style={[{ backgroundColor: '#e0e0e0' }, { width, height, borderRadius }, { opacity }, style]} />
  );
}

// ── ChatListScreen ────────────────────────────────────────────────────────────
export function ChatListScreen({ navigation }) {
  const [allChats,   setAllChats]   = useState([]);
  const [loading,    setLoading]    = useState(true);
  const [error,      setError]      = useState(null);
  const [query_str,  setQueryStr]   = useState('');
  const [showSearch, setShowSearch] = useState(false);

  const myUid = auth.currentUser?.uid;

  // Derived — filtered list
  const filteredChats = query_str.trim()
    ? allChats.filter(c =>
        (c.name ?? '').toLowerCase().includes(query_str.toLowerCase()) ||
        (c.lastMessage ?? '').toLowerCase().includes(query_str.toLowerCase())
      )
    : allChats;

  // Tab badge — total unread
  useEffect(() => {
    const total = allChats.reduce((sum, c) => sum + (c.unread ?? 0), 0);
    navigation.setOptions({ tabBarBadge: total > 0 ? total : undefined });
  }, [allChats, navigation]);

  // Live Firestore listener
  useEffect(() => {
    if (!myUid) return;
    setLoading(true);

    const q = query(
      collection(db, 'chats'),
      where('members', 'array-contains', myUid),
      orderBy('lastMessageAt', 'desc')
    );

    const unsubscribe = onSnapshot(q,
      (snapshot) => {
        const chats = snapshot.docs.map(doc => {
          const data = doc.data();

            id:          doc.id,
            ...data,

        setLoading(false);
        setError(null);
      },
      (err) => {
        console.error(err);
        setError('Could not load chats. Check your connection.');
        setLoading(false);
      }
    );

    return unsubscribe;   // unsubscribe on unmount
  }, [myUid]);

Common issues: (1) The query requires an index error in the console — click the link in the error message to auto-create the composite index in the Firebase console; wait ~1 min for it to build.

Vite + React Project Setup

A8 — Lesson 1 of 4 ~45 min
Why this matters for Token

The redemption page (tokn.app/t/CODE) is a separate web app — not the mobile app, not React Native Web. It's a plain Vite + React project that runs in any browser. Holders never install anything; they open a URL and communicate through it. This web app lives in the web/ folder of your repo, shares TypeScript types with the mobile app via shared/, and deploys as its own container on Coolify alongside the API.

Why a separate web app?

Token has two clients with completely different users:

  • Mobile app (React Native + Expo) — for the token issuer who manages their tokens, sees conversations, takes calls
  • Web app (Vite + React) — for the token holder who redeems a code and communicates through the browser

The web app is intentionally lightweight. No account required. No install. Just open the link and talk.

Creating the web/ directory

Inside your Token repo, create the web app with Vite:

# From the token/ root
npm create vite@latest web -- --template react-ts

cd web
npm install
npm install react-router-dom
npm install -D tailwindcss @tailwindcss/vite

vite.config.ts

The Vite config handles path aliases (so you can import from shared/) and the development proxy:

import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import tailwindcss from '@tailwindcss/vite';
import path from 'path';

export default defineConfig({
  plugins: [react(), tailwindcss()],
  resolve: {
    alias: {
      '@': path.resolve(__dirname, './src'),
      '@shared': path.resolve(__dirname, '../shared'),
    },
  },
  server: {
    port: 5173,
    proxy: {
      '/api': {
        target: 'http://localhost:3000',
        changeOrigin: true,
      },
      '/ws': {
        target: 'ws://localhost:3000',
        ws: true,
      },
    },
  },
});

The proxy means during development, fetch('/api/tokens/ABC') hits your local Express server without CORS issues.

Environment variables

Vite exposes env vars prefixed with VITE_:

# web/.env.development
VITE_API_URL=http://localhost:3000
VITE_WS_URL=ws://localhost:3000

# web/.env.production
VITE_API_URL=https://api.tokn.app
VITE_WS_URL=wss://api.tokn.app
// src/lib/api.ts
const API_URL = import.meta.env.VITE_API_URL || '';
const WS_URL = import.meta.env.VITE_WS_URL || '';

export { API_URL, WS_URL };
Important

import.meta.env.VITE_* variables are embedded at build time, not runtime. If you change them, you must rebuild. Never put secrets in VITE_ vars — they end up in the browser bundle.

Shared types from shared/

The web app reuses the same TypeScript types as the mobile app:

App.tsx with React Router

// web/src/App.tsx
import { BrowserRouter, Routes, Route } from 'react-router-dom';
import { RedeemPage } from './pages/RedeemPage';
import { ChatPage } from './pages/ChatPage';
import { CallPage } from './pages/CallPage';
import { ExpiredPage } from './pages/ExpiredPage';

export default function App() {
  return (
    <BrowserRouter>
      <Routes>
        {/* The main redemption URL pattern */}
        <Route path="/t/:code" element={<RedeemPage />} />

        {/* After redemption, holder enters chat */}
        <Route path="/t/:code/chat" element={<ChatPage />} />

        {/* Voice/video call page */}
        <Route path="/t/:code/call" element={<CallPage />} />

        {/* Token no longer valid */}
        <Route path="/t/:code/expired" element={<ExpiredPage />} />

        {/* Fallback */}
        <Route path="*" element={<div>Invalid link</div>} />
      </Routes>
    </BrowserRouter>
  );
}

Notice the URL pattern: /t/:code. Short, clean, easy to type or scan from a QR code.

Dockerfile for Coolify deployment

Multi-stage build: build with Node, serve with nginx:

# web/Dockerfile
FROM node:20-alpine AS builder

WORKDIR /app

# Copy shared types first (needed at build time)
COPY shared/ /shared/

# Install and build the web app
COPY web/package*.json ./
RUN npm ci

COPY web/ ./
ENV VITE_API_URL=https://api.tokn.app
ENV VITE_WS_URL=wss://api.tokn.app
RUN npm run build

# --- Production stage ---
FROM nginx:alpine

# Custom nginx config for SPA routing
COPY web/nginx.conf /etc/nginx/conf.d/default.conf

# Copy built files
COPY --from=builder /app/dist /usr/share/nginx/html

EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

nginx.conf for SPA routing

Single-page apps need all routes to serve index.html:

# web/nginx.conf
server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;

    # SPA fallback — all routes serve index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # Cache static assets aggressively
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # Don't cache index.html (always serve fresh)
    location = /index.html {
        expires -1;
        add_header Cache-Control "no-store";
    }
}

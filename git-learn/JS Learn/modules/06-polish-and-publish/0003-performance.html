Polish & Publish · Lesson 3

Performance

FlatList tuning · React.memo · Image caching · Hermes · Bundle size ~50 min Hands-on
Why this matters for your WhatsApp clone

WhatsApp handles hundreds of chats and thousands of messages without stuttering. If your chat list takes a second to scroll or your message thread lags when new messages arrive, users will leave. Performance isn't about fancy algorithms — it's about not doing unnecessary work. This lesson shows you the specific patterns that make the difference between "feels sluggish" and "feels instant" on real devices.

1. The biggest performance problem: unnecessary re-renders

Every time a React component re-renders, it recalculates its styles, runs its functions, and re-creates its JSX tree. In a list of 200 chats, if one chat gets a new message and all 200 re-render, that's 199 wasted renders.

How to see the problem: Wrap your component in a console.log:

function ChatRow({ chat }) {
  console.log('Rendering:', chat.name);  // Watch how often this fires
  return (
    <View>
      <Text>{chat.name}</Text>
      <Text>{chat.lastMessage}</Text>
    </View>
  );
}

When you scroll or when any state changes in the parent, you'll see EVERY row re-render. That's the problem we're fixing.

2. React.memo — skip re-renders when props haven't changed

React.memo wraps a component and tells React: "only re-render this if its props actually changed." This is the single biggest performance win for lists:

import React from 'react';

// ❌ Without memo — re-renders every time parent renders
function ChatRow({ chat, onPress }) {
  return (
    <Pressable onPress={onPress}>
      <Text>{chat.name}</Text>
      <Text>{chat.lastMessage}</Text>
    </Pressable>
  );
}

// ✅ With memo — only re-renders when chat or onPress changes
const ChatRow = React.memo(function ChatRow({ chat, onPress }) {
  return (
    <Pressable onPress={onPress}>
      <Text>{chat.name}</Text>
      <Text>{chat.lastMessage}</Text>
    </Pressable>
  );
});

Important: React.memo does a shallow comparison of props. This means:

  • Strings, numbers, booleans → compared by value (works automatically)
  • Objects, arrays → compared by reference (a new object = re-render, even if contents are the same)
  • Functions → a new function reference every render unless you use useCallback

3. useCallback — stabilizing function references

This is a common trap. When you pass an inline function to a memoized child, it gets a new reference every render — defeating the memo:

// ❌ Creates a new function on every render — ChatRow always re-renders
function ChatList() {
  const [chats, setChats] = useState(CHATS);

  return (
    <FlatList
      data={chats}
      renderItem={({ item }) => (
        <ChatRow
          chat={item}
          onPress={() => navigateToChat(item.id)}  // ← new function every time
        />
      )}
    />
  );
}

// ✅ Stable function reference — ChatRow stays memoized
function ChatList() {
  const [chats, setChats] = useState(CHATS);

  const handlePress = useCallback((chatId) => {
    navigateToChat(chatId);
  }, []);  // Empty deps = same function forever

  return (
    <FlatList
      data={chats}
      renderItem={({ item }) => (
        <ChatRow
          chat={item}
          onPress={() => handlePress(item.id)}
        />
      )}
    />
  );
}

Even better — pass the ID and let the child call back:

const ChatRow = React.memo(function ChatRow({ chat, onPress }) {
  return (
    <Pressable onPress={() => onPress(chat.id)}>
      <Text>{chat.name}</Text>
    </Pressable>
  );
});

// Parent:
const handlePress = useCallback((chatId) => {
  navigation.navigate('Chat', { chatId });
}, [navigation]);

4. FlatList performance props

FlatList has built-in props specifically for performance. Here's the complete list you should use for a production chat app:

<FlatList
  data={chats}
  renderItem={renderChatRow}
  keyExtractor={(item) => item.id}

  // ─── Performance props ───
  removeClippedSubviews={true}        // Detach off-screen items from native view hierarchy
  maxToRenderPerBatch={15}            // Render 15 items per frame (default 10)
  windowSize={10}                     // Keep 10 screens worth in memory (default 21)
  initialNumToRender={12}             // Render first 12 items immediately
  updateCellsBatchingPeriod={50}      // Wait 50ms between batch renders (default 50)
  getItemLayout={(data, index) => (   // Skip measurement if heights are fixed
    { length: 72, offset: 72 * index, index }
  )}
/>

What each prop does:

Prop Effect When to use
removeClippedSubviews Removes off-screen views from the native rendering tree Always (Android especially)
getItemLayout Tells FlatList the height of every item without measuring When all items have the same height (chat rows = 72px)
windowSize How many screens above/below to keep rendered Lower = less memory, higher = smoother scroll
maxToRenderPerBatch Items rendered per batch during fast scroll Increase for shorter items, decrease for complex items
initialNumToRender Items rendered on first mount Set to fill one screen (avoids blank space)

5. Message list: inverted FlatList performance

Your message thread uses inverted={true} to show newest messages at the bottom. This has a specific performance consideration — new messages prepend to the data array, which can cause the entire list to re-measure:

// ❌ Spreading creates a new array reference every time
function addMessage(newMsg) {
  setMessages((prev) => [...prev, newMsg]);
}

// ✅ For inverted lists, prepend (newest first in data):
function addMessage(newMsg) {
  setMessages((prev) => [newMsg, ...prev]);
}

// ✅ With getItemLayout for fixed-height messages (if possible):
// Note: Chat bubbles have variable heights, so you usually CAN'T use getItemLayout here.
// Instead, rely on React.memo for each MessageBubble component.

For message threads with variable-height bubbles:

const MessageBubble = React.memo(function MessageBubble({ message }) {
  const isMine = message.senderId === currentUserId;
  return (
    <View style={[styles.bubble, isMine ? styles.sent : styles.received]}>
      <Text>{message.text}</Text>
      <Text style={styles.time}>{message.time}</Text>
    </View>
  );
});

// FlatList for messages:
<FlatList
  data={messages}
  renderItem={({ item }) => <MessageBubble message={item} />}
  inverted={true}
  keyExtractor={(item) => item.id}
  removeClippedSubviews={true}
  maxToRenderPerBatch={20}
  windowSize={15}
/>

6. Image caching with expo-image

The default React Native Image component re-downloads images every time. For a chat app with profile pictures and sent photos, this wastes data and causes flickering. Use expo-image instead — it caches automatically:

npx expo install expo-image
import { Image } from 'expo-image';

// Drop-in replacement with automatic caching
<Image
  source={{ uri: user.avatarUrl }}
  style={{ width: 50, height: 50, borderRadius: 25 }}
  placeholder={require('../assets/avatar-placeholder.png')}
  contentFit="cover"
  transition={200}          // Fade in over 200ms
  cachePolicy="memory-disk" // Cache in RAM and on disk
/>

Why expo-image over React Native's Image:

  • Disk caching — downloaded once, loaded from disk forever after
  • Memory caching — recently viewed images stay in RAM
  • Placeholder — shows a low-res image or colour while loading
  • BlurHash support — show a blurred preview before the image loads
  • Animated transitions — smooth fade-in instead of pop
  • Better performance — uses native image decoders (not JavaScript)

7. Avoiding expensive computations: useMemo

If you compute derived data on every render (filtering, sorting, counting), that computation runs even when the source data hasn't changed. Use useMemo to cache the result:

// ❌ Filters the entire list on EVERY render
function ChatList({ chats, searchQuery }) {
  const filtered = chats.filter((c) =>
    c.name.toLowerCase().includes(searchQuery.toLowerCase())
  );
  return <FlatList data={filtered} ... />;
}

// ✅ Only re-filters when chats or searchQuery actually changes
function ChatList({ chats, searchQuery }) {
  const filtered = useMemo(() => {
    if (!searchQuery) return chats;
    const q = searchQuery.toLowerCase();
    return chats.filter((c) => c.name.toLowerCase().includes(q));
  }, [chats, searchQuery]);

  return <FlatList data={filtered} ... />;
}

Other places to use useMemo in your WhatsApp clone:

  • Unread count badge: useMemo(() => chats.filter(c => c.unread > 0).length, [chats])
  • Sorted chat list: useMemo(() => [...chats].sort((a,b) => b.lastTime - a.lastTime), [chats])
  • Group member names: useMemo(() => members.map(m => m.name).join(', '), [members])

8. Hermes engine — enabled by default

Hermes is a JavaScript engine built specifically for React Native. It compiles your JavaScript to bytecode during the build, so the phone doesn't have to parse raw JavaScript at startup. This gives you:

  • Faster startup — 30-50% faster cold start
  • Lower memory usage — ~30% less RAM
  • Smaller bundle — bytecode is more compact than raw JS

With Expo SDK 49+, Hermes is enabled by default. Verify in your app.json:

{
  "expo": {
    "jsEngine": "hermes"   // This is the default — don't set it to "jsc"
  }
}

If you ever see "jsEngine": "jsc" in an old project, change it to "hermes" for free performance gains.

9. Reducing bundle size

A smaller app downloads faster and runs faster. Check what's taking space:

# See your bundle contents (after building)
npx expo export --platform android
npx react-native-bundle-visualizer

Common size wins:

Problem Fix Savings
Importing entire lodash import debounce from 'lodash/debounce' (not import _ from 'lodash') ~70KB
Large image assets Compress PNGs, use WebP for photos Varies (often 50%+)
Unused Firebase packages Only import modules you use (auth, firestore, storage) ~200KB
moment.js for dates Use date-fns (tree-shakeable) or native Intl.DateTimeFormat ~230KB

10. Network performance: Firestore query optimization

Firestore charges per read and bad queries can cause slow loads. Optimize for your WhatsApp clone:

// ❌ Fetches ALL messages (could be thousands)
const q = query(collection(db, 'chats', chatId, 'messages'));

// ✅ Fetch only the latest 50 messages, ordered by time
const q = query(
  collection(db, 'chats', chatId, 'messages'),
  orderBy('createdAt', 'desc'),
  limit(50)
);

// ✅ For the chat list: only fetch chats where user is a member
const q = query(
  collection(db, 'chats'),
  where('members', 'array-contains', currentUid),
  orderBy('lastMessageTime', 'desc'),
  limit(30)
);

// ✅ Paginate: load more when user scrolls to top
const nextPageQuery = query(
  collection(db, 'chats', chatId, 'messages'),
  orderBy('createdAt', 'desc'),
  startAfter(lastVisibleDoc),
  limit(50)
);

Key rules:

  • Always use limit() — never fetch unbounded collections
  • Always use orderBy() — ensures consistent pagination
  • Use startAfter() for pagination — loads next page from where you left off
  • Use onSnapshot for real-time data, getDocs for one-time reads (like old messages)

What to look for:

  • "Why did this render?" tooltip — shows which props changed

12. Full runnable App.js — Optimized chat list

This example demonstrates all performance techniques: React.memo, useCallback, useMemo, FlatList props, and expo-image. It handles 500+ chats without stuttering.

// App.js — Performance-optimized chat list
import React, { useState, useCallback, useMemo } from 'react';
import {
  View, Text, FlatList, Pressable, TextInput, StyleSheet,
  StatusBar, Platform,
} from 'react-native';
import { Image } from 'expo-image';

// ─── Design tokens ──────────────────────────────────────────────────
const COLORS = {
  darkGreen: '#075E54',
  lightGreen: '#25D366',
  gray200: '#E8E8E8',
  gray500: '#667781',
  gray900: '#111B21',
  white: '#FFFFFF',
};

// ─── Generate 200 sample chats for testing ──────────────────────────
const NAMES = ['Priya', 'Rahul', 'Neha', 'Ashish', 'Meera', 'Vikram', 'Ananya', 'Arjun', 'Divya', 'Karthik'];
const MESSAGES = ['Hey!', 'See you tomorrow', 'The meeting is at 3', 'Sent the file', 'Okay sounds good', 'Can you call me?', 'Haha 😂', 'On my way', 'Thanks!', 'Got it'];

const SAMPLE_CHATS = Array.from({ length: 200 }, (_, i) => ({
  id: String(i),
  name: NAMES[i % NAMES.length] + (i > 9 ? ` ${Math.floor(i / 10)}` : ''),
  message: MESSAGES[i % MESSAGES.length],
  time: `${9 + (i % 12)}:${String(i % 60).padStart(2, '0')}`,
  unread: i % 7 === 0 ? Math.ceil(Math.random() * 5) : 0,
  avatar: `https://i.pravatar.cc/100?img=${(i % 70) + 1}`,
}));

const ITEM_HEIGHT = 72;

// ─── Memoized Chat Row ──────────────────────────────────────────────
const ChatRow = React.memo(function ChatRow({ chat, onPress }) {
  return (
    <Pressable
      onPress={() => onPress(chat.id)}
      style={styles.chatRow}
      android_ripple={{ color: 'rgba(0,0,0,0.08)' }}
    >
      <Image
        source={{ uri: chat.avatar }}
        style={styles.avatar}
        contentFit="cover"
        cachePolicy="memory-disk"
        transition={150}
      />
      <View style={styles.chatContent}>
        <View style={styles.topRow}>
          <Text style={styles.name} numberOfLines={1}>{chat.name}</Text>
          <Text style={[styles.time, chat.unread > 0 && { color: COLORS.lightGreen }]}>
            {chat.time}
          </Text>
        </View>
        <View style={styles.bottomRow}>
          <Text style={styles.message} numberOfLines={1}>{chat.message}</Text>
          {chat.unread > 0 && (
            <View style={styles.badge}>
              <Text style={styles.badgeText}>{chat.unread}</Text>
            </View>
          )}
        </View>
      </View>
    </Pressable>
  );
});

// ─── Memoized separator ─────────────────────────────────────────────
const Separator = React.memo(function Separator() {
  return (
    <View style={styles.separatorOuter}>
      <View style={styles.separatorLine} />
    </View>
  );
});

// ─── Main App ───────────────────────────────────────────────────────
export default function App() {
  const [chats] = useState(SAMPLE_CHATS);
  const [search, setSearch] = useState('');

  // ✅ useMemo: only re-filter when chats or search changes
  const filteredChats = useMemo(() => {
    if (!search.trim()) return chats;
    const q = search.toLowerCase();
    return chats.filter((c) => c.name.toLowerCase().includes(q));
  }, [chats, search]);

  // ✅ useCallback: stable function reference for memoized children
  const handleChatPress = useCallback((chatId) => {
    console.log('Navigate to chat:', chatId);
  }, []);

  // ✅ getItemLayout: skip measurement for fixed-height rows
  const getItemLayout = useCallback((data, index) => ({
    length: ITEM_HEIGHT,
    offset: ITEM_HEIGHT * index,
    index,
  }), []);

  // ✅ Stable renderItem function
  const renderItem = useCallback(({ item }) => (
    <ChatRow chat={item} onPress={handleChatPress} />
  ), [handleChatPress]);

  // ✅ Stable keyExtractor
  const keyExtractor = useCallback((item) => item.id, []);

  return (
    <View style={styles.container}>
      <StatusBar barStyle="light-content" backgroundColor={COLORS.darkGreen} />

      {/* Header */}
      <View style={styles.header}>
        <Text style={styles.headerTitle}>WhatsApp</Text>
      </View>

      {/* Search bar */}
      <View style={styles.searchContainer}>
        <TextInput
          style={styles.searchInput}
          placeholder="Search chats..."
          placeholderTextColor={COLORS.gray500}
          value={search}
          onChangeText={setSearch}
        />
      </View>

      {/* Chat list */}
      <FlatList
        data={filteredChats}
        renderItem={renderItem}
        keyExtractor={keyExtractor}
        ItemSeparatorComponent={Separator}
        getItemLayout={getItemLayout}
        removeClippedSubviews={true}
        maxToRenderPerBatch={15}
        windowSize={10}
        initialNumToRender={12}
      />

      {/* Count indicator */}
      <View style={styles.countBar}>
        <Text style={styles.countText}>
          {filteredChats.length} chats {search ? `(filtered from ${chats.length})` : ''}
        </Text>
      </View>
    </View>
  );
}

// ─── Styles ─────────────────────────────────────────────────────────
const styles = StyleSheet.create({
  container: { flex: 1, backgroundColor: COLORS.white },
  header: {
    backgroundColor: COLORS.darkGreen,
    paddingTop: Platform.OS === 'ios' ? 54 : 40,
    paddingBottom: 12,
    paddingHorizontal: 16,
  },
  headerTitle: { fontSize: 22, fontWeight: 'bold', color: COLORS.white },
  searchContainer: { padding: 8, backgroundColor: COLORS.white },
  searchInput: {
    backgroundColor: '#F0F2F5',
    borderRadius: 20,
    paddingHorizontal: 16,
    paddingVertical: 8,
    fontSize: 15,
  },
  chatRow: {
    flexDirection: 'row',
    alignItems: 'center',
    height: ITEM_HEIGHT,
    paddingHorizontal: 16,
  },
  avatar: { width: 50, height: 50, borderRadius: 25 },
  chatContent: { flex: 1, marginLeft: 12 },
  topRow: { flexDirection: 'row', justifyContent: 'space-between', alignItems: 'center', marginBottom: 3 },
  name: { fontSize: 16, fontWeight: '600', color: COLORS.gray900, flex: 1 },
  time: { fontSize: 12, color: COLORS.gray500, marginLeft: 8 },
  bottomRow: { flexDirection: 'row', justifyContent: 'space-between', alignItems: 'center' },
  message: { fontSize: 14, color: COLORS.gray500, flex: 1 },
  badge: {
    backgroundColor: COLORS.lightGreen, borderRadius: 10,
    minWidth: 20, height: 20, justifyContent: 'center', alignItems: 'center',
    paddingHorizontal: 6, marginLeft: 8,
  },
  badgeText: { color: COLORS.white, fontSize: 12, fontWeight: 'bold' },
  separatorOuter: { paddingLeft: 78 },
  separatorLine: { height: StyleSheet.hairlineWidth, backgroundColor: COLORS.gray200 },
  countBar: { padding: 8, alignItems: 'center', backgroundColor: '#F7F8FA' },
  countText: { fontSize: 12, color: COLORS.gray500 },
});

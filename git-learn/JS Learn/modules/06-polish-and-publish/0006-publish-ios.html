Polish & Publish · Lesson 6

Build & Publish to iOS

Apple Developer · EAS Build · App Store Connect · TestFlight · Release ~60 min Step-by-step
Why this matters for your WhatsApp clone

This is the final step — putting your app on the Apple App Store where every iPhone user in the world can download it. The iOS publishing process is stricter than Android: Apple reviews every app against detailed guidelines, requires specific metadata, and enforces CallKit for VoIP apps (which you already built in Module 5). The good news: EAS Build handles all the Xcode complexity — no Mac needed for building. By the end of this lesson, your WhatsApp clone is live on both stores and the course is complete.

1. Before you start — prerequisites

Requirement Details Cost

Expo account + EAS CLI Same as Android (already set up) Free
Bundle Identifier Unique reverse-domain ID (e.g. com.yourname.whatsappclone) —
Privacy policy URL Hosted publicly (Lesson 4) Free
Screenshots (6.7" and 5.5") At least 2 per required device size —
No Mac needed for building!

EAS Build runs Xcode in the cloud. You submit from your Windows/Linux/Mac machine — Expo's servers do the iOS build for you. You only need an Apple Developer account (not a physical Mac).

2. Enrolling in the Apple Developer Program

  1. Go to developer.apple.com/programs
  2. Sign in with your Apple ID (create one if needed)
  3. Click "Enrol" → choose Individual (not Organisation, unless you have a company)
  4. Pay the $99/year fee
  5. Wait for approval (usually instant for individuals, up to 48 hours)
  6. Once approved, you can access App Store Connect at appstoreconnect.apple.com

Apple ID two-factor authentication is required — make sure it's enabled on your Apple ID before enrolling.

3. Configuring app.json for iOS

Your app.json needs iOS-specific configuration. Here's the complete iOS section:

{
  "expo": {
    "name": "WhatsApp Clone",
    "slug": "whatsapp-clone",
    "version": "1.0.0",
    "ios": {
      "bundleIdentifier": "com.yourname.whatsappclone",
      "buildNumber": "1",
      "supportsTablet": false,
      "icon": "./assets/icon.png",
      "splash": {
        "image": "./assets/splash.png",
        "resizeMode": "contain",
        "backgroundColor": "#075E54"
      },
      "infoPlist": {
        "UIBackgroundModes": ["voip", "audio", "fetch", "remote-notification"],
        "NSCameraUsageDescription": "WhatsApp Clone needs camera access to make video calls and take photos to send in chats.",
        "NSMicrophoneUsageDescription": "WhatsApp Clone needs microphone access to make voice and video calls, and to record voice messages.",
        "NSPhotoLibraryUsageDescription": "WhatsApp Clone needs photo library access to send existing photos and videos in chats.",
        "NSPhotoLibraryAddUsageDescription": "WhatsApp Clone saves received photos and videos to your device.",
        "NSContactsUsageDescription": "WhatsApp Clone can access your contacts to help you find friends who also use the app."
      },
      "config": {
        "usesNonExemptEncryption": false
      }
    }
  }
}

Key fields:

  • bundleIdentifier — unique ID registered with Apple. Must match what you create in App Store Connect.
  • buildNumber — must increment with every upload (like Android's versionCode). String format: "1", "2", "3".
  • UIBackgroundModes — tells iOS your app needs background VoIP, audio, and push capabilities.
  • usesNonExemptEncryption: false — your app uses HTTPS (standard) but not custom encryption. Without this, Apple asks every time you submit.

4. iOS code signing — certificates and profiles

iOS has a complex signing system with certificates, provisioning profiles, and device registrations. The good news: EAS handles all of it automatically.

# First time you build for iOS, EAS asks:
# "Log in to your Apple Developer account"
# Then: "Would you like EAS to manage your credentials?"
# Answer: Yes to both

eas build --platform ios --profile production

# EAS will:
# 1. Log in to your Apple Developer account
# 2. Create a Distribution Certificate
# 3. Create a Provisioning Profile
# 4. Register your Bundle ID
# 5. Build and sign the .ipa
# All automatically — no Xcode, no Mac, no manual steps.

What EAS creates for you:

Credential What it is
Distribution Certificate Proves the build came from you (your Apple Developer identity)
Provisioning Profile Links your certificate + bundle ID + capabilities (VoIP, push, etc.)
Push Notification Key Allows your server to send push notifications via APNs

5. Building the production IPA

# Make sure your eas.json has an iOS production profile:
{
  "build": {
    "production": {
      "ios": {
        "autoIncrement": true
      }
    }
  }
}

# Build:
eas build --platform ios --profile production

This takes 15–30 minutes. When done, you get a download URL for the .ipa file (though you usually don't need to download it — EAS Submit uploads it directly).

autoIncrement: true — automatically bumps the buildNumber each time you build, so you never get "build number already exists" errors from Apple.

6. Creating your app in App Store Connect

  1. Go to appstoreconnect.apple.com
  2. Click "My Apps" → "+" → "New App"
  3. Fill in:
    • Platform: iOS
    • Name: Your app name (must be unique on the App Store)
    • Primary language: English
    • Bundle ID: Select the one EAS registered (com.yourname.whatsappclone)
    • SKU: Any unique string (e.g. "whatsappclone001")
  4. Click "Create"

7. Submitting with EAS Submit

Add iOS submit configuration to your eas.json:

{
  "submit": {
    "production": {
      "ios": {
        "appleId": "your@email.com",
        "ascAppId": "1234567890",
        "appleTeamId": "ABCDE12345"
      }
    }
  }
}

Where to find these values:

  • appleId — your Apple ID email address
  • ascAppId — in App Store Connect → your app → General → App Information → Apple ID (numeric)
  • appleTeamId — developer.apple.com → Membership → Team ID
# Submit the latest iOS build to App Store Connect:
eas submit --platform ios --latest

# Or build + submit in one step:
eas build --platform ios --profile production --auto-submit

EAS uploads the .ipa to App Store Connect. You'll need to enter your Apple ID password or use an app-specific password (recommended — generate one at appleid.apple.com → Security → App-Specific Passwords).

8. Filling out the App Store listing

In App Store Connect → your app → App Information and Version Information:

App Information:

  • Category: Social Networking
  • Content Rights: "Does not contain third-party content"
  • Age Rating: Complete the questionnaire (Lesson 4 — likely 12+)
  • Privacy Policy URL: Your hosted privacy policy

Version Information (per version):

Field Details
Screenshots 6.7" display (iPhone 15 Pro Max) — required. 5.5" (iPhone 8 Plus) — required if supporting older phones.
Promotional text 170 chars — shown above description, can change without new version
Description 4000 chars — feature list and overview (same as Android is fine)
Keywords 100 chars — comma-separated search terms (messaging,chat,calls,video,free)
Support URL A webpage or email where users can get help
What's New Release notes for this version

Screenshots — required sizes:

Display size Resolution Devices
6.7" display 1290 × 2796 px iPhone 15 Pro Max, 14 Pro Max
6.5" display 1284 × 2778 px iPhone 14 Plus, 13 Pro Max
5.5" display 1242 × 2208 px iPhone 8 Plus (if supporting)

Tip: If you provide 6.7" screenshots, Apple auto-uses them for all sizes. You only need one set of screenshots for most cases.

9. App Review Information

This section tells Apple's reviewers how to test your app:

App Review Information:
─────────────────────
Contact: Your Name
Email: your@email.com
Phone: +91-XXXXXXXXXX

Demo Account:
  Email: demo@test.com
  Password: DemoPass123!

Notes for reviewer:
  "This is a messaging and calling app. To test messaging,
  log in with the demo account. A second test account
  (demo2@test.com / DemoPass123!) is available for testing
  calls between two users. The app uses CallKit for incoming
  calls and WebRTC for peer-to-peer audio/video."
Create real demo accounts!

Before submitting, create two test accounts in your Firebase Auth with sample chat history. The reviewer WILL try to log in. If login fails, your app is instantly rejected.

10. App Privacy (nutrition labels)

In App Store Connect → your app → App Privacy, you fill out what data your app collects. This creates the "nutrition label" users see on your App Store page:

For your WhatsApp clone, select:

Data Used to Track You: None

Data Linked to You:

  • Contact Info → Email Address (Purpose: App Functionality)
  • Contact Info → Name (Purpose: App Functionality)
  • User Content → Photos or Videos (Purpose: App Functionality)
  • User Content → Audio Data (Purpose: App Functionality)
  • User Content → Other User Content — messages (Purpose: App Functionality)
  • Identifiers → User ID (Purpose: App Functionality)

Data Not Linked to You:

  • Diagnostics → Crash Data (if using Firebase Crashlytics)

11. TestFlight — beta testing before release

Once your build is uploaded to App Store Connect, it appears in TestFlight — Apple's built-in beta testing platform:

  1. In App Store Connect → TestFlight tab
  2. Your uploaded build appears (may take 5–15 minutes to process)
  3. Click the build → Manage Compliance → answer the encryption question (select "No" for standard HTTPS)
  4. Add Internal Testers (up to 100 — your App Store Connect team members)
  5. Or create an External Testing Group (up to 10,000 testers — requires a quick Apple review)
  6. Testers receive an email invitation → install TestFlight app → install your beta

Why TestFlight before production?

  • Verify the build works on real iPhones before going public
  • Test push notifications, CallKit, and VoIP push in a production-like environment
  • Get feedback from friends before the full public launch
  • Internal testing needs no Apple review — available within minutes

12. Submitting for App Store review

  1. In App Store Connect → your app → App Store tab
  2. Select the build you want to submit (from the dropdown under "Build")
  3. Verify all required fields are filled:
    • ☐ Screenshots uploaded
    • ☐ Description written
    • ☐ Keywords set
    • ☐ Support URL provided
    • ☐ Privacy Policy URL set
    • ☐ App Privacy labels completed
    • ☐ Age rating answered
    • ☐ Review notes + demo account provided
  4. Click "Add for Review"
  5. Click "Submit to App Review"

Review timeline: Usually 24–48 hours. First submissions sometimes take up to 7 days. You'll get an email when approved (or if rejected with specific issues to fix).

13. Common iOS rejection reasons and fixes

Rejection Fix
"Demo account doesn't work" Create fresh test accounts right before submission. Verify login works.
"VoIP app must use CallKit" (Guideline 4.2) You already built this in Module 5 Lesson 8. Verify CallKit is working in your production build.
"Permission purpose string too vague" Update Info.plist strings to be specific (Lesson 4).
"App crashes on launch" Test the production build via TestFlight before submitting.
"No account deletion" Implement the delete account flow from Lesson 4.
"Guideline 4.3 — Spam" (duplicate apps) Make sure your app has unique branding — don't use WhatsApp's name or icon.
"IPv6 compatibility" React Native + Firebase handle this automatically. Not usually an issue.

If rejected: Apple provides a specific reason in the Resolution Centre. Fix the issue, rebuild, resubmit. Second reviews are usually faster (24 hours).

14. After approval — releasing to the public

Once approved, you have options:

  • Manual release: You click "Release this version" when you're ready
  • Automatic release: Goes live as soon as Apple approves
  • Scheduled release: Set a specific date and time

Choose "Manual release" for your first version — it gives you time to coordinate (tell friends, post on social media, etc.).

15. Updating your iOS app

// 1. Bump version in app.json:
{
  "expo": {
    "version": "1.1.0",
    "ios": {
      "buildNumber": "2"    // or use autoIncrement: true in eas.json
    }
  }
}

// 2. Build:
eas build --platform ios --profile production

// 3. Submit:
eas submit --platform ios --latest

// 4. In App Store Connect: fill in "What's New" and submit for review

OTA updates work on iOS too:

# Push JS-only changes without App Store review:
eas update --branch production --message "Fix chat ordering bug"

16. Complete command reference — iOS publishing

# ─── One-time setup ───────────────────────────────────────
npm install -g eas-cli
eas login
eas build:configure

# ─── Build for App Store ──────────────────────────────────
eas build --platform ios --profile production

# ─── Submit to App Store Connect ──────────────────────────
eas submit --platform ios --latest

# ─── Build + Submit in one step ───────────────────────────
eas build --platform ios --profile production --auto-submit

# ─── Build for BOTH platforms at once ─────────────────────
eas build --platform all --profile production

# ─── Push OTA update (both platforms) ────────────────────
eas update --branch production --message "Bug fix"

# ─── Check credentials ───────────────────────────────────
eas credentials --platform ios

# ─── Check build status ──────────────────────────────────
eas build:list --platform ios

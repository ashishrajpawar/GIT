Metrics That Answer a Question

C7 — Lesson 3 of 4  |  ~50 min

Why this matters for Token

Logs tell you what happened to one request. Metrics tell you whether things are getting worse, and they are the only one of the three that is cheap enough to keep for a year.

Token has one number that has to be watched from the very first deploy, and it is not a latency: TURN relay bandwidth. ADR-0008 puts iceTransportPolicy: 'relay' on every call, so 100% of media crosses the server and crosses it twice — in from one peer, out to the other. That is a certainty rather than a risk, and it is the likeliest surprise on the bill. A trend you can see in month one is a decision; a trend you discover from an invoice is an emergency.

And there is a shape of metric Token must never collect, which is the same shape that makes metrics expensive. That coincidence is the most useful thing in this lesson.

1 · Four numbers per service, and they have names

The standard set for anything serving requests is RED:

  • Rate — requests per second.
  • Errors — how many of them failed.
  • Duration — how long they took, as a distribution.

For a resource — Postgres, Redis, the disk, coturn — the equivalent is USE: utilisation, saturation, errors. Saturation is the interesting one and the one people skip: a connection pool at 100% utilisation is working; a connection pool with a queue of forty waiting is about to time out.

Everything else is a follow-up question. Start with these and add a metric when an incident proves you could not answer something.

2 · The average is the one number that hides the problem

Duration is a distribution, and reducing it to a mean throws away the part that matters.

p50 is what a typical user gets; p99 is what your noisiest 1% get — and on a busy service, 1% of requests is a lot of people, several times a day each.

Two things you cannot do with a percentile

You cannot average percentiles. The mean of two instances' p99s is not the p99 of the whole service, and it is not any number at all. Percentiles have to be computed from the underlying distribution, which is why metric systems store latency as buckets rather than as a single figure.

You cannot get one from a counter. A total and a count give you a mean and nothing else. If you want a p99, that has to be decided before you start recording.

A per-user label is the behavioural timeline ADR-0012 forbids

A time series named requests_total{user_id="4102"}, sampled every fifteen seconds and kept for a year, is a minute-by-minute record of when one person used the product. Nobody set out to build that. It arrives as a debugging convenience.

ADR-0012's promise is not kept by policy but by there being nothing behavioural in the system to prohibit — event counts have no subject. A user-labelled metric creates the subject, and it does so in the one system whose retention is measured in years rather than the minutes C3/0002 gave the abuse counters.

So: no user id, no token id, no code, no phone hash, in a label. Ever. The cardinality argument and the privacy argument point the same way here, which is convenient and slightly dangerous — convenient because one rule serves both, dangerous because somebody who only knows the cost argument will happily add a label with fifty possible values that happens to identify a person.

The rule that follows: a label's value set must be small and known in advance. Route, method, status class, region. Anything unbounded — an id, a URL with an id in it, an error message — is a bug, and a budget on distinct values per label catches it before the disk does.

6 · The window with nothing in it

A window containing no requests has no error rate. Zero divided by zero is not zero; it is undefined, and JavaScript will hand you NaN, which compares false against every threshold you will ever write.

Reporting 0 instead is worse than NaN, because it is plausible: a service that has stopped receiving requests altogether has a 0% error rate, and an alert watching error rate will never fire. That failure belongs to the next lesson; the part that belongs here is refusing to invent the number in the first place.

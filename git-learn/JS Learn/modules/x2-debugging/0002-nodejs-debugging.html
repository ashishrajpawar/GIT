Node.js Debugging

X2 — Lesson 2 of 2 ~40 min
Why this matters for Token

Token's API server runs on Node.js. When a token redemption fails, or a WebSocket message doesn't arrive, you need to trace the problem through middleware, database queries, and socket events. Server bugs are harder than UI bugs — there's no visual feedback. These tools replace your eyes.

The --inspect flag

Node's built-in debugger connects to Chrome DevTools — same interface you already know:

# Start your server with the inspector:
node --inspect api/src/server.ts

# Or with ts-node for TypeScript:
npx ts-node --inspect api/src/server.ts

# Or with nodemon for auto-restart:
npx nodemon --inspect api/src/server.ts

Then open Chrome and go to chrome://inspect. Your Node process appears under "Remote Target" — click "inspect" to open DevTools.

Setting breakpoints in VS Code

VS Code has a built-in Node debugger — no Chrome needed:

  1. Click the line number gutter to set a breakpoint (red dot appears)
  2. Open the Run & Debug panel (Ctrl+Shift+D)
  3. Create a launch config or use "Node.js: Launch Program"

Add to .vscode/launch.json:

{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Debug API",
      "type": "node",
      "request": "launch",
      "program": "${workspaceFolder}/api/src/server.ts",
      "runtimeExecutable": "npx",
      "runtimeArgs": ["ts-node"],
      "console": "integratedTerminal",
      "env": {
        "NODE_ENV": "development",
        "DATABASE_URL": "postgres://localhost:5432/token_dev"
      }
    }
  ]
}

Press F5 to start debugging. Execution pauses at breakpoints. You can inspect variables, step through code, and watch expressions.

Structured logging

In production, you can't attach a debugger. Logs are your only visibility. Make them useful:

// Bad — unstructured, no context
console.log('token redeemed');
console.log(error);

// Good — structured, searchable, contextual
console.log(JSON.stringify({
  event: 'token_redeemed',
  tokenCode: token.code,
  holderIp: req.ip,
  timestamp: new Date().toISOString(),
}));

console.error(JSON.stringify({
  event: 'token_redemption_failed',
  tokenCode: req.params.code,
  reason: error.message,
  stack: error.stack,
}));

In later lessons (B9 — Docker & Deployment), you'll use a proper logging library (pino). For now, structured JSON is the habit to build.

Reading Node.js stack traces

Error: Token not found
    at findToken (api/src/services/tokens.ts:42:11)
    at redeemHandler (api/src/routes/redeem.ts:18:24)
    at Layer.handle (node_modules/express/lib/router/layer.js:95:5)
    at next (node_modules/express/lib/router/route.js:144:13)
    at authMiddleware (api/src/middleware/auth.ts:31:5)

Read top-down:

  1. The error: "Token not found"
  2. Where it was thrown: tokens.ts:42 in the findToken function
  3. Who called it: redeemHandler at redeem.ts:18
  4. Framework internals: Express routing (you can ignore these)
  5. Earlier middleware: authMiddleware ran first (bottom = earliest)

Focus on your code (the api/src/ paths). Framework internals (node_modules/) are rarely the problem.

Debugging database queries

When a query returns wrong results or fails:

// Log the actual query being sent to Postgres
async function findTokenByCode(code: string) {
  const query = 'SELECT * FROM tokens WHERE code = $1 AND status = $2';
  const params = [code, 'active'];

  console.log('[DB]', query, params);  // See exactly what's sent

  const result = await db.query(query, params);
  console.log('[DB] Rows returned:', result.rows.length);

  return result.rows[0];
}

Common issues:

  • Empty result — is the WHERE clause too restrictive? Log the params.
  • Wrong data — are column names what you expect? Log result.fields.
  • Connection error — is DATABASE_URL correct? Is Postgres running?

Debugging async code

The trickiest Node bugs involve async operations — promises that silently fail, callbacks that never fire, or errors that vanish:

// Bug: unhandled promise rejection (error disappears silently)
app.get('/api/tokens/:code', (req, res) => {
  findToken(req.params.code).then(token => {
    res.json(token);
  });
  // If findToken throws, nothing catches it!
});

// Fix: always handle errors in async routes
app.get('/api/tokens/:code', async (req, res, next) => {
  try {
    const token = await findToken(req.params.code);
    res.json(token);
  } catch (err) {
    next(err);  // Express error handler catches it
  }
});

Add a global unhandled rejection handler during development:

process.on('unhandledRejection', (reason, promise) => {
  console.error('Unhandled Rejection:', reason);
  // In dev: crash loudly so you notice
  process.exit(1);
});

Environment-specific debugging

// Only log in development
if (process.env.NODE_ENV === 'development') {
  console.log('[DEBUG]', data);
}

// Or use a DEBUG flag
const DEBUG = process.env.DEBUG === 'true';

function debugLog(...args: unknown[]) {
  if (DEBUG) console.log('[DEBUG]', ...args);
}

// Run with: DEBUG=true node api/src/server.ts

Quick reference: when to use what

Situation Tool
Quick check of a value console.log
Need to step through logic line by line VS Code debugger or --inspect + Chrome
API returning wrong data Log the query + params sent to the database
Error silently disappearing Add unhandledRejection handler, wrap in try/catch
Production issue Structured JSON logs + search them

React Native Debugging

X2 — Lesson 1 of 2 ~45 min
Why this matters for Token

When a token doesn't appear in the list, or a WebSocket message vanishes, debugging skills are the difference between fixing it in 5 minutes and staring at code for 2 hours. This lesson gives you the tools to see what's happening inside your running app — state, network requests, component hierarchy, and errors.

The debugging mindset

Debugging is not randomly changing code until it works. It's a process:

  1. Reproduce — make the bug happen reliably
  2. Isolate — narrow down where the problem is (which component, which function, which line)
  3. Inspect — look at actual values at that point (state, variables, network responses)
  4. Fix — change one thing, verify it works
  5. Verify — confirm the original bug is gone and you didn't break something else

Console methods beyond console.log

// Group related logs together
console.group('Token fetch');
console.log('URL:', url);
console.log('Response:', data);
console.groupEnd();

// Table format for arrays/objects
console.table(tokens.map(t => ({ code: t.code, status: t.status })));

// Warnings and errors (stand out visually)
console.warn('Token about to expire:', token.code);
console.error('Failed to revoke:', error.message);

// Timing how long something takes
console.time('api-call');
const result = await fetch(url);
console.timeEnd('api-call');  // "api-call: 230ms"

React DevTools

React DevTools lets you inspect the component tree, props, and state of any component in your running app.

Install:

npm install -g react-devtools

Run it alongside your Expo app:

# Terminal 1 — DevTools
react-devtools

# Terminal 2 — Your app
npx expo start

What you can do in React DevTools:

  • Inspect components — click any component to see its props and state
  • Edit state live — change a state value and watch the UI update instantly
  • Search — find a component by name (e.g. "TokenCard")
  • Highlight updates — see which components re-render (helps find performance issues)

Expo DevTools and the developer menu

Shake your phone (or press m in the Expo terminal) to open the dev menu:

  • Reload — reload the JS bundle (like refreshing a browser)
  • Open JS Debugger — opens Chrome DevTools connected to your app
  • Toggle Inspector — tap any element to see its styles (like browser dev tools)
  • Performance Monitor — shows FPS, RAM, and thread usage

Network inspection

Seeing what your app sends to the API and what comes back is critical for Token. Two approaches:

Option 1: Intercepting fetch (simple, built-in)

// Add to app/_layout.tsx during development only:
if (__DEV__) {
  const originalFetch = global.fetch;
  global.fetch = async (...args) => {
    console.log('[FETCH]', args[0], args[1]?.method || 'GET');
    const response = await originalFetch(...args);
    const clone = response.clone();
    const body = await clone.text();
    console.log('[RESPONSE]', response.status, body.slice(0, 200));
    return response;
  };
}

Option 2: Flipper (full network inspector)

Flipper is a desktop app by Meta with React Native plugins:

  • Network tab — see every HTTP request/response with headers and bodies
  • Layout inspector — component tree with styles
  • React DevTools built in
  • Database inspector — see SQLite contents

For Token, the network tab is the most valuable — you'll debug API calls constantly.

Reading error messages

React Native errors look intimidating but follow a pattern:

TypeError: undefined is not an object (evaluating 'token.code')
    at TokenCard (TokenCard.tsx:12)
    at FlatList
    at TokenListScreen (TokenListScreen.tsx:34)

Read it bottom-up:

  1. The call stack shows where: TokenListScreen renders a FlatList which renders TokenCard
  2. The file and line: TokenCard.tsx:12
  3. The error: token is undefined — the object you're accessing .code on doesn't exist

Fix: check where token comes from at line 12. Likely the FlatList data contains an undefined entry, or the prop isn't being passed.

Breakpoints (Chrome Debugger)

Sometimes console.log isn't enough. Breakpoints pause execution so you can inspect every variable at that moment:

  1. Open dev menu → "Open JS Debugger"
  2. In Chrome: Sources tab → find your file
  3. Click a line number to set a breakpoint
  4. Trigger the code path in your app
  5. Execution pauses — inspect variables in the Scope panel
  6. Step through line by line with F10 (step over) or F11 (step into)

Or add debugger; in your code — it acts like a breakpoint:

function handleTokenPress(token: Token) {
  debugger; // execution pauses here when Chrome Debugger is open
  navigation.navigate('TokenDetail', { tokenCode: token.code });
}

Common React Native debugging patterns

State not updating?

// Wrong — mutating state directly
tokens.push(newToken);
setTokens(tokens);  // React doesn't see a change (same reference)

// Right — new array reference
setTokens([...tokens, newToken]);

Infinite re-render loop?

// Wrong — useEffect with no dependency array
useEffect(() => {
  setTokens(fetchTokens());  // triggers re-render → triggers effect → infinite
});

// Right — empty array means "run once on mount"
useEffect(() => {
  fetchTokens().then(setTokens);
}, []);

Component not showing?

// Check: does it have height? (flex: 1 requires parent to have height)
// Check: is the data actually loaded? (add a temporary console.log)
// Check: is there a conditional render hiding it?
{tokens.length > 0 && <TokenList />}  // won't show if array is empty

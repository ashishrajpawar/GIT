Access Rules Engine

B7 — Lesson 2 of 3 • ~50 min

Why this matters for Token

Rules are what make Token more than a contact form. A user can say "this delivery driver can message me only between 9 AM and 6 PM, only text, max 5 messages per day." The rules are stored as JSONB in the tokens table — the engine evaluates them on every message or call attempt. If the engine is wrong, privacy erodes. Deny-by-default: if a rule cannot be evaluated, the action is blocked.

The Rules Schema

Rules live in the rules JSONB column of the tokens table. The structure supports multiple rule types that are evaluated together — ALL must pass for an action to be allowed. 

// The rules JSONB structure
interface TokenRules {
  time_window?: {
    days: number[];        // 0=Sun, 1=Mon, ..., 6=Sat
    start_time: string;    // "09:00" (24h format)
    end_time: string;      // "18:00"
    timezone: string;      // "Asia/Kolkata"
  };
  contact_limit?: {
    max_messages_per_day: number;
    max_calls_per_day: number;
  };
  channel_restrict?: {
    allow_text: boolean;
    allow_voice: boolean;
    allow_video: boolean;
  };
}

// Example rules stored in the database:
{
  "time_window": {
    "days": [1, 2, 3, 4, 5],
    "start_time": "09:00",
    "end_time": "18:00",
    "timezone": "Asia/Kolkata"
  },
  "contact_limit": {
    "max_messages_per_day": 10,
    "max_calls_per_day": 2
  },
  "channel_restrict": {
    "allow_text": true,
    "allow_voice": true,
    "allow_video": false
  }
}

The Core evaluateRules Function

This is the heart of the token engine. Every action (send message, initiate call) passes through this function. It returns either { allowed: true } or { allowed: false, reason: string }. 

// api/src/engine/rules.ts
import { pool } from '../db';

type Action = 'message' | 'voice_call' | 'video_call';

interface RuleResult {
  allowed: boolean;
  reason?: string;
}

export async function evaluateRules(
  tokenId: number,
  action: Action
): Promise<RuleResult> {
  // Fetch rules from token
  const { rows } = await pool.query(
    'SELECT rules FROM tokens WHERE id = $1',
    [tokenId]
  );

  if (rows.length === 0) {
    return { allowed: false, reason: 'Token not found' };
  }

  const rules = rows[0].rules;

  // No rules means open access (user chose not to restrict)
  if (!rules || Object.keys(rules).length === 0) {
    return { allowed: true };
  }

  // Evaluate each rule type — ALL must pass
  if (rules.channel_restrict) {
    const result = evaluateChannelRestrict(rules.channel_restrict, action);
    if (!result.allowed) return result;
  }

  if (rules.time_window) {
    const result = evaluateTimeWindow(rules.time_window);
    if (!result.allowed) return result;
  }

  if (rules.contact_limit) {
    const result = await evaluateContactLimit(rules.contact_limit, tokenId, action);
    if (!result.allowed) return result;
  }

  return { allowed: true };
}

Channel Restriction Evaluation

The simplest rule — a direct boolean check against the action type. 

function evaluateChannelRestrict(
  rule: { allow_text: boolean; allow_voice: boolean; allow_video: boolean },
  action: Action
): RuleResult {
  switch (action) {
    case 'message':
      if (!rule.allow_text) {
        return { allowed: false, reason: 'Text messages are not allowed on this token' };
      }
      break;
    case 'voice_call':
      if (!rule.allow_voice) {
        return { allowed: false, reason: 'Voice calls are not allowed on this token' };
      }
      break;
    case 'video_call':
      if (!rule.allow_video) {
        return { allowed: false, reason: 'Video calls are not allowed on this token' };
      }
      break;
  }
  return { allowed: true };
}

Time Window Evaluation

Checks the current time in the token owner's timezone against the allowed window. This handles day-of-week and time range. 

function evaluateTimeWindow(
  rule: { days: number[]; start_time: string; end_time: string; timezone: string }
): RuleResult {
  // Get current time in the token owner's timezone
  const now = new Date();
  const options: Intl.DateTimeFormatOptions = {
    timeZone: rule.timezone,
    hour: '2-digit',
    minute: '2-digit',
    hour12: false,
    weekday: 'short'
  };

  const formatter = new Intl.DateTimeFormat('en-US', options);
  const parts = formatter.formatToParts(now);

  // Extract day of week (0-6)
  const dayFormatter = new Intl.DateTimeFormat('en-US', {
    timeZone: rule.timezone,
    weekday: 'short'
  });
  const dayStr = dayFormatter.format(now);
  const dayMap: Record<string, number> = {
    Sun: 0, Mon: 1, Tue: 2, Wed: 3, Thu: 4, Fri: 5, Sat: 6
  };
  const currentDay = dayMap[dayStr];

  // Check day is allowed
  if (!rule.days.includes(currentDay)) {
    return { allowed: false, reason: 'Contact not allowed on this day' };
  }

  // Extract current time as HH:MM
  const hourPart = parts.find(p => p.type === 'hour')?.value || '00';
  const minutePart = parts.find(p => p.type === 'minute')?.value || '00';
  const currentTime = `${hourPart}:${minutePart}`;

  // Compare as strings (works because HH:MM format sorts correctly)
  if (currentTime < rule.start_time || currentTime >= rule.end_time) {
    return {
      allowed: false,
      reason: `Contact allowed only between ${rule.start_time} and ${rule.end_time} (${rule.timezone})`
    };
  }

  return { allowed: true };
}

Contact Limit Evaluation

Counts today's actions in the database. This requires a query on each check, but correctness matters more than speed here. Caching would risk allowing messages past the limit. 

async function evaluateContactLimit(
  rule: { max_messages_per_day: number; max_calls_per_day: number },
  tokenId: number,
  action: Action
): Promise<RuleResult> {
  // Get start of today in UTC (we count by calendar day)
  const todayStart = new Date();
  todayStart.setUTCHours(0, 0, 0, 0);

  if (action === 'message') {
    const { rows } = await pool.query(
      `SELECT COUNT(*)::int as cnt FROM messages m
       JOIN conversations c ON m.conversation_id = c.id
       WHERE c.token_id = $1
         AND m.sender_role = 'holder'
         AND m.created_at >= $2`,
      [tokenId, todayStart.toISOString()]
    );

    if (rows[0].cnt >= rule.max_messages_per_day) {
      return {
        allowed: false,
        reason: `Daily message limit reached (${rule.max_messages_per_day})`
      };
    }
  }

  if (action === 'voice_call' || action === 'video_call') {
    const { rows } = await pool.query(
      `SELECT COUNT(*)::int as cnt FROM calls
       WHERE token_id = $1
         AND initiated_by = 'holder'
         AND created_at >= $2`,
      [tokenId, todayStart.toISOString()]
    );

    if (rows[0].cnt >= rule.max_calls_per_day) {
      return {
        allowed: false,
        reason: `Daily call limit reached (${rule.max_calls_per_day})`
      };
    }
  }

  return { allowed: true };
}

Integrating into Chat and Call Handlers

Every incoming message or call request passes through evaluateRules before being processed. 

// In your WebSocket message handler:
ws.on('message', async (data) => {
  const { type, conversationId, content } = JSON.parse(data);

  if (type === 'chat_message') {
    // Get tokenId from conversation
    const { rows } = await pool.query(
      'SELECT token_id FROM conversations WHERE id = $1',
      [conversationId]
    );
    const tokenId = rows[0].token_id;

    // Evaluate rules BEFORE processing
    const ruleCheck = await evaluateRules(tokenId, 'message');
    if (!ruleCheck.allowed) {
      ws.send(JSON.stringify({
        type: 'error',
        code: 'RULE_DENIED',
        reason: ruleCheck.reason
      }));
      return;  // Message blocked
    }

    // Rules passed — save and broadcast message
    await saveMessage(conversationId, content);
    broadcastToConversation(conversationId, content);
  }
});

Deny-by-Default Principle

If anything goes wrong during rule evaluation — a database error, an unexpected rule format, a missing timezone — the action is DENIED. This is the security-first approach: bugs should restrict access, never grant it. 

export async function evaluateRulesSafe(
  tokenId: number,
  action: Action
): Promise<RuleResult> {
  try {
    return await evaluateRules(tokenId, action);
  } catch (err) {
    console.error('Rule evaluation failed, denying by default:', err);
    return { allowed: false, reason: 'Rule evaluation error — access denied' };
  }
}

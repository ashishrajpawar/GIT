Build the Message Thread Screen

Capstone · Combines lessons 2–13 ~55 min Hands-on
Why this matters for Token

The message thread is the most complex screen in Token, and the place a token stops being a row in a list and becomes an actual conversation. Messages bubble up from the bottom, the keyboard pushes the composer with it, new messages auto-scroll, and ticks show delivery. This final Module 2 capstone wires everything together: inverted FlatList, KeyboardAvoidingView, useRef for scrolling, useState for message state, and the navigation shell from Lesson 8.

Remember who is at the other end. The holder redeemed a code; you do not know their name and they do not know yours. The header carries the token's label, not a person's — and there is no avatar, because there is no one to picture.

1. Why FlatList must be inverted

In a message thread, the newest message is at the bottom and the list starts scrolled to the bottom. The easiest way to achieve this is the inverted prop on FlatList — it flips the list visually so item [0] appears at the bottom. You simply keep your messages array sorted newest-last (which is natural) and FlatList handles the rest.

// Messages array — oldest first, newest last (natural append order)
const messages = [
  { id: 'm1', text: 'Hey!',           sender: 'them', time: '10:30' },
  { id: 'm2', text: 'Hi! How are you?', sender: 'me', time: '10:31' },
  { id: 'm3', text: 'Great, you?',    sender: 'them', time: '10:31' },
];

// FlatList with inverted — newest message (m3) appears at the bottom
<FlatList
  data={messages}
  inverted                    // flips list so [0] is at bottom
  keyExtractor={item => item.id}
  renderItem={({ item }) => <MessageBubble message={item} />}
/>
inverted vs manual scroll

The alternative is calling flatListRef.current.scrollToEnd() after every new message. That works but can cause a visible flash. inverted is how every serious messaging app does it — the list naturally starts at the bottom and new items append there without any scroll management code.

keyboardVerticalOffset on iOS with custom headers

When headerShown: false is set (which you use so your custom green header shows), iOS doesn't automatically account for the status bar height. If the input bar jumps too high when the keyboard opens, set keyboardVerticalOffset to the height of your custom header + status bar (typically 90–100 on modern iPhones). 3. Message bubble component

Sent messages appear on the right with a green bubble. Received messages appear on the left with a white bubble. A single component handles both — the sender field determines the style.

function MessageBubble({ message }) {
  const isMe = message.sender === 'me';

  return (
    <View style={[styles.bubbleRow, isMe ? styles.rowRight : styles.rowLeft]}>
      <View style={[styles.bubble, isMe ? styles.bubbleMe : styles.bubbleThem]}>

}

4. The input bar — multiline TextInput + Send button

The input bar grows as the user types multiple lines (up to a maximum height), then becomes scrollable. Use a multiline TextInput with a capped height.

const [inputText, setInputText] = useState('');

function sendMessage() {
  const text = inputText.trim();
  if (!text) return;          // don't send empty messages

  const newMessage = {
    id:     Date.now().toString(),
    text,
    sender: 'me',
    time:   new Date().toLocaleTimeString([], { hour: '2-digit', minute: '2-digit' }),
    read:   false,
  };

  setMessages(prev => [...prev, newMessage]);
  setInputText('');            // clear after sending
  // In A6: socket.send('message:send', { tokenId, text, localId });
}

// Input bar JSX
<View style={styles.inputBar}>
  <TextInput
    style={styles.textInput}
    value={inputText}
    onChangeText={setInputText}
    placeholder="Message"
    placeholderTextColor="#aaa"
    multiline
    maxHeight={120}            // caps at ~5 lines before scrolling internally
    returnKeyType="default"    // Enter adds a newline (not send) — send via button
    // iOS multiline needs explicit paddingTop to centre text vertically:
    paddingTop={Platform.OS === 'ios' ? 10 : undefined}
  />
  <Pressable
    style={[styles.sendButton, !inputText.trim() && styles.sendButtonDisabled]}
    onPress={sendMessage}
    disabled={!inputText.trim()}
  >
    <Text style={styles.sendIcon}>➤</Text>
  </Pressable>
</View>
iOS multiline paddingTop

On iOS, a multiline TextInput doesn't vertically centre its text by default. Adding paddingTop (usually 8–12) fixes this. Android handles it correctly without the workaround. Always use Platform.OS === 'ios' ? 10 : undefined so Android is unaffected.

5. Simulating read ticks and a reply

Read ticks work like this: one grey tick = sent to server. Two grey ticks = delivered to recipient's device. Two blue ticks = the holder opened the thread. For now, simulate a reply and a tick update with setTimeout — the WebSocket replaces this in A6.

// After user sends a message, simulate a reply after 2 seconds
function sendMessage() {
  const text = inputText.trim();
  if (!text) return;

  const myMsg = {
    id: Date.now().toString(), text, sender: 'me',
    time: formatTime(), read: false,
  };
  setMessages(prev => [...prev, myMsg]);
  setInputText('');

  // Simulate: message marked as read after 1s
  setTimeout(() => {
    setMessages(prev => prev.map(m =>
      m.id === myMsg.id ? { ...m, read: true } : m
    ));
  }, 1000);

  // Simulate: reply arrives after 2s
  setTimeout(() => {
    setMessages(prev => [...prev, {
      id:     (Date.now() + 1).toString(),
      text:   getAutoReply(text),
      sender: 'them',
      time:   formatTime(),
      read:   false,
    }]);
  }, 2000);
}

function getAutoReply(text) {
  const replies = [
    'Got it! 👍',
    'Sounds good!',
    'Sure, let me check.',
    'Can we talk later?',
    '😄',
  ];
  return replies[Math.floor(Math.random() * replies.length)];
}

function formatTime() {
  return new Date().toLocaleTimeString([], { hour: '2-digit', minute: '2-digit' });
}

6. Date separators between messages

Show "Today", "Yesterday", or a date between messages from different days. Insert separator items into the messages array before passing it to FlatList.

// Add a date separator before the first message of each day
function insertDateSeparators(messages) {
  const result = [];
  let lastDate = null;

  for (const msg of messages) {
    const day = msg.date ?? 'Today';    // 'Today', 'Yesterday', or 'Mon 14 Jul'
    if (day !== lastDate) {
      result.push({ id: `sep-${day}`, type: 'separator', label: day });
      lastDate = day;
    }
    result.push(msg);
  }
  return result;
}

// In renderItem — handle both types
renderItem={({ item }) =>
  item.type === 'separator'
    ? <DateSeparator label={item.label} />
    : <MessageBubble message={item} />
}

function DateSeparator({ label }) {
  return (
    <View style={styles.dateSepRow}>
      <View style={styles.dateSepPill}>
        <Text style={styles.dateSepText}>{label}</Text>
      </View>
    </View>
  );
}

Try it yourself — this one is broken on purpose

The version above takes a pre-formatted msg.date string, which quietly assumes somebody else already did the hard part. Real messages carry a timestamp. Here is the obvious way to turn one into "Today":

"Less than 24 hours ago" is not the same question as "today". A message sent at 11pm yesterday is two hours old at 1am and belongs under Yesterday; a message sent at 9am today is fourteen hours old at 11pm and belongs under Today. Subtracting timestamps answers a question nobody asked.

Calendar days are not durations

The fix is to compare the dates, not the gap: same year, same month, same day. It costs three comparisons and it is right at every hour of the clock, including the two hours around midnight when the naive version is most confidently wrong.

The same trap catches "is this token expiring today?" and "how many days has this been paused?". Whenever a rule is stated in calendar terms, answer it in calendar terms.

7. Full working example — production message thread screen

This is the complete, production-quality message thread for Token. Every feature is here: inverted FlatList, KeyboardAvoidingView, message bubbles, read ticks, multiline input, send button, simulated reply, and date separators. This slots directly into the navigation shell from Lesson 8. Replace your entire App.js with this.

import { useState, useEffect, useRef } from 'react';
import { NavigationContainer } from '@react-navigation/native';
import { createNativeStackNavigator } from '@react-navigation/native-stack';
import { createBottomTabNavigator }   from '@react-navigation/bottom-tabs';

const Stack = createNativeStackNavigator();
const Tab   = createBottomTabNavigator();

const INITIAL_MESSAGES = [
  { id: '1', text: 'Hey! Are you free this weekend?', sender: 'them', time: '10:28', read: false, date: 'Today' },
  { id: '2', text: 'Yes! What did you have in mind?', sender: 'me',   time: '10:29', read: true,  date: 'Today' },
  { id: '3', text: 'Thought we could go hiking 🏔️',   sender: 'them', time: '10:30', read: false, date: 'Today' },
  { id: '4', text: 'That sounds amazing!',            sender: 'me',   time: '10:31', read: true,  date: 'Today' },
  { id: '5', text: 'Perfect, see you Saturday then!', sender: 'them', time: '10:32', read: false, date: 'Today' },
];

function insertDateSeparators(messages) {
  const result = [];
  let lastDate = null;
  for (const msg of messages) {
    const day = msg.date ?? 'Today';
    if (day !== lastDate) {
      result.push({ id: `sep-${day}-${msg.id}`, type: 'separator', label: day });
      lastDate = day;
    }
    result.push({ ...msg, type: 'message' });
  }
  return result;
}

function MessageThreadScreen({ route, navigation }) {
  const {
    tokenId    = '1',
    tokenLabel = 'Flipkart delivery',
    status     = 'active',
  } = route.params ?? {};

  const [messages,  setMessages]  = useState(INITIAL_MESSAGES);
  const [inputText, setInputText] = useState('');
  const [isTyping,  setIsTyping]  = useState(false);

  // Hide React Navigation's default header — we have a custom one
  useEffect(() => {
    navigation.setOptions({ headerShown: false });
  }, []);

  const displayItems = insertDateSeparators(messages);

  function sendMessage() {
    const text = inputText.trim();
    if (!text) return;

    const myMsg = {
      id:     Date.now().toString(),
      text,
      sender: 'me',
      time:   formatTime(),
      read:   false,
      date:   'Today',
    };

    setMessages(prev => [...prev, myMsg]);
    setInputText('');
    Keyboard.dismiss();

    // Simulate: message marked as read after 1s
    setTimeout(() => {
      setMessages(prev => prev.map(m =>
        m.id === myMsg.id ? { ...m, read: true } : m
      ));
    }, 1000);

    // Show typing indicator, then reply after 2s
    setTimeout(() => setIsTyping(true),  1200);
    setTimeout(() => {
      setIsTyping(false);
      setMessages(prev => [...prev, {
        id:     (Date.now() + 1).toString(),
        text:   getAutoReply(text),
        sender: 'them',
        time:   formatTime(),
        read:   false,
        date:   'Today',
      }]);
    }, 2500);
  }

  return (
    <KeyboardAvoidingView
      style={styles.screen}
      behavior={Platform.OS === 'ios' ? 'padding' : 'height'}
      keyboardVerticalOffset={Platform.OS === 'ios' ? 0 : 0}
    >

      {/* Custom green header */}
      <View style={styles.header}>
        <Pressable onPress={() => navigation.goBack()} style={styles.backBtn}>
          <Text style={styles.backArrow}>←</Text>
        </Pressable>
        <View style={styles.iconCircleSmall}>
          <Text style={styles.iconLetterSmall}>{tokenLabel[0].toUpperCase()}</Text>
        </View>
        <View style={styles.headerInfo}>
          <Text style={styles.headerName}>{tokenLabel}</Text>
          <Text style={styles.headerStatus}>
            {isTyping ? 'typing…' : status}
          </Text>
        </View>
        <View style={styles.headerActions}>
          <Pressable style={styles.headerIcon}>
            <Text style={styles.headerIconText}>📹</Text>
          </Pressable>
          <Pressable style={styles.headerIcon}>
            <Text style={styles.headerIconText}>📞</Text>
          </Pressable>
        </View>
      </View>

      {/* Message list — inverted so newest is at bottom */}
      <FlatList
        data={displayItems}
        keyExtractor={item => item.id}
        inverted
        style={styles.messageList}
        contentContainerStyle={styles.messageListContent}
        keyboardShouldPersistTaps="handled"
        renderItem={({ item }) =>
          item.type === 'separator'
            ? <DateSeparator label={item.label} />
            : <MessageBubble message={item} />
        }
      />

      {/* Input bar */}
      <View style={styles.inputBar}>
        <Pressable style={styles.attachBtn}>
          <Text style={styles.attachIcon}>📎</Text>
        </Pressable>
        <TextInput
          style={styles.textInput}
          value={inputText}
          onChangeText={setInputText}
          placeholder="Message"
          placeholderTextColor="#aaa"
          multiline
          maxHeight={120}
          returnKeyType="default"
          paddingTop={Platform.OS === 'ios' ? 10 : undefined}
        />
        <Pressable
          style={[styles.sendButton, !inputText.trim() && styles.sendButtonDisabled]}
          onPress={sendMessage}
          disabled={!inputText.trim()}
        >
          <Text style={styles.sendIcon}>➤</Text>
        </Pressable>
      </View>

    </KeyboardAvoidingView>
  );
}

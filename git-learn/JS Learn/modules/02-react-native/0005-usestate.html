React Native · Lesson 5

useState

State · Re-rendering · Derived values ~30 min Hands-on
Why this matters for your WhatsApp clone

Every time something on screen changes — a message is sent, a user types, a button is pressed, a notification arrives — React Native needs to know what changed and re-draw the affected parts of the screen. useState is the mechanism that makes this happen. Without it, your UI would be a static picture that never updates. With it, your app comes alive.

1. The problem useState solves

Try this — a counter that is supposed to increase when you press a button:

// BROKEN — this does NOT work
import { View, Text, Pressable, StyleSheet } from 'react-native';

export default function App() {
  let count = 0;   // plain variable

  function handlePress() {
    count = count + 1;
    console.log('count is now:', count); // logs correctly in console...
  }

  return (
    <View style={styles.container}>
      <Text style={styles.number}>{count}</Text>
      <Pressable style={styles.button} onPress={handlePress}>
        <Text style={styles.buttonText}>Press me</Text>
      </Pressable>
    </View>
  );
}

const styles = StyleSheet.create({
  container:  { flex: 1, alignItems: 'center', justifyContent: 'center' },
  number:     { fontSize: 64, fontWeight: 'bold', marginBottom: 24 },
  button:     { backgroundColor: '#075E54', padding: 16, borderRadius: 8 },
  buttonText: { color: '#fff', fontSize: 18, fontWeight: '600' },
});

Run this. Press the button. The console correctly shows the count going up — but the screen still shows 0. The variable changes, but the UI never updates.

This is because React Native only re-draws a component when it has a reason to. A plain variable changing is not a reason. useState is how you give React Native a reason.

2. useState — the fix

// FIXED — using useState
import { useState } from 'react';
import { View, Text, Pressable, StyleSheet } from 'react-native';

export default function App() {
  const [count, setCount] = useState(0);  // declare state

  function handlePress() {
    setCount(count + 1);  // update state → triggers re-render
  }

  return (
    <View style={styles.container}>
      <Text style={styles.number}>{count}</Text>
      <Pressable style={styles.button} onPress={handlePress}>
        <Text style={styles.buttonText}>Press me</Text>
      </Pressable>
    </View>
  );
}

Now press the button. The number updates on screen every time.

Let's break down the one line that does all the work:

const [count, setCount] = useState(0);
//     ^^^^^  ^^^^^^^^          ^
//     current  updater       initial
//     value    function       value
  • count — the current value. Use this to display or compute things.
  • setCount — the function to change the value. Calling it triggers a re-render.
  • useState(0) — sets the starting value to 0. Runs only on the first render.
Never modify state directly — always use the setter
// WRONG — mutating state directly, screen will not update
count = count + 1;

// CORRECT — using the setter function
setCount(count + 1);

If you change count directly, React Native doesn't know it changed and won't re-render. The setter function is what triggers the re-draw.

3. State can hold any value

State isn't limited to numbers. It can hold strings, booleans, arrays, objects — anything.

// String state — message input text
const [messageText, setMessageText] = useState('');

// Boolean state — is the send button loading?
const [isSending, setIsSending] = useState(false);

// Array state — list of messages
const [messages, setMessages] = useState([]);

// Object state — current user profile
const [user, setUser] = useState({
  name: 'Ashish',
  status: 'online',
  avatar: null,
});

// Multiple state values in one component — totally normal
const [inputText, setInputText]   = useState('');
const [isLoading, setIsLoading]   = useState(false);
const [error, setError]           = useState(null);

4. Updating arrays and objects in state

When state holds an array or object, you must always create a new one instead of mutating the existing one. This is the spread operator from Module 1 Lesson 11 in action.

Adding to an array

const [messages, setMessages] = useState([
  { id: 'm1', text: 'Hey!' }
]);

function addMessage(newText) {
  const newMessage = { id: 'm' + Date.now(), text: newText };

  // WRONG — mutating the existing array
  messages.push(newMessage);          // screen won't update
  setMessages(messages);              // still won't update — same reference

  // CORRECT — create a new array with spread
  setMessages([...messages, newMessage]);
}

Updating one item in an array

// Mark a specific message as read
function markAsRead(messageId) {
  setMessages(
    messages.map(msg =>
      msg.id === messageId
        ? { ...msg, read: true }   // create new object with read changed
        : msg                       // leave others untouched
    )
  );
}

Removing an item from an array

// Delete a message
function deleteMessage(messageId) {
  setMessages(messages.filter(msg => msg.id !== messageId));
}

Updating one field in an object

const [user, setUser] = useState({ name: 'Ashish', status: 'online' });

// Change just the status
function goOffline() {
  setUser({ ...user, status: 'offline' });
  // spread copies all existing fields, then override status
}
This is why you learned spread and map in Module 1

Every state update that involves an array or object uses spread (...), map, or filter. Those weren't abstract concepts — they're the exact tools React Native state management is built on.

5. The functional updater form

When your new state depends on the previous state, use the functional updater form — pass a function to the setter instead of a value. This guarantees you always work with the most up-to-date state, even when updates happen quickly.

// Basic form — fine for most cases
setCount(count + 1);

// Functional updater — safer when state changes rapidly
setCount(prev => prev + 1);

// Real example: adding a message safely
function addMessage(newMessage) {
  setMessages(prev => [...prev, newMessage]);
  // 'prev' is guaranteed to be the latest state value
  // even if multiple messages arrive at nearly the same time
}
When to use the functional form

For simple toggles (setIsOpen(prev => !prev)) and when appending to arrays in rapid succession (new chat messages arriving fast from Firebase), always use the functional form. For simple replacements like setName('Ashish'), the direct form is fine.

6. Derived values — compute from state, don't store separately

A common beginner mistake is storing values in state that can be computed from other state. This creates two sources of truth that can get out of sync.

// BAD — storing unreadCount separately
const [messages, setMessages]       = useState([]);
const [unreadCount, setUnreadCount] = useState(0);  // duplicate!

// Every time you add a message you now have to update BOTH —
// and if you forget to update one, they go out of sync.

// GOOD — compute it directly from messages
const [messages, setMessages] = useState([]);
const unreadCount = messages.filter(m => !m.read).length;
// unreadCount is always correct — no separate state needed
// More examples of derived values
const [messages, setMessages] = useState([...]);
const [searchQuery, setSearchQuery] = useState('');

// Derived — no extra state needed
const filteredMessages = messages.filter(m =>
  m.text.toLowerCase().includes(searchQuery.toLowerCase())
);

const lastMessage = messages[messages.length - 1];

const hasUnread = messages.some(m => !m.read);
Rule of thumb

If a value can be calculated from existing state in a single expression, don't put it in state — just compute it. Store only the source of truth data in state. Everything else is derived.

7. Common WhatsApp state patterns

Here are the exact state variables you'll write on your WhatsApp screens:

// ── Chat List Screen ──────────────────────────────────────────────────────
const [chats, setChats]         = useState([]);       // all chat threads
const [isLoading, setIsLoading] = useState(true);     // loading from Firebase
const [searchQuery, setSearchQuery] = useState('');   // search bar text

// Derived
const filteredChats = chats.filter(c =>
  c.participant.name.toLowerCase().includes(searchQuery.toLowerCase())
);


// ── Message Thread Screen ─────────────────────────────────────────────────
const [messages, setMessages]   = useState([]);       // messages in this chat
const [inputText, setInputText] = useState('');       // text being typed
const [isSending, setIsSending] = useState(false);    // send in progress
const [isLoading, setIsLoading] = useState(true);     // initial load


// ── Login Screen ──────────────────────────────────────────────────────────
const [email, setEmail]         = useState('');
const [password, setPassword]   = useState('');
const [isLoading, setIsLoading] = useState(false);
const [error, setError]         = useState(null);     // error message to show


// ── Profile Screen ────────────────────────────────────────────────────────
const [name, setName]           = useState('');
const [about, setAbout]         = useState('');
const [avatar, setAvatar]       = useState(null);
const [isSaving, setIsSaving]   = useState(false);

8. Full example — a working chat screen with live state

This builds on Lesson 4's example and makes it fully state-driven. Every part of the UI — the message list, the input text, the send button state, the unread count — is controlled by state.

import { useState, useRef } from 'react';
import {
  View, Text, TextInput, Pressable, ScrollView,
  KeyboardAvoidingView, Platform, StyleSheet
} from 'react-native';

const MY_USER_ID = 'user-ashish-01';

export default function App() {
  // ── State ───────────────────────────────────────────────────────────────
  const [messages, setMessages] = useState([
    { id: 'm1', senderId: 'user-priya-02', text: 'Hey! You free tonight?',    time: '10:01', read: true  },
    { id: 'm2', senderId: MY_USER_ID,       text: 'Yes! What time?',           time: '10:02', read: true  },
    { id: 'm3', senderId: 'user-priya-02', text: 'Around 8?',                  time: '10:03', read: false },
  ]);
  const [inputText, setInputText] = useState('');
  const [isSending, setIsSending] = useState(false);

  // ── Derived values ───────────────────────────────────────────────────────
  const unreadCount  = messages.filter(m => !m.read).length;
  const canSend      = inputText.trim().length > 0 && !isSending;

  // ── Refs ─────────────────────────────────────────────────────────────────
  const scrollRef = useRef(null);
  const inputRef  = useRef(null);

  // ── Handlers ─────────────────────────────────────────────────────────────
  function handleSend() {
    if (!canSend) return;

    setIsSending(true);

    const newMsg = {
      id:       'msg-' + Date.now(),
      senderId: MY_USER_ID,
      text:     inputText.trim(),
      time:     new Date().toLocaleTimeString([], { hour: '2-digit', minute: '2-digit' }),
      read:     false,
    };

    setMessages(prev => [...prev, newMsg]);
    setInputText('');
    setIsSending(false);
    inputRef.current?.focus();

    setTimeout(() => scrollRef.current?.scrollToEnd({ animated: true }), 50);
  }

  function markAllRead() {
    setMessages(prev => prev.map(m => ({ ...m, read: true })));
  }

  // ── Render ────────────────────────────────────────────────────────────────
  return (
    <KeyboardAvoidingView
      style={styles.screen}
      behavior={Platform.OS === 'ios' ? 'padding' : 'height'}
    >
      {/* Header — shows live unread count */}
      <View style={styles.header}>
        <View>
          <Text style={styles.headerTitle}>Priya Sharma</Text>
          <Text style={styles.headerSub}>
            {unreadCount > 0 ? `${unreadCount} unread` : 'all caught up'}
          </Text>
        </View>
        {unreadCount > 0 && (
          <Pressable style={styles.readAllBtn} onPress={markAllRead}>
            <Text style={styles.readAllText}>Mark all read</Text>
          </Pressable>
        )}
      </View>

      {/* Message list */}
      <ScrollView
        ref={scrollRef}
        style={styles.messageList}
        contentContainerStyle={{ paddingVertical: 8 }}
        keyboardDismissMode="on-drag"
        keyboardShouldPersistTaps="handled"
      >
        {messages.map(msg => {
          const isMe = msg.senderId === MY_USER_ID;
          return (
            <View
              key={msg.id}
              style={[styles.bubbleRow, isMe ? styles.myRow : styles.theirRow]}
            >
              <View style={[styles.bubble, isMe ? styles.myBubble : styles.theirBubble]}>
                <Text style={styles.bubbleText}>{msg.text}</Text>
                <View style={styles.bubbleMeta}>
                  <Text style={styles.timeText}>{msg.time}</Text>
                  {isMe && (
                    <Text style={[styles.tick, msg.read && styles.tickRead]}>
                      {msg.read ? ' ✓✓' : ' ✓'}
                    </Text>
                  )}
                </View>
              </View>
            </View>
          );
        })}
      </ScrollView>

      {/* Input bar */}
      <View style={styles.inputBar}>
        <TextInput
          ref={inputRef}
          style={styles.input}
          placeholder="Type a message..."
          placeholderTextColor="#999"
          value={inputText}
          onChangeText={setInputText}
          multiline
          maxLength={4096}
          returnKeyType="send"
          onSubmitEditing={handleSend}
          blurOnSubmit={false}
        />
        <Pressable
          style={[styles.sendBtn, !canSend && styles.sendBtnOff]}
          onPress={handleSend}
          disabled={!canSend}
        >
          <Text style={styles.sendIcon}>➤</Text>
        </Pressable>
      </View>

    </KeyboardAvoidingView>
  );
}

const styles = StyleSheet.create({
  screen: { flex: 1, backgroundColor: '#ECE5DD' },

  header: {
    backgroundColor: '#075E54',
    paddingTop: 48, paddingBottom: 12, paddingHorizontal: 16,
    flexDirection: 'row', alignItems: 'center', justifyContent: 'space-between',
  },
  headerTitle:  { color: '#fff', fontSize: 18, fontWeight: '700' },
  headerSub:    { color: '#b2dfdb', fontSize: 12, marginTop: 1 },
  readAllBtn:   { backgroundColor: '#25D366', paddingHorizontal: 10, paddingVertical: 5, borderRadius: 12 },
  readAllText:  { color: '#fff', fontSize: 12, fontWeight: '600' },

  messageList:  { flex: 1 },

  bubbleRow:    { paddingHorizontal: 8, marginVertical: 2 },
  myRow:        { alignItems: 'flex-end' },
  theirRow:     { alignItems: 'flex-start' },
  bubble:       { maxWidth: '75%', paddingVertical: 6, paddingHorizontal: 10, borderRadius: 8 },
  myBubble:     { backgroundColor: '#DCF8C6' },
  theirBubble:  { backgroundColor: '#fff' },
  bubbleText:   { fontSize: 15, color: '#303030', lineHeight: 20 },
  bubbleMeta:   { flexDirection: 'row', alignItems: 'center', justifyContent: 'flex-end', marginTop: 2 },
  timeText:     { fontSize: 11, color: '#999' },
  tick:         { fontSize: 11, color: '#999' },
  tickRead:     { color: '#53bdeb' },  // WhatsApp blue double tick

  inputBar: {
    flexDirection: 'row', alignItems: 'flex-end',
    paddingHorizontal: 8, paddingVertical: 8,
    backgroundColor: '#f0f2f5', borderTopWidth: 1, borderTopColor: '#e0e0e0',
  },
  input: {
    flex: 1, backgroundColor: '#fff', borderRadius: 24,
    paddingHorizontal: 16,
    paddingTop: Platform.OS === 'ios' ? 10 : 8,
    paddingBottom: 8,
    fontSize: 16, maxHeight: 120, minHeight: 44, marginRight: 8,
  },
  sendBtn:    { width: 44, height: 44, borderRadius: 22, backgroundColor: '#25D366', alignItems: 'center', justifyContent: 'center' },
  sendBtnOff: { backgroundColor: '#b2dfdb' },
  sendIcon:   { color: '#fff', fontSize: 18 },
});

Run this on your phone. Type and send a few messages. Notice:

  • The header shows the live unread count, derived from state — no separate counter
  • The "Mark all read" button appears when unread > 0 and disappears when you tap it
  • Sent messages show a single tick ✓, which would turn blue ✓✓ when read (you can test by calling markAllRead)
  • The send button is greyed out when the input is empty

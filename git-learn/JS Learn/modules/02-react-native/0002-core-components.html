React Native · Lesson 2

Core Components

View · Text · Image · ScrollView · Pressable ~35 min Hands-on
Why this matters for Token

Every screen in Token — the token list, the token detail page, the message thread with a holder — is built from a small set of core components. These are the building blocks of all React Native UIs, the same way <div>, <p>, and <img> are the building blocks of web pages. Learn these five and you can build any screen layout.

The first screen you will build is the token list: one row per token you have issued, showing its label, its code, and whether anyone has used it. Everything in this lesson exists to get you there.

1. What is a component?

A component is a reusable piece of UI. In React Native, everything on screen is a component — a box of content, a line of text, a button, an image. You nest components inside each other to build layouts, exactly like nesting HTML tags.

Here is how HTML compares to React Native:

HTML (web) React Native (mobile) What it does
<div> <View> A container box — holds other components
<p>, <span>, <h1> <Text> Displays text — all text must be inside Text
<img> <Image> Displays an image
<div style="overflow:scroll"> <ScrollView> A scrollable container
<button> <Pressable> Responds to taps — the modern button
You cannot use HTML tags in React Native

<div>, <p>, <button> do not exist in React Native — your app runs on a phone, not in a browser. Use View, Text, and Pressable instead. If you accidentally use an HTML tag, React Native will throw an error or silently render nothing.

What is JSX?

The HTML-looking syntax you saw in Lesson 1 (<View>, <Text>) is called JSX. It is JavaScript with an XML-like syntax extension that lets you describe UI in a readable way. Under the hood, JSX is just JavaScript function calls — but you never have to think about that. Write it like HTML, with a few differences:

  • Every tag must be closed — <View></View> or self-closing <Image />
  • Use className → style in React Native (no CSS classes)
  • Embed JavaScript inside JSX with curly braces: {variableName}

Try it yourself

Curly braces put a value on screen, and React Native is fussy about which values it will accept. null, undefined, false and true all render nothing at all. A number renders itself — including zero. Run this and read what each expression actually evaluates to:

That last line is the important one. && does not return true or false — it returns one of its operands. When unread is 0, the whole expression is 0, and React Native will happily try to render that zero. You will meet the consequence in section 7.

2. View — the container

View is the most fundamental component. It is a rectangular box that holds other components. Think of it as the <div> of React Native.

import { View, Text, StyleSheet } from 'react-native';

export default function App() {
  return (
    <View style={styles.container}>
      <View style={styles.box}>
        <Text>I am inside a box</Text>
      </View>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#fff',
    padding: 16,
  },
  box: {
    backgroundColor: '#DCF8C6',  // pale green — an active token's tint
    padding: 12,
    borderRadius: 8,
  },
});

By itself View is invisible — it only becomes visible when you give it a background colour or border. Its main job is to group and position other components.

In Token

Every token card, every list row, every header bar, every screen background — all View components. When you look at the Token UI and wonder "how is that laid out?", the answer is almost always nested Views.

3. Text — displaying words

Text is the only component that can display text. Unlike HTML where you can put text almost anywhere, in React Native all text must be inside a Text component.

import { View, Text, StyleSheet } from 'react-native';

export default function App() {
  const tokenLabel = "Flipkart delivery";
  const tokenCode  = "KART-4KN9-RT2M";
  const lastUsed   = "10:32 AM";

  return (
    <View style={styles.container}>

      {/* Embedding JavaScript variables inside JSX using {} */}
      <Text style={styles.sender}>{tokenLabel}</Text>
      <Text style={styles.message}>{tokenCode}</Text>
      <Text style={styles.time}>{lastUsed}</Text>

      {/* Nesting Text inside Text — for mixed styles */}
      <Text style={styles.message}>
        Issued to <Text style={styles.bold}>Flipkart</Text>: 3 uses left
      </Text>

    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, padding: 20, backgroundColor: '#fff' },
  sender:  { fontSize: 14, fontWeight: '600', color: '#075E54' },
  message: { fontSize: 16, color: '#303030', marginTop: 2 },
  time:    { fontSize: 11, color: '#999', marginTop: 4, alignSelf: 'flex-end' },
  bold:    { fontWeight: 'bold' },
});
JSX comments use {/* */} not //

Inside JSX (between component tags), you must use {/* comment */} for comments, not //. Outside JSX, in regular JavaScript, // works fine. You'll get an error if you use // inside a JSX block.

numberOfLines — truncating long text

In the token list, a long label must not push the code and the time off the row. Use numberOfLines to cap it:

<Text numberOfLines={1} style={styles.label}>
  Flipkart delivery — returns pickup, weekday mornings only
</Text>
{/* Shows: "Flipkart delivery — returns pickup, weekday morn..." */}

numberOfLines truncates visually — the full string is still in memory, and it is still what a screen reader reads out. That matters for a token code: never truncate one. A code that reads KART-4KN9-… is not a code anyone can type.

Try it yourself

Sometimes you need the shortening in JavaScript rather than in the layout — for a notification, say, where there is no Text component to set the prop on. This playground is broken on purpose. It is meant to shorten a label to 20 characters and add an ellipsis, but it does something subtly wrong. Run it, read the output, then fix it:

Both lines come out wrong, and for the same reason: the condition is inverted. Short labels get truncated and an ellipsis added; long ones are returned untouched. Swap < for > and check both cases again — the boundary, where the label is exactly 20 characters, is the one worth thinking about twice.

4. Image — showing pictures

Image displays images. It can show images from the internet (a URL) or from local files inside your project.

import { View, Image, Text, StyleSheet } from 'react-native';

export default function App() {
  return (
    <View style={styles.container}>

      {/* Image from the internet */}
      <Image
        source={{ uri: 'https://i.pravatar.cc/100?img=5' }}
        style={styles.avatar}
      />

      {/* Local image from your assets folder */}
      <Image
        source={require('./assets/icon.png')}
        style={styles.icon}
      />

      <Text>Profile photo</Text>

    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, alignItems: 'center', justifyContent: 'center' },
  avatar: {
    width: 60,
    height: 60,
    borderRadius: 30,   // half of width/height = perfect circle
    marginBottom: 8,
  },
  icon: {
    width: 40,
    height: 40,
  },
});
Image always needs explicit width and height

Unlike HTML where images size themselves automatically, React Native images show nothing if you don't give them a width and height. Always set both. Use borderRadius equal to half the width/height to make a circular avatar — this is how WhatsApp contact photos are displayed.

resizeMode — controlling how images fit

<Image
  source={{ uri: 'https://i.pravatar.cc/300' }}
  style={{ width: 100, height: 100 }}
  resizeMode="cover"   // crop to fill — most common for avatars
/>

{/* resizeMode options:
  'cover'   — fills the box, crops if needed (default, use for avatars)
  'contain' — fits the whole image in the box, may leave gaps
  'stretch' — distorts the image to fill exactly
*/}

5. ScrollView — making content scrollable

By default, if content is taller than the screen, it gets cut off. ScrollView makes its contents scrollable — the user can swipe up and down to see everything.

import { ScrollView, View, Text, StyleSheet } from 'react-native';

export default function App() {
  // Simulate the messages on one token's thread. The holder has no name —
  // that is the whole point of Token, so they are just "holder".
  const messages = [
    { id: 1, from: 'holder', text: 'Delivery arriving between 2 and 4pm.' },
    { id: 2, from: 'you',    text: 'Leave it with the guard, please.' },
    { id: 3, from: 'holder', text: 'Will do.' },
    { id: 4, from: 'you',    text: 'Thanks.' },
    { id: 5, from: 'holder', text: 'Attempted delivery, nobody home.' },
    { id: 6, from: 'you',    text: 'Try again tomorrow morning?' },
    { id: 7, from: 'holder', text: 'Booked for 9am.' },
    { id: 8, from: 'you',    text: 'Perfect.' },
  ];

  return (
    <ScrollView style={styles.container}>
      {messages.map(msg => (
        <View key={msg.id} style={styles.bubble}>
          <Text style={styles.sender}>{msg.from}</Text>
          <Text>{msg.text}</Text>
        </View>
      ))}
    </ScrollView>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, padding: 16, backgroundColor: '#ECE5DD' },
  bubble: {
    backgroundColor: '#fff',
    padding: 10,
    borderRadius: 8,
    marginBottom: 8,
    maxWidth: '80%',
  },
  sender: { fontWeight: '600', color: '#075E54', marginBottom: 2 },
});
ScrollView vs FlatList — important difference

ScrollView renders all its children at once — even the ones off screen. For short content (a settings page, a profile form) this is fine. But for long lists like a message thread with hundreds of messages, it's slow and uses too much memory. For lists, use FlatList (covered in Lesson 7) — it only renders what's visible. For now, use ScrollView to get things on screen, and you'll upgrade to FlatList later.

6. Pressable — handling taps

Pressable is the modern way to make anything tappable in React Native. Wrap any component in Pressable and give it an onPress handler — that function runs when the user taps it.

import { View, Text, Pressable, StyleSheet, Alert } from 'react-native';

export default function App() {
  function handleSend() {
    Alert.alert('Message sent!', 'Your message was delivered.');
  }

  function handleChatPress(chatName) {
    Alert.alert('Opening chat with ' + chatName);
  }

  return (
    <View style={styles.container}>

      {/* Basic button */}
      <Pressable style={styles.sendButton} onPress={handleSend}>
        <Text style={styles.sendButtonText}>Send</Text>
      </Pressable>

      {/* Pressable with visual feedback — changes style when pressed */}
      <Pressable
        style={({ pressed }) => [
          styles.chatRow,
          pressed && styles.chatRowPressed   // apply extra style while finger is down
        ]}
        onPress={() => handleTokenPress('KART-4KN9-RT2M')}
      >
        <Text style={styles.chatName}>Flipkart delivery</Text>
        <Text style={styles.preview}>KART-4KN9-RT2M · 3 uses left</Text>
      </Pressable>

    </View>
  );
}

const styles = StyleSheet.create({
  container:       { flex: 1, padding: 20, backgroundColor: '#fff' },
  sendButton:      { backgroundColor: '#25D366', padding: 14, borderRadius: 8, alignItems: 'center' },
  sendButtonText:  { color: '#fff', fontWeight: '700', fontSize: 16 },
  chatRow:         { padding: 16, borderBottomWidth: 1, borderBottomColor: '#f0f0f0' },
  chatRowPressed:  { backgroundColor: '#f5f5f5' },
  chatName:        { fontSize: 16, fontWeight: '600' },
  preview:         { fontSize: 14, color: '#666', marginTop: 2 },
});
({ pressed }) — destructuring in action

Notice style={({ pressed }) => [...]} — that's the destructuring from Module 1 Lesson 11. Pressable passes an object { pressed: true/false } to the style function. You destructure pressed right in the parameter to use it. This is exactly the kind of place modern JS syntax clicks into place.

onLongPress — handling hold gestures

<Pressable
  onPress={() => openToken(token.id)}
  onLongPress={() => showTokenOptions(token.id)}
>
  {/* token row content */}
</Pressable>
{/* In Token: tap opens the token detail, long-press offers pause and revoke */}

7. Putting it together — a token list row

Let's combine all five components to build a real Token list row — category icon, label, code, last-used time, and an unread badge, side by side.

Notice what is missing: faces

A chat app puts a photo of a person on every row. Token cannot, and would not want to. The holder of KART-4KN9-RT2M is whoever redeemed it — you never learn their name, their number, or their face, and they never learn yours. The row shows what the token is for, not who is on the other end. That is the product in one screen.

So the Image in each row is a category icon — delivery, gym, bank — not an avatar.

Replace your entire App.js with this and run it on your phone:

// A single token row component
function TokenRow({ token, onPress }) {
  return (
    <Pressable
      style={({ pressed }) => [styles.row, pressed && styles.rowPressed]}
      onPress={() => onPress(token)}
    >
      {/* Category icon — not a face. Nobody has one here. */}
      <Image
        source={{ uri: token.icon }}
        style={styles.icon}
        resizeMode="contain"
      />

      {/* Middle — label and code */}
      <View style={styles.middle}>
        <Text style={styles.name} numberOfLines={1}>{token.label}</Text>
        <Text style={styles.preview} numberOfLines={1}>{token.code}</Text>
      </View>

      {/* Right — last used and unread badge */}
      <View style={styles.right}>
        <Text style={styles.time}>{token.lastUsed}</Text>
        {token.unread > 0 && (
          <View style={styles.badge}>
            <Text style={styles.badgeText}>{token.unread}</Text>
          </View>
        )}
      </View>
    </Pressable>
  );
}

// Main app
export default function App() {
  function handleTokenPress(token) {
    // In Lesson 8 (Navigation) this will open the token detail screen
    console.log('Tapped:', token.label);
  }

  return (
    <View style={styles.screen}>
      {/* Header */}
      <View style={styles.header}>
        <Text style={styles.headerTitle}>My tokens</Text>
      </View>

      {/* Token list */}
      <ScrollView>
        {tokens.map(token => (
          <TokenRow key={token.id} token={token} onPress={handleTokenPress} />

      </ScrollView>
    </View>
  );
}

Run this on your phone. You should see a working token list — a header, category icons, labels, codes, times, and unread count badges. All five core components working together.

Notice what you just learned without realising it
  • Custom components — ChatRow is a function you wrote that returns JSX. This is how React Native apps are structured: small reusable components composed together.
  • Props — ChatRow receives chat and onPress as inputs (called props). This is how parent components pass data down to children.
  • Conditional rendering — {chat.unread > 0 && (...)} only renders the badge if there are unread messages. The && short-circuit pattern is the standard way to conditionally show/hide UI in React Native.

You'll use all three of these patterns in every screen you build.

Try it yourself

Look again at the badge line in TokenRow:

{token.unread > 0 && (
  <View style={styles.badge}>…</View>
)}

The > 0 looks like clutter. It is the most important character in the row. This playground shows both versions side by side:

The tempting version yields 0 for the gym token — not false, not nothing, the number zero. React Native renders numbers, so it tries to draw that zero, discovers it is not inside a <Text>, and throws "Text strings must be rendered within a <Text> component". The screen goes red on the one row that has nothing to show.

Why this bug survives review

{token.unread && …} is correct on every row that has unread messages. It only fails on rows with exactly zero — and zero is the state you are least likely to have in your test data, because you were testing badges. It ships, and it crashes the first time a real user opens the app with a quiet token.

The habit that prevents it: make the condition a boolean, not a value. > 0, !== null, Boolean(x). Never lean on truthiness inside JSX.

React Native · Lesson 1

Expo Setup & EAS Build

Setup ~30 min Hands-on
What you'll have by the end of this lesson

A real React Native app running on your phone — both Android and iOS. You'll also have EAS Build set up, which is what you'll use later to include WebRTC (calls) and publish to the Play Store and App Store. This is the foundation everything else is built on.

1. What is Expo?

React Native lets you build mobile apps using JavaScript. But setting up a raw React Native project is complex — you need Android Studio, Xcode, SDKs, emulators, and a lot of configuration just to see "Hello World".

Expo is a layer on top of React Native that handles all that setup for you. Instead of configuring native build tools yourself, Expo gives you:

  • A ready-to-go project structure
  • A phone app (Expo Go) to instantly preview your code by scanning a QR code
  • Pre-built access to camera, notifications, location, and more
  • EAS Build — a cloud service that builds your final app for Android and iOS
Expo is how professionals start React Native projects

Companies like Shopify, Discord, and Coinbase have all used Expo. It's not a beginner shortcut — it's the recommended way to build React Native apps in 2024.

Expo Go vs EAS Build — what's the difference?

This distinction matters for your project, so understand it now:

Expo Go EAS Build
How it works Scan QR code — app runs inside Expo Go app Cloud builds a real .apk/.ipa you install directly
Speed Instant — great for learning 5–15 min build time
Native modules (WebRTC) Not supported Fully supported
Use for Modules 01–02 and Track A up to A6 (learning, screens, API, messaging) A7 onward (WebRTC calls, publishing)

For now you'll use Expo Go — it's instant and perfect for the next several modules. You'll switch to EAS Build in Module 5 when you add WebRTC. This lesson sets up both so you're ready.

2. What you need to install

You need three things on your computer:

  1. Node.js — JavaScript runtime. Expo runs on it.
  2. Expo CLI — the command-line tool to create and run Expo projects.
  3. Expo Go app — installed on your phone to preview the app instantly.

Step 1 — Install Node.js

Go to nodejs.org and download the LTS version (the one labelled "Recommended For Most Users"). Install it like any normal program.

Verify it worked — open your terminal (Command Prompt or PowerShell on Windows) and run:

node --version
# Should print something like: v20.11.0

npm --version
# Should print something like: 10.2.4
If you see 'node is not recognized'

Close your terminal completely and reopen it after installing Node. Sometimes the terminal needs a restart to pick up the new installation.

Step 2 — Install Expo CLI

In your terminal, run:

npm install -g expo-cli

The -g flag installs it globally — meaning you can use it from any folder on your computer.

Step 3 — Install Expo Go on your phone

  • Android: Search "Expo Go" on the Google Play Store and install it.
  • iOS: Search "Expo Go" on the App Store and install it.

Make sure your phone and computer are on the same Wi-Fi network — this is how your phone connects to your computer's development server.

3. Create your project

In your terminal, navigate to where you want to create the project. Then run:

npx create-expo-app token-app --template blank

cd token-app

This creates a new folder called token-app with a basic Expo project inside. The blank template gives you the cleanest starting point.

Your project folder will look like this:

token-app/
├── app.json          ← App config (name, icon, version)
├── App.js            ← Your app's entry point — start here
├── package.json      ← Dependencies list
├── assets/           ← Images, fonts, icons
└── node_modules/     ← Installed packages (don't touch this)

Open App.js

Open the project in VS Code (or any code editor). The App.js file is where your app starts. It currently looks like this:

import { StatusBar } from 'expo-status-bar';
import { StyleSheet, Text, View } from 'react-native';

export default function App() {
  return (
    <View style={styles.container}>
      <Text>Open up App.js to start working on your app!</Text>
      <StatusBar style="auto" />
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#fff',
    alignItems: 'center',
    justifyContent: 'center',
  },
});

This might look unfamiliar — it's JSX, a mix of JavaScript and HTML-like syntax used by React Native. You'll learn exactly how it works in the next lesson. For now, just get it running.

4. Run the app on your phone

In your terminal, inside the token-app folder, run:

npx expo start

You'll see output like this in your terminal, with a QR code:

Starting project at /your/path/token-app
...
› Metro waiting on exp://192.168.1.5:8081
› Scan the QR code above with Expo Go (Android) or the Camera app (iOS)

› Press a │ open Android
› Press i │ open iOS simulator
› Press w │ open web

On Android: Open the Expo Go app → tap "Scan QR Code" → scan the QR code in your terminal.

On iOS: Open the default Camera app → point it at the QR code → tap the Expo Go banner that appears.

Your phone will load the app. You should see the text "Open up App.js to start working on your app!" on a white screen.

Live reload — save and see instantly

Now open App.js in your editor and change the text to "Building Token!". Save the file. Your phone updates automatically — no need to reload manually. This is called Fast Refresh and it's one of the best parts of the Expo development experience.

Phone and computer must be on the same Wi-Fi

If the QR code scan fails or the app doesn't load, the most common reason is that your phone and computer are on different networks. Check both are on the same Wi-Fi. If you're on a university or office network that blocks device-to-device connections, use a mobile hotspot from your phone and connect your computer to it instead.

5. Make your first edit

Let's make a small change so you see how editing works. Open App.js and replace the entire file with this:

import { StyleSheet, Text, View } from 'react-native';

export default function App() {
  return (
    <View style={styles.container}>
      <Text style={styles.title}>Token</Text>
      <Text style={styles.subtitle}>Built by Ashish</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#12263A',  // Token ink
    alignItems: 'center',
    justifyContent: 'center',
  },
  title: {
    fontSize: 28,
    fontWeight: 'bold',
    color: '#fff',
    marginBottom: 8,
  },
  subtitle: {
    fontSize: 16,
    color: '#DCF3EA',  // Token accent-soft (your own message bubble)
  },
});

Save the file. Your phone should now show a dark screen with white text — Token's colour scheme from Lesson 3. You just wrote your first React Native screen.

6. Set up EAS Build (do this now, use it later)

EAS Build is what you'll use in Module 5 (WebRTC calls) and Module 6 (publishing). Setting it up now takes 5 minutes and means you won't be blocked later.

Step 1 — Create a free Expo account

Go to expo.dev and sign up for a free account.

Step 2 — Log in from your terminal

npx expo login

Enter the email and password you just created.

Step 3 — Install EAS CLI

npm install -g eas-cli

Step 4 — Link your project to your Expo account

eas init

Run this inside your token-app folder. It creates an eas.json config file and links the project to your account.

Step 5 — Verify with a test build (optional but recommended)

You don't need to build now, but when you do, the command is:

# Build for Android
eas build --platform android --profile preview

# Build for iOS
eas build --platform ios --profile preview
What 'preview' means

EAS has build profiles — preview creates an internal test build (not for the store). production creates a store-ready build. Use preview throughout development, switch to production only when you're ready to publish in Module 6.

iOS builds need Apple Developer account for device testing

You can build for iOS on EAS without a Mac, but to install the .ipa on a real iPhone (outside the App Store), you need an Apple Developer account ($99/year) to register your device. For now, you can develop and test using the iOS simulator via EAS or just focus on Android for Modules 2–4.

6b. Inside eas.json — profiles and what must never go in one

eas init wrote you an eas.json. It is a small file with a large amount of behaviour in it, and it is worth reading rather than accepting:

{
  "build": {
    "base": {
      "node": "20.11.0",
      "env": { "API_URL": "https://api.tokn.app" }
    },
    "development": {
      "extends": "base",
      "developmentClient": true,
      "distribution": "internal",
      "env": { "API_URL": "http://192.168.1.20:3000" }
    },
    "preview": {
      "extends": "base",
      "distribution": "internal"
    },
    "production": {
      "extends": "base",
      "autoIncrement": true
    }
  }
}

A profile can extends another, and its own keys win. development above is the base profile with a local API URL swapped in — which is why you can point a dev build at the laptop on your desk without touching the production settings.

Try it yourself

The resolution rule is simple and worth watching happen once:

Nothing secret goes in env or extra. Ever.

Everything in a build profile's env, and everything in app.config.js's extra, is compiled into the app bundle. An .apk is a zip file; anyone who downloads your app can read those values in about a minute. That is not a vulnerability in Expo — it is what a client-side app is.

So the API URL belongs there, and TOKEN_CODE_PEPPER never does. Token's pepper and encryption key are what make a stolen database useless; ship one inside the app and every token ever issued is compromised by anyone who installs it. Secrets live on the server, in the API's own environment, and the app asks the API.

Now build it yourself

Nothing else in this lesson can be checked on this page — installing Node and scanning a QR code are things you do, not things a function returns. Profile resolution is the exception, and it is the part you will actually get wrong.

7. Your project structure going forward

As Token grows, your folder structure will grow with it. Here's what it will eventually look like — it's good to have this picture in your head now:

token-app/
├── App.js                    ← Entry point, sets up navigation
├── app.json                  ← App config
├── eas.json                  ← EAS Build config
├── package.json
│
├── screens/                  ← One file per screen
│   ├── LoginScreen.js
│   ├── RegisterScreen.js
│   ├── TokenListScreen.js
│   ├── TokenDetailScreen.js
│   ├── CreateTokenScreen.js
│   ├── MessageThreadScreen.js
│   └── SettingsScreen.js
│
├── components/               ← Reusable UI pieces
│   ├── MessageBubble.js
│   ├── TokenRow.js
│   └── QrCode.js
│
├── api/                      ← Your own backend, one module per area
│   ├── client.js             ← fetch wrapper: base URL, headers, errors
│   ├── auth.js               ← login, register, token refresh
│   └── tokens.js             ← issue, list, revoke
│
└── assets/                   ← Images, icons, fonts

You'll build this structure piece by piece across the modules. For now it's just App.js — and that's fine.

React Native · Lesson 6

useEffect

Side effects · Lifecycle · Cleanup ~30 min Hands-on
Why this matters for Token

When a user opens their token list your app needs to fetch it from the API. When they leave a token's thread, you need to stop listening for new messages so you are not wasting battery and data. While the list is open, you need a live subscription so a redemption shows up the instant it happens. All of this — loading data when a screen opens, subscribing to live updates, cleaning up when leaving — is what useEffect handles.

1. What is a side effect?

A React Native component's job is to take some data and return UI. That's it. But real apps need to do things beyond just rendering — fetch data from a server, set up a timer, subscribe to live updates over a WebSocket, update the navigation title. These are called side effects because they reach outside the component into the outside world.

You cannot do these things directly inside the component function body — that code runs on every render, which would mean fetching data on every keystroke, opening a new subscription repeatedly, and leaking memory. useEffect gives you a controlled place to run side effects.

// WRONG — fetching data directly in the component body
export default function ThreadScreen() {
  // This runs on EVERY render — including every keystroke in the input!
  const messages = fetchMessagesFromApi();  // runs constantly

  return <View>...</View>;
}

// CORRECT — useEffect runs only when you tell it to
export default function ThreadScreen() {
  const [messages, setMessages] = useState([]);

  useEffect(() => {
    // This only runs once when the screen opens
    fetchMessagesFromApi().then(msgs => setMessages(msgs));
  }, []);  // empty array = run once on mount

  return <View>...</View>;
}

2. useEffect syntax — the three forms

useEffect takes two arguments: a function (the effect), and a dependency array that controls when it runs.

import { useEffect } from 'react';

// ── Form 1: No dependency array — runs after EVERY render ─────────────────
useEffect(() => {
  console.log('I run after every single render');
});
// Avoid this — usually not what you want

// ── Form 2: Empty array [] — runs ONCE when component mounts ──────────────
useEffect(() => {
  console.log('I run once when the screen opens');
}, []);
// Use for: initial data fetch, setting up subscriptions

// ── Form 3: Array with values — runs when those values change ─────────────
useEffect(() => {
  console.log('tokenId changed — fetch new messages');
}, [tokenId]);
// Runs once on mount AND again whenever tokenId changes
The dependency array — the most important thing to get right

The dependency array tells React Native when to re-run the effect. Empty array [] means "only on mount". An array with values like [tokenId, userId] means "on mount, and any time tokenId or userId changes". No array at all means "every render" — almost never what you want.

3. Loading data when a screen opens

The most common use of useEffect — fetch data from your API when the screen first appears.

import { useState, useEffect } from 'react';
import { View, Text, ActivityIndicator, StyleSheet } from 'react-native';

// Simulated API call
function fetchMessages(tokenId) {
  return new Promise(resolve => {
    setTimeout(() => {
      resolve([
        { id: 'm1', from: 'holder', text: 'Out for delivery.',  time: '10:01' },
        { id: 'm2', from: 'owner',  text: 'Leave with guard.',  time: '10:02' },
      ]);
    }, 1000);  // simulate 1 second network delay
  });
}

export default function ThreadScreen({ tokenId = 'tok-001' }) {
  const [messages, setMessages]   = useState([]);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError]         = useState(null);

  useEffect(() => {
    async function loadMessages() {
      try {
        setIsLoading(true);
        setError(null);
        const msgs = await fetchMessages(tokenId);
        setMessages(msgs);
      } catch (err) {
        setError('Could not load messages. Check your connection.');
        console.error('loadMessages error:', err);
      } finally {
        setIsLoading(false);
      }
    }

    loadMessages();
  }, [tokenId]);  // re-fetch if the user opens a different token

  // ── Render loading state ──────────────────────────────────────────────────
  if (isLoading) {
    return (
      <View style={styles.centre}>
        <ActivityIndicator size="large" color="#12263A" />
        <Text style={styles.loadingText}>Loading messages...</Text>
      </View>
    );
  }

  // ── Render error state ────────────────────────────────────────────────────
  if (error) {
    return (
      <View style={styles.centre}>
        <Text style={styles.errorText}>{error}</Text>
      </View>
    );
  }

  // ── Render messages ───────────────────────────────────────────────────────
  return (
    <View style={styles.container}>
      {messages.map(msg => (
        <Text key={msg.id} style={styles.message}>
          {msg.from}: {msg.text}
        </Text>
      ))}
    </View>
  );
}

const styles = StyleSheet.create({
  container:   { flex: 1, padding: 16, backgroundColor: '#ECE5DD' },
  centre:      { flex: 1, alignItems: 'center', justifyContent: 'center' },
  loadingText: { marginTop: 12, color: '#667781', fontSize: 14 },
  errorText:   { color: '#e53e3e', fontSize: 15, textAlign: 'center', paddingHorizontal: 24 },
  message:     { fontSize: 15, marginBottom: 8 },
});
useEffect cannot be async directly — use an inner function

You cannot write useEffect(async () => { ... }) — React Native expects the effect function to return either nothing or a cleanup function, not a Promise. The pattern is to define an async function inside the effect and call it immediately, as shown above. You'll write this pattern on every screen that loads data.

4. Cleanup — stopping effects when a screen closes

Some effects set things up that need to be torn down — timers, socket subscriptions, event listeners. If you don't clean up, those effects keep running after the screen is gone, wasting resources and causing bugs (updating state on unmounted components).

Return a function from your effect — React Native calls it when the component unmounts or before re-running the effect.

useEffect(() => {
  // Set up the effect
  const timer = setInterval(() => {
    console.log('checking for new messages...');
  }, 5000);

  // Return a cleanup function
  return () => {
    clearInterval(timer);  // runs when component unmounts
    console.log('timer cleared');
  };
}, []);  // set up once, clean up once

A live subscription with cleanup

This is the exact pattern you'll use in A6, when the screen is fed by your own WebSocket server:

useEffect(() => {
  // subscribe returns the function that undoes it
  const unsubscribe = socket.subscribe(`token:${tokenId}`, (message) => {
    setMessages(prev => [...prev, message]);
  });

  // Clean up — stop listening when the screen closes
  return () => unsubscribe();
}, [tokenId]);
This is how live updates work

When you open a token thread, the screen subscribes to that conversation — any new message the server pushes triggers your callback and updates the list. When you leave the thread, the cleanup function calls unsubscribe() and the messages stop arriving. Your battery and data thank you.

The shape matters more than the library: a subscribe call returns the function that undoes it. Timers, event listeners and sockets all work this way, which is why one cleanup pattern covers all three.

Try it yourself — this one is broken on purpose

An effect that subscribes and forgets to clean up. The user opens three token threads in a row. Run it and count the deliveries:

Every thread the user opened is still listening. By the third token, one incoming message is handled three times — so the message appears three times, or a counter increments by three, or three network requests go out. Nothing crashes. It simply gets worse the longer the app stays open.

Why the leak is invisible in testing

Open one screen and it is perfect. Open it, leave, come back — now every action happens twice, and you will probably blame the action. The symptom appears far from the cause, and only after navigation the tester did not think to repeat.

On a phone this also drains the battery: every abandoned subscription is a socket the app keeps alive.

5. Running effects when values change

Put a value in the dependency array and the effect re-runs every time that value changes. This is how you re-fetch data when the user opens a different token.

// Fetch messages for whichever token thread is currently open
useEffect(() => {
  if (!tokenId) return;   // guard against undefined on first render

  async function load() {
    setIsLoading(true);
    const msgs = await fetchMessages(tokenId);
    setMessages(msgs);
    setIsLoading(false);
  }

  load();
}, [tokenId]);  // re-runs every time tokenId changes

// User opens tok-001 → effect runs, loads tok-001 messages
// User opens tok-002 → tokenId changes → effect re-runs, loads tok-002 messages

Multiple dependencies

// Re-run if either userId or filter changes
useEffect(() => {
  loadFilteredMessages(userId, filter);
}, [userId, filter]);
Include everything the effect uses in the dependency array

If your effect reads a variable (like tokenId), put it in the dependency array. If you don't, the effect uses the stale value from the first render — a subtle bug where the thread shows the previous token's messages after the user switches. React's ESLint plugin (eslint-plugin-react-hooks) will warn you if you miss a dependency.

6. Common useEffect patterns for Token's screens

// ── Pattern 1: Load data once on mount ───────────────────────────────────
useEffect(() => {
  async function loadTokens() {
    setIsLoading(true);
    const data = await fetchUserTokens(userId);
    setTokens(data);
    setIsLoading(false);
  }
  loadTokens();
}, []);


// ── Pattern 2: Live socket subscription with cleanup ──────────────────────
useEffect(() => {
  const unsub = socket.subscribe('token:' + tokenId, (message) => {
    setMessages(prev => [...prev, message]);
  });
  return () => unsub();
}, [tokenId]);


// ── Pattern 3: Update screen title when data loads ────────────────────────
useEffect(() => {
  if (token) {
    navigation.setOptions({ title: token.label });
  }
}, [token]);


// ── Pattern 4: Auto-scroll to bottom when messages change ─────────────────
useEffect(() => {
  if (messages.length > 0) {
    scrollRef.current?.scrollToEnd({ animated: true });
  }
}, [messages]);


// ── Pattern 5: Search filter — re-run when query changes ─────────────────
useEffect(() => {
  if (!searchQuery.trim()) {
    setFilteredTokens(tokens);
    return;
  }
  const results = tokens.filter(t =>
    t.label.toLowerCase().includes(searchQuery.toLowerCase())
  );
  setFilteredTokens(results);
}, [searchQuery, tokens]);

7. Full example — the token list with live loading and search

This is the real token list screen — it loads your tokens on mount with a spinner, then lets you search them live as you type. Replace your App.js and run it.

Note where the search happens: in the client, over labels you wrote yourself. Token has no server-side search, because messages are end-to-end encrypted and the server cannot read them. The label is yours, so it is the one thing that can be searched.

import { useState, useEffect } from 'react';
import {
  View, Text, TextInput, FlatList,
  ActivityIndicator, Pressable, StyleSheet
} from 'react-native';

// ── Simulated API call ─────────────────────────────────────────────────────
function fetchTokens() {
  return new Promise(resolve => {
    setTimeout(() => {
      resolve([
        { id: '1', label: 'Flipkart delivery', code: 'KART-4KN9-RT2M', time: '10:32', unread: 2 },
        { id: '2', label: 'Gym membership',    code: 'GYMX-7PQ8-VN3K', time: '09:15', unread: 0 },
        { id: '3', label: 'Flat viewing',      code: 'RENT-2WX7-HJ5D', time: 'Yesterday', unread: 5 },
        { id: '4', label: 'Car service',       code: 'CARS-9KM3-BF6P', time: 'Yesterday', unread: 0 },
        { id: '5', label: 'Dentist booking',   code: 'DENT-9KRW-3TF8', time: 'Monday',    unread: 0 },
        { id: '6', label: 'Courier pickup',    code: 'MERC-8GH2-KP4X', time: 'Monday',    unread: 1 },
      ]);
    }, 1200);
  });
}

// ── Token row component ────────────────────────────────────────────────────
function TokenRow({ token, onPress }) {
  return (
    <Pressable
      style={({ pressed }) => [styles.row, pressed && styles.rowPressed]}
      onPress={() => onPress(token)}
    >
      <View style={styles.iconCircle}>
        <Text style={styles.iconLetter}>
          {token.label.charAt(0).toUpperCase()}
        </Text>
      </View>
      <View style={styles.middle}>
        <Text style={styles.name} numberOfLines={1}>{token.label}</Text>
        <Text style={styles.preview} numberOfLines={1}>{token.code}</Text>
      </View>
      <View style={styles.right}>
        <Text style={styles.time}>{token.time}</Text>
        {token.unread > 0 && (
          <View style={styles.badge}>
            <Text style={styles.badgeText}>{token.unread}</Text>
          </View>
        )}
      </View>
    </Pressable>
  );
}

// ── Main screen ────────────────────────────────────────────────────────────
export default function App() {
  const [tokens, setTokens]          = useState([]);
  const [isLoading, setIsLoading]   = useState(true);
  const [error, setError]           = useState(null);
  const [searchQuery, setSearchQuery] = useState('');

  // ── Effect 1: Load tokens on mount ───────────────────────────────────────
  useEffect(() => {
    async function loadTokens() {
      try {
        setIsLoading(true);
        setError(null);
        const data = await fetchTokens();
        setTokens(data);
      } catch (err) {
        setError('Could not load your tokens. Pull down to retry.');
      } finally {
        setIsLoading(false);
      }
    }
    loadTokens();
  }, []);  // empty array — run once on mount

  // ── Derived: filter tokens based on search query ──────────────────────────
  // Label only. The code is not searched: a code is capability material, and
  // typing a fragment of one into a search box is not how anyone finds a token.
  const filteredTokens = tokens.filter(t =>
    t.label.toLowerCase().includes(searchQuery.toLowerCase())
  );

  // ── Handlers ──────────────────────────────────────────────────────────────
  function handleTokenPress(token) {
    // In Lesson 8 (Navigation) this will navigate to the token detail screen
    console.log('Opening:', token.label);
  }

  // ── Render ─────────────────────────────────────────────────────────────────
  return (
    <View style={styles.screen}>

      {/* Header */}
      <View style={styles.header}>
        <Text style={styles.headerTitle}>My tokens</Text>
      </View>

      {/* Search bar */}
      <View style={styles.searchBar}>
        <TextInput
          style={styles.searchInput}
          placeholder="Search your tokens"
          placeholderTextColor="#667781"
          value={searchQuery}
          onChangeText={setSearchQuery}
        />
      </View>

      {/* Loading state */}
      {isLoading && (
        <View style={styles.centre}>
          <ActivityIndicator size="large" color="#12263A" />
          <Text style={styles.loadingText}>Loading your tokens...</Text>
        </View>
      )}

      {/* Error state */}
      {error && !isLoading && (
        <View style={styles.centre}>
          <Text style={styles.errorText}>{error}</Text>
        </View>
      )}

      {/* Empty search result */}
      {!isLoading && !error && filteredTokens.length === 0 && (
        <View style={styles.centre}>
          <Text style={styles.emptyText}>No tokens match "{searchQuery}"</Text>
        </View>
      )}

      {/* Token list */}
      {!isLoading && !error && (
        <FlatList
          data={filteredTokens}
          keyExtractor={item => item.id}
          renderItem={({ item }) => (
            <TokenRow token={item} onPress={handleTokenPress} />
          )}
        />
      )}

    </View>
  );
}

const styles = StyleSheet.create({
  screen:      { flex: 1, backgroundColor: '#fff' },

  header:      { backgroundColor: '#12263A', paddingTop: 48, paddingBottom: 12, paddingHorizontal: 16 },
  headerTitle: { color: '#fff', fontSize: 20, fontWeight: '700' },

  searchBar:   { backgroundColor: '#f0f2f5', paddingHorizontal: 12, paddingVertical: 8 },
  searchInput: { backgroundColor: '#fff', borderRadius: 20, paddingHorizontal: 16, paddingVertical: 8, fontSize: 15, color: '#111' },

  centre:      { flex: 1, alignItems: 'center', justifyContent: 'center' },
  loadingText: { marginTop: 12, color: '#667781', fontSize: 14 },
  errorText:   { color: '#e53e3e', fontSize: 15, textAlign: 'center', paddingHorizontal: 24 },
  emptyText:   { color: '#667781', fontSize: 15 },

  row:         { flexDirection: 'row', alignItems: 'center', paddingHorizontal: 16, paddingVertical: 12, borderBottomWidth: 1, borderBottomColor: '#f0f2f5' },
  rowPressed:  { backgroundColor: '#f5f5f5' },

  iconCircle:   { width: 52, height: 52, borderRadius: 26, backgroundColor: '#12263A', alignItems: 'center', justifyContent: 'center' },
  iconLetter:   { color: '#fff', fontSize: 22, fontWeight: '700' },

  middle:      { flex: 1, marginLeft: 12, marginRight: 8 },
  name:        { fontSize: 16, fontWeight: '600', color: '#111' },
  preview:     { fontSize: 14, color: '#667781', marginTop: 2 },

  right:       { alignItems: 'flex-end' },
  time:        { fontSize: 12, color: '#667781' },
  badge:       { backgroundColor: '#2F9E7E', borderRadius: 10, minWidth: 20, height: 20, alignItems: 'center', justifyContent: 'center', marginTop: 4, paddingHorizontal: 5 },

Run this. You'll see a 1.2 second loading spinner, then the full token list appears. Type in the search bar — the list filters live as you type.

Notice what this screen does with just two effects
  • Effect 1 (empty array) — loads your tokens once when the screen opens, handles loading and error states
  • Derived value — the filtered list recomputes instantly from state on every render, no effect needed

You also used FlatList here for the first time — you'll learn it fully in Lesson 7. It's the performant list component for long lists.

Now build it yourself

The effect body itself is barely any code — the work is in the subscription it manages. Written as a plain function, that part is testable without a screen at all.

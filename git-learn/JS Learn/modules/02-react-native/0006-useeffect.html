React Native · Lesson 6

useEffect

Side effects · Lifecycle · Cleanup ~30 min Hands-on
Why this matters for your WhatsApp clone

When a user opens a chat screen your app needs to immediately fetch messages from Firebase. When they leave the screen, you need to stop listening for new messages so you're not wasting battery and data. When the chat list is open, you need a live listener that updates the list the instant a new message arrives. All of this — loading data when a screen opens, subscribing to live updates, cleaning up when leaving — is what useEffect handles.

1. What is a side effect?

A React Native component's job is to take some data and return UI. That's it. But real apps need to do things beyond just rendering — fetch data from a server, set up a timer, subscribe to Firebase updates, update the navigation title. These are called side effects because they reach outside the component into the outside world.

You cannot do these things directly inside the component function body — that code runs on every render, which would mean fetching data on every keystroke, creating new Firebase subscriptions repeatedly, and leaking memory. useEffect gives you a controlled place to run side effects.

// WRONG — fetching data directly in the component body
export default function ChatScreen() {
  // This runs on EVERY render — including every keystroke in the input!
  const messages = fetchMessagesFromFirebase();  // runs constantly

  return <View>...</View>;
}

// CORRECT — useEffect runs only when you tell it to
export default function ChatScreen() {
  const [messages, setMessages] = useState([]);

  useEffect(() => {
    // This only runs once when the screen opens
    fetchMessagesFromFirebase().then(msgs => setMessages(msgs));
  }, []);  // empty array = run once on mount

  return <View>...</View>;
}

2. useEffect syntax — the three forms

useEffect takes two arguments: a function (the effect), and a dependency array that controls when it runs.

import { useEffect } from 'react';

// ── Form 1: No dependency array — runs after EVERY render ─────────────────
useEffect(() => {
  console.log('I run after every single render');
});
// Avoid this — usually not what you want

// ── Form 2: Empty array [] — runs ONCE when component mounts ──────────────
useEffect(() => {
  console.log('I run once when the screen opens');
}, []);
// Use for: initial data fetch, setting up subscriptions

// ── Form 3: Array with values — runs when those values change ─────────────
useEffect(() => {
  console.log('chatId changed — fetch new messages');
}, [chatId]);
// Runs once on mount AND again whenever chatId changes
The dependency array — the most important thing to get right

The dependency array tells React Native when to re-run the effect. Empty array [] means "only on mount". An array with values like [chatId, userId] means "on mount, and any time chatId or userId changes". No array at all means "every render" — almost never what you want.

3. Loading data when a screen opens

The most common use of useEffect — fetch data from Firebase (or any API) when the screen first appears.

import { useState, useEffect } from 'react';
import { View, Text, ActivityIndicator, StyleSheet } from 'react-native';

// Simulated Firebase fetch
function fetchMessages(chatId) {
  return new Promise(resolve => {
    setTimeout(() => {
      resolve([
        { id: 'm1', sender: 'Priya',  text: 'Hey!',         time: '10:01' },
        { id: 'm2', sender: 'Ashish', text: 'Hi! All good?', time: '10:02' },
      ]);
    }, 1000);  // simulate 1 second network delay
  });
}

export default function ChatScreen({ chatId = 'chat-001' }) {
  const [messages, setMessages]   = useState([]);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError]         = useState(null);

  useEffect(() => {
    async function loadMessages() {
      try {
        setIsLoading(true);
        setError(null);
        const msgs = await fetchMessages(chatId);
        setMessages(msgs);
      } catch (err) {
        setError('Could not load messages. Check your connection.');
        console.error('loadMessages error:', err);
      } finally {
        setIsLoading(false);
      }
    }

    loadMessages();
  }, [chatId]);  // re-fetch if the user switches to a different chat

  // ── Render loading state ──────────────────────────────────────────────────
  if (isLoading) {
    return (
      <View style={styles.centre}>
        <ActivityIndicator size="large" color="#075E54" />
        <Text style={styles.loadingText}>Loading messages...</Text>
      </View>
    );
  }

  // ── Render error state ────────────────────────────────────────────────────
  if (error) {
    return (
      <View style={styles.centre}>
        <Text style={styles.errorText}>{error}</Text>
      </View>
    );
  }

  // ── Render messages ───────────────────────────────────────────────────────
  return (
    <View style={styles.container}>
      {messages.map(msg => (
        <Text key={msg.id} style={styles.message}>
          {msg.sender}: {msg.text}
        </Text>
      ))}
    </View>
  );
}

const styles = StyleSheet.create({
  container:   { flex: 1, padding: 16, backgroundColor: '#ECE5DD' },
  centre:      { flex: 1, alignItems: 'center', justifyContent: 'center' },
  loadingText: { marginTop: 12, color: '#667781', fontSize: 14 },
  errorText:   { color: '#e53e3e', fontSize: 15, textAlign: 'center', paddingHorizontal: 24 },
  message:     { fontSize: 15, marginBottom: 8 },
});
useEffect cannot be async directly — use an inner function

You cannot write useEffect(async () => { ... }) — React Native expects the effect function to return either nothing or a cleanup function, not a Promise. The pattern is to define an async function inside the effect and call it immediately, as shown above. You'll write this pattern on every screen that loads data.

4. Cleanup — stopping effects when a screen closes

Some effects set things up that need to be torn down — timers, Firebase listeners, event subscriptions. If you don't clean up, those effects keep running after the screen is gone, wasting resources and causing bugs (updating state on unmounted components).

Return a function from your effect — React Native calls it when the component unmounts or before re-running the effect.

useEffect(() => {
  // Set up the effect
  const timer = setInterval(() => {
    console.log('checking for new messages...');
  }, 5000);

  // Return a cleanup function
  return () => {
    clearInterval(timer);  // runs when component unmounts
    console.log('timer cleared');
  };
}, []);  // set up once, clean up once

Firebase real-time listener with cleanup

This is the exact pattern you'll use in Module 3 when connecting to Firestore:

useEffect(() => {
  // onSnapshot returns an unsubscribe function
  const unsubscribe = firebase
    .firestore()
    .collection('chats')
    .doc(chatId)
    .collection('messages')
    .orderBy('timestamp')
    .onSnapshot(snapshot => {
      const msgs = snapshot.docs.map(doc => ({
        id: doc.id,
        ...doc.data(),
      }));
      setMessages(msgs);
    });

  // Clean up — stop listening when the screen closes
  return () => unsubscribe();
}, [chatId]);
This is how WhatsApp's live updates work

When you open a chat, a Firestore listener is set up — any new message written to that chat document instantly triggers your callback and updates the screen. When you close the chat, the cleanup function calls unsubscribe() and the listener stops. Your battery and data thank you.

5. Running effects when values change

Put a value in the dependency array and the effect re-runs every time that value changes. This is how you re-fetch data when the user navigates to a different chat.

// Fetch messages for whichever chat is currently open
useEffect(() => {
  if (!chatId) return;   // guard against undefined on first render

  async function load() {
    setIsLoading(true);
    const msgs = await fetchMessages(chatId);
    setMessages(msgs);
    setIsLoading(false);
  }

  load();
}, [chatId]);  // re-runs every time chatId changes

// User opens chat-001 → effect runs, loads chat-001 messages
// User navigates to chat-002 → chatId changes → effect re-runs, loads chat-002 messages

Multiple dependencies

// Re-run if either userId or filter changes
useEffect(() => {
  loadFilteredMessages(userId, filter);
}, [userId, filter]);
Include everything the effect uses in the dependency array

If your effect reads a variable (like chatId), put it in the dependency array. If you don't, the effect uses the stale value from the first render — a subtle bug where your chat screen shows old messages when the user switches chats. React's ESLint plugin (eslint-plugin-react-hooks) will warn you if you miss a dependency.

// ── Pattern 1: Load data once on mount ───────────────────────────────────
useEffect(() => {

    setIsLoading(false);
  }

// ── Pattern 2: Live Firebase listener with cleanup ────────────────────────
useEffect(() => {
  const unsub = db.collection('messages')
    .where('chatId', '==', chatId)
    .onSnapshot(snap => {
      setMessages(snap.docs.map(d => ({ id: d.id, ...d.data() })));
    });
  return () => unsub();
}, [chatId]);


// ── Pattern 3: Update screen title when data loads ────────────────────────

// ── Pattern 5: Search filter — re-run when query changes ─────────────────
useEffect(() => {

7. Full example — chat list with live loading and search

This simulates the real WhatsApp chat list screen — it loads chats on mount with a spinner, then lets you search through them live as you type. Replace your App.js and run it.

import { useState, useEffect } from 'react';
import {
  View, Text, TextInput, FlatList,
  ActivityIndicator, Pressable, StyleSheet
} from 'react-native';

// ── Simulated Firebase fetch ───────────────────────────────────────────────
function fetchChats() {
  return new Promise(resolve => {
    setTimeout(() => {
      resolve([
        { id: '1', name: 'Priya Sharma',  preview: 'Perfect, see you then!',       time: '10:32', unread: 2 },
        { id: '2', name: 'Rahul Mehta',   preview: 'Check out this article',        time: '09:15', unread: 0 },
        { id: '3', name: 'Family Group',  preview: 'Mom: Dinner at 7, don\'t be late', time: 'Yesterday', unread: 5 },
        { id: '4', name: 'Work Team',     preview: 'Meeting moved to 3pm',          time: 'Yesterday', unread: 0 },
        { id: '5', name: 'Anil Kumar',    preview: 'Sounds good 👍',               time: 'Monday',    unread: 0 },
        { id: '6', name: 'Sara Singh',    preview: 'Haha yes exactly!',             time: 'Monday',    unread: 1 },
      ]);
    }, 1200);
  });
}

// ── Chat row component ─────────────────────────────────────────────────────
function ChatRow({ chat, onPress }) {
  return (
    <Pressable
      style={({ pressed }) => [styles.row, pressed && styles.rowPressed]}
      onPress={() => onPress(chat)}
    >
      <View style={styles.avatar}>
        <Text style={styles.avatarLetter}>
          {chat.name.charAt(0).toUpperCase()}
        </Text>
      </View>
      <View style={styles.middle}>
        <Text style={styles.name} numberOfLines={1}>{chat.name}</Text>
        <Text style={styles.preview} numberOfLines={1}>{chat.preview}</Text>
      </View>
      <View style={styles.right}>
        <Text style={styles.time}>{chat.time}</Text>
        {chat.unread > 0 && (
          <View style={styles.badge}>
            <Text style={styles.badgeText}>{chat.unread}</Text>
          </View>
        )}
      </View>
    </Pressable>
  );
}

// ── Main screen ────────────────────────────────────────────────────────────
export default function App() {
  const [chats, setChats]           = useState([]);
  const [isLoading, setIsLoading]   = useState(true);
  const [error, setError]           = useState(null);
  const [searchQuery, setSearchQuery] = useState('');

  // ── Effect 1: Load chats on mount ────────────────────────────────────────
  useEffect(() => {
    async function loadChats() {
      try {
        setIsLoading(true);
        setError(null);
        const data = await fetchChats();
        setChats(data);
      } catch (err) {
        setError('Could not load chats. Pull down to retry.');
      } finally {
        setIsLoading(false);
      }
    }
    loadChats();
  }, []);  // empty array — run once on mount

  // ── Derived: filter chats based on search query ───────────────────────────
  const filteredChats = chats.filter(c =>
    c.name.toLowerCase().includes(searchQuery.toLowerCase()) ||
    c.preview.toLowerCase().includes(searchQuery.toLowerCase())
  );

  // ── Handlers ──────────────────────────────────────────────────────────────
  function handleChatPress(chat) {
    // In Lesson 8 (Navigation) this will navigate to the message screen
    console.log('Opening:', chat.name);
  }

  // ── Render ─────────────────────────────────────────────────────────────────
  return (
    <View style={styles.screen}>

      {/* Header */}
      <View style={styles.header}>
        <Text style={styles.headerTitle}>WhatsApp</Text>
      </View>

      {/* Search bar */}
      <View style={styles.searchBar}>
        <TextInput
          style={styles.searchInput}
          placeholder="Search or start new chat"
          placeholderTextColor="#667781"
          value={searchQuery}
          onChangeText={setSearchQuery}
        />
      </View>

      {/* Loading state */}
      {isLoading && (
        <View style={styles.centre}>
          <ActivityIndicator size="large" color="#075E54" />
          <Text style={styles.loadingText}>Loading chats...</Text>
        </View>
      )}

      {/* Error state */}
      {error && !isLoading && (
        <View style={styles.centre}>
          <Text style={styles.errorText}>{error}</Text>
        </View>
      )}

      {/* Empty search result */}
      {!isLoading && !error && filteredChats.length === 0 && (
        <View style={styles.centre}>
          <Text style={styles.emptyText}>No chats match "{searchQuery}"</Text>
        </View>
      )}

      {/* Chat list */}
      {!isLoading && !error && (
        <FlatList
          data={filteredChats}
          keyExtractor={item => item.id}
          renderItem={({ item }) => (
            <ChatRow chat={item} onPress={handleChatPress} />
          )}
        />
      )}

    </View>
  );
}

const styles = StyleSheet.create({
  screen:      { flex: 1, backgroundColor: '#fff' },

  header:      { backgroundColor: '#075E54', paddingTop: 48, paddingBottom: 12, paddingHorizontal: 16 },
  headerTitle: { color: '#fff', fontSize: 20, fontWeight: '700' },

  searchBar:   { backgroundColor: '#f0f2f5', paddingHorizontal: 12, paddingVertical: 8 },
  searchInput: { backgroundColor: '#fff', borderRadius: 20, paddingHorizontal: 16, paddingVertical: 8, fontSize: 15, color: '#111' },

  centre:      { flex: 1, alignItems: 'center', justifyContent: 'center' },
  loadingText: { marginTop: 12, color: '#667781', fontSize: 14 },
  errorText:   { color: '#e53e3e', fontSize: 15, textAlign: 'center', paddingHorizontal: 24 },
  emptyText:   { color: '#667781', fontSize: 15 },

  row:         { flexDirection: 'row', alignItems: 'center', paddingHorizontal: 16, paddingVertical: 12, borderBottomWidth: 1, borderBottomColor: '#f0f2f5' },
  rowPressed:  { backgroundColor: '#f5f5f5' },

  avatar:       { width: 52, height: 52, borderRadius: 26, backgroundColor: '#075E54', alignItems: 'center', justifyContent: 'center' },
  avatarLetter: { color: '#fff', fontSize: 22, fontWeight: '700' },

  middle:      { flex: 1, marginLeft: 12, marginRight: 8 },
  name:        { fontSize: 16, fontWeight: '600', color: '#111' },
  preview:     { fontSize: 14, color: '#667781', marginTop: 2 },

  right:       { alignItems: 'flex-end' },
  time:        { fontSize: 12, color: '#667781' },
  badge:       { backgroundColor: '#25D366', borderRadius: 10, minWidth: 20, height: 20, alignItems: 'center', justifyContent: 'center', marginTop: 4, paddingHorizontal: 5 },
  badgeText:   { color: '#fff', fontSize: 11, fontWeight: '700' },
});

Run this. You'll see a 1.2 second loading spinner, then the full chat list appears. Type in the search bar — the list filters live as you type. This is exactly how the WhatsApp chat list screen works.

Notice what this screen does with just two effects
  • Effect 1 (empty array) — loads chats once when the screen opens, handles loading and error states
  • Derived value — the filtered list recomputes instantly from state on every render, no effect needed

You also used FlatList here for the first time — you'll learn it fully in Lesson 7. It's the performant list component for long lists.

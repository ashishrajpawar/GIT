React Native · Lesson 3

Styling & Flexbox

StyleSheet · Flexbox · Layout ~35 min Hands-on
Why this matters for Token

Every layout decision in Token — a token row with its icon on the left and its badge on the right, a header pinned to the top, a message composer fixed to the bottom, a code centred on the share screen — is solved with Flexbox. React Native uses Flexbox as its only layout system. Once you understand it, you can build any screen layout you can imagine.

The row you built in Lesson 2 already depended on it. This lesson is where the flexDirection: 'row' and flex: 1 you copied start making sense.

1. StyleSheet — how styling works in React Native

In React Native there are no CSS files. Styles are written as JavaScript objects and applied via the style prop. The StyleSheet.create() function takes an object of style definitions and returns them back — it also validates your style names in development so you catch typos early.

import { View, Text, StyleSheet } from 'react-native';

export default function App() {
  return (
    <View style={styles.container}>
      <Text style={styles.heading}>My tokens</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#12263A',
    padding: 16,
  },
  heading: {
    fontSize: 24,
    fontWeight: 'bold',
    color: '#ffffff',
  },
});

CSS vs React Native styles — key differences

CSS (web) React Native
background-color: #fff backgroundColor: '#fff' (camelCase)
font-size: 16px fontSize: 16 (number, no 'px')
border-radius: 8px borderRadius: 8
margin: 8px 16px marginVertical: 8, marginHorizontal: 16
display: flex Everything is flex by default — no need to set it
Class names, IDs, cascading No classes — styles are objects applied directly per component
All property names are camelCase and numbers have no units

The two rules that catch everyone: font-size becomes fontSize, background-color becomes backgroundColor. And sizes are plain numbers — 16 not '16px'. React Native uses density-independent pixels (dp) automatically, so your layout looks consistent across different screen sizes.

Inline styles vs StyleSheet

// Inline style — fine for one-off overrides
<Text style={{ color: 'red', fontSize: 14 }}>Error message</Text>

// StyleSheet — preferred for reusable styles
<Text style={styles.error}>Error message</Text>

// Combining styles — pass an array
<Text style={[styles.text, styles.bold, { color: 'red' }]}>
  Bold red text
</Text>

2. Flexbox — the layout system

Flexbox is how you control where things appear on screen — side by side, stacked, centred, spread out. In React Native, every View is a flex container by default. You don't need to write display: flex.

There are three properties you use constantly:

  • flexDirection — which way children stack
  • justifyContent — spacing along the main axis
  • alignItems — alignment on the cross axis

3. flexDirection — row or column

flexDirection controls which direction children are laid out inside a View.

  • 'column' (default) — children stack top to bottom
  • 'row' — children line up left to right
import { View, Text, StyleSheet } from 'react-native';

export default function App() {
  return (
    <View style={styles.screen}>

      {/* column — default, items stack vertically */}
      <View style={styles.columnBox}>
        <Text style={styles.item}>Message 1</Text>
        <Text style={styles.item}>Message 2</Text>
        <Text style={styles.item}>Message 3</Text>
      </View>

      {/* row — items sit side by side horizontally */}
      <View style={styles.rowBox}>
        <Text style={styles.item}>Icon</Text>
        <Text style={styles.item}>Name & Preview</Text>
        <Text style={styles.item}>Time</Text>
      </View>

    </View>
  );
}

const styles = StyleSheet.create({
  screen:    { flex: 1, padding: 16, backgroundColor: '#fff' },
  columnBox: { backgroundColor: '#DCF3EA', padding: 8, marginBottom: 16, flexDirection: 'column' },
  rowBox:    { backgroundColor: '#F3F1EC', padding: 8, flexDirection: 'row' },
  item:      { backgroundColor: '#fff', margin: 4, padding: 8, borderRadius: 4 },
});
In Token

flexDirection: 'column' — the overall screen layout (header on top, token list in the middle, tab bar at the bottom).
flexDirection: 'row' — every token list row (category icon on the left, label and code in the middle, last-used time and badge on the right).

4. justifyContent — spacing along the main axis

When flexDirection is 'column', justifyContent controls vertical spacing. When it's 'row', it controls horizontal spacing.

// flex-start  — pack children at the START (default)
// flex-end    — pack children at the END
// center      — centre children
// space-between — first at start, last at end, equal gaps between
// space-around  — equal space around each child
// space-evenly  — equal space between AND around all children

<View style={{ flex: 1, flexDirection: 'column', justifyContent: 'space-between' }}>
  <View style={styles.header}>
    <Text style={styles.headerText}>My tokens</Text>
  </View>

  <View style={styles.tokenList}>
    {/* messages here */}
  </View>

  <View style={styles.inputBar}>
    {/* input + send button */}
  </View>
</View>
{/* space-between pushes header to top, composer to bottom, message list in middle */}
space-between is how every thread screen is built

The token message thread — header pinned to top, messages in the middle taking all available space, composer pinned to bottom — is achieved with justifyContent: 'space-between' on the outer container. You'll use this in Lesson 14.

5. alignItems — alignment on the cross axis

alignItems controls alignment on the axis perpendicular to flexDirection.

  • In a column container — controls horizontal alignment
  • In a row container — controls vertical alignment
// stretch  — children fill the full cross-axis width/height (default)
// center   — children centred on the cross axis
// flex-start — children aligned to the start
// flex-end   — children aligned to the end

// Example: centre content on screen
<View style={{ flex: 1, justifyContent: 'center', alignItems: 'center' }}>
  <Text>I am perfectly centred</Text>
</View>

// Example: token row — category icon, label, and time vertically centred
<View style={{ flexDirection: 'row', alignItems: 'center' }}>
  <Image style={styles.categoryIcon} source={{ uri: '...' }} />
  <Text style={styles.label}>Flipkart delivery</Text>
</View>

6. flex — controlling how much space a child takes

The flex property on a child controls how much of the parent's remaining space it claims. Think of it as shares — a child with flex: 2 gets twice as much space as a child with flex: 1.

// The most common pattern in React Native:
<View style={{ flex: 1 }}>       {/* takes all available space */}
  <Text>I fill the screen</Text>
</View>

// Token row: label/preview takes all middle space, time is fixed width
<View style={{ flexDirection: 'row', alignItems: 'center' }}>
  <Image style={styles.categoryIcon} source={{ uri: '...' }} />

  <View style={{ flex: 1 }}>   {/* takes all remaining space */}
    <Text numberOfLines={1}>Flipkart delivery</Text>
    <Text numberOfLines={1}>Perfect, see you then!</Text>
  </View>

  <Text style={{ width: 50, textAlign: 'right' }}>10:32</Text>
  {/* fixed width — doesn't shrink or grow */}
</View>
flex: 1 is the most-written style in any React Native app

flex: 1 on the top-level container means "fill the whole screen". flex: 1 on a middle child means "take all the remaining space that siblings don't need". You'll write it dozens of times.

Try it yourself

flex is not a size. It is a share of what is left over, and the arithmetic is worth doing by hand once. This is the Lesson 2 token row: a 40dp icon, a middle section that flexes, and a right-hand column sized to its content.

Change the middle child's flex from 1 to 3 and run it again. Nothing moves — with only one flexible child, it takes everything left over no matter what number you write. The number only matters once there are two of them.

Try it yourself — this one is broken on purpose

Now two flexible children. This code is meant to split the leftover space in proportion to each child's flex, but it does something else. Run it, compare the two rows, and work out what:

It divides by the number of flexible children instead of by the total of their flex values. The first row is correct — because with two children of flex: 1, the count and the total are both 2. The second row is wrong, and by a lot: flex: 3 gets the same space as flex: 1.

Why this kind of bug ships

Almost every real layout uses flex: 1 and nothing else. A formula that is only correct when every flex value is 1 will pass every screen you have built so far, and break the first time somebody writes flex: 2 — probably months later, in a screen you are not looking at.

Divide by the sum, not the count. The two are equal in the common case, which is exactly why the mistake survives.

7. Spacing — margin and padding

Margin and padding work the same as CSS, but use camelCase and numbers.

// All four sides at once
margin: 16          // 16dp on all sides
padding: 16

// Individual sides
marginTop: 8
marginBottom: 8
marginLeft: 16
marginRight: 16

// Shorthand axes (very common in React Native)
marginVertical: 8      // top + bottom
marginHorizontal: 16   // left + right
paddingVertical: 12
paddingHorizontal: 16

// Example: a message bubble
const styles = StyleSheet.create({
  bubble: {
    backgroundColor: '#DCF3EA',
    paddingVertical: 8,
    paddingHorizontal: 12,
    borderRadius: 8,
    marginVertical: 2,
    marginHorizontal: 8,
    maxWidth: '75%',    // bubble can't be wider than 75% of the screen
  },
});

8. position: 'absolute' — overlapping elements

By default all components are positioned in the normal flow. position: 'absolute' takes a component out of the flow so it can sit on top of other components — useful for badges, floating buttons, and overlays.

// Unread badge positioned over the token's category icon
<View style={{ position: 'relative' }}>
  <Image style={styles.categoryIcon} source={{ uri: '...' }} />

  {/* Badge overlaps the icon in the bottom-right corner */}
  <View style={styles.unreadDot} />
</View>

const styles = StyleSheet.create({
  categoryIcon: { width: 52, height: 52, borderRadius: 26 },
  unreadDot: {
    position: 'absolute',
    bottom: 2,
    right: 2,
    width: 12,
    height: 12,
    borderRadius: 6,
    backgroundColor: '#2F9E7E',  // Token accent
    borderWidth: 2,
    borderColor: '#fff',
  },
});

9. Putting it all together — the token message thread

The most important layout in the app: message bubbles that sit on the right for your messages and on the left for the holder's. This uses everything from this lesson.

Remember who is on the other side. There is no name above the left-hand bubbles and no avatar beside them, because you do not know who redeemed the token — only that they hold it. The layout has to read clearly with one anonymous party.

Replace your App.js with this and run it:

import { View, Text, ScrollView, StyleSheet } from 'react-native';

const ME = 'owner';

const messages = [
  { id: 'm1', from: 'holder', text: 'Out for delivery, arriving 2-4pm.', time: '10:01' },
  { id: 'm2', from: 'owner',  text: 'Leave it with the guard, please.',  time: '10:02' },
  { id: 'm3', from: 'holder', text: 'Guard is not at the desk.',        time: '10:03' },
  { id: 'm4', from: 'owner',  text: 'Try the side entrance.',           time: '10:04' },
  { id: 'm5', from: 'holder', text: 'Delivered, thanks.',               time: '10:05' },
  { id: 'm6', from: 'owner',  text: 'Great.',                           time: '10:05' },
];

function MessageBubble({ message }) {
  const isMe = message.from === ME;

  return (
    // alignItems pushes bubble to right (flex-end) or left (flex-start)
    <View style={[styles.bubbleRow, isMe ? styles.myRow : styles.theirRow]}>
      <View style={[styles.bubble, isMe ? styles.myBubble : styles.theirBubble]}>
        <Text style={styles.bubbleText}>{message.text}</Text>
        <Text style={styles.timeText}>{message.time}</Text>
      </View>
    </View>
  );
}

export default function App() {
  return (
    <View style={styles.screen}>

      {/* Header */}
      <View style={styles.header}>
        <Text style={styles.headerTitle}>Flipkart delivery</Text>
        <Text style={styles.headerSub}>KART-4KN9-RT2M</Text>
      </View>

      {/* Message list */}
      <ScrollView
        style={styles.messageList}
        contentContainerStyle={styles.messageListContent}
      >
        {messages.map(msg => (
          <MessageBubble key={msg.id} message={msg} />
        ))}
      </ScrollView>

      {/* Input bar placeholder */}
      <View style={styles.inputBar}>
        <Text style={styles.inputPlaceholder}>Type a message</Text>
      </View>

    </View>
  );
}

const styles = StyleSheet.create({
  screen: { flex: 1, backgroundColor: '#F3F1EC' },

  // Header
  header: {
    backgroundColor: '#12263A',
    paddingTop: 48,
    paddingBottom: 12,
    paddingHorizontal: 16,
  },
  headerTitle: { color: '#fff', fontSize: 18, fontWeight: '700' },
  headerSub:   { color: '#b2dfdb', fontSize: 13, marginTop: 1 },

  // Message list
  messageList:        { flex: 1 },
  messageListContent: { paddingVertical: 8 },

  // Each bubble row — full width, aligned left or right
  bubbleRow:  { paddingHorizontal: 8, marginVertical: 2 },
  myRow:      { alignItems: 'flex-end' },    // my messages → right
  theirRow:   { alignItems: 'flex-start' },  // their messages → left

  // The bubble itself
  bubble: {
    maxWidth: '75%',
    paddingVertical: 6,
    paddingHorizontal: 10,
    borderRadius: 8,
  },
  myBubble:    { backgroundColor: '#DCF3EA' },  // accentSoft — my messages
  theirBubble: { backgroundColor: '#ffffff' },  // white — their messages

  bubbleText: { fontSize: 15, color: '#303030', lineHeight: 20 },
  timeText:   { fontSize: 11, color: '#999', alignSelf: 'flex-end', marginTop: 2 },

  // Input bar
  inputBar: {
    backgroundColor: '#fff',
    paddingVertical: 14,
    paddingHorizontal: 16,
    borderTopWidth: 1,
    borderTopColor: '#e0e0e0',
  },
  inputPlaceholder: { color: '#999', fontSize: 15 },
});

Run this on your phone. You should see a working message thread — accent bubbles on the right for your messages, white bubbles on the left for the holder's. The key insight is alignItems: 'flex-end' vs 'flex-start' on the row container.

Note what the header carries: the token's label and its code, not a person. That is the only identity either side has here.

What this taught you without you noticing
  • Conditional styles — [styles.bubble, isMe ? styles.myBubble : styles.theirBubble] applies different styles based on a condition. Style arrays are the standard way to combine and override styles.
  • contentContainerStyle — ScrollView has two style props: style (the outer container) and contentContainerStyle (the inner scrollable area). Use contentContainerStyle for padding inside the scroll area.
  • alignSelf — like alignItems but for a single child overriding the parent's alignment.

10. Token colour reference

Keep these handy — you'll use them throughout the course:

const TokenColors = {
  // Brand
  ink:          '#12263A',   // header background, primary buttons
  inkMuted:     '#33566F',   // pressed state on dark surfaces
  accent:       '#2F9E7E',   // active token, send button, FAB
  accentSoft:   '#DCF3EA',   // your own message bubble background

  // Token states — these carry meaning, so keep them distinct
  stateActive:  '#2F9E7E',   // issued and usable
  statePaused:  '#C98A16',   // temporarily off, can be resumed
  stateRevoked: '#B3392F',   // dead forever, never reusable

  // Backgrounds
  threadBg:     '#F3F1EC',   // message thread background
  white:        '#FFFFFF',   // the holder's message bubble
  screenBg:     '#F0F2F5',   // general screen background

  // Text
  primaryText:  '#111111',
  secondaryText:'#667781',
  timestamp:    '#999999',

  // Borders
  divider:      '#E9EDEF',
};
Colour is never the only signal

The three state colours above are the difference between a token that works, one that is paused, and one that is dead. Roughly one man in twelve cannot reliably tell the green from the red. If the only thing separating "active" from "revoked" on your row is a coloured dot, those users cannot read their own token list.

Every state needs a second signal — the word, an icon shape, a strikethrough. You will build exactly this in a5/0003, and it is far cheaper to design it in now than to retrofit it after launch.

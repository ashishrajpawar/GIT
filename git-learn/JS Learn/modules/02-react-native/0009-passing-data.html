Passing Data Between Screens

route.params · useRoute · navigation.setOptions · callbacks ~35 min Hands-on
Why this matters for your WhatsApp clone

When a user taps Priya's chat row, the message thread screen needs to know it's Priya's chat — not Rahul's. It needs her name to show in the header, her chatId to load her messages from Firebase, and her avatar. In Lesson 8 you learned the basic pattern. This lesson goes deep: what data is safe to pass, how to read it cleanly, how to update the header title dynamically, and how to pass a callback back to the previous screen — the exact patterns your WhatsApp clone will use every day.

1. What are route params — and what to pass

When you call navigation.navigate('MessageThread', { chatId: '1', chatName: 'Priya Sharma' }), that second argument is the params object. React Navigation stores it and makes it available in the target screen via route.params.

The rule for what to pass is simple: pass the minimum needed to identify the data, not the data itself.

Safe to passDo NOT pass
IDs: chatId, userId, messageIdLarge arrays of messages — slows down navigation
Short display strings: chatName, avatarUriFunctions / callbacks (use the pattern in Section 5)
Booleans: isGroup: trueClass instances or objects with methods
Numbers: unreadCount: 3React components or JSX

Pass the chatId, navigate to the thread screen, then load the messages from Firebase inside that screen using useEffect. The thread screen is responsible for its own data — the chat list screen only hands off the key.

2. Reading params — two ways

There are two ways to read params in a screen component. Both work; pick one and stick to it.

Method A — the route prop (most common)

Every screen registered in a navigator receives route and navigation as props automatically. Destructure route.params at the top of the component.

function MessageThreadScreen({ route, navigation }) {
  // Destructure everything you need from params
  const { chatId, chatName, isGroup } = route.params;

  return (
    <View>
      <Text>{chatName}</Text>
      <Text>Chat ID: {chatId}</Text>
    </View>
  );
}

Method B — the useRoute hook

If you have a component that is not a registered screen (e.g. a child component rendered inside a screen), it doesn't receive the route prop. Use the useRoute hook instead.

import { useRoute } from '@react-navigation/native';

// Works in any component, not just top-level screens
function ChatHeader() {
  const route = useRoute();
  const { chatName } = route.params;

  return (
    <View style={styles.header}>
      <Text style={styles.headerTitle}>{chatName}</Text>
    </View>
  );
}
useRoute only works inside NavigationContainer

useRoute() throws an error if called outside a navigator. Only use it in components that are rendered inside a screen that is inside a NavigationContainer.

3. Default params — handling missing data safely

What if a screen is opened without all the params it expects? Always provide defaults so the app doesn't crash.

function MessageThreadScreen({ route }) {
  // Provide defaults with destructuring fallbacks
  const {
    chatId   = '',
    chatName = 'Unknown',
    isGroup  = false,
    avatarUri = null,
  } = route.params ?? {};
  //                 ↑ ?? {} protects against route.params being undefined
  //                   (can happen in deep links or during testing)

  return (
    <View>
      <Text>Chat with {chatName}</Text>
      {isGroup && <Text>Group chat</Text>}
    </View>
  );
}
The ?? {} pattern

route.params ?? {} means "use route.params if it exists, otherwise use an empty object". Without this, destructuring undefined throws a TypeError. This is especially important for screens that can be opened via deep links, where params may not be set.

4. Updating the header title dynamically

The message thread header should show the contact's name — not a hard-coded string from the navigator definition. Use navigation.setOptions inside useEffect to set it once the screen mounts.

import { useEffect } from 'react';

function MessageThreadScreen({ route, navigation }) {
  const { chatId, chatName } = route.params;

  // Update the navigation header once we know the chat name
  useEffect(() => {
    navigation.setOptions({
      title:           chatName,
      headerStyle:     { backgroundColor: '#075E54' },
      headerTintColor: '#fff',
    });
  }, [chatName, navigation]);
  //  ↑ Re-run if chatName changes (rare, but correct)

  return <View>...</View>;
}

You can also set options directly on the <Stack.Screen> definition using a function that receives the route:

// In your navigator definition — static approach
<Stack.Screen
  name="MessageThread"
  component={MessageThreadScreen}
  options={({ route }) => ({
    title:           route.params.chatName,
    headerStyle:     { backgroundColor: '#075E54' },
    headerTintColor: '#fff',
  })}
/>

Both approaches work. The navigation.setOptions pattern is more flexible — you can call it anywhere in the component, including after async data loads.

5. Passing a callback back to the previous screen

Sometimes the destination screen needs to send data back to the screen that opened it. Example: the message thread screen marks all messages as read — the chat list screen should update its unread count badge.

You cannot pass functions directly as route params (they are not serialisable). The clean solution is to use navigation.navigate with params on the way back:

Pattern A — pass data back via navigate

// MessageThreadScreen — passing data back when leaving
function MessageThreadScreen({ route, navigation }) {
  const { chatId } = route.params;

  function markAsRead() {
    // Navigate back AND pass data to the previous screen
    navigation.navigate('ChatList', {
      markedReadChatId: chatId,   // ChatList picks this up from route.params
    });
  }

  return (
    <Pressable onPress={markAsRead}>
      <Text>Mark as read and go back</Text>
    </Pressable>
  );
}

// ChatListScreen — reading the data passed back
function ChatListScreen({ route, navigation }) {
  const [chats, setChats] = useState(INITIAL_CHATS);

  // Watch for markedReadChatId coming back from the thread screen
  useEffect(() => {
    if (route.params?.markedReadChatId) {
      setChats(prev => prev.map(c =>
        c.id === route.params.markedReadChatId
          ? { ...c, unread: 0 }
          : c
      ));
    }
  }, [route.params?.markedReadChatId]);

  return <View>...</View>;
}

Pattern B — use a ref callback (advanced)

For more complex two-way communication (e.g. a contact picker that needs to return to a form), store a callback in a useRef on the parent, pass a signal via params, and handle it in useEffect. This is an advanced pattern — Pattern A covers most real WhatsApp use cases.

For your WhatsApp clone: stick to Pattern A

Passing a markedReadChatId back when leaving the thread is all you need. Firebase will handle real-time unread counts in Module 3 — then you won't need this pattern at all because the data will sync automatically.

6. The useNavigation hook

Like useRoute, there is a useNavigation hook for accessing the navigation object in non-screen components.

import { useNavigation } from '@react-navigation/native';

// A send button component that is NOT a registered screen
function SendButton({ chatId, chatName }) {
  const navigation = useNavigation();

  return (
    <Pressable
      style={styles.sendBtn}
      onPress={() => navigation.navigate('MessageThread', { chatId, chatName })}
    >
      <Text style={styles.sendText}>Open chat</Text>
    </Pressable>
  );
}

Use useNavigation when you need to navigate from a child component that is not itself a registered screen — for example, a chat row component, a notification banner, or a button inside a modal.

7. Navigating between tabs

Your app has nested navigators — the Chats tab contains a stack. When you need to navigate to a screen in a different tab, you navigate to the tab first, then to the screen inside it.

// From the Settings tab — navigate to a specific chat
navigation.navigate('Chats', {           // first: go to the Chats TAB
  screen: 'MessageThread',               // then: navigate to this SCREEN inside Chats
  params: {                              // params for MessageThread
    chatId:   '1',
    chatName: 'Priya Sharma',
  },
});

// From anywhere — jump to a tab without specifying a nested screen
navigation.navigate('Calls');   // just open the Calls tab

This nested navigate syntax — passing screen and params as properties — is what you'll use when a push notification arrives and needs to deep-link the user into a specific conversation from any tab.

8. Full working example — tap a chat, open the thread, go back

This example ties together everything in this lesson: a chat list that passes chatId and chatName to the thread screen, a dynamic header, and an "unread cleared" signal passed back to the list when the user returns. Replace your entire App.js with this.

import { useState, useEffect } from 'react';
import { NavigationContainer } from '@react-navigation/native';
import { createNativeStackNavigator } from '@react-navigation/native-stack';
import { createBottomTabNavigator }   from '@react-navigation/bottom-tabs';
import {
  View, Text, FlatList, Pressable, StyleSheet
} from 'react-native';

const Stack = createNativeStackNavigator();
const Tab   = createBottomTabNavigator();

// ── Sample data ───────────────────────────────────────────────────────────────
const INITIAL_CHATS = [
  { id: '1', name: 'Priya Sharma',  preview: 'Perfect, see you then!',  time: '10:32',    unread: 2, isGroup: false },
  { id: '2', name: 'Rahul Mehta',   preview: 'Check out this article',  time: '09:15',    unread: 0, isGroup: false },
  { id: '3', name: 'Family Group',  preview: 'Mom: Dinner at 7!',       time: 'Yesterday',unread: 5, isGroup: true  },
  { id: '4', name: 'Work Team',     preview: 'Meeting moved to 3pm',    time: 'Yesterday',unread: 0, isGroup: true  },
];

// ── Screen: Chat List ─────────────────────────────────────────────────────────
function ChatListScreen({ route, navigation }) {
  const [chats, setChats] = useState(INITIAL_CHATS);

  // Watch for markedReadChatId coming back from MessageThreadScreen
  useEffect(() => {
    const clearedId = route.params?.markedReadChatId;
    if (clearedId) {
      setChats(prev => prev.map(c =>
        c.id === clearedId ? { ...c, unread: 0 } : c
      ));
    }
  }, [route.params?.markedReadChatId]);

  return (
    <View style={styles.screen}>
      <View style={styles.header}>
        <Text style={styles.headerTitle}>WhatsApp</Text>
        <Text style={styles.headerSub}>
          {chats.reduce((sum, c) => sum + c.unread, 0)} unread
        </Text>
      </View>

      <FlatList
        data={chats}
        keyExtractor={item => item.id}
        ItemSeparatorComponent={() => <View style={styles.sep} />}
        renderItem={({ item }) => (
          <Pressable
            style={({ pressed }) => [styles.row, pressed && styles.rowPressed]}
            onPress={() => navigation.navigate('MessageThread', {
              chatId:   item.id,
              chatName: item.name,
              isGroup:  item.isGroup,
            })}
          >
            <View style={styles.avatarCircle}>
              <Text style={styles.avatarLetter}>{item.name[0]}</Text>
            </View>
            <View style={styles.middle}>
              <View style={styles.topRow}>
                <Text style={styles.name}>{item.name}</Text>
                {item.isGroup && (
                  <Text style={styles.groupBadge}>Group</Text>
                )}
              </View>
              <Text style={styles.preview} numberOfLines={1}>{item.preview}</Text>
            </View>
            <View style={styles.right}>
              <Text style={[styles.time, item.unread > 0 && styles.timeGreen]}>
                {item.time}
              </Text>
              {item.unread > 0 && (
                <View style={styles.badge}>
                  <Text style={styles.badgeText}>{item.unread}</Text>
                </View>
              )}
            </View>
          </Pressable>
        )}
      />
    </View>
  );
}

// ── Screen: Message Thread ────────────────────────────────────────────────────
function MessageThreadScreen({ route, navigation }) {
  // Safely destructure with fallback in case params are missing
  const {
    chatId   = '',
    chatName = 'Unknown',
    isGroup  = false,
  } = route.params ?? {};

  // Set the custom green header once the screen mounts
  useEffect(() => {
    navigation.setOptions({ headerShown: false });
  }, []);

  // Simulated messages — in Module 3 these come from Firebase
  const messages = [
    { id: 'm1', text: 'Hey! Are you free tomorrow?',  sender: 'them' },
    { id: 'm2', text: 'Yes, I\'m free after 3pm.',    sender: 'me'   },
    { id: 'm3', text: 'Perfect, see you then!',        sender: 'them' },
  ];

  function goBackAndMarkRead() {
    // Pass markedReadChatId back so ChatList can clear the badge
    navigation.navigate('ChatList', { markedReadChatId: chatId });
  }

  return (
    <View style={styles.screen}>
      {/* Custom green header */}
      <View style={styles.header}>
        <Pressable onPress={goBackAndMarkRead} style={styles.backBtn}>
          <Text style={styles.backArrow}>←</Text>
        </Pressable>
        <View style={styles.avatarCircleSmall}>
          <Text style={styles.avatarLetterSmall}>{chatName[0]}</Text>
        </View>
        <View style={styles.headerInfo}>
          <Text style={styles.headerTitle}>{chatName}</Text>
          <Text style={styles.headerSub}>
            {isGroup ? 'Group · tap for info' : 'online'}
          </Text>
        </View>
      </View>

      {/* Message bubbles */}
      <FlatList
        data={messages}
        keyExtractor={item => item.id}
        contentContainerStyle={styles.messageList}
        style={{ backgroundColor: '#ECE5DD' }}
        renderItem={({ item }) => (
          <View style={[
            styles.bubble,
            item.sender === 'me' ? styles.bubbleMe : styles.bubbleThem,
          ]}>
            <Text style={styles.bubbleText}>{item.text}</Text>
          </View>
        )}
      />

      {/* Footer showing the params received */}
      <View style={styles.footer}>
        <Text style={styles.footerText}>
          chatId: {chatId} · isGroup: {String(isGroup)}
        </Text>
      </View>
    </View>
  );
}

Run this. Tap a chat row — notice the thread header shows the correct name and whether it's a group. The footer shows the raw params so you can see exactly what was passed. Tap the back arrow — the unread badge on that chat row disappears in the list.

What just happened

The chat list passed { chatId, chatName, isGroup } to the thread screen. The thread read those params, built a custom header with them, and when going back passed markedReadChatId to the list. The list's useEffect watched for that param and cleared the badge. This is the full data-passing loop your real app will use — before Firebase takes over in Module 3.

Anything unclear? Ask your teacher. Common issues: (1) route.params is undefined — you opened the screen directly without navigating, so no params were passed; always use the ?? {} fallback. (2) The unread badge doesn't clear — check that markedReadChatId is exactly the same string as the chat's id; a type mismatch (string vs number) will cause the find to miss. (3) useNavigation or useRoute throwing — make sure the component is rendered inside a NavigationContainer.

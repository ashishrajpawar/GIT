Passing Data Between Screens

route.params · useRoute · navigation.setOptions · callbacks ~35 min Hands-on
Why this matters for Token

When a user taps the Flipkart row, the detail screen needs to know which token — not the gym one. It needs the label for the header and the id to load the token from the API. In Lesson 8 you learned the basic pattern. This lesson goes deep: what data is safe to pass, how to read it cleanly, how to update the header title dynamically, and how to pass a callback back to the previous screen.

And one thing Token must never pass: the token code. Route params end up in navigation state, which is serialised into deep links and attached to crash reports. A code that travels through a param has left the places you control.

1. What are route params — and what to pass

When you call navigation.navigate('TokenDetail', { tokenId: '1', label: 'Flipkart delivery' }), that second argument is the params object. React Navigation stores it and makes it available in the target screen via route.params.

The rule for what to pass is simple: pass the minimum needed to identify the data, not the data itself.

Safe to passDo NOT pass
IDs: tokenId, userId, messageIdToken codes — see the warning below
Short display strings: label, iconUriLarge arrays of messages — slows down navigation
Booleans: isPaused: trueFunctions / callbacks (use the pattern in Section 5)
Numbers: unreadCount: 3Class instances, JSX, anything with methods

Pass the tokenId, navigate to the detail screen, then load the token from the API inside that screen using useEffect. The detail screen is responsible for its own data — the list screen only hands off the key.

Never put a token code in a route param

Token's rule is that a code never travels anywhere it can be recorded. On the server that means codes go in a POST body, never a URL path, because a path reaches the proxy access log, browser history and crash reports. Route params are the client-side version of the same hazard: React Navigation keeps them in navigation state, which is what gets serialised into a deep link and what a crash reporter attaches when the app dies.

Pass tokenId. The detail screen fetches the token it needs, and the code is shown once, on screen, and never written down along the way.

2. Reading params — two ways

There are two ways to read params in a screen component. Both work; pick one and stick to it.

Method A — the route prop (most common)

Every screen registered in a navigator receives route and navigation as props automatically. Destructure route.params at the top of the component.

function TokenDetailScreen({ route, navigation }) {
  // Destructure everything you need from params
  const { tokenId, label, isPaused } = route.params;

  return (
    <View>
      <Text>{label}</Text>
      <Text>Token ID: {tokenId}</Text>
    </View>
  );
}

Method B — the useRoute hook

If you have a component that is not a registered screen (e.g. a child component rendered inside a screen), it doesn't receive the route prop. Use the useRoute hook instead.

import { useRoute } from '@react-navigation/native';

// Works in any component, not just top-level screens
function TokenHeader() {
  const route = useRoute();
  const { label } = route.params;

  return (
    <View style={styles.header}>
      <Text style={styles.headerTitle}>{label}</Text>
    </View>
  );
}
useRoute only works inside NavigationContainer

useRoute() throws an error if called outside a navigator. Only use it in components that are rendered inside a screen that is inside a NavigationContainer.

3. Default params — handling missing data safely

What if a screen is opened without all the params it expects? Always provide defaults so the app doesn't crash.

function TokenDetailScreen({ route }) {
  // Provide defaults with destructuring fallbacks
  const {
    tokenId = '',
    label   = 'Untitled token',
    isPaused  = false,
    avatarUri = null,
  } = route.params ?? {};
  //                 ↑ ?? {} protects against route.params being undefined
  //                   (can happen in deep links or during testing)

  return (
    <View>
      <Text>{label}</Text>
      {isPaused && <Text>Paused</Text>}
    </View>
  );
}
The ?? {} pattern

route.params ?? {} means "use route.params if it exists, otherwise use an empty object". Without this, destructuring undefined throws a TypeError. This is especially important for screens that can be opened via deep links, where params may not be set.

4. Updating the header title dynamically

The message thread header should show the contact's name — not a hard-coded string from the navigator definition. Use navigation.setOptions inside useEffect to set it once the screen mounts.

import { useEffect } from 'react';

function TokenDetailScreen({ route, navigation }) {
  const { tokenId, label } = route.params;

  // Update the navigation header once we know the token's label
  useEffect(() => {
    navigation.setOptions({
      title:           label,
      headerStyle:     { backgroundColor: '#075E54' },
      headerTintColor: '#fff',
    });
  }, [label, navigation]);
  //  ↑ Re-run if the label changes (the user can rename a token)

  return <View>...</View>;
}

You can also set options directly on the <Stack.Screen> definition using a function that receives the route:

// In your navigator definition — static approach
<Stack.Screen
  name="TokenDetail"
  component={TokenDetailScreen}
  options={({ route }) => ({
    title:           route.params.label,
    headerStyle:     { backgroundColor: '#075E54' },
    headerTintColor: '#fff',
  })}
/>

Both approaches work. The navigation.setOptions pattern is more flexible — you can call it anywhere in the component, including after async data loads.

5. Passing a callback back to the previous screen

Sometimes the destination screen needs to send data back to the screen that opened it. Example: the token detail screen revokes a token, and the list behind it must stop showing it as active. The detail screen thread screen marks all messages as read — the token list screen should update its unread count badge.

You cannot pass functions directly as route params (they are not serialisable). The clean solution is to use navigation.navigate with params on the way back:

Pattern A — pass data back via navigate

// TokenDetailScreen — passing data back when leaving
function TokenDetailScreen({ route, navigation }) {
  const { tokenId } = route.params;

  function markAsRead() {
    // Navigate back AND pass data to the previous screen
    navigation.navigate('TokenList', {
      revokedTokenId: tokenId,   // TokenList picks this up from route.params
    });
  }

  return (
    <Pressable onPress={markAsRead}>
      <Text>Mark as read and go back</Text>
    </Pressable>
  );
}

// TokenListScreen — reading the data passed back
function TokenListScreen({ route, navigation }) {
  const [tokens, setTokens] = useState(INITIAL_TOKENS);

  // Watch for revokedTokenId coming back from the thread screen
  useEffect(() => {
    if (route.params?.revokedTokenId) {
      setChats(prev => prev.map(c =>
        c.id === route.params.revokedTokenId
          ? { ...c, unread: 0 }
          : c
      ));
    }
  }, [route.params?.revokedTokenId]);

  return <View>...</View>;
}

Pattern B — use a ref callback (advanced)

For more complex two-way communication (for example a rule picker that returns to the create-token form), store a callback in a useRef on the parent, pass a signal via params, and handle it in useEffect. This is an advanced pattern — Pattern A covers most real Token use cases.

For Token: stick to Pattern A

Passing a revokedTokenId back when leaving the detail screen is all you need. In A6 the WebSocket handles unread counts — then you won't need this pattern at all, because the server pushes the change and every screen showing that token updates itself.

6. The useNavigation hook

Like useRoute, there is a useNavigation hook for accessing the navigation object in non-screen components.

import { useNavigation } from '@react-navigation/native';

// A send button component that is NOT a registered screen
function OpenTokenButton({ tokenId, label }) {
  const navigation = useNavigation();

  return (
    <Pressable
      style={styles.sendBtn}
      onPress={() => navigation.navigate('TokenDetail', { tokenId, label })}
    >
      <Text style={styles.sendText}>Open token</Text>
    </Pressable>
  );
}

Use useNavigation when you need to navigate from a child component that is not itself a registered screen — for example, a token row component, a notification banner, or a button inside a modal.

7. Navigating between tabs

Your app has nested navigators — the Tokens tab contains a stack. When you need to navigate to a screen in a different tab, you navigate to the tab first, then to the screen inside it.

// From the Settings tab — navigate to a specific token
navigation.navigate('Tokens', {          // first: go to the Tokens TAB
  screen: 'TokenDetail',               // then: navigate to this SCREEN inside it
  params: {                              // params for TokenDetail
    tokenId:   '1',
    label: 'Flipkart delivery',
  },
});

// From anywhere — jump to a tab without specifying a nested screen
navigation.navigate('Calls');   // just open the Calls tab

This nested navigate syntax — passing screen and params as properties — is what you'll use when a push notification arrives and needs to deep-link the user into a specific conversation from any tab.

8. Full working example — tap a token, open its detail, go back

This example ties together everything in this lesson: a token list that passes tokenId and label to the thread screen, a dynamic header, and an "unread cleared" signal passed back to the list when the user returns. Replace your entire App.js with this.

import { useState, useEffect } from 'react';
import { NavigationContainer } from '@react-navigation/native';
import { createNativeStackNavigator } from '@react-navigation/native-stack';
import { createBottomTabNavigator }   from '@react-navigation/bottom-tabs';
import {
  View, Text, FlatList, Pressable, StyleSheet
} from 'react-native';

const Stack = createNativeStackNavigator();
const Tab   = createBottomTabNavigator();

// ── Sample data ───────────────────────────────────────────────────────────────
const INITIAL_TOKENS = [
  { id: '1', label: 'Flipkart delivery', code: 'KART-4KN9-RT2M', time: '10:32',    unread: 2, isPaused: false },
  { id: '2', label: 'Gym membership',    code: 'GYMX-7PQ8-VN3K', time: '09:15',    unread: 0, isPaused: true  },
  { id: '3', name: 'Family Group',  preview: 'Mom: Dinner at 7!',       time: 'Yesterday',unread: 5, isPaused: true  },
  { id: '4', name: 'Work Team',     preview: 'Meeting moved to 3pm',    time: 'Yesterday',unread: 0, isPaused: true  },
];

// ── Screen: Token List ────────────────────────────────────────────────────────
function TokenListScreen({ route, navigation }) {
  const [tokens, setTokens] = useState(INITIAL_TOKENS);

  // Watch for revokedTokenId coming back from TokenDetailScreen
  useEffect(() => {
    const clearedId = route.params?.revokedTokenId;
    if (clearedId) {
      setChats(prev => prev.map(c =>
        c.id === clearedId ? { ...c, unread: 0 } : c
      ));
    }
  }, [route.params?.revokedTokenId]);

  return (
    <View style={styles.screen}>
      <View style={styles.header}>
        <Text style={styles.headerTitle}>My tokens</Text>
        <Text style={styles.headerSub}>
          {tokens.reduce((sum, t) => sum + t.unread, 0)} unread
        </Text>
      </View>

      <FlatList
        data={tokens}
        keyExtractor={item => item.id}
        ItemSeparatorComponent={() => <View style={styles.sep} />}
        renderItem={({ item }) => (
          <Pressable
            style={({ pressed }) => [styles.row, pressed && styles.rowPressed]}
            onPress={() => navigation.navigate('TokenDetail', {
              tokenId:   item.id,
              label: item.name,
              isPaused:  item.isPaused,
            })}
          >
            <View style={styles.avatarCircle}>
              <Text style={styles.avatarLetter}>{item.name[0]}</Text>
            </View>
            <View style={styles.middle}>
              <View style={styles.topRow}>
                <Text style={styles.name}>{item.name}</Text>
                {item.isPaused && (
                  <Text style={styles.groupBadge}>Group</Text>
                )}
              </View>
              <Text style={styles.preview} numberOfLines={1}>{item.preview}</Text>
            </View>
            <View style={styles.right}>
              <Text style={[styles.time, item.unread > 0 && styles.timeGreen]}>
                {item.time}
              </Text>
              {item.unread > 0 && (
                <View style={styles.badge}>
                  <Text style={styles.badgeText}>{item.unread}</Text>
                </View>
              )}
            </View>
          </Pressable>
        )}
      />
    </View>
  );
}

// ── Screen: Message Thread ────────────────────────────────────────────────────
function TokenDetailScreen({ route, navigation }) {
  // Safely destructure with fallback in case params are missing
  const {
    tokenId = '',
    label   = 'Untitled token',
    isPaused  = false,
  } = route.params ?? {};

  // Set the custom green header once the screen mounts
  useEffect(() => {
    navigation.setOptions({ headerShown: false });
  }, []);

  // Simulated messages — in A3 these come from the Token API
  const messages = [
    { id: 'm1', text: 'Hey! Are you free tomorrow?',  sender: 'them' },
    { id: 'm2', text: 'Yes, I\'m free after 3pm.',    sender: 'me'   },
    { id: 'm3', text: 'Perfect, see you then!',        sender: 'them' },
  ];

  function goBackAndMarkRead() {
    // Pass revokedTokenId back so TokenList can clear the badge
    navigation.navigate('TokenList', { revokedTokenId: tokenId });
  }

  return (
    <View style={styles.screen}>
      {/* Custom green header */}
      <View style={styles.header}>
        <Pressable onPress={goBackAndMarkRead} style={styles.backBtn}>
          <Text style={styles.backArrow}>←</Text>
        </Pressable>
        <View style={styles.avatarCircleSmall}>
          <Text style={styles.avatarLetterSmall}>{label[0]}</Text>
        </View>
        <View style={styles.headerInfo}>
          <Text style={styles.headerTitle}>{label}</Text>
          <Text style={styles.headerSub}>
            {isPaused ? 'Group · tap for info' : 'online'}
          </Text>
        </View>
      </View>

      {/* Message bubbles */}
      <FlatList
        data={messages}
        keyExtractor={item => item.id}
        contentContainerStyle={styles.messageList}
        style={{ backgroundColor: '#ECE5DD' }}
        renderItem={({ item }) => (
          <View style={[
            styles.bubble,
            item.sender === 'me' ? styles.bubbleMe : styles.bubbleThem,
          ]}>
            <Text style={styles.bubbleText}>{item.text}</Text>
          </View>
        )}
      />

      {/* Footer showing the params received */}
      <View style={styles.footer}>
        <Text style={styles.footerText}>
          tokenId: {tokenId} · isPaused: {String(isPaused)}
        </Text>
      </View>
    </View>
  );
}

Run this. Tap a token row — notice the detail header shows the correct label and whether it is paused. The footer shows the raw params so you can see exactly what was passed. Tap the back arrow — the unread badge on that token row disappears in the list.

What just happened

The token list passed { tokenId, label, isPaused } to the detail screen. The detail read those params, built a custom header with them, and when going back passed revokedTokenId to the list. The list's useEffect watched for that param and cleared the badge. This is the full data-passing loop your real app will use — before the API and the WebSocket take over in A3 and A6.

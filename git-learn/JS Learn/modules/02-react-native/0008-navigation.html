React Native · Lesson 8

React Navigation

Stack · Bottom Tabs · Nested navigators ~40 min Hands-on
Why this matters for Token

Right now all your code lives in one App.js file. Token has many screens — the token list, a token's detail, the create-token form, message threads, settings — and users move between them by tapping. React Navigation handles all of it: sliding screens in and out, the back button, the bottom tab bar, and passing data from one screen to another.

Token's structure is already decided, and this lesson builds it: Login and Register live in the root stack, outside the tabs. That is not a style choice — it is what stops a logged-out user seeing a tab bar, and what stops the back button walking someone back into the app after they log out.

1. How navigation works in React Native

On the web, navigation is handled by the browser — URLs, the back button, the history stack. React Native has no browser, so you manage navigation yourself using a library. The standard library used by almost every React Native app is React Navigation.

React Navigation gives you two main navigator types you'll use constantly:

  • Stack Navigator — screens stack on top of each other. Tap a token row → its detail screen slides in from the right. Press back → it slides back out. This is the standard mobile navigation pattern.
  • Bottom Tab Navigator — a tab bar at the bottom with icons. Token's Tokens / Messages / Calls / Settings tabs are a bottom tab navigator.

In Token the two are nested — the bottom tabs sit inside the root stack. Tapping a token row from the Tokens tab pushes its detail screen onto the stack on top of everything.

2. Installation

React Navigation is not built into React Native — install it in your app/ project:

# Core library
npm install @react-navigation/native

# Required peer dependencies
npx expo install react-native-screens react-native-safe-area-context

# Stack navigator
npm install @react-navigation/native-stack

# Bottom tab navigator
npm install @react-navigation/bottom-tabs
Use npx expo install for Expo-managed dependencies

npx expo install (not plain npm install) picks the version of a package that is compatible with your current Expo SDK version. Use it for any package that has native code — like react-native-screens. Use plain npm install for pure JS packages like @react-navigation/native-stack.

3. Setting up the NavigationContainer

Every React Navigation app needs a NavigationContainer at the root — it manages the navigation state for the whole app. Wrap your entire app in it inside App.js.

// App.js — the root of your app
import { NavigationContainer } from '@react-navigation/native';

export default function App() {
  return (
    <NavigationContainer>
      {/* All your navigators and screens go inside here */}
    </NavigationContainer>
  );
}

4. Stack Navigator — pushing and popping screens

A stack navigator lets you push screens on top of each other and pop them off when pressing back — exactly like a stack of cards.

import { NavigationContainer } from '@react-navigation/native';
import { createNativeStackNavigator } from '@react-navigation/native-stack';
import { View, Text, Pressable, StyleSheet } from 'react-native';

const Stack = createNativeStackNavigator();

// ── Screen components ──────────────────────────────────────────────────────

function TokenListScreen({ navigation }) {
  return (
    <View style={styles.screen}>
      <Text style={styles.title}>Token List</Text>
      <Pressable
        style={styles.button}
        onPress={() => navigation.navigate('TokenDetail')}
      >
        <Text style={styles.buttonText}>Open the Flipkart token</Text>
      </Pressable>
    </View>
  );
}

function TokenDetailScreen({ navigation }) {
  return (
    <View style={styles.screen}>
      <Text style={styles.title}>Token Detail</Text>
      <Pressable
        style={styles.button}
        onPress={() => navigation.goBack()}
      >
        <Text style={styles.buttonText}>← Go back</Text>
      </Pressable>
    </View>
  );
}

// ── Navigator ─────────────────────────────────────────────────────────────

export default function App() {
  return (
    <NavigationContainer>
      <Stack.Navigator initialRouteName="TokenList">
        <Stack.Screen name="TokenList"   component={TokenListScreen} />
        <Stack.Screen name="TokenDetail" component={TokenDetailScreen} />
      </Stack.Navigator>
    </NavigationContainer>
  );
}

const styles = StyleSheet.create({
  screen:     { flex: 1, alignItems: 'center', justifyContent: 'center', backgroundColor: '#fff' },
  title:      { fontSize: 24, fontWeight: '700', marginBottom: 24 },
  button:     { backgroundColor: '#075E54', paddingHorizontal: 24, paddingVertical: 12, borderRadius: 8 },
  buttonText: { color: '#fff', fontSize: 16, fontWeight: '600' },
});

Run this. Tap the button — the token detail screen slides in from the right. Press the hardware back button (Android) or swipe right (iOS) — it slides back. React Navigation handles the animation and back gesture automatically.

The navigation prop

Every screen component registered in a navigator automatically receives a navigation prop. The key methods are:
navigation.navigate('ScreenName') — go to a screen
navigation.goBack() — go back one screen
navigation.push('ScreenName') — push a new instance even if already in the stack
navigation.replace('ScreenName') — replace current screen (useful for login → home)

Try it yourself — this one is broken on purpose

Those four methods look interchangeable and are not. This models the stack as what it is — an array — and runs the login flow through it:

After logging in with navigate, Login is still on the stack underneath. The user presses back once and is looking at the login form again, inside an app they are already logged into. With replace, Login is gone and back does nothing, which is what you want.

This is the single most common navigation bug

It never shows up while you are building the login screen, because you are testing forwards. It shows up the first time somebody presses back out of habit — and on Android, that is the hardware button every user reaches for constantly.

The rule: replace when the screen you are leaving should not be returned to. Login → Main, splash → Main, and the last step of an onboarding flow.

5. Passing data between screens — route params

When the user taps a token row, you need to tell the detail screen which token to show. You pass data via route params.

// Sending params — from TokenListScreen
function TokenListScreen({ navigation }) {
  const tokens = [
    { id: '1', label: 'Flipkart delivery', code: 'KART-4KN9-RT2M' },
    { id: '2', label: 'Gym membership',    code: 'GYMX-7PQ8-VN3K' },
  ];

  return (
    <View style={styles.screen}>
      {tokens.map(token => (
        <Pressable
          key={token.id}
          style={styles.row}
          onPress={() => navigation.navigate('TokenDetail', {
            tokenId:    token.id,    // pass any data you need
            tokenLabel: token.label,
          })}
        >
          <Text style={styles.name}>{token.label}</Text>
          <Text style={styles.preview}>{token.code}</Text>
        </Pressable>
      ))}
    </View>
  );
}

// Receiving params — in TokenDetailScreen
function TokenDetailScreen({ route, navigation }) {
  const { tokenId, tokenLabel } = route.params;  // destructure what was passed

  return (
    <View style={styles.screen}>
      <Text style={styles.title}>{tokenLabel}</Text>
      <Text style={styles.sub}>Token ID: {tokenId}</Text>
    </View>
  );
}
Only pass plain serialisable data as params

Route params must be serialisable — strings, numbers, booleans, plain objects, arrays. Don't pass class instances, functions, or React components. Pass the ID and fetch the full data inside the target screen using useEffect. This keeps navigation fast and avoids bugs when the app is backgrounded.

6. Customising the header

// Option 1 — set title per screen in the navigator
<Stack.Screen
  name="TokenDetail"
  component={TokenDetailScreen}
  options={{ title: 'Flipkart delivery' }}
/>

// Option 2 — dynamic title from route params
<Stack.Screen
  name="TokenDetail"
  component={TokenDetailScreen}
  options={({ route }) => ({ title: route.params.tokenLabel })}
/>

// Option 3 — set options from inside the screen using navigation.setOptions
function TokenDetailScreen({ route, navigation }) {
  const { tokenLabel } = route.params;

  useEffect(() => {
    navigation.setOptions({
      title: tokenLabel,
      headerStyle:     { backgroundColor: '#075E54' },
      headerTintColor: '#fff',         // back button and title colour
      headerTitleStyle:{ fontWeight: '700' },
    });
  }, [tokenLabel]);

  return <View>...</View>;
}

// Hide the header entirely — for screens with custom headers
<Stack.Screen
  name="TokenList"
  component={TokenListScreen}
  options={{ headerShown: false }}
/>
headerShown: false for your main screens

Your token list and thread screens have custom headers you built in earlier lessons. Set headerShown: false on those screens so React Navigation's default header doesn't appear on top of yours.

7. Bottom Tab Navigator — Token's tab bar

Token has four tabs at the bottom: Tokens, Messages, Calls, Settings. This is a bottom tab navigator.

import { createBottomTabNavigator } from '@react-navigation/bottom-tabs';
import { Text } from 'react-native';

const Tab = createBottomTabNavigator();

// Placeholder screen components
function TokensScreen()   { return <Text>Tokens</Text>; }
function CallsScreen()    { return <Text>Calls</Text>; }
function MessagesScreen() { return <Text>Messages</Text>; }
function SettingsScreen() { return <Text>Settings</Text>; }

function TabNavigator() {
  return (
    <Tab.Navigator
      screenOptions={{
        tabBarActiveTintColor:   '#075E54',
        tabBarInactiveTintColor: '#667781',
        tabBarStyle:             { backgroundColor: '#fff' },
        headerShown:             false,
      }}
    >
      <Tab.Screen
        name="Tokens"
        component={TokensScreen}
        options={{
          tabBarIcon: ({ color }) => <Text style={{ color, fontSize: 20 }}>💬</Text>,
          tabBarBadge: 3,   // unread count badge on the tab icon
        }}
      />
      <Tab.Screen
        name="Calls"
        component={CallsScreen}
        options={{
          tabBarIcon: ({ color }) => <Text style={{ color, fontSize: 20 }}>📞</Text>,
        }}
      />
      <Tab.Screen
        name="Messages"
        component={MessagesScreen}
        options={{
          tabBarIcon: ({ color }) => <Text style={{ color, fontSize: 20 }}>⊙</Text>,
        }}
      />
      <Tab.Screen
        name="Settings"
        component={SettingsScreen}
        options={{
          tabBarIcon: ({ color }) => <Text style={{ color, fontSize: 20 }}>⚙</Text>,
        }}
      />
    </Tab.Navigator>
  );
}
Use react-native-vector-icons for real tab icons

The emoji approach above works for learning, but your real app should use proper icons. Install @expo/vector-icons (already included in Expo) for sharp, scalable icons: import { Ionicons } from '@expo/vector-icons'. Then use <Ionicons name="chatbubbles" size={24} color={color} /> as the tabBarIcon.

8. Nested navigators — Token's full structure

Token nests a stack inside the Tokens tab — so tapping a token row pushes its detail screen on top, while the tab bar stays put.

import { NavigationContainer } from '@react-navigation/native';
import { createNativeStackNavigator }  from '@react-navigation/native-stack';
import { createBottomTabNavigator }    from '@react-navigation/bottom-tabs';

const Stack = createNativeStackNavigator();
const Tab   = createBottomTabNavigator();

// ── Placeholder screens ────────────────────────────────────────────────────
function TokenListScreen({ navigation }) {
  return /* your token list from Lesson 7 */;
}

function TokenDetailScreen({ route }) {
  const { tokenId, tokenLabel } = route.params;
  return /* your message thread from Lesson 5 */;
}

function CallsScreen()    { /* calls list */ }
function MessagesScreen() { /* conversation list */ }
function SettingsScreen() { /* settings */ }

// ── Tokens stack - token list + token detail ─────────────────────────────
function TokensStack() {
  return (
    <Stack.Navigator screenOptions={{ headerShown: false }}>
      <Stack.Screen name="TokenList"   component={TokenListScreen} />
      <Stack.Screen name="TokenDetail" component={TokenDetailScreen} />
    </Stack.Navigator>
  );
}

// ── Root tab navigator ─────────────────────────────────────────────────────
function RootTabs() {
  return (
    <Tab.Navigator
      screenOptions={{
        headerShown:             false,
        tabBarActiveTintColor:   '#075E54',
        tabBarInactiveTintColor: '#667781',
      }}
    >
      <Tab.Screen name="Tokens"   component={TokensStack} />
      <Tab.Screen name="Calls"    component={CallsScreen} />
      <Tab.Screen name="Messages" component={MessagesStack} />
      <Tab.Screen name="Settings" component={SettingsScreen} />
    </Tab.Navigator>
  );
}

// ── Root — auth stack wraps everything ────────────────────────────────────
// Login and Register screens are outside the tabs so they have no tab bar
function RootStack() {
  return (
    <Stack.Navigator screenOptions={{ headerShown: false }}>
      <Stack.Screen name="Login"    component={LoginScreen} />
      <Stack.Screen name="Register" component={RegisterScreen} />
      <Stack.Screen name="Main"     component={RootTabs} />
    </Stack.Navigator>
  );
}

// ── Entry point ───────────────────────────────────────────────────────────
export default function App() {
  return (
    <NavigationContainer>
      <RootStack />
    </NavigationContainer>
  );
}

This is Token's complete navigation structure. The flow is:

  1. App opens → Login screen (no tab bar)
  2. User logs in → navigation.replace('Main') → Bottom tabs appear
  3. User taps a token row → navigation.navigate('TokenDetail', { tokenId, tokenLabel }) → Detailage thread slides in over the tabs
  4. User presses back → Returns to the token list with tabs

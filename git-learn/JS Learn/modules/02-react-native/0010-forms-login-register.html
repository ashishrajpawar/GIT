Forms — Login & Register Screens

Controlled inputs · Validation · KeyboardAvoidingView · returnKeyType ~40 min Hands-on
Why this matters for Token

The first two screens a user sees are Login and Register. If the form is broken — the keyboard hides the inputs, errors do not show clearly, tapping Next does not jump to the next field — users give up before they have an account. This lesson builds both screens with proper validation and keyboard handling on iOS and Android.

Notice what Token's registration form does not ask for: an email address or a phone number. That is not an oversight. The entire product exists so a user does not have to hand those out, and an app that collects one to create the account has undermined itself on its first screen. Registration is a username and a password. Nothing else.

1. Controlled inputs — connecting TextInput to state

A controlled input means the TextInput's value is always driven by a state variable. Every keystroke updates the state; the state drives the display. This is the standard pattern in React Native.

import { useState } from 'react';
import { View, TextInput, Text, StyleSheet } from 'react-native';

function LoginScreen() {
  const [username, setUsername] = useState('');
  const [password, setPassword] = useState('');

  return (
    <View>
      <TextInput
        style={styles.input}
        value={username}                 // driven by state
        onChangeText={setUsername}       // updates state on every keystroke
        placeholder="Username"
        autoCapitalize="none"
      />
      <TextInput
        style={styles.input}
        value={password}
        onChangeText={setPassword}
        placeholder="Password"
        secureTextEntry                  // hides characters
      />

      <Text>Username is: {username}</Text>
    </View>
  );
}
Why controlled inputs?

With controlled inputs, the state is always the single source of truth. When the user taps Login, you read username and password from state — you don't have to query the DOM or use refs. It also lets you validate in real time and clear the fields programmatically by calling setUsername('').

2. Jumping between fields — useRef and returnKeyType

On a real form, tapping "Next" on the keyboard should move focus to the next field — not dismiss the keyboard. This requires a ref on each input and returnKeyType to control the keyboard's return key label.

import { useState, useRef } from 'react';
import { View, TextInput, StyleSheet } from 'react-native';

function RegisterScreen() {
  const [username, setUsername] = useState('');
  const [password, setPassword] = useState('');
  const [confirm,  setConfirm]  = useState('');

  // A ref gives you direct access to the TextInput component
  const passwordRef = useRef(null);
  const confirmRef  = useRef(null);

  return (
    <View>
      <TextInput
        style={styles.input}
        value={username}
        onChangeText={setUsername}
        placeholder="Username"
        autoCapitalize="none"
        returnKeyType="next"            // shows "Next" on the keyboard
        onSubmitEditing={() => passwordRef.current?.focus()}  // move focus on Next
        blurOnSubmit={false}            // don't dismiss keyboard when tapping Next
      />
      <TextInput
        ref={passwordRef}               // attach the ref
        style={styles.input}
        value={password}
        onChangeText={setPassword}
        placeholder="Password"
        secureTextEntry
        returnKeyType="next"
        onSubmitEditing={() => confirmRef.current?.focus()}
        blurOnSubmit={false}
      />
      <TextInput
        ref={confirmRef}
        style={styles.input}
        value={confirm}
        onChangeText={setConfirm}
        placeholder="Confirm password"
        secureTextEntry
        returnKeyType="done"            // last field: shows "Done" / dismisses keyboard
      />
    </View>
  );
}

The chain is: Username field → tap Next → passwordRef.current.focus() → Password field → tap Next → confirmRef.current.focus() → Confirm field → tap Done → keyboard dismisses.

3. Keyboard-aware layout — KeyboardAvoidingView

When the keyboard appears, it covers the bottom half of the screen. If your inputs are near the bottom, they get hidden behind it. KeyboardAvoidingView solves this by pushing the content up.

import { KeyboardAvoidingView, Platform, ScrollView } from 'react-native';

function LoginScreen() {
  return (
    <KeyboardAvoidingView
      style={{ flex: 1 }}
      behavior={Platform.OS === 'ios' ? 'padding' : 'height'}
      //        ↑ iOS needs 'padding' — adds padding equal to keyboard height
      //          Android needs 'height' — shrinks the view's height instead
    >
      <ScrollView
        contentContainerStyle={{ flexGrow: 1 }}
        keyboardShouldPersistTaps="handled"
        //                         ↑ lets you tap buttons while keyboard is open
      >
        {/* your form inputs go here */}
      </ScrollView>
    </KeyboardAvoidingView>
  );
}
Always use Platform.OS for behavior

'padding' on iOS, 'height' on Android. Using the wrong one causes the layout to jump or not move at all. This is one of the most common React Native gotchas — always check both platforms.

4. Form validation

Validate the inputs before sending them to the server. Do it in a plain JavaScript function that returns an errors object.

function validate(username, password) {
  const errors = {};

  const name = username.trim();          // trimming a username is a kindness
  if (!name) {
    errors.username = 'Username is required';
  } else if (name.length < 3) {
    errors.username = 'Username must be at least 3 characters';
  } else if (!/^[a-z0-9_]+$/i.test(name)) {
    errors.username = 'Letters, numbers and underscores only';
  }

  // NOTE: password is NOT trimmed. A space is a legal password character,
  // and trimming it changes the user's password without telling them.
  if (!password) {
    errors.password = 'Password is required';
  } else if (password.length < 8) {
    errors.password = 'Password must be at least 8 characters';
  } else if (password.length > 128) {
    errors.password = 'Password must be 128 characters or fewer';
  }

  return errors;   // empty object {} means no errors
}

// Usage inside a screen
function handleLogin() {
  const errors = validate(username, password);
  if (Object.keys(errors).length > 0) {
    setFormErrors(errors);   // show errors — don't submit
    return;
  }
  // All good — call your auth API here (A4)
  console.log('Logging in:', username.trim());
}

Try it yourself — this one is broken on purpose

This validator looks like the one above and does one extra, helpful-seeming thing. Run it and watch what happens to a perfectly good password:

Trimming the username is a kindness — nobody means the space they pasted. Trimming the password silently changes it. The user registers with " hunter2 ", the app stores the hash of "hunter2", and later some other client that does not trim sends the real thing and login fails. The password they typed is correct and it does not work.

Never transform a password. Only measure it.

Length, yes. Trimming, case-folding, stripping "unsafe" characters, silently truncating to a maximum — all no. A space is a legal password character and so is an emoji. The only safe operations on a password are counting it and passing it on.

The 128-character cap is a rejection, not a truncation, and it exists for the reason B4 gives: argon2 is deliberately slow, so hashing a megabyte-long password ties up a CPU for seconds. Tell the user it is too long; never quietly shorten it.

5. Displaying errors under each field

Show the error message directly under the input that failed. Clear the error for a field as soon as the user starts typing in it.

const [formErrors, setFormErrors] = useState({});

// Clear the error for this field as user types
<TextInput
  value={username}
  onChangeText={text => {
    setUsername(text);
    if (formErrors.username) {
      setFormErrors(prev => ({ ...prev, username: '' }));
    }
  }}
  style={[
    styles.input,
    formErrors.username && styles.inputError,   // red border on error
  ]}
/>

{/* Error text under the input */}
{formErrors.username ? (
  <Text style={styles.errorText}>{formErrors.username}</Text>
) : null}

6. Loading state while waiting for the server

After the user taps Login, it takes a moment for the server to respond. Show a loading indicator on the button and disable it so the user can't tap twice.

import { ActivityIndicator } from 'react-native';

const [loading, setLoading] = useState(false);

async function handleLogin() {
  const errors = validate(username, password);
  if (Object.keys(errors).length > 0) {
    setFormErrors(errors);
    return;
  }

  setLoading(true);
  try {
    // await api.post('/auth/login', { username, password });  // Module 3
    await new Promise(r => setTimeout(r, 1500));  // fake delay for now
    navigation.replace('Main');
  } catch (err) {
    setFormErrors({ general: 'Incorrect username or password' });
  } finally {
    setLoading(false);
  }
}

// Button with loading state
<Pressable
  style={[styles.button, loading && styles.buttonDisabled]}
  onPress={handleLogin}
  disabled={loading}
>
  {loading
    ? <ActivityIndicator color="#fff" />
    : <Text style={styles.buttonText}>LOG IN</Text>
  }
</Pressable>

7. Full working example — Login and Register screens

This is the complete Login and Register UI for Token. The screens live in the root stack from Lesson 8 (outside the tab navigator, so there's no tab bar during onboarding). Replace your entire App.js with this.

import { useState, useRef } from 'react';
import { NavigationContainer } from '@react-navigation/native';
import { createNativeStackNavigator } from '@react-navigation/native-stack';
import { createBottomTabNavigator }   from '@react-navigation/bottom-tabs';
import {
  View, Text, TextInput, Pressable,
  StyleSheet, KeyboardAvoidingView, ScrollView,
  Platform, ActivityIndicator,
} from 'react-native';

const Stack = createNativeStackNavigator();
const Tab   = createBottomTabNavigator();

// ── Validation helper ─────────────────────────────────────────────────────────
function validate({ username, password, confirm, isRegister }) {
  const errors = {};

  const name = username.trim();
  if (!name) {
    errors.username = 'Username is required';
  } else if (name.length < 3) {
    errors.username = 'Username must be at least 3 characters';
  } else if (!/^[a-z0-9_]+$/i.test(name)) {
    errors.username = 'Letters, numbers and underscores only';
  }

  // Deliberately not trimmed — see the note in Section 4.
  if (!password) {
    errors.password = 'Password is required';
  } else if (password.length < 8) {
    errors.password = 'Password must be at least 8 characters';
  } else if (password.length > 128) {
    errors.password = 'Password must be 128 characters or fewer';
  }

  if (isRegister && confirm !== password) {
    errors.confirm = 'Passwords do not match';
  }

  return errors;
}

// ── Screen: Login ─────────────────────────────────────────────────────────────
function LoginScreen({ navigation }) {
  const [username,      setUsername]      = useState('');
  const [password,   setPassword]   = useState('');
  const [formErrors, setFormErrors] = useState({});
  const [loading,    setLoading]    = useState(false);

  const passwordRef = useRef(null);

  function clearError(field) {
    if (formErrors[field]) {
      setFormErrors(prev => ({ ...prev, [field]: '' }));
    }
  }

  async function handleLogin() {
    const errors = validate({ username, password, isRegister: false });
    if (Object.keys(errors).length > 0) {
      setFormErrors(errors);
      return;
    }
    setLoading(true);
    try {
      // TODO A4: await api.post('/auth/login', { username, password })
      await new Promise(r => setTimeout(r, 1200));  // simulated network delay
      navigation.replace('Main');
    } catch {
      setFormErrors({ general: 'Incorrect username or password. Try again.' });
    } finally {
      setLoading(false);
    }
  }

  return (
    <KeyboardAvoidingView
      style={styles.flex}
      behavior={Platform.OS === 'ios' ? 'padding' : 'height'}
    >
      <ScrollView
        contentContainerStyle={styles.formScroll}
        keyboardShouldPersistTaps="handled"
      >
        {/* Logo area */}
        <View style={styles.logoArea}>
          <View style={styles.logoCircle}>
            <Text style={styles.logoEmoji}>💬</Text>
          </View>
          <Text style={styles.appName}>Token</Text>
        </View>

        <Text style={styles.formTitle}>Log in to your account</Text>

        {/* General error (e.g. wrong password) */}
        {formErrors.general ? (
          <View style={styles.generalError}>
            <Text style={styles.generalErrorText}>{formErrors.general}</Text>
          </View>
        ) : null}

        {/* Username */}
        <Text style={styles.label}>Username</Text>
        <TextInput
          style={[styles.input, formErrors.username && styles.inputError]}
          value={username}
          onChangeText={t => { setUsername(t); clearError('username'); }}
          placeholder="you@example.com"
          placeholderTextColor="#aaa"
          autoCapitalize="none"
                    autoCorrect={false}
          returnKeyType="next"
          onSubmitEditing={() => passwordRef.current?.focus()}
          blurOnSubmit={false}
        />
        {formErrors.username ? <Text style={styles.errorText}>{formErrors.username}</Text> : null}

        {/* Password */}
        <Text style={styles.label}>Password</Text>
        <TextInput
          ref={passwordRef}
          style={[styles.input, formErrors.password && styles.inputError]}
          value={password}
          onChangeText={t => { setPassword(t); clearError('password'); }}
          placeholder="At least 6 characters"
          placeholderTextColor="#aaa"
          secureTextEntry
          returnKeyType="done"
          onSubmitEditing={handleLogin}
        />
        {formErrors.password ? <Text style={styles.errorText}>{formErrors.password}</Text> : null}

        {/* Submit button */}
        <Pressable
          style={[styles.button, loading && styles.buttonDisabled]}
          onPress={handleLogin}
          disabled={loading}
        >
          {loading
            ? <ActivityIndicator color="#fff" />
            : <Text style={styles.buttonText}>LOG IN</Text>
          }
        </Pressable>

        {/* Switch to register */}
        <Pressable
          style={styles.switchLink}
          onPress={() => navigation.navigate('Register')}
        >
          <Text style={styles.switchText}>
            Don't have an account? <Text style={styles.switchTextBold}>Register</Text>
          </Text>
        </Pressable>
      </ScrollView>
    </KeyboardAvoidingView>
  );
}

What A4 adds

Right now the login is fake — it just waits 1.2 seconds and navigates. In A4 you replace those two // TODO lines with calls to your own auth API: POST /auth/login and POST /auth/register, returning a token pair you store in expo-secure-store. The entire form structure, validation, and navigation stay exactly the same — only the async call changes.

Now build it yourself

The screen is React Native and the validation is not. Written as a plain function, the rules that decide whether an account can be created are something you can test exhaustively — which is worth doing, because this is the one form every single user has to get through.

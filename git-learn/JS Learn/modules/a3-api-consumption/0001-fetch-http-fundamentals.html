fetch & HTTP Fundamentals

A3 — Lesson 1 of 4 ~50 min
Why this matters for Token

The mobile app and web page talk to your API over HTTP. Every screen that shows data — the token list, a conversation, user settings — makes HTTP requests to your Express server. Understanding the request/response cycle, status codes, headers, and JSON parsing is fundamental to connecting your clients to the backend you just built.

HTTP request anatomy

Every HTTP request has:

  • Method — GET, POST, PATCH, DELETE (what to do)
  • URL — where to send it (http://localhost:3000/api/tokens)
  • Headers — metadata (auth token, content type)
  • Body — data payload (JSON for POST/PATCH)

The response has:

  • Status code — 200, 201, 400, 401, 404, 500
  • Headers — content type, rate limit info, caching
  • Body — the JSON response data

fetch — the built-in HTTP client

fetch is available in both React Native and browsers. No libraries needed:

// GET request (simplest)
const response = await fetch('http://localhost:3000/api/tokens');
const json = await response.json();
console.log(json.data);

Two steps: (1) fetch sends the request and returns a Response object, (2) .json() parses the body as JSON.

Making different request types

// POST — create a token
const response = await fetch('http://localhost:3000/api/tokens', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': 'Bearer eyJhbG...',
  },
  body: JSON.stringify({
    label: 'Amazon Delivery',
    maxUses: 3,
  }),
});

const result = await response.json();
// result = { data: { code: 'MERC-8GH2-LP4X', ... }, success: true }
// PATCH — update a token
await fetch('http://localhost:3000/api/tokens/MERC-8GH2-LP4X', {
  method: 'PATCH',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': 'Bearer eyJhbG...',
  },
  body: JSON.stringify({ label: 'Amazon Prime Delivery' }),
});

// DELETE — revoke a token
await fetch('http://localhost:3000/api/tokens/MERC-8GH2-LP4X', {
  method: 'DELETE',
  headers: { 'Authorization': 'Bearer eyJhbG...' },
});

Handling responses properly

fetch does NOT throw on 4xx/5xx errors — only on network failures. You must check response.ok:

const response = await fetch(url, options);

if (!response.ok) {
  // Status is 4xx or 5xx
  const error = await response.json();
  throw new Error(error.error || `HTTP ${response.status}`);
}

const data = await response.json();
return data;
Common mistake

fetch only throws on network errors (no connection, DNS failure). A 404 or 500 response is still a "successful" fetch — you get a Response object with response.ok === false. Always check before parsing.

Status code handling

async function apiCall(url: string, options?: RequestInit) {
  const response = await fetch(url, options);

  switch (response.status) {
    case 401:
      // Token expired — trigger refresh flow
      throw new AuthExpiredError();
    case 403:
      throw new Error('Access denied');
    case 404:
      return null;  // resource doesn't exist
    case 429:
      // Rate limited — extract retry time from headers
      const retryAfter = response.headers.get('RateLimit-Reset');
      throw new RateLimitError(retryAfter);
  }

  if (!response.ok) {
    const body = await response.json().catch(() => ({}));
    throw new Error(body.error || `Request failed: ${response.status}`);
  }

  // 204 No Content — no body to parse
  if (response.status === 204) return null;

  return response.json();
}

Headers you'll use in Token

// Request headers
'Content-Type': 'application/json'     // telling the server: body is JSON
'Authorization': 'Bearer ' // authenticating the request
'Accept': 'application/json'           // telling the server: send JSON back

// Response headers you'll read
'RateLimit-Remaining'                  // requests left before throttle
'RateLimit-Reset'                      // when the limit resets

The base URL problem

Different environments need different API URLs:

// Development: your local machine
http://localhost:3000/api

// Staging: a test server
https://staging.tokn.app/api

// Production: the real thing
https://api.tokn.app/api

Never hardcode the URL. Use environment config (covered in detail in A11, but the principle now):

// app/config.ts
const API_URL = __DEV__
  ? 'http://localhost:3000/api'     // development
  : 'https://api.tokn.app/api';     // production

export { API_URL };

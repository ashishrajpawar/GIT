Types and Interfaces

A2 — Lesson 1 of 3 ~50 min
Why this matters for Token

Every file in the Token repo — app, web, api, shared — is TypeScript. When you define a token's shape once in shared/types.ts, the compiler tells you instantly if the app sends wrong data to the API or the API returns an unexpected field. Bugs caught at write-time, not in production.

What TypeScript adds to JavaScript

TypeScript is JavaScript with type annotations. The code runs the same way — TS compiles down to JS — but the compiler checks your logic before it runs.

In plain JS, you'd only discover the bug when the function is called with wrong arguments. TS catches it before the code ever runs.

Primitive types

const tokenCode: string = 'MERC-8GH2-LP4X';
const maxUses: number = 5;
const isRevoked: boolean = false;
const revokedAt: null = null;        // explicitly null
const expiresAt: undefined = undefined;  // explicitly undefined

TypeScript infers types when you assign — you don't need to annotate everything:

const tokenCode = 'MERC-8GH2-LP4X';  // TS infers: string
const maxUses = 5;                     // TS infers: number
let isRevoked = false;                 // TS infers: boolean

Rule: annotate function parameters and return types. Let inference handle local variables.

Arrays

const tokenCodes: string[] = ['MERC-8GH2', 'SHOP-4KN9', 'RENT-2WX7'];
const usageCounts: number[] = [3, 0, 12];

// Alternative syntax (same thing):
const codes: Array<string> = ['MERC-8GH2', 'SHOP-4KN9'];

Objects — type aliases

A type alias names a shape:

type Token = {
  code: string;
  issuedTo: string;
  createdAt: string;
  isRevoked: boolean;
  maxUses: number;
};

const myToken: Token = {
  code: 'MERC-8GH2-LP4X',
  issuedTo: 'Amazon Delivery',
  createdAt: '2025-01-15T10:30:00Z',
  isRevoked: false,
  maxUses: 3,
};

If you misspell a property or forget one, the compiler flags it immediately.

Interfaces

An interface does the same thing as a type alias for objects, with slightly different syntax:

interface AccessRule {
  tokenId: string;
  allowedHours: { start: number; end: number };
  maxCallsPerDay: number;
  categories: string[];
}

const rule: AccessRule = {
  tokenId: 'abc-123',
  allowedHours: { start: 9, end: 18 },
  maxCallsPerDay: 2,
  categories: ['delivery', 'support'],
};

type vs interface — when to use which

  • interface — use for object shapes that might be extended (e.g. API response types). Interfaces can be extended with extends.
  • type — use for everything else: unions, tuples, function signatures, computed types.

In Token's shared/ folder, most definitions will be interfaces (they represent data going over the wire). Inside components, type aliases for local shapes.

Optional and readonly

interface Token {
  code: string;
  issuedTo: string;
  revokedAt?: string;      // optional — may or may not exist
  readonly createdAt: string; // can't be reassigned after creation
}

? means the property can be undefined. readonly means you can't reassign it — the compiler stops you.

Union types

A value that can be one of several types:

type TokenStatus = 'active' | 'paused' | 'revoked';

function getStatusColor(status: TokenStatus): string {
  switch (status) {
    case 'active':  return '#16a34a';
    case 'paused':  return '#d97706';
    case 'revoked': return '#dc2626';
  }
}

// This won't compile — 'deleted' isn't in the union:
// getStatusColor('deleted');  // Error!

Union types with string literals are how Token represents states. The compiler ensures every switch case is handled.

Function types

// Annotate parameters and return type
function generateTokenCode(prefix: string, length: number): string {
  const chars = 'ABCDEFGHJKLMNPQRSTUVWXYZ23456789';
  let code = prefix + '-';
  for (let i = 0; i < length; i++) {
    code += chars[Math.floor(Math.random() * chars.length)];
  }
  return code;
}

// Arrow function with types
const isExpired = (expiresAt: string | null): boolean => {
  if (!expiresAt) return false;
  return new Date(expiresAt) < new Date();
};

Type narrowing

When a value could be multiple types, TypeScript tracks which type it is after a check:

function formatExpiry(expiresAt: string | null): string {
  if (expiresAt === null) {
    // TS knows: expiresAt is null here
    return 'Never expires';
  }
  // TS knows: expiresAt is string here
  return `Expires: ${new Date(expiresAt).toLocaleDateString()}`;
}

This is called narrowing. TS narrows the type based on runtime checks you write — if, typeof, in, etc.

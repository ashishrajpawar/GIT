Track A

Core Token Features

5 lessons Phase 3 — Client Meets Server
Module goal

Build the primary product actions: generating tokens, displaying them, sharing via QR codes, managing the token list, configuring access rules, and warning when sharing paths would leak identity. After this module, the app does its job.

Lessons

  1. Token Generation & Display

    Crypto-safe random codes, the XXXX-XXXX-XXXX format, copy-to-clipboard, and the creation flow from the API through to the screen.

  2. QR Generation & Scanning

    Generating QR codes from token URLs, scanning with the camera, and handling the redemption link.

  3. Token List & Management

    FlatList of issued tokens, pull-to-refresh, swipe-to-revoke, pause/resume toggle, and real-time status.

  4. Access Rules UI

    Time windows, contact limits, category restrictions — letting users control what each token allows.

  5. Share-Path Warnings

    Detecting when the user tries to share a token via a channel that already identifies them, and warning appropriately.

What you'll build

  • app/src/screens/CreateToken.tsx — token creation form + code display
  • app/src/screens/TokenDetail.tsx — full token view with QR and rules
  • app/src/screens/TokenList.tsx — main screen with swipe actions
  • app/src/components/QRCode.tsx — QR generator component
  • app/src/components/QRScanner.tsx — camera-based scanner
  • app/src/components/AccessRuleEditor.tsx — rule configuration UI
  • app/src/components/ShareWarning.tsx — identity-leak warning modal
  • shared/src/token.ts — code generation + validation logic (shared with API)

Prerequisites

  • A4 — Auth on the Client (you need authenticated API calls)
  • B2 — Schema Design (you need to know the token table structure)
  • B3 — Node & HTTP Server (the token endpoints exist on the server)

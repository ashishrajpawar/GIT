Token Generation & Display

A5 — Lesson 1 of 5 ~50 min
Why this matters for Token

This is the primary action in the app. A user taps "Create Token", picks a label ("Amazon Delivery", "NoBroker Agent"), and gets a code like MERC-8GH2-LP4X they can share. The code must be cryptographically unpredictable (so nobody can guess another user's token), human-readable (so it can be spoken aloud or typed), and copy-to-clipboard ready. Everything else in the app — rules, revocation, chat — flows from this one action.

Code format decisions

A Token code must satisfy competing requirements:

RequirementDecision
UnpredictableCrypto-random source (not Math.random())
SpeakableUppercase letters + digits, no ambiguous chars (0/O, 1/I/L)
Short enough to type12 characters → 3 groups of 4
Collision-resistant28-char alphabet × 12 = 2812 ≈ 1.2 × 1017 possibilities
URL-safeAlphanumeric only, dashes are separators not part of the code

The safe alphabet

// shared/src/token.ts
const ALPHABET = '23456789ABCDEFGHJKMNPQRSTUVWXYZ';
// 29 characters — removed: 0, O, 1, I, L (too similar)

29 characters × 12 positions = 2912 ≈ 1.7 × 1017 possible codes. Even at 1 million tokens created per second, it would take 5,400 years to exhaust the space. Collisions are negligible.

Crypto-safe randomness

Math.random() is a pseudo-random number generator (PRNG). It's seeded from a predictable state — an attacker who observes a few outputs can predict future ones. For security-sensitive values like token codes, you need a cryptographically secure random number generator (CSPRNG).

On the server (Node.js)

import { randomBytes } from 'node:crypto';

function generateTokenCode(): string {
  const ALPHABET = '23456789ABCDEFGHJKMNPQRSTUVWXYZ';
  const bytes = randomBytes(12);
  let code = '';
  for (let i = 0; i < 12; i++) {
    code += ALPHABET[bytes[i] % ALPHABET.length];
  }
  // Format: XXXX-XXXX-XXXX
  return `${code.slice(0, 4)}-${code.slice(4, 8)}-${code.slice(8, 12)}`;
}

On the client (React Native / browser)

import * as Crypto from 'expo-crypto';

async function generateTokenCode(): Promise<string> {
  const ALPHABET = '23456789ABCDEFGHJKMNPQRSTUVWXYZ';
  const bytes = await Crypto.getRandomBytesAsync(12);
  let code = '';
  for (let i = 0; i < 12; i++) {
    code += ALPHABET[bytes[i] % ALPHABET.length];
  }
  return `${code.slice(0, 4)}-${code.slice(4, 8)}-${code.slice(8, 12)}`;
}

Why both? The server generates the real code (stored in the database). The client generates a preview for instant UI feedback while the API call is in-flight. But only the server's code is canonical — the client replaces its preview with the server's response.

The modulo bias problem

Using bytes[i] % ALPHABET.length introduces a slight bias when 256 doesn't divide evenly by the alphabet length. With 29 characters: 256 / 29 = 8 remainder 24. The first 24 characters appear with probability 9/256, the rest with 8/256 — about 12% bias.

For Token, this is acceptable. The bias doesn't help an attacker guess codes because:

  • The absolute entropy is still massive (>55 bits)
  • Each position is independent — knowing one doesn't help guess another
  • Rate limiting on the redemption endpoint prevents brute force

If you wanted zero bias, you'd use rejection sampling:

// Rejection sampling — unbiased but slightly slower
function unbiasedRandomChar(bytes: Uint8Array, offset: number): string {
  const ALPHABET = '23456789ABCDEFGHJKMNPQRSTUVWXYZ';
  const limit = 256 - (256 % ALPHABET.length); // largest multiple ≤ 256
  let value = bytes[offset];
  while (value >= limit) {
    // reject and re-roll (need fresh random bytes)
    value = crypto.getRandomValues(new Uint8Array(1))[0];
  }
  return ALPHABET[value % ALPHABET.length];
}

We'll use the simpler modulo approach. The math says it's fine for our use case.

Shared code in shared/

Since both the server and client need the same alphabet and format validation, put the shared logic in the shared/ folder:

// shared/src/token.ts

export const TOKEN_ALPHABET = '23456789ABCDEFGHJKMNPQRSTUVWXYZ';
export const TOKEN_LENGTH = 12;
export const TOKEN_FORMAT_REGEX = /^[23456789ABCDEFGHJKMNPQRSTUVWXYZ]{4}-[23456789ABCDEFGHJKMNPQRSTUVWXYZ]{4}-[23456789ABCDEFGHJKMNPQRSTUVWXYZ]{4}$/;

export function formatTokenCode(raw: string): string {
  const clean = raw.replace(/-/g, '').toUpperCase();
  if (clean.length !== TOKEN_LENGTH) throw new Error('Invalid token length');
  return `${clean.slice(0, 4)}-${clean.slice(4, 8)}-${clean.slice(8, 12)}`;
}

export function isValidTokenCode(code: string): boolean {
  return TOKEN_FORMAT_REGEX.test(code);
}

export function stripDashes(code: string): string {
  return code.replace(/-/g, '');
}

The generation function itself is NOT shared — it depends on platform-specific crypto APIs. But validation and formatting are identical everywhere.

The API endpoint

Token creation is a server-side operation. The client sends the label and optional rules; the server generates the code, stores it, and returns the result:

// api/src/routes/tokens.ts
import { Router } from 'express';
import { randomBytes } from 'node:crypto';
import { TOKEN_ALPHABET } from '@token/shared/token';
import { requireAuth } from '../middleware/auth';
import { db } from '../db';

const router = Router();

router.post('/tokens', requireAuth, async (req, res) => {
  const { label } = req.body;
  if (!label || typeof label !== 'string' || label.trim().length === 0) {
    return res.status(400).json({ error: 'Label is required' });
  }

  // Generate crypto-safe code
  const bytes = randomBytes(12);
  let raw = '';
  for (let i = 0; i < 12; i++) {
    raw += TOKEN_ALPHABET[bytes[i] % TOKEN_ALPHABET.length];
  }
  const code = `${raw.slice(0, 4)}-${raw.slice(4, 8)}-${raw.slice(8, 12)}`;

  // Insert into database
  const result = await db.query(
    `INSERT INTO tokens (code, user_id, label)
     VALUES ($1, $2, $3)
     RETURNING id, code, label, status, created_at`,
    [code, req.user.id, label.trim()]
  );

  res.status(201).json({ data: result.rows[0] });
});

export default router;

Handling collisions

With 1.7 × 1017 possible codes, a collision is astronomically unlikely. But the database enforces UNIQUE on the code column — if it happens, you get a constraint violation. Handle it with a retry:

async function createToken(userId: number, label: string) {
  const MAX_RETRIES = 3;

  for (let attempt = 0; attempt < MAX_RETRIES; attempt++) {
    const code = generateTokenCode();
    try {
      const result = await db.query(
        `INSERT INTO tokens (code, user_id, label)
         VALUES ($1, $2, $3)
         RETURNING id, code, label, status, created_at`,
        [code, userId, label]
      );
      return result.rows[0];
    } catch (err: any) {
      if (err.code === '23505' && attempt < MAX_RETRIES - 1) {
        continue; // unique violation — retry with new code
      }
      throw err;
    }
  }
  throw new Error('Failed to generate unique token code');
}

Postgres error code 23505 = unique_violation. In practice, you'll never hit this retry. But defense in depth.

The client-side creation flow

The CreateToken screen: a text input for the label, a "Create" button, and then the generated code displayed large and copyable.

// app/src/screens/CreateToken.tsx
import { useState } from 'react';
import {
  View, Text, TextInput, TouchableOpacity, StyleSheet,
  ActivityIndicator, Alert,
} from 'react-native';
import * as Clipboard from 'expo-clipboard';
import { apiRequest } from '../api/client';

interface TokenResponse {
  data: {
    id: number;
    code: string;
    label: string;
    status: string;
    created_at: string;
  };
}

export function CreateTokenScreen({ navigation }) {
  const [label, setLabel] = useState('');
  const [loading, setLoading] = useState(false);
  const [createdToken, setCreatedToken] = useState<TokenResponse['data'] | null>(null);

  async function handleCreate() {
    if (!label.trim()) {
      Alert.alert('Label required', 'Give this token a name so you know who it\'s for.');
      return;
    }

    setLoading(true);
    try {
      const res = await apiRequest<TokenResponse>('POST', '/tokens', {
        label: label.trim(),
      });
      setCreatedToken(res.data);
    } catch (err: any) {
      Alert.alert('Error', err.message || 'Failed to create token');
    } finally {
      setLoading(false);
    }
  }

  async function handleCopy() {
    if (!createdToken) return;
    await Clipboard.setStringAsync(createdToken.code);
    Alert.alert('Copied!', 'Token code copied to clipboard.');
  }

  if (createdToken) {
    return (
      <View style={styles.container}>
        <Text style={styles.successLabel}>Token created for</Text>
        <Text style={styles.label}>{createdToken.label}</Text>

        <View style={styles.codeCard}>
          <Text style={styles.code}>{createdToken.code}</Text>
        </View>

        <TouchableOpacity style={styles.copyButton} onPress={handleCopy}>
          <Text style={styles.copyButtonText}>Copy Code</Text>
        </TouchableOpacity>

        <TouchableOpacity
          style={styles.doneButton}
          onPress={() => navigation.goBack()}
        >
          <Text style={styles.doneButtonText}>Done</Text>
        </TouchableOpacity>
      </View>
    );
  }

  return (
    <View style={styles.container}>
      <Text style={styles.heading}>Create a Token</Text>
      <Text style={styles.subtext}>
        Give it a label so you remember who it's for.
      </Text>

      <TextInput
        style={styles.input}
        placeholder="e.g. Amazon Delivery, NoBroker Agent"
        value={label}
        onChangeText={setLabel}
        autoFocus
        maxLength={60}
      />

      <TouchableOpacity
        style={[styles.createButton, loading && styles.disabled]}
        onPress={handleCreate}
        disabled={loading}
      >
        {loading ? (
          <ActivityIndicator color="#fff" />
        ) : (
          <Text style={styles.createButtonText}>Generate Token</Text>
        )}
      </TouchableOpacity>
    </View>
  );
}

Copy to clipboard

The expo-clipboard package handles clipboard access on both iOS and Android:

// Install: npx expo install expo-clipboard

import * as Clipboard from 'expo-clipboard';

// Write to clipboard
await Clipboard.setStringAsync('MERC-8GH2-LP4X');

// Read from clipboard (for paste-to-redeem features later)
const text = await Clipboard.getStringAsync();

Platform note: On iOS 14+, the system shows a paste notification banner ("App pasted from Clipboard"). This is expected behaviour — it's Apple's transparency feature. You can't suppress it.

Display design for the code

The generated code should be the hero of the screen — large, monospace, high contrast. The dashes are visual separators that make it easy to read aloud ("MERC — 8GH2 — LP4X"). Design rules:

  • Monospace font — every character takes equal width, aligning the groups
  • Letter spacing — slightly increased for readability
  • Large size — minimum 24pt, ideally 28–32pt
  • High contrast — dark text on light card, or vice versa in dark mode
  • Tappable to copy — the whole code card is a touch target

What the server returns

After the POST /tokens call succeeds, the server returns the created token object:

{
  "data": {
    "id": 42,
    "code": "MERC-8GH2-LP4X",
    "label": "Amazon Delivery",
    "status": "active",
    "max_uses": 0,
    "use_count": 0,
    "expires_at": null,
    "created_at": "2026-08-07T10:30:00.000Z"
  }
}

The client stores this in local state and displays the code. No second fetch needed.

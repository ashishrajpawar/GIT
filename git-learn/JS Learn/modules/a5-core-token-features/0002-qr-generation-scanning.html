QR Generation & Scanning

A5 — Lesson 2 of 5 ~50 min
Why this matters for Token

A QR code is the primary sharing path that preserves privacy. The user shows their screen, the holder scans it — no phone number, email, or name ever travels over a network. The QR encodes a redemption URL (tokn.app/t/MERC8GH2LP4X) that works whether or not the holder has the app installed. This is the interaction that makes Token feel like magic: scan → connected, with zero personal data exchanged.

What the QR encodes

The QR code contains a single URL:

https://tokn.app/t/MERC8GH2LP4X

Design decisions:

DecisionReason
Full URL, not just the codeHolders without the app can open it in a browser → redemption web page
No dashes in the URL pathShorter URL, fewer characters in the QR → smaller/denser QR = easier to scan
/t/ prefixShort, leaves room for other URL paths later (/u/, /about)
HTTPSRequired for Universal Links / App Links (deep linking, covered in A9)

The code in the URL has no dashes — MERC8GH2LP4X not MERC-8GH2-LP4X. The dashes are display-only formatting. Use stripDashes() from shared/src/token.ts when building the URL.

Generating QR codes

The library: react-native-qrcode-svg

This is the best open-source QR generator for React Native. It renders as SVG (sharp at any size), supports custom colors, and works on both iOS and Android with no native module linking.

npx expo install react-native-qrcode-svg react-native-svg

react-native-svg is a peer dependency — it provides the SVG rendering primitives.

Basic usage

import QRCode from 'react-native-qrcode-svg';

function TokenQR({ code }: { code: string }) {
  const url = `https://tokn.app/t/${code.replace(/-/g, '')}`;

  return (
    <QRCode
      value={url}
      size={220}
      backgroundColor="#ffffff"
      color="#000000"
    />
  );
}

Adding a logo in the center

QR codes have built-in error correction — up to 30% of the code can be obscured and it still scans. This means you can place a small logo in the center:

import QRCode from 'react-native-qrcode-svg';

const logo = require('../../assets/token-logo.png');

function TokenQR({ code }: { code: string }) {
  const url = `https://tokn.app/t/${code.replace(/-/g, '')}`;

  return (
    <QRCode
      value={url}
      size={220}
      backgroundColor="#ffffff"
      color="#1e293b"
      logo={logo}
      logoSize={44}
      logoBackgroundColor="#ffffff"
      logoMargin={4}
      logoBorderRadius={8}
      ecl="H"   // highest error correction level
    />
  );
}

ecl="H" sets the error correction level to High (30% recovery). This is essential when using a logo — without it, the logo might obscure critical data modules and break scanning. The tradeoff: H-level codes are denser (more modules), so they need to be displayed larger.

Error correction levels

LevelRecoveryUse case
L (Low)~7%Maximum data density, no logo
M (Medium)~15%Default — good balance
Q (Quartile)~25%Printed codes that might get dirty
H (High)~30%Codes with logos or heavy styling

The QRCode component

Wrap the library in a reusable component with Token-specific defaults:

// app/src/components/QRCode.tsx
import { View, StyleSheet } from 'react-native';
import QRCodeSVG from 'react-native-qrcode-svg';
import { stripDashes } from '@token/shared/token';

interface TokenQRCodeProps {
  code: string;
  size?: number;
}

export function TokenQRCode({ code, size = 220 }: TokenQRCodeProps) {
  const url = `https://tokn.app/t/${stripDashes(code)}`;

  return (
    <View style={styles.container}>
      <QRCodeSVG
        value={url}
        size={size}
        backgroundColor="#ffffff"
        color="#1e293b"
        ecl="M"
      />
    </View>
  );
}

const styles = StyleSheet.create({
  container: {
    padding: 16,
    backgroundColor: '#ffffff',
    borderRadius: 12,
    alignItems: 'center',
    // Subtle shadow for the card feel
    shadowColor: '#000',
    shadowOffset: { width: 0, height: 2 },
    shadowOpacity: 0.08,
    shadowRadius: 8,
    elevation: 3,  // Android shadow
  },
});

Scanning QR codes

The library: expo-camera

expo-camera includes a built-in barcode scanner. No separate barcode library needed.

npx expo install expo-camera

Permissions

Camera access requires explicit user permission on both platforms:

import { Camera } from 'expo-camera';

const [permission, requestPermission] = Camera.useCameraPermissions();

if (!permission) {
  // Still loading
  return null;
}

if (!permission.granted) {
  // Show a "Grant camera access" button
  return (
    <View>
      <Text>Camera access is needed to scan QR codes.</Text>
      <TouchableOpacity onPress={requestPermission}>
        <Text>Allow Camera</Text>
      </TouchableOpacity>
    </View>
  );
}

Platform behaviour:

  • iOS: Shows a system dialog. If denied, you can't re-ask — direct user to Settings.
  • Android: Shows a system dialog. After two denials, Android won't show it again — same as iOS, direct to Settings.

The scanner component

// app/src/components/QRScanner.tsx
import { useState } from 'react';
import { View, Text, TouchableOpacity, StyleSheet, Alert } from 'react-native';
import { CameraView, Camera } from 'expo-camera';

interface QRScannerProps {
  onScan: (code: string) => void;
  onClose: () => void;
}

export function QRScanner({ onScan, onClose }: QRScannerProps) {
  const [permission, requestPermission] = Camera.useCameraPermissions();
  const [scanned, setScanned] = useState(false);

  if (!permission) return null;

  if (!permission.granted) {
    return (
      <View style={styles.permissionContainer}>
        <Text style={styles.permissionText}>
          Camera access is needed to scan Token QR codes.
        </Text>
        <TouchableOpacity style={styles.allowButton} onPress={requestPermission}>
          <Text style={styles.allowButtonText}>Allow Camera</Text>
        </TouchableOpacity>
        <TouchableOpacity onPress={onClose}>
          <Text style={styles.cancelText}>Cancel</Text>
        </TouchableOpacity>
      </View>
    );
  }

  function handleBarCodeScanned({ data }: { data: string }) {
    if (scanned) return;  // prevent multiple fires

    // Validate it's a Token URL
    const match = data.match(/^https?:\/\/tokn\.app\/t\/([23456789ABCDEFGHJKMNPQRSTUVWXYZ]{12})$/);
    if (!match) {
      Alert.alert('Not a Token', 'This QR code is not a valid Token code.');
      return;
    }

    setScanned(true);
    onScan(match[1]);  // pass the 12-char code (no dashes)
  }

  return (
    <View style={styles.scannerContainer}>
      <CameraView
        style={styles.camera}
        facing="back"
        barcodeScannerSettings={{
          barcodeTypes: ['qr'],
        }}
        onBarcodeScanned={scanned ? undefined : handleBarCodeScanned}
      />
      <View style={styles.overlay}>
        <View style={styles.scanArea} />
        <Text style={styles.hint}>Point at a Token QR code</Text>
      </View>
      <TouchableOpacity style={styles.closeButton} onPress={onClose}>
        <Text style={styles.closeText}>Close</Text>
      </TouchableOpacity>
    </View>
  );
}

Preventing double scans

The barcode scanner fires continuously while a QR code is visible — multiple times per second. Without the scanned flag, you'd process the same code 10+ times. The pattern:

const [scanned, setScanned] = useState(false);

// In the handler:
if (scanned) return;
setScanned(true);
onScan(code);

// To scan again (e.g. "Scan another" button):
setScanned(false);

Setting onBarcodeScanned to undefined when scanned is true also tells the camera to stop processing frames — better for battery.

Validating scanned data

Not every QR code is a Token. Someone could scan a random URL, a vCard, or WiFi credentials. Always validate before acting:

function extractTokenCode(qrData: string): string | null {
  // Must be a tokn.app URL with a valid 12-char code
  const match = qrData.match(
    /^https?:\/\/tokn\.app\/t\/([23456789ABCDEFGHJKMNPQRSTUVWXYZ]{12})$/
  );
  return match ? match[1] : null;
}

If validation fails, show a user-friendly message — not a crash. The user might have accidentally scanned a different QR code on the same page.

The full flow: show → scan → redeem

Showing (issuer side)

On the TokenDetail screen, the QR is always visible below the code text:

// app/src/screens/TokenDetail.tsx (relevant section)
import { TokenQRCode } from '../components/QRCode';

function TokenDetailScreen({ route }) {

  return (
    <ScrollView style={styles.container}>

        They scan it — no phone number or email exchanged.
      </Text>

      {/* ... status, rules, revoke button ... */}
    </ScrollView>
  );
}

Scanning (holder side)

The holder either:

  1. Has the Token app → scans QR → app opens TokenRedeem screen
  2. Doesn't have the app → opens URL in browser → redemption web page

For now, we build the in-app scanner. Deep linking (option 2) is covered in A9.

// app/src/screens/ScanToken.tsx
import { useState } from 'react';
import { View } from 'react-native';
import { QRScanner } from '../components/QRScanner';
import { formatTokenCode } from '@token/shared/token';

export function ScanTokenScreen({ navigation }) {
  function handleScan(rawCode: string) {
    // rawCode is 12 chars without dashes
    const formatted = formatTokenCode(rawCode);
    // Navigate to the redemption flow
    navigation.replace('RedeemToken', { code: formatted });
  }

  return (
    <QRScanner
      onScan={handleScan}
      onClose={() => navigation.goBack()}
    />
  );
}

Brightness boost while showing QR

When the user shows their QR to be scanned, the screen should be at maximum brightness — dim screens in sunlight are hard to scan. Use expo-brightness:

import * as Brightness from 'expo-brightness';
import { useEffect, useRef } from 'react';

function useMaxBrightness() {
  const originalBrightness = useRef<number>(0);

  useEffect(() => {
    async function boost() {
      originalBrightness.current = await Brightness.getBrightnessAsync();
      await Brightness.setBrightnessAsync(1);  // max
    }
    boost();

    return () => {
      // Restore original brightness when leaving the screen
      Brightness.setBrightnessAsync(originalBrightness.current);
    };
  }, []);
}

Call useMaxBrightness() in the TokenDetail screen (or specifically when the QR tab is active). The cleanup function in useEffect restores the original brightness when the user navigates away.

npx expo install expo-brightness

Permissions: On Android, expo-brightness needs the WRITE_SETTINGS permission for system brightness. App brightness (within your app only) doesn't need a permission. Use setBrightnessAsync (app-level) rather than setSystemBrightnessAsync to avoid the permission prompt.

Saving QR as image (share to print)

Users might want to save the QR code as an image — to print on a business card, paste in a listing, or send to a print shop. Use react-native-view-shot to capture the QR component as a PNG:

npx expo install react-native-view-shot expo-sharing
import { useRef } from 'react';
import ViewShot from 'react-native-view-shot';
import * as Sharing from 'expo-sharing';

function TokenDetailScreen({ route }) {
  const qrRef = useRef<ViewShot>(null);

  async function handleSaveQR() {
    const uri = await qrRef.current?.capture();
    if (uri) {
      await Sharing.shareAsync(uri, {
        mimeType: 'image/png',
        dialogTitle: 'Save or share your Token QR code',
      });
    }
  }

  return (
    <ScrollView>
      {/* ... */}
      <ViewShot ref={qrRef} options={{ format: 'png', quality: 1 }}>
        <TokenQRCode code={token.code} size={300} />
      </ViewShot>
      <TouchableOpacity onPress={handleSaveQR}>
        <Text>Save QR Image</Text>
      </TouchableOpacity>
    </ScrollView>
  );
}

Privacy note: Saving the QR as an image is safe — it only contains the redemption URL, not the user's identity. This is one of the valid sharing paths from the product rules (printed/displayed QR).

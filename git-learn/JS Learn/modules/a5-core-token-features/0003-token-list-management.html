Token List & Management

A5 — Lesson 3 of 5 ~55 min
Why this matters for Token

The token list is the app's main screen — the first thing users see after login. It shows every token they've issued: who it's for, whether it's active or paused, and how many times it's been used. From here, users can create new tokens, tap into detail, swipe to revoke, or toggle pause. If this screen isn't fast, clear, and satisfying to use, the app feels broken.

The API endpoint

The token list fetches from GET /tokens with cursor-based pagination (built in A3 lesson 4):

// GET /tokens?limit=20&cursor=42
// Response:
{
  "data": [
    {
      "id": 45,
      "label": "Amazon Delivery",
      "status": "active",
      "max_uses": null,
      "use_count": 3,
      "expires_at": null,
      "created_at": "2026-08-01T10:30:00.000Z"
    },
    {
      "id": 44,
      "label": "NoBroker Agent",
      "status": "paused",
      "max_uses": 5,
      "use_count": 2,
      "expires_at": "2026-09-01T00:00:00.000Z",
      "created_at": "2026-07-28T14:00:00.000Z"
    }
    // ... more tokens
  ],
  "cursor": 38,
  "hasMore": true
}

Sorted by created_at DESC — newest first. The cursor is the last token's id.

Two things this response does not contain

There is no code field, and there never will be on this endpoint. ADR-0007 returns a token code exactly once, in the reply to POST /tokens; after that the database holds only code_hash and code_enc. Seeing a code again is a separate, deliberately logged request for one token. That is a policy, but it is also just mechanics: serving codes in a list would mean AES-decrypting every row on every scroll, and writing a log line for each. The list shows the label and the state — which is exactly what a list is for.

max_uses is null, not 0. Null means unlimited. Zero means zero uses are permitted — a token nobody can redeem. They are opposite meanings and one is falsy, which is why if (token.max_uses) is the bug Module 01 keeps returning to. A token with three redemptions and max_uses: 0 is not a token with an unlimited allowance; it is a contradiction the server should never have stored.

The TokenList screen

// app/src/screens/TokenList.tsx
import { useState, useEffect, useCallback } from 'react';
import {
  View, Text, FlatList, TouchableOpacity, RefreshControl,
  StyleSheet, ActivityIndicator,
} from 'react-native';
import { apiRequest } from '../api/client';

interface Token {
  id: number;
  label: string;
  // What the SERVER stores. Three values, changed only by an explicit act.
  status: 'active' | 'paused' | 'revoked';
  max_uses: number | null;      // null = unlimited; 0 = no uses permitted
  use_count: number;
  expires_at: string | null;    // null = never expires
  created_at: string;
}

interface TokensResponse {
  data: Token[];
  cursor: number | null;
  hasMore: boolean;
}

export function TokenListScreen({ navigation }) {
  const [tokens, setTokens] = useState<Token[]>([]);
  const [loading, setLoading] = useState(true);
  const [refreshing, setRefreshing] = useState(false);
  const [loadingMore, setLoadingMore] = useState(false);
  const [cursor, setCursor] = useState<number | null>(null);
  const [hasMore, setHasMore] = useState(true);

  const fetchTokens = useCallback(async (reset = false) => {
    const params = reset ? '?limit=20' : `?limit=20&cursor=${cursor}`;
    const res = await apiRequest<TokensResponse>('GET', `/tokens${params}`);

    if (reset) {
      setTokens(res.data);
    } else {
      setTokens(prev => [...prev, ...res.data]);
    }
    setCursor(res.cursor);
    setHasMore(res.hasMore);
  }, [cursor]);

  useEffect(() => {
    fetchTokens(true).finally(() => setLoading(false));
  }, []);

  async function handleRefresh() {
    setRefreshing(true);
    await fetchTokens(true);
    setRefreshing(false);
  }

  async function handleLoadMore() {
    if (!hasMore || loadingMore) return;
    setLoadingMore(true);
    await fetchTokens(false);
    setLoadingMore(false);
  }

  function renderToken({ item }: { item: Token }) {
    return (
      <TouchableOpacity
        style={styles.tokenCard}
        onPress={() => navigation.navigate('TokenDetail', { token: item })}
      >
        <View style={styles.tokenHeader}>
          <Text style={styles.tokenLabel}>{item.label}</Text>
          {/* The DERIVED status, not item.status -- see displayStatus below */}
          <StatusBadge status={displayStatus(item, Date.now())} />
        </View>
        {/* The list never receives the code. Revealing it is a separate,
            logged request on TokenDetail. */}
        <Text style={styles.tokenCode}>••••-••••-••••</Text>
        <View style={styles.tokenMeta}>
          <Text style={styles.metaText}>
            {/* != null, not > 0: max_uses of 0 is a real limit, and null is
                the one that means there is no limit to show. */}
            Used {item.use_count}{item.max_uses != null ? `/${item.max_uses}` : ''} times
          </Text>
          <Text style={styles.metaText}>
            {new Date(item.created_at).toLocaleDateString()}
          </Text>
        </View>
      </TouchableOpacity>
    );
  }

  if (loading) {
    return (
      <View style={styles.center}>
        <ActivityIndicator size="large" color="#2563eb" />
      </View>
    );
  }

  return (
    <View style={styles.container}>
      <FlatList
        data={tokens}
        keyExtractor={item => item.id.toString()}
        renderItem={renderToken}
        refreshControl={
          <RefreshControl refreshing={refreshing} onRefresh={handleRefresh} />
        }
        onEndReached={handleLoadMore}
        onEndReachedThreshold={0.3}
        ListFooterComponent={loadingMore ? <ActivityIndicator style={{ padding: 16 }} /> : null}
        ListEmptyComponent={
          <View style={styles.empty}>
            <Text style={styles.emptyTitle}>No tokens yet</Text>
            <Text style={styles.emptyText}>
              Create your first token to start sharing access without revealing your identity.
            </Text>
          </View>
        }
        contentContainerStyle={tokens.length === 0 ? styles.emptyContainer : undefined}
      />

      <TouchableOpacity
        style={styles.fab}
        onPress={() => navigation.navigate('CreateToken')}
      >
        <Text style={styles.fabText}>+</Text>
      </TouchableOpacity>
    </View>
  );
}

Stored status and displayed status are not the same thing

The status column has three values, and the state machine below governs all three. But a token can stop working without anybody changing that column: its expires_at passes, or its use_count reaches its max_uses. Nothing writes to the database when a clock ticks over.

So the badge cannot render token.status directly. If it does, a token that expired last Tuesday shows a green "active" badge — and the whole point of this screen is telling the user what is currently live. The stored status is one input to the displayed status, not the answer:

DisplayedComes fromReversible?
revokedstatus columnNo — terminal
expiredexpires_at vs nowNo, not by the app
exhausteduse_count vs max_usesNo, not by the app
pausedstatus columnYes — resume
activenone of the above applied—

The order matters, and it is the reason this is worth writing as a function rather than a chain of ternaries in JSX. Paused comes last of the four: a paused token that has also expired reads expired, because resuming it would achieve nothing and offering a Resume button on it is a lie. Revoked comes first for the mirror-image reason — it is the one state the user chose, and it outranks whatever the clock says.

The StatusBadge component

The badge takes the derived status, so it needs all five:

type DisplayStatus = 'active' | 'paused' | 'expired' | 'exhausted' | 'revoked';

function StatusBadge({ status }: { status: DisplayStatus }) {
  const colors = {
    active:    { bg: '#dcfce7', text: '#166534' },
    paused:    { bg: '#fef3c7', text: '#92400e' },
    expired:   { bg: '#e2e8f0', text: '#475569' },
    exhausted: { bg: '#e2e8f0', text: '#475569' },
    revoked:   { bg: '#fee2e2', text: '#991b1b' },
  };

  const { bg, text } = colors[status];

  return (
    <View style={[styles.badge, { backgroundColor: bg }]}>
      <Text style={[styles.badgeText, { color: text }]}>{status}</Text>
    </View>
  );
}

Swipe-to-revoke with Swipeable

Revoking a token is destructive and permanent. A swipe gesture makes it quick but not accidental — the user must swipe far enough to trigger:

npx expo install react-native-gesture-handler react-native-reanimated
import { Swipeable } from 'react-native-gesture-handler';

function SwipeableTokenCard({ item, onRevoke, onPress }) {
  function renderRightActions() {
    return (
      <TouchableOpacity
        style={styles.revokeAction}
        onPress={() => onRevoke(item.id)}
      >
        <Text style={styles.revokeText}>Revoke</Text>
      </TouchableOpacity>
    );
  }

  // Only allow swipe on active/paused tokens (not already revoked)
  if (item.status === 'revoked') {
    return <TokenCard item={item} onPress={onPress} />;
  }

  return (
    <Swipeable renderRightActions={renderRightActions}>
      <TokenCard item={item} onPress={onPress} />
    </Swipeable>
  );
}

Confirming revocation

Revocation is permanent — once revoked, a token can never be reactivated. Always confirm:

import { Alert } from 'react-native';

function handleRevoke(tokenId: number) {
  Alert.alert(
    'Revoke Token',
    'This is permanent. The token holder will immediately lose all access. Continue?',
    [
      { text: 'Cancel', style: 'cancel' },
      {
        text: 'Revoke',
        style: 'destructive',
        onPress: async () => {
          await apiRequest('PATCH', `/tokens/${tokenId}`, { status: 'revoked' });
          // Update local state
          setTokens(prev =>
            prev.map(t => t.id === tokenId ? { ...t, status: 'revoked' } : t)
          );
        },
      },
    ]
  );
}

Pause/resume toggle

Unlike revoke, pause is reversible. A paused token rejects all redemption attempts but can be resumed later. This is for situations like: "I don't want delivery people calling me this weekend, but I'll re-enable it Monday."

async function handleTogglePause(token: Token) {
  const newStatus = token.status === 'active' ? 'paused' : 'active';
  await apiRequest('PATCH', `/tokens/${token.id}`, { status: newStatus });

  setTokens(prev =>
    prev.map(t => t.id === token.id ? { ...t, status: newStatus } : t)
  );
}

In the UI, a simple toggle switch or button:

import { Switch } from 'react-native';

<Switch
  value={token.status === 'active'}
  onValueChange={() => handleTogglePause(token)}
  disabled={token.status === 'revoked'}
  trackColor={{ false: '#e2e8f0', true: '#bbf7d0' }}
  thumbColor={token.status === 'active' ? '#16a34a' : '#94a3b8'}
/>

The PATCH endpoint (server side)

// api/src/routes/tokens.ts — add to existing router
router.patch('/tokens/:id', requireAuth, async (req, res) => {
  const { id } = req.params;
  const { status } = req.body;

  // Validate status transition
  const validStatuses = ['active', 'paused', 'revoked'];
  if (!validStatuses.includes(status)) {
    return res.status(400).json({ error: 'Invalid status' });
  }

  // Fetch the current token (must belong to this user)
  const current = await db.query(
    'SELECT id, status FROM tokens WHERE id = $1 AND user_id = $2',
    [id, req.user.id]
  );

  if (current.rows.length === 0) {
    return res.status(404).json({ error: 'Token not found' });
  }

  const currentStatus = current.rows[0].status;

  // Enforce state machine rules
  if (currentStatus === 'revoked') {
    return res.status(400).json({ error: 'Cannot modify a revoked token' });
  }
  if (status === 'active' && currentStatus !== 'paused') {
    return res.status(400).json({ error: 'Can only resume a paused token' });
  }

  // Apply the update
  const revokedAt = status === 'revoked' ? 'NOW()' : 'NULL';
  const result = await db.query(
    `UPDATE tokens
     SET status = $1, revoked_at = ${status === 'revoked' ? 'NOW()' : 'NULL'}
     WHERE id = $2
     RETURNING id, code, label, status, max_uses, use_count, expires_at, created_at, revoked_at`,
    [status, id]
  );

  res.json({ data: result.rows[0] });
});

State machine

Tokens follow a strict state machine:

active ──→ paused ──→ active (toggle)
active ──→ revoked (permanent, one-way)
paused ──→ revoked (permanent, one-way)
revoked ──→ (nothing — terminal state)

The server enforces this. Even if a client bug sends an invalid transition, the API rejects it.

Optimistic updates

When the user taps pause/resume, the UI should respond instantly — don't wait for the API round-trip. Update local state immediately, then roll back on error:

async function handleTogglePause(token: Token) {
  const newStatus = token.status === 'active' ? 'paused' : 'active';

  // Optimistic: update UI immediately
  setTokens(prev =>
    prev.map(t => t.id === token.id ? { ...t, status: newStatus } : t)
  );

  try {
    await apiRequest('PATCH', `/tokens/${token.id}`, { status: newStatus });
  } catch {
    // Rollback on failure
    setTokens(prev =>
      prev.map(t => t.id === token.id ? { ...t, status: token.status } : t)
    );
    Alert.alert('Error', 'Failed to update token status');
  }
}

This makes the toggle feel instant on fast networks and gracefully handles failures on slow ones.

Pull-to-refresh

RefreshControl gives you the native pull-to-refresh pattern on both iOS and Android. When the user pulls down, it resets the list to the first page:

<FlatList
  refreshControl={
    <RefreshControl
      refreshing={refreshing}
      onRefresh={handleRefresh}
      colors={['#2563eb']}          // Android spinner color
      tintColor="#2563eb"            // iOS spinner color
    />
  }
/>

Important: handleRefresh fetches with reset = true, which replaces the entire list. This picks up new tokens created on another device, tokens revoked elsewhere, and updated use counts.

Empty state

When the user has no tokens, the list shouldn't be a blank screen. Show an encouraging message and a clear call-to-action:

<FlatList

contentContainerStyle={{ flex: 1 }} when empty makes the empty component fill the screen and center vertically. Without it, the empty component sits at the top.

Refreshing after creation

When the user navigates back from CreateToken, the list should show the new token. Two approaches:

Option A: Refresh on focus

import { useFocusEffect } from '@react-navigation/native';

useFocusEffect(
  useCallback(() => {
    fetchTokens(true);
  }, [])
);

Refetches every time the screen comes into focus. Simple but causes a flash on every tab switch.

Option B: Pass data back via navigation params

// In CreateToken, after success:
navigation.navigate('TokenList', { newToken: res.data });

// In TokenList:
useEffect(() => {
  if (route.params?.newToken) {
    setTokens(prev => [route.params.newToken, ...prev]);
    navigation.setParams({ newToken: undefined });
  }
}, [route.params?.newToken]);

Instantly prepends the new token — no network round-trip. We'll use Option B for the immediate feedback and Option A as a fallback (catches tokens created on other devices).

First, the badge that has to be right

Everything else on this screen is a list, a swipe and a spinner. The one thing a user actually reads is the badge, and it is the one thing the server does not hand you. Write the derivation and the rest of the screen has nothing left to get wrong.

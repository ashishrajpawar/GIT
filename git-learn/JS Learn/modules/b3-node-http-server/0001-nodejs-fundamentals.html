Node.js Fundamentals

B3 — Lesson 1 of 4 ~50 min
Why this matters for Token

Token's API server runs on Node.js — the same JavaScript you already know, but running on a server instead of in a browser. Node handles HTTP requests from your mobile app and web page, queries the database, manages WebSocket connections, and sends push notifications. Understanding how Node works under the hood prevents the most common server bugs.

What is Node.js?

Node.js is JavaScript running outside the browser. It uses the V8 engine (same as Chrome) but replaces browser APIs (DOM, window) with server APIs (filesystem, network, processes).

  • Browser JS: document, window, fetch, localStorage
  • Node JS: fs (filesystem), http (server), path, process, crypto
  • Both: console, setTimeout, Promise, JSON, Array, String

The event loop — Node's core concept

Node is single-threaded but handles thousands of concurrent connections. How? The event loop:

  1. Your code runs top-to-bottom
  2. When it hits an async operation (DB query, file read, network request), Node hands it off to the OS
  3. Node continues running other code (serving other requests)
  4. When the async operation completes, its callback is queued
  5. The event loop picks up the callback and runs it

This means: never block the event loop. A heavy CPU computation or synchronous file read blocks ALL other requests. Everything I/O must be async.

Modules — organizing code

Node uses modules to split code across files. Token uses ES modules (the modern standard):

// api/src/utils/token-code.ts
// Shown for the import/export shape. B7 replaces the body with
// crypto.randomBytes and rejection sampling.
export function generateTokenCode(prefix: string): string {
  const chars = '23456789ABCDEFGHJKMNPQRSTUVWXYZ';   // 31 - no 0, O, 1, I, L
  let code = '';
  for (let i = 0; i < 8; i++) {
    code += chars[Math.floor(Math.random() * chars.length)];
  }
  return `${prefix}-${code.slice(0, 4)}-${code.slice(4)}`;
}

// api/src/routes/tokens.ts
import { generateTokenCode } from '../utils/token-code.js';

To use ES modules, set "type": "module" in api/package.json.

Environment variables

Configuration that changes between environments (dev vs production) lives in environment variables — never hardcoded:

// Access via process.env
const port = process.env.PORT || 3000;
const dbUrl = process.env.DATABASE_URL || 'postgres://localhost:5432/token_dev';
const jwtSecret = process.env.JWT_SECRET;  // must be set, no fallback for secrets

if (!jwtSecret) {
  console.error('JWT_SECRET is required');
  process.exit(1);
}

Store them in a .env file (never committed to git):

# api/.env
PORT=3000
DATABASE_URL=postgres://localhost:5432/token_dev
JWT_SECRET=dev-secret-change-in-production

Load them with dotenv:

npm install dotenv
// api/src/server.ts — first line
import 'dotenv/config';

The built-in http module

Node can create an HTTP server with zero dependencies:

import { createServer } from 'http';

const server = createServer((req, res) => {
  // req = incoming request (URL, method, headers, body)
  // res = your response (status code, headers, body)

  if (req.method === 'GET' && req.url === '/health') {
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ status: 'ok' }));
    return;
  }

  res.writeHead(404);
  res.end('Not found');
});

server.listen(3000, () => {
  console.log('Server running on http://localhost:3000');
});

This works, but it's tedious for a real API. That's why we use Express or Fastify — they handle routing, parsing, and middleware. But understanding the raw http module helps when debugging.

Filesystem operations

import { readFile, writeFile } from 'fs/promises';
import { join } from 'path';

// Read a file (async — doesn't block)
const content = await readFile(join(process.cwd(), 'config.json'), 'utf8');
const config = JSON.parse(content);

// Write a file
await writeFile('output.json', JSON.stringify(data, null, 2));

For Token, you'll rarely read files at runtime — data lives in Postgres. But you'll use fs for migrations and configuration loading.

The process object

// Current working directory
console.log(process.cwd());

// Environment variables
console.log(process.env.NODE_ENV);

// Command line arguments
console.log(process.argv);  // ['node', 'script.js', ...args]

// Exit the process
process.exit(1);  // 1 = error, 0 = success

// Handle graceful shutdown
process.on('SIGTERM', () => {
  console.log('Shutting down...');
  server.close();
  pool.end();  // close DB connections
  process.exit(0);
});

Graceful shutdown is important for Token's production server — you want to finish serving active requests and close database connections cleanly before the process exits.

Crypto — secure random values

import { randomBytes, createHash } from 'crypto';

// Generate a secure random token code
function generateSecureCode(): string {
  return randomBytes(9)
    .toString('base64url')
    .slice(0, 12)
    .toUpperCase();
}

// Hash a phone number (one-way — can't reverse)
function hashPhone(phone: string): string {
  return createHash('sha256').update(phone).digest('hex');
}

Always use crypto.randomBytes for security-sensitive values (token codes, session IDs). Never use Math.random() — it's predictable.

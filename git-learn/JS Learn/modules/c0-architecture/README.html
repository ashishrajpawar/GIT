Architecture & System Design

Track C

Phase 1 — 2 lessons  |  before B1, because the schema is downstream of this

Module goal

Two questions, and every later module is an answer to one of them.

Where are the boundaries? Token's promise is not a feature, it is a set of places data is not allowed to reach. Knowing where those lines are — and what form data must be in to cross one — is what makes the rest of the course make sense.

How does a decision survive? You will make choices in this course that someone, possibly you in four months, will want to undo. A decision recorded with its cost can be overturned on evidence. One recorded without can only be re-argued from scratch, forever.

Lessons

  1. Trust Boundaries — the four zones, what crosses each line and in what form, and why deny-by-default is a structural choice rather than a cautious one
  2. Decisions That Survive — architecture decision records, supersession, and where the seams in a system actually go

What you'll build

  • crossBoundary(field, destination) — a deny-by-default policy function that decides whether a piece of data may reach a zone, and in what form. It encodes six real decisions from Token's own ADRs, including the one where the same field is allowed in one direction and refused in the other
  • inForce(records) — resolve a chain of superseding decisions and answer “which decision governs this question now?”, refusing a cycle rather than guessing at one
Why this module comes before SQL

It is tempting to start with tables. The trouble is that a schema is a set of answers to architecture questions that were never asked out loud.

Three of Token's schema decisions are only explicable from this module: the token code is stored twice and never in the clear, message bodies are stored as ciphertext the server cannot read, and the calls table deliberately has no column for a network address. None of those are database decisions. All three arrive in B2 as constraints you cannot argue with unless you know where they came from.

Prerequisites

  • Module 01 — JavaScript Fundamentals — both exercises are plain functions with objects, arrays and early returns
  • X1 — Git & Dev Environment — ADRs live in the repo, and lesson 2 assumes you know what a commit is

In-App Deep Link Handling

A9 — Lesson 2 of 2 ~50 min
Why this matters for Token

When the app opens from a tokn.app/t/CODE link, it needs to parse the URL, extract the token code, and navigate directly to the redemption screen — not just open to the home screen. The user who tapped that link expects to land on that specific token immediately.

Two scenarios: cold start vs warm

When a deep link opens your app, one of two things is happening:

  • Cold start — the app was NOT running. The OS launches it fresh and passes the URL. You get it from Linking.getInitialURL().
  • Warm start — the app was already running (backgrounded). The OS brings it to the foreground and fires a URL event. You get it from the Linking.addEventListener('url', ...) listener.

You must handle BOTH. If you only handle warm start, cold-start users will land on the home screen. If you only handle cold start, background users won't navigate when they tap a second link.

Expo Linking API basics

import * as Linking from 'expo-linking';

// Cold start — get the URL that launched the app
const initialUrl = await Linking.getInitialURL();
// Returns string | null
// null means the app was opened normally (from icon)

// Warm start — listen for new URLs while app is running
const subscription = Linking.addEventListener('url', (event) => {
  // event.url is the full URL string
  handleDeepLink(event.url);
});

// Clean up when component unmounts
subscription.remove();

Parsing the URL to extract the token code

The URL will be either https://tokn.app/t/MERC-8GH2-LP4X (Universal Link) or tokn://t/MERC-8GH2-LP4X (custom scheme in development):

import * as Linking from 'expo-linking';

function parseTokenUrl(url: string): string | null {
  // Linking.parse handles both https:// and custom scheme://
  const parsed = Linking.parse(url);
  // parsed = { scheme: 'https', hostname: 'tokn.app', path: 't/MERC-8GH2-LP4X', ... }
  // or parsed = { scheme: 'tokn', hostname: null, path: 't/MERC-8GH2-LP4X', ... }

  // Extract token code from the path
  if (parsed.path?.startsWith('t/')) {
    const tokenCode = parsed.path.replace('t/', '');
    return tokenCode || null;
  }

  return null;
}

// Usage:
parseTokenUrl('https://tokn.app/t/MERC-8GH2-LP4X');  // 'MERC-8GH2-LP4X'
parseTokenUrl('tokn://t/MERC-8GH2-LP4X');             // 'MERC-8GH2-LP4X'
parseTokenUrl('https://tokn.app/about');               // null

React Navigation deep linking config

Instead of manually parsing URLs and calling navigation.navigate(), React Navigation can handle this declaratively via its linking prop:

// app/src/navigation/linking.ts
import * as Linking from 'expo-linking';

const prefix = Linking.createURL('/');
// In dev: "tokn://"
// In production: handled by Universal/App Links

export const linkingConfig = {
  prefixes: [
    'https://tokn.app',
    'tokn://',        // custom scheme for development
    prefix,           // Expo development URL
  ],
  config: {
    screens: {
      // Maps URL paths to screen names in your navigation tree
      Main: {
        screens: {
          Tokens: {
            screens: {
              TokenRedeem: 't/:code',
              // URL /t/MERC-8GH2-LP4X → TokenRedeem screen with params.code = "MERC-8GH2-LP4X"
            },
          },
        },
      },
      // Auth screens (no deep linking needed)
      Login: 'login',
    },
  },
};

Then apply it to your NavigationContainer:

// app/src/navigation/RootNavigator.tsx
import { NavigationContainer } from '@react-navigation/native';
import { linkingConfig } from './linking';

export function RootNavigator() {
  return (
    <NavigationContainer linking={linkingConfig}>
      {/* Your stack/tab navigators */}
    </NavigationContainer>
  );
}

With this config, React Navigation automatically:

  • Calls Linking.getInitialURL() on cold start
  • Subscribes to Linking.addEventListener for warm start
  • Parses the URL using your config.screens mapping
  • Navigates to the matching screen with the extracted params

Screen params from deep links

The :code in 't/:code' becomes a route param:

// app/src/screens/TokenRedeemScreen.tsx
import { useRoute } from '@react-navigation/native';

type TokenRedeemParams = {
  code: string;  // from the URL: /t/:code
};

export function TokenRedeemScreen() {
  const route = useRoute();
  const { code } = route.params as TokenRedeemParams;

  // code = "MERC-8GH2-LP4X" (extracted from the URL automatically)

  // Now fetch the token details from the API
  const [token, setToken] = useState(null);
  const [error, setError] = useState(null);

  useEffect(() => {
    async function loadToken() {
      try {
        const result = await api.tokens.getByCode(code);
        setToken(result);
      } catch (err) {
        setError(err.message);
      }
    }
    loadToken();
  }, [code]);

  if (error) return <TokenError code={code} message={error} />;
  if (!token) return <LoadingSpinner />;
  return <TokenRedemption token={token} />;
}

Handling invalid and expired tokens

A deep link might carry a token code that is invalid, expired, or revoked. You need graceful error handling:

// app/src/screens/TokenRedeemScreen.tsx
function TokenError({ code, message }: { code: string; message: string }) {
  return (
    <View style={styles.errorContainer}>
      <Text style={styles.errorTitle}>Token unavailable</Text>
      <Text style={styles.errorCode}>{code}</Text>
      <Text style={styles.errorMessage}>{message}</Text>
      <TouchableOpacity onPress={() => navigation.navigate('Main')}>
        <Text>Go to home screen</Text>
      </TouchableOpacity>
    </View>
  );
}

// API responses to handle:
// 404 — token code doesn't exist
// 410 — token was revoked (Gone)
// 403 — token has reached max uses

Auth gate for deep links

What if the user is not logged in when the deep link opens? The token redemption screen requires authentication. You need to:

  1. Detect that auth is needed
  2. Save the intended deep link destination
  3. Show login/register
  4. After auth completes, navigate to the saved destination
// app/src/navigation/RootNavigator.tsx
import { useAuth } from '../hooks/useAuth';

export function RootNavigator() {
  const { isAuthenticated, isLoading } = useAuth();
  const [pendingDeepLink, setPendingDeepLink] = useState<string | null>(null);

  const linkingConfig = {
    prefixes: ['https://tokn.app', 'tokn://'],
    config: { /* ... */ },
    // Custom getInitialURL to intercept when not authed
    async getInitialURL() {
      const url = await Linking.getInitialURL();
      if (url && !isAuthenticated) {
        setPendingDeepLink(url);
        return null;  // don't navigate yet
      }
      return url;
    },
  };

  // After login completes, process the pending deep link
  useEffect(() => {
    if (isAuthenticated && pendingDeepLink) {
      // Slight delay to let navigation mount
      setTimeout(() => {
        Linking.openURL(pendingDeepLink);
        setPendingDeepLink(null);
      }, 100);
    }
  }, [isAuthenticated, pendingDeepLink]);

  return (
    <NavigationContainer linking={linkingConfig}>
      {isAuthenticated ? <MainTabs /> : <AuthStack />}
    </NavigationContainer>
  );
}

Complete deep linking flow — putting it all together

// The full sequence when a holder taps a token link:

// 1. OS routes to app (Universal Link / App Link — lesson 1)
// 2. App receives URL

// 3a. COLD START:
//   - App launches → NavigationContainer mounts
//   - linkingConfig.getInitialURL() is called
//   - Returns "https://tokn.app/t/MERC-8GH2-LP4X"
//   - React Navigation parses it against config.screens
//   - Matches: Main → Tokens → TokenRedeem with params { code: "MERC-8GH2-LP4X" }
//   - Navigates directly to TokenRedeemScreen

// 3b. WARM START:
//   - App is already running (backgrounded)
//   - Linking 'url' event fires
//   - React Navigation receives the event (it subscribed internally)
//   - Same parsing and navigation as above

// 4. TokenRedeemScreen mounts
//   - Reads route.params.code → "MERC-8GH2-LP4X"
//   - Calls API: GET /api/tokens/MERC-8GH2-LP4X/redeem
//   - Shows token info, lets holder communicate

// 5. Error cases:
//   - 404 → "This token doesn't exist"
//   - 410 → "This token has been revoked"
//   - 403 → "This token has reached its usage limit"
//   - Not authed → save link, show login, then redirect

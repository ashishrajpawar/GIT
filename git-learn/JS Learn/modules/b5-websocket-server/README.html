WebSocket Server

3 lessons Phase 4 — Real-time
Module goal

Build the real-time backbone of Token. After this module, clients can establish persistent connections, authenticate on the socket, send and receive messages in real time, and see typing indicators and online/offline status. This replaces Firebase's real-time listeners with your own infrastructure — you control the protocol, the routing, and the data.

Lessons

  1. WS Connection Lifecycle

    The HTTP upgrade, authenticating on connect, heartbeat/ping-pong, reconnection handling, and graceful shutdown.

  2. Message Routing

    Routing messages to the right socket(s), fan-out to multiple devices, conversation-based delivery, and offline queueing.

  3. Presence & Typing

    Tracking online/offline state, typing indicators as ephemeral events, debouncing, and the Redis pub/sub option for multi-server.

What you'll build

  • api/src/ws/server.ts — WebSocket server attached to the HTTP server
  • api/src/ws/auth.ts — JWT verification on WebSocket upgrade
  • api/src/ws/heartbeat.ts — ping/pong keepalive with dead connection cleanup
  • api/src/ws/router.ts — message type dispatcher
  • api/src/ws/presence.ts — online/offline tracking and broadcast
  • api/src/ws/handlers/chat.ts — message delivery and fan-out
  • api/src/ws/handlers/typing.ts — ephemeral typing indicators

Prerequisites

  • B3 — Node & HTTP Server (Express setup, middleware)
  • B4 — Auth Server (JWT verification)
  • A5 — Core Token Features (tokens exist; messages flow between token issuer and holder)

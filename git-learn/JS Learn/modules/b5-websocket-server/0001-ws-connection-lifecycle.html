WS Connection Lifecycle

B5 — Lesson 1 of 3 ~55 min
Why this matters for Token

HTTP is request-response: the client asks, the server answers, the connection closes. But chat needs the server to push messages to the client the instant they arrive — without the client asking. WebSocket gives you a persistent, bidirectional channel. One connection stays open for the entire session. The server can push a message at any moment. This is how real-time chat, typing indicators, and presence all work.

HTTP vs. WebSocket — the mental model

HTTPWebSocket
ConnectionOpens, sends request, gets response, closesOpens once, stays open indefinitely
DirectionClient → Server (server can only respond)Both directions at any time
OverheadFull HTTP headers on every request2-byte frame header after handshake
Server pushNot possible (polling or SSE as workarounds)Native — server sends whenever it wants
Use caseREST APIs, page loads, file uploadsChat, live updates, gaming, presence

The upgrade handshake

A WebSocket connection starts as a normal HTTP request with special headers asking to "upgrade" the protocol:

// Client sends:
GET /ws HTTP/1.1
Host: api.tokn.app
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==
Sec-WebSocket-Version: 13

// Server responds:
HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Accept: s3pPLMBiTxaQ9kYGzzhZRbK+xOo=

After this handshake, the TCP connection stays open and both sides can send frames at any time. The HTTP server hands off the socket to the WebSocket library.

Setting up the WS server

We use the ws library — the most mature, fastest WebSocket implementation for Node.js. It's the foundation that Socket.IO uses internally.

npm install ws
npm install -D @types/ws

Attaching to the existing HTTP server

// api/src/ws/server.ts
import { WebSocketServer, WebSocket } from 'ws';
import { Server as HttpServer } from 'http';
import { verifyWsToken } from './auth';
import { setupHeartbeat } from './heartbeat';

interface AuthenticatedSocket extends WebSocket {
  userId: number;
  isAlive: boolean;
}

const clients = new Map<number, Set<AuthenticatedSocket>>();

export function createWsServer(httpServer: HttpServer) {
  const wss = new WebSocketServer({ noServer: true });

  // Handle the HTTP upgrade manually (for auth)
  httpServer.on('upgrade', async (request, socket, head) => {
    try {
      const userId = await verifyWsToken(request);
      wss.handleUpgrade(request, socket, head, (ws) => {
        const authWs = ws as AuthenticatedSocket;
        authWs.userId = userId;
        authWs.isAlive = true;
        wss.emit('connection', authWs, request);
      });
    } catch (err) {
      socket.write('HTTP/1.1 401 Unauthorized\r\n\r\n');
      socket.destroy();
    }
  });

  wss.on('connection', (ws: AuthenticatedSocket) => {
    // Track this connection
    if (!clients.has(ws.userId)) {
      clients.set(ws.userId, new Set());
    }
    clients.get(ws.userId)!.add(ws);

    console.log(`User ${ws.userId} connected (${clients.get(ws.userId)!.size} devices)`);

    ws.on('message', (data) => {
      handleMessage(ws, data);
    });

    ws.on('close', () => {
      clients.get(ws.userId)?.delete(ws);
      if (clients.get(ws.userId)?.size === 0) {
        clients.delete(ws.userId);
      }
      console.log(`User ${ws.userId} disconnected`);
    });

    ws.on('pong', () => {
      ws.isAlive = true;
    });
  });

  setupHeartbeat(wss);

  return wss;
}

export function getClients() {
  return clients;
}

Authenticating on connect

Unlike HTTP requests where you send an Authorization header with every call, WebSocket authenticates once — during the upgrade handshake. The token is sent as a query parameter (because you can't set custom headers in the browser's WebSocket API):

// api/src/ws/auth.ts
import { IncomingMessage } from 'http';
import { URL } from 'url';
import jwt from 'jsonwebtoken';

const JWT_SECRET = process.env.JWT_SECRET!;

export async function verifyWsToken(request: IncomingMessage): Promise<number> {
  const url = new URL(request.url!, `http://${request.headers.host}`);
  const token = url.searchParams.get('token');

  if (!token) {
    throw new Error('No token provided');
  }

  try {
    const payload = jwt.verify(token, JWT_SECRET) as { sub: number };
    return payload.sub;
  } catch {
    throw new Error('Invalid token');
  }
}

Why query parameter, not header? The browser's new WebSocket(url) API doesn't support custom headers. The only way to send auth credentials is via the URL itself. This is standard practice — even Socket.IO does it this way.

Security note: The token in the URL will appear in server access logs. Use a short-lived access token (15 min), not the refresh token. If the access token expires mid-connection, the server can request re-authentication over the WebSocket itself.

The noServer pattern

We use noServer: true instead of passing the HTTP server directly to WebSocketServer. This gives us control over the upgrade event — specifically, we can reject unauthorized connections before the WebSocket handshake completes:

// With noServer: true, we manually handle 'upgrade':
httpServer.on('upgrade', async (request, socket, head) => {
  // Authenticate FIRST
  const userId = await verifyWsToken(request);
  // Only THEN complete the handshake
  wss.handleUpgrade(request, socket, head, (ws) => { ... });
});

// Without noServer, auth would have to happen AFTER connection:
// wss.on('connection', (ws) => { /* too late — handshake already done */ });

Rejecting before handshake is cleaner — unauthorized clients get a proper 401, not a connected-then-immediately-closed experience.

Heartbeat — detecting dead connections

TCP connections can die silently — phone loses signal, laptop lid closed, router reboots. Without heartbeat, the server keeps dead sockets open indefinitely, leaking memory and corrupting presence state.

The WebSocket protocol has built-in ping/pong frames for this:

// api/src/ws/heartbeat.ts
import { WebSocketServer, WebSocket } from 'ws';

interface AuthenticatedSocket extends WebSocket {
  userId: number;
  isAlive: boolean;
}

export function setupHeartbeat(wss: WebSocketServer) {
  const interval = setInterval(() => {
    wss.clients.forEach((ws) => {
      const authWs = ws as AuthenticatedSocket;
      if (!authWs.isAlive) {
        // Didn't respond to last ping — connection is dead
        authWs.terminate();
        return;
      }
      authWs.isAlive = false;   // reset flag
      authWs.ping();            // send ping frame
    });
  }, 30000); // every 30 seconds

  wss.on('close', () => {
    clearInterval(interval);
  });
}

How it works

  1. Every 30 seconds, server sends a ping frame to every client
  2. Live clients automatically respond with a pong frame (handled by the WS protocol, not your code)
  3. On receiving pong, we set isAlive = true
  4. On the next interval, if isAlive is still false — the client didn't respond. Connection is dead. terminate().

Why 30 seconds? A balance between detection speed and battery/bandwidth. Mobile clients on cellular don't want pings every 5 seconds (drains battery). But waiting 60+ seconds means dead connections linger too long.

Integrating with Express

// api/src/index.ts
import express from 'express';
import { createServer } from 'http';
import { createWsServer } from './ws/server';

const app = express();

// ... existing middleware and routes ...

// Create HTTP server (don't use app.listen — we need the server reference)
const httpServer = createServer(app);

// Attach WebSocket server
createWsServer(httpServer);

const PORT = process.env.PORT || 3000;
httpServer.listen(PORT, () => {
  console.log(`HTTP + WS server listening on port ${PORT}`);
});

Important: We use createServer(app) instead of app.listen(). Both start an HTTP server, but createServer gives us the httpServer reference we need to attach the WebSocket upgrade handler. app.listen() creates the server internally and doesn't return it in a useful way for WebSocket attachment.

Message protocol

We need a consistent format for messages sent over the WebSocket. JSON with a type field:

// Client → Server
{ "type": "chat:send", "payload": { "conversationId": 7, "text": "Hello" } }
{ "type": "typing:start", "payload": { "conversationId": 7 } }
{ "type": "typing:stop", "payload": { "conversationId": 7 } }

// Server → Client
{ "type": "chat:receive", "payload": { "id": 123, "from": 5, "text": "Hello", "sentAt": "..." } }
{ "type": "typing:update", "payload": { "conversationId": 7, "userId": 5, "isTyping": true } }
{ "type": "presence:update", "payload": { "userId": 5, "status": "online" } }
{ "type": "error", "payload": { "message": "Invalid conversation" } }

Parsing incoming messages

// api/src/ws/router.ts
import { WebSocket } from 'ws';

interface WsMessage {
  type: string;
  payload: unknown;
}

interface AuthenticatedSocket extends WebSocket {
  userId: number;
  isAlive: boolean;
}

type Handler = (ws: AuthenticatedSocket, payload: any) => void | Promise<void>;

const handlers = new Map<string, Handler>();

export function registerHandler(type: string, handler: Handler) {
  handlers.set(type, handler);
}

export function handleMessage(ws: AuthenticatedSocket, raw: Buffer | string) {
  let message: WsMessage;

  try {
    message = JSON.parse(raw.toString());
  } catch {
    sendError(ws, 'Invalid JSON');
    return;
  }

  if (!message.type || typeof message.type !== 'string') {
    sendError(ws, 'Missing message type');
    return;
  }

  const handler = handlers.get(message.type);
  if (!handler) {
    sendError(ws, `Unknown message type: ${message.type}`);
    return;
  }

  handler(ws, message.payload);
}

export function sendError(ws: WebSocket, message: string) {
  ws.send(JSON.stringify({ type: 'error', payload: { message } }));
}

export function sendTo(ws: WebSocket, type: string, payload: unknown) {
  if (ws.readyState === WebSocket.OPEN) {
    ws.send(JSON.stringify({ type, payload }));
  }
}

Graceful shutdown

When the server restarts (deploy, crash, scaling), don't just kill connections. Give clients a close frame so they know to reconnect:

// api/src/index.ts — add to existing server setup
process.on('SIGTERM', () => {
  console.log('SIGTERM received — closing WebSocket connections');

  wss.clients.forEach((ws) => {
    ws.close(1001, 'Server shutting down');
  });

  httpServer.close(() => {
    console.log('HTTP server closed');
    process.exit(0);
  });

  // Force exit after 10 seconds if connections don't close cleanly
  setTimeout(() => process.exit(1), 10000);
});

Close code 1001 means "going away" — the server is shutting down intentionally. The client knows to reconnect after a brief delay.

Client-side connection (preview)

This is covered fully in A6, but here's how the client connects:

// app/src/ws/connection.ts (client side — preview)
import { getAccessToken } from '../api/client';

const WS_URL = __DEV__ ? 'ws://localhost:3000' : 'wss://api.tokn.app';

function connect() {
  const token = getAccessToken();
  const ws = new WebSocket(`${WS_URL}/ws?token=${token}`);

  ws.onopen = () => console.log('WS connected');
  ws.onmessage = (event) => {
    const msg = JSON.parse(event.data);
    // dispatch to handlers based on msg.type
  };
  ws.onclose = (event) => {
    if (event.code === 1001) {
      // Server shutting down — reconnect after brief delay
      setTimeout(connect, 2000);
    }
  };
}

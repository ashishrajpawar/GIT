Store Compliance · Lesson 1

Block & Report Users

Block list · Report flow · Firestore schema · Settings UI · Security rules ~60 min Hands-on
Why this matters for your WhatsApp clone

This is the #1 reason messaging apps get rejected from both stores. Apple Guideline 1.2 states: "Apps with user-generated content must include a method for filtering objectionable material, a mechanism to report offensive content, and the ability to block abusive users." Google Play's User Generated Content policy has the same requirement. Without block and report, your app will not pass review — no exceptions. WhatsApp has both features in every chat's menu. You'll build the same thing in this lesson.

1. How blocking works — the concept

When Priya blocks Rahul:

  • Rahul's messages no longer appear in Priya's chat list or message thread
  • Rahul cannot start a new chat with Priya
  • Priya's online status and "last seen" are hidden from Rahul
  • Rahul doesn't know he's blocked — his messages still appear sent on his side (same as WhatsApp)
  • Priya can unblock Rahul at any time from Settings

Key design decision: blocking is client-side filtering + server-side enforcement. The client hides blocked users' content, and Firestore security rules prevent blocked users from writing to the blocker's data.

2. Firestore data model for blocking

You need a place to store who each user has blocked. Add a blockedUsers array to the user's profile document:

// Firestore document: /users/{uid}
{
  uid: 'priya123',
  displayName: 'Priya Sharma',
  email: 'priya@example.com',
  // ... other profile fields ...
  blockedUsers: ['rahul456', 'spam789']  // array of blocked UIDs
}

Why an array on the user document?

  • Fast lookup — when loading chats, one read gives you the entire block list
  • Simple filtering — blockedUsers.includes(senderId) on the client
  • Security rules can check it — Firestore rules can read this array to enforce blocks server-side
  • Limit — Firestore documents have a 1 MB limit; even 10,000 UIDs (each ~28 chars) is only ~280 KB, well within limits

3. Blocking a user — the code

When Priya taps "Block" on Rahul's profile or in a chat menu:

import { doc, updateDoc, arrayUnion, arrayRemove } from 'firebase/firestore';
import { auth, db } from './firebaseConfig';

// Block a user
async function blockUser(targetUid) {
  const myUid = auth.currentUser.uid;
  const myDocRef = doc(db, 'users', myUid);

  await updateDoc(myDocRef, {
    blockedUsers: arrayUnion(targetUid)
  });
}

// Unblock a user
async function unblockUser(targetUid) {
  const myUid = auth.currentUser.uid;
  const myDocRef = doc(db, 'users', myUid);

  await updateDoc(myDocRef, {
    blockedUsers: arrayRemove(targetUid)
  });
}

arrayUnion adds the UID only if it's not already there (no duplicates). arrayRemove removes it. Both are atomic — safe even if two devices act at the same time.

4. Filtering blocked users on the client

When you load the chat list or messages, filter out anything from blocked users:

import { useState, useEffect } from 'react';
import { collection, query, where, orderBy, onSnapshot, doc } from 'firebase/firestore';
import { auth, db } from './firebaseConfig';

function useChatList() {
  const [chats, setChats] = useState([]);
  const [blockedUsers, setBlockedUsers] = useState([]);

  useEffect(() => {
    const myUid = auth.currentUser.uid;

    // Listen to my profile for block list changes
    const unsubProfile = onSnapshot(doc(db, 'users', myUid), (snap) => {
      const data = snap.data();
      setBlockedUsers(data?.blockedUsers || []);
    });

    // Listen to my chats
    const chatsQuery = query(
      collection(db, 'chats'),
      where('members', 'array-contains', myUid),
      orderBy('lastMessageAt', 'desc')
    );

    const unsubChats = onSnapshot(chatsQuery, (snapshot) => {
      const allChats = snapshot.docs.map(d => ({ id: d.id, ...d.data() }));
      setChats(allChats);
    });

    return () => { unsubProfile(); unsubChats(); };
  }, []);

  // Filter out chats where the other person is blocked (1:1 chats only)
  const visibleChats = chats.filter(chat => {
    if (chat.isGroup) return true; // don't hide group chats
    const otherUid = chat.members.find(uid => uid !== auth.currentUser.uid);
    return !blockedUsers.includes(otherUid);
  });

  return visibleChats;
}

For message threads, filter individual messages from blocked users in group chats:

// Inside a group chat message list
const visibleMessages = messages.filter(msg => {
  return !blockedUsers.includes(msg.senderId);
});

5. Security rules — enforcing blocks server-side

Client-side filtering is not enough — a malicious user could bypass your app and write directly to Firestore. Add rules that check the block list:

// firestore.rules
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Users collection
    match /users/{userId} {
      allow read: if request.auth != null;
      allow write: if request.auth.uid == userId;
    }

    // Chats collection
    match /chats/{chatId} {
      allow read: if request.auth.uid in resource.data.members;

      // Can only create a chat if you're not blocked by the other person
      allow create: if request.auth.uid in request.resource.data.members
        && !isBlockedByAnyMember(request.resource.data.members);

      allow update: if request.auth.uid in resource.data.members;

      // Messages sub-collection
      match /messages/{messageId} {
        allow read: if request.auth.uid in get(/databases/$(database)/documents/chats/$(chatId)).data.members;

        // Can only send if not blocked by a member
        allow create: if request.auth.uid == request.resource.data.senderId
          && request.auth.uid in get(/databases/$(database)/documents/chats/$(chatId)).data.members
          && !senderIsBlocked(chatId);
      }
    }

    // Helper: check if the sender is in any member's blockedUsers
    function senderIsBlocked(chatId) {
      let chat = get(/databases/$(database)/documents/chats/$(chatId)).data;
      let otherMembers = chat.members.removeAll([request.auth.uid]);
      // For 1:1 chats, check if the other user blocked us
      return otherMembers.size() == 1
        && request.auth.uid in get(/databases/$(database)/documents/users/$(otherMembers[0])).data.blockedUsers;
    }

    function isBlockedByAnyMember(members) {
      // Simplified: for 1:1, check the other member's block list
      let otherMembers = members.removeAll([request.auth.uid]);
      return otherMembers.size() == 1
        && request.auth.uid in get(/databases/$(database)/documents/users/$(otherMembers[0])).data.blockedUsers;
    }
  }
}

Important: Each get() in security rules counts as one document read and adds latency. For 1:1 chats this is fine (one extra read). For large group chats, checking every member's block list is too expensive — rely on client-side filtering for groups instead.

6. The "Block" action in the chat UI

WhatsApp puts "Block" in the three-dot menu of a chat and on the user's profile. Here's a long-press action sheet pattern:

import { Alert } from 'react-native';

function showBlockOptions(targetUid, targetName) {
  Alert.alert(
    `Block ${targetName}?`,
    'Blocked contacts can no longer send you messages or see your online status. You can unblock them later from Settings.',
    [
      { text: 'Cancel', style: 'cancel' },
      {
        text: 'Block',
        style: 'destructive',
        onPress: () => blockUser(targetUid),
      },
    ]
  );
}

Call this from your chat header menu or contact profile screen. Always show a confirmation dialog — blocking is a significant action.

7. Reporting a user or message

Reporting is separate from blocking. When someone reports content, you store it in a /reports collection for review. The user doesn't need to block in order to report (but you can offer both together).

Reports collection schema

// Firestore document: /reports/{autoId}
{
  reportedBy: 'priya123',           // who filed the report
  reportedUser: 'spam789',          // who is being reported
  chatId: 'chat_abc',              // which chat (optional)
  messageId: 'msg_xyz',           // specific message (optional)
  messageText: 'Buy cheap...',    // snapshot of the message content
  reason: 'spam',                  // category: spam | harassment | hate | other
  details: 'Keeps sending ads',   // optional free text
  status: 'pending',              // pending | reviewed | actioned | dismissed
  createdAt: Timestamp
}

Submitting a report

import { collection, addDoc, serverTimestamp } from 'firebase/firestore';
import { auth, db } from './firebaseConfig';

async function reportUser({ reportedUser, chatId, messageId, messageText, reason, details }) {
  await addDoc(collection(db, 'reports'), {
    reportedBy: auth.currentUser.uid,
    reportedUser,
    chatId: chatId || null,
    messageId: messageId || null,
    messageText: messageText || null,
    reason,
    details: details || '',
    status: 'pending',
    createdAt: serverTimestamp(),
  });
}

9. Block list screen in Settings

Users need a way to see who they've blocked and unblock them. Add this to your Settings tab:

import { useState, useEffect } from 'react';
import { View, Text, FlatList, Pressable, Alert, StyleSheet } from 'react-native';
import { doc, onSnapshot, getDoc } from 'firebase/firestore';
import { auth, db } from './firebaseConfig';

function BlockedUsersScreen() {
  const [blockedProfiles, setBlockedProfiles] = useState([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    const myUid = auth.currentUser.uid;

    const unsub = onSnapshot(doc(db, 'users', myUid), async (snap) => {
      const blockedUids = snap.data()?.blockedUsers || [];

      // Fetch each blocked user's profile
      const profiles = await Promise.all(
        blockedUids.map(async (uid) => {
          const profileSnap = await getDoc(doc(db, 'users', uid));
          return profileSnap.exists()
            ? { uid, ...profileSnap.data() }
            : { uid, displayName: 'Deleted User' };
        })
      );

      setBlockedProfiles(profiles);
      setLoading(false);
    });

    return unsub;
  }, []);

  function confirmUnblock(targetUid, targetName) {
    Alert.alert(
      `Unblock ${targetName}?`,
      'They will be able to send you messages and see your online status again.',
      [
        { text: 'Cancel', style: 'cancel' },
        { text: 'Unblock', onPress: () => unblockUser(targetUid) },
      ]
    );
  }

  function renderItem({ item }) {
    return (
      <View style={styles.row}>
        <View style={styles.avatar}>
          <Text style={styles.avatarText}>
            {item.displayName?.charAt(0)?.toUpperCase() || '?'}
          </Text>
        </View>
        <Text style={styles.name}>{item.displayName}</Text>
        <Pressable
          style={styles.unblockButton}
          onPress={() => confirmUnblock(item.uid, item.displayName)}
        >
          <Text style={styles.unblockText}>Unblock</Text>
        </Pressable>
      </View>
    );
  }

  if (loading) return <Text style={styles.loading}>Loading...</Text>;

  return (
    <View style={styles.container}>
      <FlatList
        data={blockedProfiles}
        keyExtractor={(item) => item.uid}
        renderItem={renderItem}
        ListEmptyComponent={
          <Text style={styles.empty}>You haven't blocked anyone.</Text>
        }
      />
    </View>
  );
}

12. Security rules for the reports collection

Users can create reports but should never read or modify other people's reports:

// firestore.rules (add to existing rules)
match /reports/{reportId} {
  // Anyone logged in can create a report
  allow create: if request.auth != null
    && request.resource.data.reportedBy == request.auth.uid
    && request.resource.data.status == 'pending'
    && request.resource.data.reason in ['spam', 'harassment', 'hate', 'inappropriate', 'other'];

  // Only admins can read or update reports (you'll set up admin in the next lesson)
  allow read, update: if false; // locked down for now
  allow delete: if false;       // reports are never deleted
}

Key points:

  • reportedBy must match the current user — can't file reports pretending to be someone else
  • status must be 'pending' on creation — users can't mark their own reports as "actioned"
  • reason must be one of the allowed values — prevents garbage data
  • Reports are write-only for regular users — they can't see other people's reports or delete their own

13. Full runnable example — Block & Report integrated into a chat screen

Copy this into your App.js to see blocking and reporting in action. This shows the message thread with a header menu containing Block and Report:

import { useState, useEffect, useCallback } from 'react';
import {
  View, Text, FlatList, TextInput, Pressable, Alert,
  KeyboardAvoidingView, Platform, Modal, StyleSheet
} from 'react-native';
import { initializeApp } from 'firebase/app';
import {
  getFirestore, collection, doc, query, orderBy, onSnapshot,
  addDoc, updateDoc, arrayUnion, arrayRemove, serverTimestamp
} from 'firebase/firestore';
import { getAuth } from 'firebase/auth';

// Replace with your Firebase config
const app = initializeApp({ /* your config */ });
const db = getFirestore(app);
const auth = getAuth(app);

// ─── Block & Report Functions ───────────────────────────────
async function blockUser(targetUid) {
  const myUid = auth.currentUser.uid;
  await updateDoc(doc(db, 'users', myUid), {
    blockedUsers: arrayUnion(targetUid),
  });
}

async function unblockUser(targetUid) {
  const myUid = auth.currentUser.uid;
  await updateDoc(doc(db, 'users', myUid), {
    blockedUsers: arrayRemove(targetUid),
  });
}

async function reportUser({ reportedUser, chatId, messageId, messageText, reason, details }) {
  await addDoc(collection(db, 'reports'), {
    reportedBy: auth.currentUser.uid,
    reportedUser,
    chatId: chatId || null,
    messageId: messageId || null,
    messageText: messageText || null,
    reason,
    details: details || '',
    status: 'pending',
    createdAt: serverTimestamp(),
  });
}

// ─── Report Reasons ─────────────────────────────────────────
const REPORT_REASONS = [
  { key: 'spam', label: 'Spam or advertising' },
  { key: 'harassment', label: 'Harassment or bullying' },
  { key: 'hate', label: 'Hate speech' },
  { key: 'inappropriate', label: 'Inappropriate content' },
  { key: 'other', label: 'Other' },
];

// ─── Main Chat Screen ───────────────────────────────────────
export default function App() {
  // In a real app, these come from navigation route params
  const chatId = 'chat_demo123';
  const otherUserId = 'rahul456';
  const otherUserName = 'Rahul Kumar';

  const [messages, setMessages] = useState([]);
  const [text, setText] = useState('');
  const [blockedUsers, setBlockedUsers] = useState([]);
  const [menuVisible, setMenuVisible] = useState(false);
  const [reportModalVisible, setReportModalVisible] = useState(false);
  const [selectedReason, setSelectedReason] = useState(null);
  const [reportDetails, setReportDetails] = useState('');

  const myUid = auth.currentUser?.uid || 'priya123';
  const isBlocked = blockedUsers.includes(otherUserId);

  // Listen to block list
  useEffect(() => {
    const unsub = onSnapshot(doc(db, 'users', myUid), (snap) => {
      setBlockedUsers(snap.data()?.blockedUsers || []);
    });
    return unsub;
  }, [myUid]);

  // Listen to messages
  useEffect(() => {
    const messagesQuery = query(
      collection(db, 'chats', chatId, 'messages'),
      orderBy('createdAt', 'asc')
    );
    const unsub = onSnapshot(messagesQuery, (snapshot) => {
      const msgs = snapshot.docs.map(d => ({ id: d.id, ...d.data() }));
      setMessages(msgs);
    });
    return unsub;
  }, [chatId]);

  // Filter messages from blocked users
  const visibleMessages = messages.filter(msg => !blockedUsers.includes(msg.senderId));

  // Send message
  async function handleSend() {
    if (!text.trim()) return;
    const messageText = text.trim();
    setText('');
    await addDoc(collection(db, 'chats', chatId, 'messages'), {
      text: messageText,
      senderId: myUid,
      createdAt: serverTimestamp(),
    });
  }

  // Block confirmation
  function handleBlock() {
    setMenuVisible(false);
    Alert.alert(
      `Block ${otherUserName}?`,
      'Blocked contacts can no longer send you messages or see your online status.',
      [
        { text: 'Cancel', style: 'cancel' },
        { text: 'Block', style: 'destructive', onPress: () => blockUser(otherUserId) },
      ]
    );
  }

  // Unblock confirmation
  function handleUnblock() {
    Alert.alert(
      `Unblock ${otherUserName}?`,
      'They will be able to send you messages again.',
      [
        { text: 'Cancel', style: 'cancel' },
        { text: 'Unblock', onPress: () => unblockUser(otherUserId) },
      ]
    );
  }

  // Report submission
  async function handleReportSubmit() {
    if (!selectedReason) {
      Alert.alert('Select a reason', 'Please choose why you are reporting.');
      return;
    }
    try {
      await reportUser({
        reportedUser: otherUserId,
        chatId,
        reason: selectedReason,
        details: reportDetails,
      });
      setReportModalVisible(false);
      setSelectedReason(null);
      setReportDetails('');

      Alert.alert('Report Submitted', 'Would you also like to block this user?', [
        { text: 'No thanks', style: 'cancel' },

      Alert.alert('Error', 'Could not submit report. Try again.');

  }

    const isMine = item.senderId === myUid;

        <Text style={styles.messageText}>{item.text}</Text>
      </View>

  }, [myUid]);

  return (
    <KeyboardAvoidingView
      style={styles.container}
      behavior={Platform.OS === 'ios' ? 'padding' : 'height'}
    >
      {/* Header with menu */}
      <View style={styles.header}>
        <Text style={styles.headerName}>{otherUserName}</Text>
        <Pressable onPress={() => setMenuVisible(true)} style={styles.menuButton}>
          <Text style={styles.menuDots}>⋮</Text>

          <Text style={styles.blockedText}>
            You blocked this contact.{' '}
          </Text>
          <Pressable onPress={handleUnblock}>
            <Text style={styles.unblockLink}>Unblock</Text>
          </Pressable>
        </View>
      )}

      {/* Messages */}
      <FlatList
        data={visibleMessages}
        keyExtractor={(item) => item.id}
        renderItem={renderMessage}
        contentContainerStyle={styles.messagesList}
        inverted={false}
      />

      {/* Input bar (hidden if blocked) */}
      {!isBlocked && (
        <View style={styles.inputBar}>
          <TextInput
            style={styles.input}
            value={text}
            onChangeText={setText}
            placeholder="Type a message"
          />
          <Pressable style={styles.sendButton} onPress={handleSend}>
            <Text style={styles.sendText}>Send</Text>
          </Pressable>
        </View>
      )}

      {/* Menu dropdown */}
      <Modal visible={menuVisible} transparent animationType="fade">
        <Pressable style={styles.menuOverlay} onPress={() => setMenuVisible(false)}>
          <View style={styles.menuDropdown}>
            <Pressable style={styles.menuItem} onPress={handleBlock}>
              <Text style={styles.menuItemText}>Block {otherUserName}</Text>
            </Pressable>
            <Pressable style={styles.menuItem} onPress={() => {
              setMenuVisible(false);
              setReportModalVisible(true);

              <Text style={[styles.menuItemText, { color: '#dc3545' }]}>Report</Text>
            </Pressable>
          </View>

      {/* Report modal */}
      <Modal visible={reportModalVisible} animationType="slide">
        <View style={styles.reportContainer}>
          <Text style={styles.reportTitle}>Report {otherUserName}</Text>
          {REPORT_REASONS.map((reason) => (
            <Pressable
              key={reason.key}
              style={[
                styles.reasonButton,
                selectedReason === reason.key && styles.reasonSelected,

            >
              <Text style={[
                styles.reasonText,
                selectedReason === reason.key && styles.reasonTextSelected,
              ]}>
                {reason.label}
              </Text>
            </Pressable>
          ))}
          <TextInput
            style={styles.detailsInput}
            placeholder="Add details (optional)"
            value={reportDetails}
            onChangeText={setReportDetails}
            multiline
            maxLength={500}
          />
          <View style={styles.reportButtons}>
            <Pressable
              style={styles.cancelButton}
              onPress={() => { setReportModalVisible(false); setSelectedReason(null); }}
            >
              <Text style={styles.cancelText}>Cancel</Text>
            </Pressable>
            <Pressable style={styles.submitButton} onPress={handleReportSubmit}>
              <Text style={styles.submitText}>Submit Report</Text>
            </Pressable>
          </View>
        </View>
      </Modal>
    </KeyboardAvoidingView>
  );
}

14. What the stores check

When Apple or Google reviews your messaging app, they verify:

Requirement Apple (Guideline 1.2) Google (UGC Policy)
Block users Required ✅ Required ✅
Report users/content Required ✅ Required ✅
Filter objectionable content Required ✅ Required ✅
Review mechanism for reports Must describe process Must describe process

Apple will ask: "How does your app handle reports?" Your answer: "Reports are stored in our database with a category and reviewed by the team. Users with multiple confirmed reports are banned." (Lesson 2 builds this system.)

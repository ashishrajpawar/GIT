Store Compliance · Lesson 5

Data Export & Terms of Service

Download my data · GDPR right of access · Terms of Service · Hosting · Store linking ~50 min Hands-on
Why this matters for your WhatsApp clone

GDPR Article 15 gives every user the right of access — they can ask for a copy of all the personal data you hold about them, and you must deliver it within 30 days. WhatsApp has "Request Account Info" in Settings for this reason. Without it, you're exposed to legal complaints and fines. Additionally, both Apple and Google can ask you to provide a Terms of Service URL during submission — it sets the legal rules for how users interact with your app. This lesson builds the "Download My Data" feature and creates a minimal Terms of Service document.

1. What data do you hold about each user?

Before building the export, map out every piece of data your app stores for a user:

Collection / Path What it contains Personal data?
/users/{uid} Profile: name, email, photo URL, about, online status Yes
/chats/{chatId} Chat metadata: members, last message, group info Yes (membership reveals who they talk to)
/chats/{chatId}/messages Messages they sent (text, timestamps) Yes
Firebase Storage Images, voice messages, profile photo Yes
/reports Reports they filed (not reports about them) Yes (reveals their activity)
/users/{uid}.consent Consent record: what they agreed to, when Yes

Under GDPR, the user has the right to receive all of this. You don't need to include other people's messages in their export — only messages they sent.

2. Data export strategy — JSON file via share sheet

The simplest approach that works on both platforms:

1. User taps "Download My Data" in Settings
2. App queries all their data from Firestore
3. App builds a JSON object with everything
4. App writes it to a temporary file
5. App opens the share sheet so user can save/email the file

This is exactly how WhatsApp's "Request Account Info" works — they email you a ZIP file. We'll use the share sheet instead (no email server needed).

3. Installing dependencies

expo-file-system writes the JSON to a temp file. expo-sharing opens the native share sheet so the user can AirDrop it, save to Files, or email it.

4. Fetching all user data from Firestore

import {
  collection, query, where, getDocs, doc, getDoc, orderBy
} from 'firebase/firestore';
import { auth, db } from './firebaseConfig';

async function fetchAllUserData() {
  const uid = auth.currentUser.uid;
  const data = {};

  // 1. Profile
  const profileSnap = await getDoc(doc(db, 'users', uid));
  data.profile = profileSnap.exists() ? profileSnap.data() : null;

  // 2. Chats they belong to
  const chatsQuery = query(
    collection(db, 'chats'),
    where('members', 'array-contains', uid)
  );
  const chatsSnap = await getDocs(chatsQuery);

  data.chats = [];

  for (const chatDoc of chatsSnap.docs) {
    const chatData = { id: chatDoc.id, ...chatDoc.data() };

    // 3. Messages they sent in each chat
    const msgsQuery = query(
      collection(db, 'chats', chatDoc.id, 'messages'),
      where('senderId', '==', uid),
      orderBy('createdAt', 'asc')
    );
    const msgsSnap = await getDocs(msgsQuery);

    chatData.messagesSent = msgsSnap.docs.map(m => ({
      id: m.id,
      ...m.data(),
      createdAt: m.data().createdAt?.toDate?.()?.toISOString() || null,
    }));

    data.chats.push(chatData);
  }

  // 4. Reports they filed
  const reportsQuery = query(
    collection(db, 'reports'),
    where('reportedBy', '==', uid)
  );
  const reportsSnap = await getDocs(reportsQuery);
  data.reportsFiled = reportsSnap.docs.map(r => ({
    id: r.id,
    ...r.data(),
    createdAt: r.data().createdAt?.toDate?.()?.toISOString() || null,
  }));

  // 5. Metadata
  data.exportedAt = new Date().toISOString();
  data.exportedFor = uid;
  data.email = auth.currentUser.email;

  return data;
}

Note: This only fetches messages the user sent. Including other people's messages in someone's export would violate the other users' privacy.

5. Writing to file and sharing

import * as FileSystem from 'expo-file-system';
import * as Sharing from 'expo-sharing';

async function exportUserData() {
  // 1. Fetch all data
  const data = await fetchAllUserData();

  // 2. Convert to formatted JSON string
  const jsonString = JSON.stringify(data, null, 2);

  // 3. Write to a temp file
  const fileName = `my-data-export-${Date.now()}.json`;
  const filePath = FileSystem.documentDirectory + fileName;
  await FileSystem.writeAsStringAsync(filePath, jsonString, {
    encoding: FileSystem.EncodingType.UTF8,
  });

  // 4. Open share sheet
  const canShare = await Sharing.isAvailableAsync();
  if (canShare) {
    await Sharing.shareAsync(filePath, {
      mimeType: 'application/json',
      dialogTitle: 'Save your data export',
      UTI: 'public.json', // iOS identifier
    });
  } else {
    // Fallback: tell user where the file is saved
    Alert.alert('Export saved', `File saved to: ${filePath}`);
  }

  // 5. Clean up temp file after sharing
  await FileSystem.deleteAsync(filePath, { idempotent: true });
}

8. Security rules for data export

The export uses standard read queries that your existing rules already allow:

  • /users/{uid} — the user reads their own profile (allowed by request.auth.uid == userId or general authenticated read)
  • /chats — filtered by array-contains their UID (allowed by membership check)
  • /chats/{id}/messages — filtered by senderId == uid (allowed by chat membership)
  • /reports — we need to add a rule that lets users read their OWN reports

Update the reports rules to allow users to read reports they filed:

match /reports/{reportId} {
  // Users can create reports
  allow create: if request.auth != null
    && request.resource.data.reportedBy == request.auth.uid
    && request.resource.data.status == 'pending';

  // Users can read their OWN reports (for data export)
  // Admins can read all reports
  allow read: if request.auth.uid == resource.data.reportedBy
    || isAdmin();

  allow update: if isAdmin();
  allow delete: if false;
}

9. GDPR compliance checklist for data export

GDPR Requirement How your app meets it
Right of access (Art. 15) "Download My Data" in Settings
Data in a machine-readable format (Art. 20) JSON file — universal, parseable by any tool
Delivered within 30 days Instant — generated on-demand in the app
Free of charge No charge — built into the app
Right to erasure (Art. 17) "Delete Account" in Settings (Module 6, Lesson 4)

10. Terms of Service — what it is and why you need it

A Terms of Service (ToS) is a legal agreement between you and your users. It covers:

  • What users can and can't do (no spam, no hate speech, no illegal activity)
  • What happens if they violate the rules (account suspension/ban)
  • Your liability limitations (you're not responsible for what users say to each other)
  • Intellectual property (users own their messages; you have a license to deliver them)
  • Dispute resolution

Both stores may ask for a ToS URL. Apple doesn't require it for all apps, but for messaging apps with user accounts it's strongly recommended. Google Play's policy pages have a "Terms of Service" field.

  ActivityIndicator, Linking, Platform, StyleSheet

import {
  getFirestore, collection, query, where, getDocs,
  doc, getDoc, orderBy
} from 'firebase/firestore';
import { getAuth } from 'firebase/auth';

const app = initializeApp({ /* your config */ });
const db = getFirestore(app);
const auth = getAuth(app);

const TERMS_URL = 'https://yourapp.web.app/terms';
const PRIVACY_URL = 'https://yourapp.web.app/privacy-policy';

// ─── Data Export Logic ──────────────────────────────────────
async function fetchAllUserData() {
  const uid = auth.currentUser.uid;
  const data = { exportedAt: new Date().toISOString(), email: auth.currentUser.email };

  // Profile
  const profileSnap = await getDoc(doc(db, 'users', uid));
  data.profile = profileSnap.exists() ? profileSnap.data() : null;

  // Chats + messages sent
  const chatsQuery = query(
    collection(db, 'chats'),
    where('members', 'array-contains', uid)
  );
  const chatsSnap = await getDocs(chatsQuery);
  data.chats = [];

  for (const chatDoc of chatsSnap.docs) {
    const chatInfo = { id: chatDoc.id, ...chatDoc.data(), messagesSent: [] };

    const msgsQuery = query(
      collection(db, 'chats', chatDoc.id, 'messages'),
      where('senderId', '==', uid),
      orderBy('createdAt', 'asc')
    );
    const msgsSnap = await getDocs(msgsQuery);
    chatInfo.messagesSent = msgsSnap.docs.map(m => ({
      id: m.id,
      text: m.data().text,
      createdAt: m.data().createdAt?.toDate?.()?.toISOString() || null,
    }));

    data.chats.push(chatInfo);
  }

  // Reports filed
  const reportsQuery = query(
    collection(db, 'reports'),
    where('reportedBy', '==', uid)
  );
  const reportsSnap = await getDocs(reportsQuery);
  data.reportsFiled = reportsSnap.docs.map(r => ({
    id: r.id,
    reason: r.data().reason,
    createdAt: r.data().createdAt?.toDate?.()?.toISOString() || null,
  }));

  return data;
}

async function exportAndShare() {
  const data = await fetchAllUserData();
  const json = JSON.stringify(data, null, 2);
  const path = FileSystem.documentDirectory + `my-data-${Date.now()}.json`;

  await FileSystem.writeAsStringAsync(path, json, {
    encoding: FileSystem.EncodingType.UTF8,
  });

  if (await Sharing.isAvailableAsync()) {
    await Sharing.shareAsync(path, {
      mimeType: 'application/json',
      dialogTitle: 'Save your data export',
    });
  }

  await FileSystem.deleteAsync(path, { idempotent: true });
}

15. Handling large exports

For users with thousands of messages, the export might take a while. Handle this gracefully:

// Show progress to the user
async function exportWithProgress(onProgress) {
  const uid = auth.currentUser.uid;
  onProgress('Fetching profile...');

  const data = {};
  const profileSnap = await getDoc(doc(db, 'users', uid));
  data.profile = profileSnap.data();

  onProgress('Fetching chats...');
  const chatsQuery = query(
    collection(db, 'chats'),
    where('members', 'array-contains', uid)
  );
  const chatsSnap = await getDocs(chatsQuery);

  data.chats = [];
  const total = chatsSnap.docs.length;

  for (let i = 0; i < total; i++) {
    onProgress(`Fetching messages (${i + 1}/${total} chats)...`);
    const chatDoc = chatsSnap.docs[i];
    // ... fetch messages for this chat
  }

  onProgress('Creating file...');
  // ... write JSON and share

  onProgress('Done!');
  return data;
}

For very large accounts (10,000+ messages), consider paginating the Firestore queries or showing a "This may take a minute" message. For a typical user with a few hundred messages, it completes in a few seconds.

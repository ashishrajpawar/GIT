Store Compliance · Lesson 2

Content Moderation System

Admin review · Auto-hide · Banning users · Moderation policy · Store Q&A ~55 min Hands-on
Why this matters for your WhatsApp clone

In Lesson 1 you built the ability for users to report content. Now what? Apple and Google will ask you during review: "How does your app handle reported content?" If your answer is "we don't" — rejected. You need a moderation system that receives reports, auto-hides dangerous content, and gives you (the admin) a way to review and act. This lesson builds that entire pipeline — from the moment a report lands in Firestore to the moment a banned user can no longer send messages.

1. The moderation pipeline — overview

Here's what happens when someone reports a message in your app:

User reports message
       ↓
Report saved to /reports (status: 'pending')
       ↓
Auto-hide check: does this user have 3+ pending reports?
       ↓  YES → auto-hide their messages (status: 'auto-hidden')
       ↓  NO  → wait for admin review
       ↓
Admin reviews in moderation dashboard
       ↓
Action taken: dismiss / warn / ban user
       ↓
If banned → user's account is disabled

You don't need a huge team. For a new app with under 10,000 users, you are the admin. The system just needs to exist and work — Apple doesn't require a 24/7 moderation team for indie apps.

2. Extended reports schema

In Lesson 1 you created a basic report document. Let's extend it with moderation fields:

// Firestore document: /reports/{autoId}
{
  // --- From Lesson 1 (user-submitted) ---
  reportedBy: 'priya123',
  reportedUser: 'spam789',
  chatId: 'chat_abc',
  messageId: 'msg_xyz',
  messageText: 'Buy cheap watches...',
  reason: 'spam',
  details: 'Keeps sending ads every day',
  status: 'pending',               // pending → reviewed → actioned → dismissed
  createdAt: Timestamp,

  // --- New: moderation fields (admin-set) ---
  reviewedBy: null,                // admin UID who reviewed
  reviewedAt: null,                // when it was reviewed
  action: null,                    // 'dismissed' | 'warned' | 'hidden' | 'banned'
  adminNotes: null                 // private notes from admin
}

The status field drives the pipeline:

  • pending — new report, not yet reviewed
  • auto-hidden — system auto-hid the content (threshold reached)
  • reviewed — admin looked at it
  • actioned — admin took action (warn, hide, or ban)
  • dismissed — admin decided it's not a violation

3. Tracking report counts per user

To auto-hide and ban, you need to know how many reports a user has. Add a counter to their profile:

// Firestore document: /users/{uid}
{
  uid: 'spam789',
  displayName: 'Spammer',
  // ... other fields ...
  blockedUsers: [],
  reportCount: 5,          // total reports received
  isBanned: false,         // set to true by admin
  isHidden: false          // set to true by auto-hide threshold
}

Increment reportCount when a new report is filed against them:

import { doc, updateDoc, increment } from 'firebase/firestore';

async function incrementReportCount(reportedUserUid) {
  await updateDoc(doc(db, 'users', reportedUserUid), {
    reportCount: increment(1),
  });
}

Call this right after creating the report document (in the reportUser function from Lesson 1):

async function reportUser({ reportedUser, chatId, messageId, messageText, reason, details }) {
  // 1. Create the report
  await addDoc(collection(db, 'reports'), {
    reportedBy: auth.currentUser.uid,
    reportedUser,
    chatId: chatId || null,
    messageId: messageId || null,
    messageText: messageText || null,
    reason,
    details: details || '',
    status: 'pending',
    createdAt: serverTimestamp(),
  });

  // 2. Increment their report count
  await incrementReportCount(reportedUser);

  // 3. Check auto-hide threshold
  await checkAutoHide(reportedUser);
}

4. Auto-hide — hiding content after N reports

If a user gets 3 or more pending reports, automatically hide their messages from other users. This protects your community while you review:

import { doc, getDoc, updateDoc } from 'firebase/firestore';

const AUTO_HIDE_THRESHOLD = 3;

async function checkAutoHide(reportedUserUid) {
  const userDoc = await getDoc(doc(db, 'users', reportedUserUid));
  const userData = userDoc.data();

  if (userData.reportCount >= AUTO_HIDE_THRESHOLD && !userData.isHidden) {
    await updateDoc(doc(db, 'users', reportedUserUid), {
      isHidden: true,
    });
  }
}

Then on the client, filter out hidden users the same way you filter blocked users:

// When rendering messages in a group chat
const visibleMessages = messages.filter(msg => {
  // Skip messages from users I've blocked
  if (blockedUsers.includes(msg.senderId)) return false;

  // Skip messages from hidden/banned users (fetch their profile flag)
  if (hiddenUserIds.includes(msg.senderId)) return false;

  return true;
});

To get hidden user IDs efficiently, listen to the users who are in your chats and check their isHidden or isBanned flags.

5. Admin role — identifying yourself as admin

You need a way to mark certain users as admins so they can access the moderation dashboard. The simplest approach for a small app: store admin UIDs in Firestore and check in security rules.

// Firestore document: /config/admins
{
  uids: ['your-uid-here', 'co-admin-uid']
}

Security rules to allow admin access to reports:

// firestore.rules
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Helper: is the current user an admin?
    function isAdmin() {
      return request.auth.uid in get(/databases/$(database)/documents/config/admins).data.uids;
    }

    // Reports: users can create, only admins can read/update
    match /reports/{reportId} {
      allow create: if request.auth != null
        && request.resource.data.reportedBy == request.auth.uid
        && request.resource.data.status == 'pending';

      allow read: if isAdmin();
      allow update: if isAdmin();
      allow delete: if false;
    }

    // Config: only admins can read (so non-admins can't see the admin list)
    match /config/{docId} {
      allow read: if isAdmin();
      allow write: if false; // change via Firebase Console only
    }
  }
}

Important: The isAdmin() function does one extra document read per rule check. This is fine for admin operations (rare) but don't use it on every message write (too expensive).

6. Moderation dashboard — reviewing reports

Build a simple screen (accessible only to admin users) that lists pending reports:

import { useState, useEffect } from 'react';

    const reportsQuery = query(
      collection(db, 'reports'),
      where('status', 'in', ['pending', 'auto-hidden']),
      orderBy('createdAt', 'desc')
    );

    const unsub = onSnapshot(reportsQuery, (snapshot) => {
      setReports(snapshot.docs.map(d => ({ id: d.id, ...d.data() })));
    });

    return unsub;

  async function handleAction(reportId, reportedUser, action) {
    // Update the report
    await updateDoc(doc(db, 'reports', reportId), {
      status: 'actioned',
      action,
      reviewedBy: auth.currentUser.uid,
      reviewedAt: serverTimestamp(),
    });

    if (action === 'banned') {
      await updateDoc(doc(db, 'users', reportedUser), {
        isBanned: true,
      });
    }

    // If dismissing, mark as dismissed instead
    if (action === 'dismissed') {
      await updateDoc(doc(db, 'reports', reportId), {
        status: 'dismissed',
        action: 'dismissed',
        reviewedBy: auth.currentUser.uid,
        reviewedAt: serverTimestamp(),
      });
    }
  }

          <>
            <Text style={styles.label}>Message content:</Text>
            <Text style={styles.messagePreview}>"{item.messageText}"</Text>
          </>
        )}

        {item.details && (
          <>
            <Text style={styles.label}>Details:</Text>
            <Text style={styles.value}>{item.details}</Text>
          </>
        )}

        <View style={styles.actions}>
          <Pressable
            style={styles.dismissBtn}
            onPress={() => confirmAction(item.id, item.reportedUser, 'dismissed')}
          >
            <Text style={styles.dismissText}>Dismiss</Text>
          </Pressable>
          <Pressable
            style={styles.warnBtn}
            onPress={() => confirmAction(item.id, item.reportedUser, 'warned')}
          >
            <Text style={styles.warnText}>Warn</Text>
          </Pressable>
          <Pressable

}

7. Enforcing bans — blocking a banned user from sending

When a user is banned (isBanned: true), they should not be able to send messages. Enforce this in security rules:

// firestore.rules — updated message creation rule
match /chats/{chatId}/messages/{messageId} {
  allow create: if request.auth.uid == request.resource.data.senderId
    && request.auth.uid in get(/databases/$(database)/documents/chats/$(chatId)).data.members
    && !isBanned(request.auth.uid)
    && !senderIsBlocked(chatId);
}

// Helper: check if user is banned
function isBanned(uid) {
  return get(/databases/$(database)/documents/users/$(uid)).data.isBanned == true;
}

On the client side, show a banned message if the current user is banned:

function ChatScreen() {
  const [myProfile, setMyProfile] = useState(null);

  useEffect(() => {
    const unsub = onSnapshot(doc(db, 'users', auth.currentUser.uid), (snap) => {

        </Text>

    );
  }

  // ... normal chat UI
}

8. Banning with Firebase Auth (stronger enforcement)

Firestore rules prevent writes, but a truly banned user should be signed out entirely. Firebase Auth lets you disable an account — but only from the server side (Admin SDK). For now, the client-side isBanned check works. In Module 8 (Cloud Functions), you'll add server-side account disabling:

// Cloud Function (you'll build this in Module 8, Lesson 4)
// This runs on the server, not in the app
const admin = require('firebase-admin');

exports.banUser = functions.firestore
  .document('users/{uid}')
  .onUpdate(async (change, context) => {
    const before = change.before.data();
    const after = change.after.data();

    // If isBanned just became true, disable the Auth account
    if (!before.isBanned && after.isBanned) {
      await admin.auth().updateUser(context.params.uid, {
        disabled: true,
      });
    }
  });

For now, the Firestore isBanned flag + security rules are enough to pass store review. The Cloud Function makes it airtight later.

11. Accessing the moderation dashboard

Add a "Moderation" option in Settings that only appears for admin users:

import { useState, useEffect } from 'react';
import { doc, getDoc } from 'firebase/firestore';
import { auth, db } from './firebaseConfig';

function useIsAdmin() {
  const [isAdmin, setIsAdmin] = useState(false);

  useEffect(() => {
    async function checkAdmin() {
      const adminDoc = await getDoc(doc(db, 'config', 'admins'));
      if (adminDoc.exists()) {
        const adminUids = adminDoc.data().uids || [];
        setIsAdmin(adminUids.includes(auth.currentUser.uid));
      }
    }
    checkAdmin();
  }, []);

  return isAdmin;
}

// In your Settings screen:
function SettingsScreen({ navigation }) {
  const isAdmin = useIsAdmin();

  return (
    <View>
      {/* ... normal settings items ... */}

      {isAdmin && (
        <Pressable

          onPress={() => navigation.navigate('Moderation')}
        >
          <Text style={styles.settingsText}>Moderation Dashboard</Text>
          <Text style={styles.settingsSubtext}>Review reports</Text>
        </Pressable>
      )}
    </View>
  );
}

import { useState, useEffect } from 'react';

  View, Text, FlatList, Pressable, Alert, Platform, StyleSheet

import { initializeApp } from 'firebase/app';
import {
  getFirestore, collection, doc, query, where, orderBy,
  onSnapshot, updateDoc, getDoc, serverTimestamp, increment
} from 'firebase/firestore';
import { getAuth } from 'firebase/auth';

const app = initializeApp({ /* your config */ });
const db = getFirestore(app);
const auth = getAuth(app);

// ─── Admin Check ────────────────────────────────────────────
function useIsAdmin() {
  const [isAdmin, setIsAdmin] = useState(false);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    async function check() {
      const adminDoc = await getDoc(doc(db, 'config', 'admins'));
      if (adminDoc.exists()) {
        setIsAdmin(adminDoc.data().uids?.includes(auth.currentUser.uid));
      }
      setLoading(false);
    }
    check();
  }, []);

  return { isAdmin, loading };
}

// ─── Moderation Actions ─────────────────────────────────────
async function dismissReport(reportId) {
  await updateDoc(doc(db, 'reports', reportId), {
    status: 'dismissed',
    action: 'dismissed',
    reviewedBy: auth.currentUser.uid,
    reviewedAt: serverTimestamp(),
  });
}

async function warnUser(reportId) {
  await updateDoc(doc(db, 'reports', reportId), {
    status: 'actioned',
    action: 'warned',
    reviewedBy: auth.currentUser.uid,
    reviewedAt: serverTimestamp(),
  });
}

async function banUser(reportId, reportedUserUid) {
  // Mark report as actioned
  await updateDoc(doc(db, 'reports', reportId), {
    status: 'actioned',
    action: 'banned',
    reviewedBy: auth.currentUser.uid,
    reviewedAt: serverTimestamp(),
  });

  // Ban the user
  await updateDoc(doc(db, 'users', reportedUserUid), {
    isBanned: true,

13. Complete Firestore rules — putting it all together

Here are the full security rules with blocking, banning, and reports integrated:

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // ─── Helper functions ─────────────────────────
    function isAdmin() {
      return request.auth.uid in get(/databases/$(database)/documents/config/admins).data.uids;
    }

    function isBanned(uid) {
      return get(/databases/$(database)/documents/users/$(uid)).data.isBanned == true;
    }

    function senderIsBlocked(chatId) {
      let chat = get(/databases/$(database)/documents/chats/$(chatId)).data;
      let others = chat.members.removeAll([request.auth.uid]);
      return others.size() == 1
        && request.auth.uid in get(/databases/$(database)/documents/users/$(others[0])).data.blockedUsers;
    }

    // ─── Users ────────────────────────────────────
    match /users/{userId} {
      allow read: if request.auth != null;
      allow create: if request.auth.uid == userId;
      allow update: if request.auth.uid == userId || isAdmin();
    }

    // ─── Chats ────────────────────────────────────
    match /chats/{chatId} {
      allow read: if request.auth.uid in resource.data.members;
      allow create: if request.auth.uid in request.resource.data.members
        && !isBanned(request.auth.uid);
      allow update: if request.auth.uid in resource.data.members
        && !isBanned(request.auth.uid);

      match /messages/{messageId} {
        allow read: if request.auth.uid in
          get(/databases/$(database)/documents/chats/$(chatId)).data.members;
        allow create: if request.auth.uid == request.resource.data.senderId
          && !isBanned(request.auth.uid)
          && !senderIsBlocked(chatId);
      }
    }

    // ─── Reports ──────────────────────────────────
    match /reports/{reportId} {
      allow create: if request.auth != null
        && request.resource.data.reportedBy == request.auth.uid
        && request.resource.data.status == 'pending'
        && request.resource.data.reason in
           ['spam', 'harassment', 'hate', 'inappropriate', 'other'];
      allow read, update: if isAdmin();
      allow delete: if false;
    }

    // ─── Config (admin list) ──────────────────────
    match /config/{docId} {
      allow read: if isAdmin();
      allow write: if false;
    }
  }
}

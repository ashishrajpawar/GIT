Voice & Video

5 lessons Phase 4 — Real-time
Module goal

Implement peer-to-peer voice and video calling using WebRTC. After this module, token holders and issuers can make real-time calls through the app — with your own signalling server (B6), proper incoming call handling on both platforms, and a relay-only privacy mode that hides IP addresses.

Lessons

  1. WebRTC Refresher + New Signalling

    ICE/STUN/TURN theory, RTCPeerConnection lifecycle, and wiring it to your own WebSocket signalling server.

  2. 1:1 Voice Call

    Audio-only peer connection with react-native-webrtc, call UI, mute/unmute, speaker toggle.

  3. 1:1 Video Call

    Adding video tracks, camera switching (front/back), picture-in-picture local preview.

  4. Incoming Calls (Android + iOS)

    FCM foreground service on Android, CallKit + VoIP push on iOS — making the phone ring even when the app is closed.

  5. Relay-Only Calls & IP Privacy

    iceTransportPolicy: 'relay', the latency and bandwidth it costs, why it is not a user setting, and auditing a live call to prove it took effect.

What you'll build

  • app/src/webrtc/PeerConnection.ts — WebRTC wrapper with signalling integration
  • app/src/screens/VoiceCall.tsx — voice call UI (timer, mute, speaker, hangup)
  • app/src/screens/VideoCall.tsx — video call UI (remote + local streams, camera flip)
  • app/src/screens/IncomingCall.tsx — ring screen with accept/reject
  • app/src/webrtc/config.ts — ICE server configuration with privacy mode

Prerequisites

  • B6 — WebRTC Signalling (your signalling server handles offer/answer/ICE)
  • A6 — Chat & Real-time (WebSocket client for signalling transport)
  • EAS Build configured (react-native-webrtc requires native code — Expo Go won't work)

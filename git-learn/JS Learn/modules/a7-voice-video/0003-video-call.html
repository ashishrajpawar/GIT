1:1 Video Call

A7 — Lesson 3 of 5 ~55 min
Why this matters for Token

Video calls let the issuer visually verify who they're dealing with — a delivery person can show the package, a repair technician can show the problem. Video adds trust without revealing identity (the holder still doesn't know the issuer's phone number). The UI challenge: showing both the remote video (full screen) and local preview (small PiP) while keeping controls accessible.

Adding video to the peer connection

The only difference from voice: request video in getUserMedia and render the streams:

// In TokenPeerConnection.initialize():
this.localStream = await mediaDevices.getUserMedia({
  audio: true,
  video: this.options.type === 'video'
    ? { facingMode: 'user', width: 640, height: 480 }
    : false,
});

RTCView — rendering video streams

import { RTCView } from 'react-native-webrtc';

// Remote video (full screen)
<RTCView
  streamURL={remoteStream?.toURL()}
  style={styles.remoteVideo}
  objectFit="cover"

/>

// Local preview (small PiP)
<RTCView
  streamURL={localStream?.toURL()}
  style={styles.localVideo}
  objectFit="cover"
  mirror={true}    // mirror front camera (natural feel)
  zOrder={1}       // render above remote video
/>

The VideoCall screen

// app/src/screens/VideoCall.tsx
import { useState, useEffect, useRef } from 'react';
import { View, Text, TouchableOpacity, StyleSheet } from 'react-native';
import { RTCView, MediaStream } from 'react-native-webrtc';
import { TokenPeerConnection } from '../webrtc/PeerConnection';
import { send, subscribe } from '../ws/connection';
import { videoStage } from '../call/videoStage';
import InCallManager from 'react-native-incall-manager';

export function VideoCallScreen({ route, navigation }) {
  const { callId, conversationId, isCaller, tokenLabel } = route.params;
  const [callState, setCallState] = useState('connecting');
  const [everConnected, setEverConnected] = useState(false);
  const [localStream, setLocalStream] = useState<MediaStream | null>(null);
  const [remoteStream, setRemoteStream] = useState<MediaStream | null>(null);
  const [muted, setMuted] = useState(false);
  const [videoOff, setVideoOff] = useState(false);
  const [frontCamera, setFrontCamera] = useState(true);

  // null, not false: the peer has not told us yet. An older client never
  // will, and "unknown" must not render as "camera off".
  const [peerVideoEnabled, setPeerVideoEnabled] = useState<boolean | null>(null);

  const pcRef = useRef<TokenPeerConnection | null>(null);
  const unsubRef = useRef<(() => void) | null>(null);

  useEffect(() => {
    startCall();
    return () => cleanup();
  }, []);

  useEffect(() => {
    if (callState === 'connected') setEverConnected(true);
  }, [callState]);

  const stage = videoStage({
    callState,
    everConnected,
    hasRemoteStream: remoteStream !== null,
    peerVideoEnabled,
    holderName: tokenLabel,
  });

  async function startCall() {
    InCallManager.start({ media: 'video' });

    const pc = new TokenPeerConnection({
      conversationId,
      callId,
      type: 'video',
      isCaller,
      onRemoteStream: (stream) => setRemoteStream(stream),
      onConnectionStateChange: (state) => setCallState(state),
      onHangup: () => navigation.goBack(),
    });

    pcRef.current = pc;
    const stream = await pc.initialize();
    setLocalStream(stream);

    // track.enabled is a LOCAL flag. The peer receives black frames and has
    // no way to tell them from a broken camera, so it has to be told.
    const unsub = subscribe((type, payload) => {
      if (payload.callId !== callId) return;
      if (type === 'call:media') setPeerVideoEnabled(payload.videoEnabled);
    });
    unsubRef.current = unsub;

    if (isCaller) await pc.createOffer();
  }

  function handleMute() {
    const isMuted = pcRef.current?.toggleMute();
    setMuted(isMuted ?? false);
  }

  function handleVideoToggle() {
    const isOff = pcRef.current?.toggleVideo();
    setVideoOff(isOff ?? false);
    // Tell the other side, or they just see a black rectangle.
    send('call:media', { callId, videoEnabled: !isOff });
  }

  function handleCameraFlip() {
    // Only flip the mirror if the camera actually switched. Flipping it
    // regardless mirrors the preview against a camera that never moved.
    if (pcRef.current?.switchCamera()) {
      setFrontCamera(f => !f);
    }
  }

  function handleHangup() {
    pcRef.current?.hangup();
    navigation.goBack();
  }

  function cleanup() {
    unsubRef.current?.();
    pcRef.current?.cleanup();
    InCallManager.stop();
  }

  return (
    <View style={styles.container}>
      {/* Remote video — full screen */}
      {stage.video ? (
        <RTCView
          streamURL={remoteStream!.toURL()}
          style={styles.remoteVideo}
          objectFit="cover"
          zOrder={0}
        />
      ) : (
        <View style={styles.remoteVideo} />
      )}

      {/* The notice sits OVER the video, because during a blip we keep the
          last frame and still have to say why it is frozen. */}
      {stage.notice && (
        <View style={styles.noticeWrap} pointerEvents="none">
          <Text style={styles.connectingText}>{stage.notice}</Text>
        </View>
      )}

      {/* Local preview — PiP */}
      {localStream && !videoOff && (
        <RTCView
          streamURL={localStream.toURL()}
          style={styles.localVideo}
          objectFit="cover"
          mirror={frontCamera}
          zOrder={1}
        />
      )}

      {/* Controls overlay */}
      <View style={styles.controls}>
        <TouchableOpacity
          style={[styles.btn, muted && styles.btnActive]}
          onPress={handleMute}
        >
          <Text style={styles.btnText}>{muted ? 'Unmute' : 'Mute'}</Text>
        </TouchableOpacity>

        <TouchableOpacity
          style={[styles.btn, videoOff && styles.btnActive]}
          onPress={handleVideoToggle}
        >
          <Text style={styles.btnText}>{videoOff ? 'Video On' : 'Video Off'}</Text>
        </TouchableOpacity>

        <TouchableOpacity style={styles.btn} onPress={handleCameraFlip}>
          <Text style={styles.btnText}>Flip</Text>
        </TouchableOpacity>

        <TouchableOpacity style={styles.hangupBtn} onPress={handleHangup}>
          <Text style={styles.hangupText}>End</Text>
        </TouchableOpacity>
      </View>
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, backgroundColor: '#000' },
  remoteVideo: { flex: 1, backgroundColor: '#1e293b', justifyContent: 'center', alignItems: 'center' },
  connectingText: { color: '#94a3b8', fontSize: 16, textAlign: 'center' },
  noticeWrap: {
    position: 'absolute', top: 0, left: 0, right: 0, bottom: 0,
    justifyContent: 'center', alignItems: 'center',
    paddingHorizontal: 32,
  },
  localVideo: {
    position: 'absolute', top: 60, right: 16,
    width: 120, height: 160,
    borderRadius: 12, overflow: 'hidden',
    borderWidth: 2, borderColor: '#fff',
  },
  controls: {
    position: 'absolute', bottom: 40,
    left: 0, right: 0,
    flexDirection: 'row', justifyContent: 'center',
    gap: 16,
  },
  btn: {
    width: 56, height: 56, borderRadius: 28,
    backgroundColor: 'rgba(255,255,255,0.2)',
    justifyContent: 'center', alignItems: 'center',
  },
  btnActive: { backgroundColor: 'rgba(255,255,255,0.4)' },
  btnText: { color: '#fff', fontSize: 10, textAlign: 'center' },
  hangupBtn: {
    width: 56, height: 56, borderRadius: 28,

    justifyContent: 'center', alignItems: 'center',
  },
  hangupText: { color: '#fff', fontSize: 12, fontWeight: '600' },
});

A black rectangle is not a state

The obvious way to decide what fills the screen is whether a remote stream exists:

{remoteStream ? <RTCView … /> : <Text>Connecting…</Text>}   // wrong

A stream object existing is not video arriving. ontrack fires when the track is added during negotiation, which is before a single frame has been decoded. And there is a worse case, which the quiz at the bottom of this page already describes: ask it what the peer sees when you set videoTrack.enabled = false and the answer is a black or frozen frame.

So when the other person turns their camera off, remoteStream is still there, the track is still there, and RTCView faithfully renders black. The user is looking at an unlabelled dark rectangle that is indistinguishable from a dead connection, a camera permission failure, and a phone in someone's pocket.

enabled = false is a local flag, and nothing carries it across

This is the part that surprises people. Muting a track does not send a message — it swaps the frames for empty ones. There is no field on the receiving end that says "the far side turned this off", because at the media layer black frames from a disabled camera and black frames from a camera pointed at a desk are the same bytes.

If you want to show "Priya turned their camera off", you have to send it yourself. Hence call:media carrying { videoEnabled } over the same WebSocket that carried the offer.

That extra message brings the three-state problem with it, and it is the same one a2/0002 met in Partial<T>:

peerVideoEnabledMeansShow
truethey told us it is onthe video
falsethey told us it is offa notice naming them
nullthey have not told usthe video

if (!peerVideoEnabled) collapses the last two, and the last two are opposites. An older client that never sends call:media would have its perfectly good video replaced by "they turned their camera off" for the entire call. Not being told something is not the same as being told no.

Camera switching

react-native-webrtc provides a private _switchCamera() method on video tracks:

function switchCamera(): boolean {
  const videoTrack = localStream?.getVideoTracks()[0];
  if (videoTrack && '_switchCamera' in videoTrack) {
    (videoTrack as any)._switchCamera();
    return true;
  }
  return false;   // no track: nothing switched
}

This toggles between front and back camera without renegotiation. The remote peer sees the switch instantly — no interruption.

Return whether it happened, or the mirror lies

Notice the boolean. The screen keeps its own frontCamera state purely to decide mirror={frontCamera}, and the tempting version is:

pcRef.current?.switchCamera();
setFrontCamera(f => !f);        // flips whatever happened

Both the optional chain and the guard inside switchCamera can decline to do anything — no peer connection yet, or a call with no video track. The state flips anyway, so the preview is now mirrored against a camera that never moved, and every subsequent flip stays inverted. The fix is not to try harder to switch; it is to only record what actually happened.

Same shape as a11/0001, where the row animated away before the revoke request had succeeded. UI state that describes the world must be set from the result, not from the intention.

Video constraints

// Requesting specific resolution:
const stream = await mediaDevices.getUserMedia({
  audio: true,
  video: {
    facingMode: 'user',  // 'user' = front, 'environment' = back
    width: { ideal: 640 },
    height: { ideal: 480 },
    frameRate: { ideal: 30 },
  },
});

// Lower quality for slow connections:
// width: 320, height: 240, frameRate: 15

Adaptive bitrate: WebRTC automatically adjusts video quality based on available bandwidth. You don't need to manually lower resolution — the encoder adapts. But starting with a reasonable constraint (640x480) prevents the initial quality from being unnecessarily high.

Mirror mode for front camera

When using the front camera, your local preview should be mirrored (like looking in a mirror). But the remote peer sees you un-mirrored (correct orientation).

<RTCView
  mirror={frontCamera}  // only mirror when front camera is active
  // ...
/>

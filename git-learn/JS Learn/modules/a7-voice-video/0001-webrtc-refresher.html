WebRTC Refresher + New Signalling

A7 — Lesson 1 of 5 ~55 min
Why this matters for Token

Voice and video calls are the highest-value communication channel in Token. A delivery person needs to ask "which floor?" — a text message takes 30 seconds of back-and-forth, a 5-second call resolves it instantly. WebRTC gives you peer-to-peer calls with no third-party SDK, no per-minute billing, and full control over privacy (relay-only mode hides IPs). This lesson wires the client-side WebRTC to your own signalling server from B6.

The WebRTC stack (refresher)

┌─────────────────────────────────────┐
│         Your Application            │
├─────────────────────────────────────┤
│    RTCPeerConnection API            │
├─────────────────────────────────────┤
│  ICE Agent  │  DTLS  │  SRTP       │
├─────────────┼────────┼─────────────┤
│         UDP / TCP Transport         │
└─────────────────────────────────────┘
  • RTCPeerConnection — the main API. You create one per call.
  • ICE Agent — finds the best network path between peers
  • DTLS — encrypts the connection (like TLS but for UDP)
  • SRTP — encrypts the media (audio/video packets)

Key fact: WebRTC is end-to-end encrypted by default. Not even your TURN server can decrypt the media — it just relays opaque encrypted packets.

RTCPeerConnection lifecycle

// 1. Create the peer connection
// iceTransportPolicy: 'relay' is NOT optional in Token — see the note below.
const pc = new RTCPeerConnection({ iceServers, iceTransportPolicy: 'relay' });

// 2. Get local media (microphone, camera)
const stream = await mediaDevices.getUserMedia({ audio: true, video: false });
stream.getTracks().forEach(track => pc.addTrack(track, stream));

// 3. Create offer (caller) or handle incoming offer (callee)
const offer = await pc.createOffer();
await pc.setLocalDescription(offer);
// Send offer.sdp via signalling

// 4. Receive answer (caller) or create answer (callee)
await pc.setRemoteDescription(new RTCSessionDescription({ type: 'answer', sdp }));

// 5. Exchange ICE candidates
pc.onicecandidate = (event) => {
  if (event.candidate) {
    // Send candidate via signalling
  }
};

// 6. Receive remote stream
pc.ontrack = (event) => {
  // event.streams[0] is the remote audio/video
};

// 7. Hang up
pc.close();

Why every connection above says iceTransportPolicy: 'relay'

Step 5 above — "exchange ICE candidates" — sounds like plumbing. It is not. An ICE candidate is an IP address and a port. Sending candidates to the other side is not a detail of how the connection is made; it is the connection being made, and each side reads the other's addresses in the process.

There are three kinds. host is the device's own address on its network. srflx ("server reflexive") is the public address a STUN server reports seeing. relay is the TURN server's address, standing in for the device. Only the third one keeps the user's address to itself.

So think about who is on the other end of a Token call. Someone redeemed a code — a delivery company, an estate agent, whoever scanned a QR label off a parcel. They are a stranger by design: they know a label and nothing else. On a direct or STUN-assisted path they now also know the user's home IP address, which geolocates to a neighbourhood.

Omitting this one line defeats everything else

The codes are hashed so the database cannot reveal them. The messages are ciphertext the server cannot read. The holder's token carries no identity. And then one srflx candidate hands over an address good enough to find the user's street.

That is why it is not a setting, and why you will not find a toggle for it anywhere in the app. A privacy control the endangered party cannot reach is not a control — and the holder is on a web page with no account and no settings screen. Whatever a toggle said, the product's default behaviour is its real behaviour. See ADR-0008 in the Token repo.

It is not free, and you should know the price before you write it:

  • Every call is relayed, including two people in the same room. There is no fast path any more, and the detour costs latency.
  • Relay bandwidth is the likeliest surprise on the bill. coturn carries the full media stream of every call in both directions, so video is real egress rather than roughly nothing.
  • A coturn outage is a total call outage, not a degraded one. Under the default policy a broken TURN server breaks the hard cases; here it breaks all of them.

Note the consequence for STUN: under this policy it is never used. Its only output is the srflx candidate, which is exactly what we are suppressing — so Token configures no STUN server at all. A STUN entry here would be dead configuration that reads like a fallback.

The PeerConnection wrapper

Wrap the raw API in a class that integrates with your signalling:

// app/src/webrtc/PeerConnection.ts
import {
  RTCPeerConnection,
  RTCSessionDescription,
  RTCIceCandidate,
  mediaDevices,
  MediaStream,
} from 'react-native-webrtc';
import { send, subscribe } from '../ws/connection';
import { getIceServers } from './config';

interface CallOptions {
  conversationId: number;
  callId: string;
  type: 'voice' | 'video';
  isCaller: boolean;
  onRemoteStream: (stream: MediaStream) => void;
  onConnectionStateChange: (state: string) => void;
  onHangup: () => void;
}

// A peer that never sends an offer must not be able to grow the queue for
// ever. Real negotiation produces a couple of dozen candidates at most, and
// under relay-only policy far fewer.
const MAX_PENDING_ICE = 64;

// How long 'disconnected' is allowed to last before we treat it as over.
// ICE recovers from ordinary network blips on its own; hanging up at the
// first sign of one turns a two-second lift-lobby dropout into a lost call.
const DISCONNECT_GRACE_MS = 8000;

export class TokenPeerConnection {
  private pc: RTCPeerConnection | null = null;
  private localStream: MediaStream | null = null;
  private unsubscribe: (() => void) | null = null;
  private options: CallOptions;

  // ICE candidates that arrived before the remote description did.
  private pendingIce: any[] = [];
  private remoteReady = false;
  private disconnectTimer: ReturnType<typeof setTimeout> | null = null;

  constructor(options: CallOptions) {
    this.options = options;
  }

  async initialize() {
    const iceServers = await getIceServers();

    // Relay-only, always. Not a setting, not a parameter of this class.
    // ICE candidates ARE IP addresses: any non-relay path hands the other
    // side the user's home address. See ADR-0008.
    this.pc = new RTCPeerConnection({
      iceServers,
      iceTransportPolicy: 'relay',
    });

    // ICE candidates → send via signalling
    this.pc.onicecandidate = (event) => {
      if (event.candidate) {
        send('call:ice', {
          callId: this.options.callId,
          candidate: event.candidate.toJSON(),
        });
      }
    };

    // Remote media arrives
    this.pc.ontrack = (event) => {
      if (event.streams[0]) {
        this.options.onRemoteStream(event.streams[0]);
      }
    };

    // Connection state monitoring.
    //
    // 'failed' is terminal — ICE has given up and will not retry.
    // 'disconnected' is NOT: it means connectivity checks are currently
    // failing, and ICE reconnects on its own most of the time. Ending the
    // call here would drop every user who walked into a lift.
    this.pc.onconnectionstatechange = () => {
      const state = this.pc!.connectionState;
      this.options.onConnectionStateChange(state);

      if (state === 'disconnected') {
        this.clearDisconnectTimer();
        this.disconnectTimer = setTimeout(() => {
          this.disconnectTimer = null;
          this.options.onHangup();
        }, DISCONNECT_GRACE_MS);
        return;
      }

      // Recovered, or moved on to something terminal — either way the
      // pending hangup no longer applies.
      this.clearDisconnectTimer();

      if (state === 'failed') {
        this.options.onHangup();
      }
    };

    // Get local media
    this.localStream = await mediaDevices.getUserMedia({
      audio: true,
      video: this.options.type === 'video',
    });

    // Add tracks to peer connection
    this.localStream.getTracks().forEach(track => {
      this.pc!.addTrack(track, this.localStream!);
    });

    // Listen for signalling messages
    this.unsubscribe = subscribe((type, payload) => {
      if (payload.callId !== this.options.callId) return;

      switch (type) {
        case 'call:offer':
          this.handleRemoteOffer(payload.sdp);
          break;
        case 'call:answer':
          this.handleRemoteAnswer(payload.sdp);
          break;
        case 'call:ice':
          this.handleRemoteIce(payload.candidate);
          break;
        case 'call:hangup':
          this.options.onHangup();
          break;
      }
    });

    return this.localStream;
  }

  // Caller: create and send offer
  async createOffer() {
    const offer = await this.pc!.createOffer({});
    await this.pc!.setLocalDescription(offer);
    send('call:offer', {
      callId: this.options.callId,
      sdp: offer.sdp,
    });
  }

  // Callee: receive offer, create and send answer
  private async handleRemoteOffer(sdp: string) {
    await this.pc!.setRemoteDescription(
      new RTCSessionDescription({ type: 'offer', sdp })
    );
    this.remoteReady = true;
    await this.flushPendingIce();

    const answer = await this.pc!.createAnswer();
    await this.pc!.setLocalDescription(answer);
    send('call:answer', {
      callId: this.options.callId,
      sdp: answer.sdp,
    });
  }

  // Caller: receive answer
  private async handleRemoteAnswer(sdp: string) {
    await this.pc!.setRemoteDescription(
      new RTCSessionDescription({ type: 'answer', sdp })
    );
    this.remoteReady = true;
    await this.flushPendingIce();
  }

  // Both: receive ICE candidate.
  //
  // Candidates and the offer travel the same signalling channel, and the
  // remote side starts gathering the moment it calls setLocalDescription —
  // so candidates routinely arrive BEFORE the offer they belong to.
  // addIceCandidate() with no remote description throws InvalidStateError.
  // Buffer until there is a description to attach them to.
  private async handleRemoteIce(candidate: any) {
    if (!this.remoteReady) {
      // Bounded: a peer that never sends an offer must not grow this for ever.
      if (this.pendingIce.length < MAX_PENDING_ICE) {
        this.pendingIce.push(candidate);
      }
      return;
    }
    await this.pc!.addIceCandidate(new RTCIceCandidate(candidate));
  }

  private async flushPendingIce() {
    const queued = this.pendingIce;
    this.pendingIce = [];
    for (const candidate of queued) {
      // One bad candidate must not strand the rest of the queue.
      try {
        await this.pc!.addIceCandidate(new RTCIceCandidate(candidate));
      } catch (err) {
        console.warn('[webrtc] dropped a buffered candidate', err);
      }
    }
  }

  // Controls
  toggleMute(): boolean {
    const audioTrack = this.localStream?.getAudioTracks()[0];
    if (audioTrack) {
      audioTrack.enabled = !audioTrack.enabled;
      return !audioTrack.enabled; // true = muted
    }
    return false;
  }

  toggleVideo(): boolean {
    const videoTrack = this.localStream?.getVideoTracks()[0];
    if (videoTrack) {
      videoTrack.enabled = !videoTrack.enabled;
      return !videoTrack.enabled; // true = video off
    }
    return false;
  }

  async switchCamera() {
    const videoTrack = this.localStream?.getVideoTracks()[0];
    if (videoTrack && '_switchCamera' in videoTrack) {
      (videoTrack as any)._switchCamera();
    }
  }

  // Cleanup
  hangup() {
    send('call:hangup', { callId: this.options.callId });
    this.cleanup();
  }

  private clearDisconnectTimer() {
    if (this.disconnectTimer) {
      clearTimeout(this.disconnectTimer);
      this.disconnectTimer = null;
    }
  }

  cleanup() {
    this.clearDisconnectTimer();
    this.localStream?.getTracks().forEach(t => t.stop());
    this.pc?.close();
    this.pc = null;
    this.localStream = null;
    this.pendingIce = [];
    this.remoteReady = false;
    this.unsubscribe?.();
  }

  getLocalStream() {
    return this.localStream;
  }
}

Why the candidates have to be buffered

The step in that class most likely to be written wrong is the smallest one. The obvious version is a single line:

private async handleRemoteIce(candidate: any) {
  await this.pc!.addIceCandidate(new RTCIceCandidate(candidate));   // wrong
}

A candidate has nowhere to go until a remote description exists. addIceCandidate throws InvalidStateError when remoteDescription is null — a candidate describes a route to a peer the connection has not yet been told about.

And they really do arrive first. The remote side begins gathering the instant it calls setLocalDescription, which happens before it sends you the offer, and both travel the same WebSocket. Look again at the subscribe callback: it calls this.handleRemoteOffer(payload.sdp) without awaiting it, so the callback returns immediately and the next frame is dispatched while the offer is still three awaits from being applied. Every call:ice landing in that gap hits a null remote description.

This is a race, so it works on your desk

Two devices on the same Wi-Fi negotiate in a few milliseconds and usually win it. A phone on patchy mobile data does not. The bug ships because the office is the best possible network — and it degrades rather than breaks, so the report is "calls sometimes don't connect", which is the hardest sentence in a bug tracker.

handleRemoteIce is async and called without await, so the InvalidStateError becomes an unhandled promise rejection. Nothing is logged, nothing is thrown to a boundary, and the call simply connects on fewer candidates — or on none.

So the fix is a queue, and it needs a bound. Buffering until a remote description arrives is correct; buffering for ever is a peer you have never authenticated deciding how much memory you use. MAX_PENDING_ICE is deliberately small — relay-only policy produces a handful of candidates, not hundreds.

Note the try/catch around each flushed candidate. Once the queue is draining, one malformed entry must not strand the ones behind it: ICE only needs one pair to work, so discarding a bad candidate and continuing is strictly better than abandoning the rest.

The call flow from the client perspective

Caller side

// 1. User taps "Call" button
send('call:initiate', { conversationId, type: 'voice' });

// 2. Server responds with callId (or busy/unavailable)
// Listen for 'call:incoming' echoed back or a confirmation

// 3. After callee accepts — create PeerConnection and offer
const peerConnection = new TokenPeerConnection({
  conversationId,
  callId,
  type: 'voice',
  isCaller: true,
  onRemoteStream: (stream) => setRemoteStream(stream),
  onConnectionStateChange: (state) => setCallState(state),
  onHangup: () => navigation.goBack(),
});

const localStream = await peerConnection.initialize();
await peerConnection.createOffer();

Callee side

// 1. Receive 'call:incoming' — show ringing UI
// 2. User taps "Accept"
const peerConnection = new TokenPeerConnection({
  conversationId,
  callId,
  type: 'voice',
  isCaller: false,
  onRemoteStream: (stream) => setRemoteStream(stream),
  onConnectionStateChange: (state) => setCallState(state),
  onHangup: () => navigation.goBack(),
});

const localStream = await peerConnection.initialize();
// The offer arrives via signalling → handleRemoteOffer runs automatically
// → creates answer → sends it back → ICE flows → connected!

Connection states

// RTCPeerConnection.connectionState:
'new'           // just created
'connecting'    // ICE + DTLS in progress
'connected'     // media is flowing!
'disconnected'  // temporarily lost (might recover)
'failed'        // ICE failed — call can't connect
'closed'        // pc.close() was called

Show appropriate UI for each state: "Connecting..." spinner, "Connected" (start timer), "Reconnecting..." (brief network blip), "Call Failed" (offer retry or give up).

disconnected is not failed, and treating it as one loses calls

Read the two lines above against each other. failed means ICE has exhausted every candidate pair and stopped — nothing further will happen without a new connection. disconnected means connectivity checks are failing right now, and the ICE agent is still trying; it recovers on its own most of the time.

They are one keystroke apart in a condition and completely different events. if (state === 'disconnected' || state === 'failed') reads as thorough and ends the call every time somebody walks into a lift. That is why the wrapper starts a timer on disconnected and cancels it on any later transition: a blip that resolves in two seconds costs the user a "Reconnecting…" label, and one that lasts past DISCONNECT_GRACE_MS ends the call properly.

Media permissions

import { mediaDevices } from 'react-native-webrtc';
import { PermissionsAndroid, Platform } from 'react-native';

async function requestMediaPermissions(video: boolean): Promise<boolean> {
  if (Platform.OS === 'android') {
    const permissions = [PermissionsAndroid.PERMISSIONS.RECORD_AUDIO];
    if (video) permissions.push(PermissionsAndroid.PERMISSIONS.CAMERA);

    const results = await PermissionsAndroid.requestMultiple(permissions);
    return Object.values(results).every(r => r === 'granted');
  }

  // iOS: permissions are requested automatically by getUserMedia
  // The config plugin strings are shown in the system dialog
  return true;
}

1:1 Voice Call

A7 — Lesson 2 of 5 ~55 min
Why this matters for Token

A voice call is the fastest way for a token holder to reach the issuer. "Which floor are you on?" takes 3 seconds by voice, 30 seconds by text. The call must connect quickly, sound clear, and have simple controls (mute, speaker, hangup). This is the first real use of the WebRTC + signalling infrastructure you've built.

The VoiceCall screen

// app/src/screens/VoiceCall.tsx
import { useState, useEffect, useRef } from 'react';
import { View, Text, TouchableOpacity, StyleSheet } from 'react-native';
import { TokenPeerConnection } from '../webrtc/PeerConnection';
import { InCallManager } from 'react-native-incall-manager';
import { callDisplay } from '../call/callDisplay';

interface VoiceCallProps {
  route: { params: { callId: string; conversationId: number; isCaller: boolean; tokenLabel: string } };
  navigation: any;
}

export function VoiceCallScreen({ route, navigation }: VoiceCallProps) {
  const { callId, conversationId, isCaller, tokenLabel } = route.params;
  const [callState, setCallState] = useState<string>('connecting');
  const [muted, setMuted] = useState(false);
  const [speakerOn, setSpeakerOn] = useState(false);

  // The moment the call first reached 'connected', not a running total.
  const [connectedAt, setConnectedAt] = useState<number | null>(null);
  const [now, setNow] = useState(() => Date.now());

  const pcRef = useRef<TokenPeerConnection | null>(null);
  const timerRef = useRef<ReturnType<typeof setInterval> | null>(null);

  useEffect(() => {
    startCall();
    return () => cleanup();
  }, []);

  // Stamp the start once, the first time we connect. A reconnection after a
  // blip must not restart the clock — it is still the same call.
  useEffect(() => {
    if (callState === 'connected' && connectedAt === null) {
      setConnectedAt(Date.now());
    }
  }, [callState, connectedAt]);

  // The interval only drives a re-render. It does NOT count the seconds —
  // callDisplay subtracts two timestamps, so drift and any gap while the app
  // was backgrounded cost nothing.
  useEffect(() => {
    if (connectedAt === null) return;
    timerRef.current = setInterval(() => setNow(Date.now()), 1000);
    return () => { if (timerRef.current) clearInterval(timerRef.current); };
  }, [connectedAt]);

  const display = callDisplay({ state: callState, connectedAt, endedAt: null }, now);

  async function startCall() {
    InCallManager.start({ media: 'audio' });
    InCallManager.setForceSpeakerphoneOn(false);

    const pc = new TokenPeerConnection({
      conversationId,
      callId,
      type: 'voice',
      isCaller,
      onRemoteStream: () => {},  // audio plays automatically
      onConnectionStateChange: (state) => setCallState(state),
      onHangup: () => navigation.goBack(),
    });

    pcRef.current = pc;
    await pc.initialize();

    if (isCaller) {
      await pc.createOffer();
    }
  }

  function handleMute() {
    const isMuted = pcRef.current?.toggleMute();
    setMuted(isMuted ?? false);
  }

  function handleSpeaker() {
    const newState = !speakerOn;
    InCallManager.setForceSpeakerphoneOn(newState);
    setSpeakerOn(newState);
  }

  function handleHangup() {
    pcRef.current?.hangup();
    navigation.goBack();
  }

  function cleanup() {
    pcRef.current?.cleanup();
    InCallManager.stop();
    if (timerRef.current) clearInterval(timerRef.current);
  }

  return (
    <View style={styles.container}>
      <Text style={styles.label}>{tokenLabel}</Text>

      {/* The clock keeps running through a blip. Losing it would tell the
          user the call they are still on has not started. */}
      <Text style={styles.state}>
        {display.phase === 'connecting' ? 'Connecting...' : display.text}
      </Text>

      {display.phase === 'reconnecting' && (
        <Text style={styles.reconnecting}>Reconnecting...</Text>
      )}

      <View style={styles.controls}>
        <TouchableOpacity
          style={[styles.controlBtn, muted && styles.controlActive]}
          onPress={handleMute}
        >
          <Text style={styles.controlText}>{muted ? 'Unmute' : 'Mute'}</Text>
        </TouchableOpacity>

        <TouchableOpacity style={styles.hangupBtn} onPress={handleHangup}>
          <Text style={styles.hangupText}>End</Text>
        </TouchableOpacity>

        <TouchableOpacity
          style={[styles.controlBtn, speakerOn && styles.controlActive]}
          onPress={handleSpeaker}
        >
          <Text style={styles.controlText}>{speakerOn ? 'Earpiece' : 'Speaker'}</Text>
        </TouchableOpacity>
      </View>
    </View>
  );
}

The call clock is a subtraction, not a counter

The obvious way to show a call duration is to count seconds:

const [duration, setDuration] = useState(0);

setInterval(() => setDuration(d => d + 1), 1000);   // wrong

That is not a measurement of time. It is a count of how many times a callback happened to run, and the two agree only while nothing interferes. setInterval drifts under load — but the real problem is bigger than drift.

A voice call is the screen the user leaves

They put the phone to their ear and the proximity sensor blanks it. They switch to Maps to read out an address. They lock the phone and keep talking. iOS suspends JavaScript timers for a backgrounded app, so the counter stops while the call carries on — and when the user looks again, a fourteen-minute call reads four minutes.

Nothing errors. The audio never stopped. The one number on the screen is simply wrong, and it is wrong by exactly the amount of time the user was not looking, which is the amount they are least able to check.

Record when the call connected and subtract. Then the interval has no arithmetic to get wrong — its only job is to make the component re-render, and a tick it misses costs nothing, because the next one recomputes from the clock.

const seconds = Math.floor((Date.now() - connectedAt) / 1000);

Stamp connectedAt once, the first time the state reaches connected — not on every transition into it. That distinction is what the next section is about.

A whole class of bug goes away with it

Several questions below are about setDuration(d => d + 1) — why the functional updater is required, and what a stale closure does if you write setDuration(duration + 1) instead. Those are real and worth knowing, and they are hazards of accumulating.

setNow(Date.now()) has neither. The new value does not depend on the old one, so there is no previous state to capture and nothing for a stale closure to get wrong. The interval still needs its clearInterval — that one is about the component unmounting, not about arithmetic, and it does not go away.

Worth noticing as a general move: the bug you cannot write is better than the bug you remember not to write.

What the screen says during a blip

0001 gave disconnected a grace period rather than hanging up on it, because ICE usually recovers. That fix created a window this screen did not previously have to render: up to eight seconds in which the call is live, the user is still talking, and callState is not 'connected'.

The original line handled it like this:

{callState === 'connected' ? formatDuration(duration) : 'Connecting...'}

So a call four minutes old displays "Connecting…" and loses its timer. Both halves are wrong in the same direction: it reports that nothing has happened yet, on a call that has been running for minutes. A user who sees it reasonably concludes the call dropped and hangs up — ending a call that was about to recover on its own.

The general shape

A ternary on one state value has room for two answers, and this screen has four: never connected, live, momentarily lost but still counting, and over. When the states outnumber the branches, the extra ones do not disappear — they get silently folded into whichever branch is the fallback, and the fallback is the one nobody chose deliberately.

Same reasoning as a5/0003's badge, which derives five displayed states from three stored ones. Stored state and displayed state are different things.

InCallManager — audio routing

react-native-incall-manager handles platform-specific audio routing during calls:

npx expo install react-native-incall-manager
  • Earpiece vs speaker — routes audio to the ear speaker (phone mode) or the loudspeaker
  • Proximity sensor — turns off the screen when the phone is near your ear (prevents accidental taps)
  • Audio focus — pauses music, takes priority over other audio apps
  • Ringtone/vibration — plays ring sound for incoming calls
import InCallManager from 'react-native-incall-manager';

// Start call audio session
InCallManager.start({ media: 'audio' });

// Route to speaker
InCallManager.setForceSpeakerphoneOn(true);

// Route to earpiece
InCallManager.setForceSpeakerphoneOn(false);

// Enable proximity sensor (screen off when near ear)
InCallManager.setProximity(true);

// Stop — restore normal audio
InCallManager.stop();

Muting — how it works

// Mute = disable the audio track (stop sending audio to the peer)
const audioTrack = localStream.getAudioTracks()[0];
audioTrack.enabled = false;  // muted — peer hears silence
audioTrack.enabled = true;   // unmuted — peer hears you again

Important: enabled = false sends silence frames. The track is still "there" — it's not removed. The peer's connection stays stable. track.stop() would permanently end the track and require renegotiation.

Initiating a call from the message thread

// In MessageThreadScreen — add a call button in the header
function handleVoiceCall() {
  send('call:initiate', { conversationId, type: 'voice' });

  // Listen for the server's response
  const unsub = subscribe((type, payload) => {
    if (type === 'call:accepted') {
      unsub();
      navigation.navigate('VoiceCall', {
        callId: payload.callId,
        conversationId,
        isCaller: true,
        tokenLabel,
      });
    } else if (type === 'call:busy' || type === 'call:unavailable') {
      unsub();
      Alert.alert('Cannot call', payload.reason);
    }
  });
}

Audio & Video Calls · Lesson 2

EAS Build Setup

Custom dev build · EAS CLI · Development client · Config plugins · Build profiles ~40 min Hands-on setup
Why this matters for your WhatsApp clone

Until now, you've been running your app with Expo Go — the purple app you scan a QR code with. Expo Go is convenient but it cannot run native libraries like react-native-webrtc because they include C++ and Objective-C code that needs to be compiled into the app binary. EAS Build creates a custom development build — your own version of Expo Go that includes any native code you need. You still get hot reload, you still use Expo tools, but now WebRTC (and any other native library) works. This is the same build system WhatsApp's team would use — and it's free for personal projects.

1. Expo Go vs Custom Dev Build — what changes

Expo Go Custom Dev Build
How you get it Download from App Store / Play Store Built with eas build command
Native libraries Only pre-included ones Any library you install
Hot reload ✅ Yes ✅ Yes (same experience)
WebRTC ❌ Cannot run ✅ Works perfectly
Build time Instant (pre-built) 5–15 min (cloud build)
Cost Free Free tier: 30 builds/month

Key point: After switching, your daily development workflow is nearly identical — you still write code, save, and see changes instantly. The only difference is you install YOUR app instead of the purple Expo Go app.

2. Install the EAS CLI

The EAS CLI is a command-line tool that triggers cloud builds:

# Install EAS CLI globally
npm install -g eas-cli

# Verify installation
eas --version
# Should print something like: eas-cli/12.x.x

# Log in to your Expo account
eas login
# Enter your expo.dev username and password

If you don't have an Expo account yet, create one free at expo.dev.

3. Configure your project for EAS Build

Run this command in your project folder to generate the eas.json config file:

# In your project root:
eas build:configure

This creates eas.json with three build profiles:

// eas.json
{
  "cli": {
    "version": ">= 12.0.0"
  },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal"
    },
    "preview": {
      "distribution": "internal"
    },
    "production": {}
  }
}

The three profiles:

  • development — includes the dev menu, hot reload, and debug tools. This is what you use daily. developmentClient: true is the magic flag.
  • preview — a test build without dev tools (for sharing with testers)
  • production — the final build you submit to the App Store / Play Store

4. Update app.json for native builds

EAS Build needs a few extra fields in your app.json that Expo Go didn't require:

// app.json
{
  "expo": {
    "name": "WhatsApp Clone",
    "slug": "whatsapp-clone",
    "version": "1.0.0",
    "orientation": "portrait",
    "icon": "./assets/icon.png",
    "splash": {
      "image": "./assets/splash.png",
      "resizeMode": "contain",
      "backgroundColor": "#075E54"
    },
    "ios": {
      "supportsTablet": false,
      "bundleIdentifier": "com.yourname.whatsappclone",
      "infoPlist": {
        "NSCameraUsageDescription": "Required for video calls",
        "NSMicrophoneUsageDescription": "Required for voice and video calls"
      }
    },
    "android": {
      "adaptiveIcon": {
        "foregroundImage": "./assets/adaptive-icon.png",
        "backgroundColor": "#075E54"
      },
      "package": "com.yourname.whatsappclone",
      "permissions": [
        "CAMERA",
        "RECORD_AUDIO",
        "MODIFY_AUDIO_SETTINGS"
      ]
    },
    "plugins": [
      "expo-dev-client"
    ]
  }
}

New fields explained:

  • bundleIdentifier (iOS) / package (Android) — unique app identifier, like a domain in reverse. Replace "yourname" with your actual name.
  • NSCameraUsageDescription / NSMicrophoneUsageDescription — iOS requires explaining WHY you need camera/mic access. These strings appear in the permission dialog.
  • permissions (Android) — declares which hardware features you need.
  • "expo-dev-client" plugin — enables the development client features (hot reload menu, error overlay).

5. Install expo-dev-client

This package enables the development menu in your custom build (the equivalent of shaking your phone in Expo Go):

npx expo install expo-dev-client

After installing, your custom dev build will have:

  • The same reload-on-save you're used to
  • A dev menu (shake phone or 3-finger long press)
  • Error overlays with stack traces
  • The ability to switch between local dev servers

6. Build for Android

Run this command to create your custom Android development build:

# Build Android development APK
eas build --platform android --profile development

What happens:

  1. EAS uploads your project config to Expo's cloud servers
  2. Cloud servers compile your app with all native dependencies (~5–10 min)
  3. You get a download link for an .apk file
  4. Install the APK on your phone (enable "Install unknown apps" in Android settings)
# After build completes, you'll see:
# ✔ Build finished
# 📱 Install: https://expo.dev/artifacts/eas/xxxxx.apk
#
# Download and install on your phone, then start dev server:
npx expo start --dev-client

Important: You only need to rebuild when you add or update a NATIVE library (like react-native-webrtc). For JavaScript changes, hot reload works instantly — same as before.

7. Build for iOS

iOS builds work the same way but require additional setup:

# Build iOS development build
eas build --platform ios --profile development

iOS-specific requirements:

  • Apple Developer account ($99/year) — needed for installing builds on physical iPhones
  • Device registration — EAS will prompt you to register your iPhone's UDID the first time
  • Provisioning profile — EAS creates this automatically (no need to touch Apple's developer portal manually)
# First iOS build — EAS will walk you through:
# 1. "Log in to your Apple Developer account" → enter Apple ID
# 2. "Register your device?" → Yes (scan QR code or enter UDID)
# 3. Build starts in the cloud (~10-15 min for iOS)
# 4. Download link: install via QR code on your iPhone
No Mac needed!

EAS Build runs on Expo's cloud Mac servers. You can build iOS apps from a Windows PC, Linux, or Chromebook — you never need a physical Mac. The $99/year Apple Developer account is the only requirement for iOS.

8. Running your dev build

Once installed on your phone, the workflow changes slightly:

# OLD workflow (Expo Go):
npx expo start
# → Scan QR code with Expo Go app

# NEW workflow (Custom Dev Build):
npx expo start --dev-client
# → Open YOUR app (not Expo Go) → it connects to your dev server automatically

The first launch: When you open your custom build for the first time, it shows a "Development Build" screen with a text field. Enter your computer's local IP (shown in the terminal) or scan the QR code. After the first connection, it remembers your server.

Daily workflow:

  1. Run npx expo start --dev-client in your terminal
  2. Open your app on your phone
  3. It auto-connects and shows your app with hot reload
  4. Edit code → save → see changes instantly (same as before)

9. When to rebuild

You only need to run eas build again when:

  • ✅ You install a new native library (e.g. react-native-webrtc, expo-av first time)
  • ✅ You change app.json fields that affect native code (permissions, plugins, bundle ID)
  • ✅ You update Expo SDK version

You do NOT need to rebuild when:

  • ❌ You change JavaScript/TypeScript code
  • ❌ You add JS-only packages (lodash, date-fns, etc.)
  • ❌ You change styles, components, or screens
  • ❌ You modify Firestore data or add new collections

In practice, you'll rebuild 2–3 times during this module (when we add WebRTC and call-related native packages) and then not again until Module 6.

10. Build for both platforms at once

To save time, you can build both platforms in parallel:

# Build both Android and iOS simultaneously
eas build --platform all --profile development

# This starts two builds in parallel on Expo's cloud
# Android: ~5-10 min
# iOS: ~10-15 min

11. Checking build status

eas build:list

# Check a specific build's status
eas build:view

13. Troubleshooting common issues

Problem Solution
"Build failed: missing bundleIdentifier" Add ios.bundleIdentifier to app.json
Android APK won't install Enable "Install unknown apps" for your browser in Android Settings → Security
iOS build says "No registered devices" Run eas device:create and scan the QR code on your iPhone
App can't find dev server Make sure phone and computer are on the same WiFi network
Build stuck in queue Free tier has a queue — wait 5–10 min. Priority builds available on paid plans.

14. Full setup — complete terminal commands

Here's every command from this lesson in order. Run these in your project folder:

# Step 1: Install EAS CLI (one-time global install)
npm install -g eas-cli

# Step 2: Log in to Expo
eas login

# Step 3: Configure EAS Build in your project
eas build:configure

# Step 4: Install the development client package
npx expo install expo-dev-client

# Step 5: Build for Android (takes ~5-10 min)
eas build --platform android --profile development

# Step 6: After build finishes — download APK and install on phone

# Step 7: Start your dev server
npx expo start --dev-client

# Step 8: Open YOUR app on your phone — it connects and shows your code

# (Optional) Step 9: Build for iOS too
eas build --platform ios --profile development
You're ready for WebRTC

Once your custom dev build is installed and running, you can install any native library and it will work. In the next lesson, we'll install react-native-webrtc and configure camera/microphone permissions — and your custom build will handle it perfectly.

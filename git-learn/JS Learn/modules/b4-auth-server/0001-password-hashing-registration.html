Password Hashing & Registration

B4 — Lesson 1 of 3 ~50 min
Why this matters for Token

Token stores user passwords for login. If a database breach happens (and breaches happen to everyone eventually), those passwords must be unreadable — even to you. Hashing converts passwords into irreversible gibberish. An attacker with your entire database can't reverse a properly hashed password. This is the difference between "users must change their passwords" and "users' bank accounts got drained."

Never store plaintext passwords

// CATASTROPHICALLY WRONG — never do this
INSERT INTO users (email, password) VALUES ('user@example.com', 'MyP@ssw0rd');

// If the database is breached, every user's password is instantly exposed.
// People reuse passwords — their email, bank, and social media accounts are now compromised.

How hashing works

A hash function takes input of any length and produces a fixed-length output that:

  • Is one-way — you can't reverse the hash back to the password
  • Is deterministic — same input always produces same output
  • Is unique — different inputs produce different outputs (collisions are astronomically unlikely)

But plain hashing (SHA-256) isn't enough for passwords. Attackers pre-compute hashes for common passwords (rainbow tables). We need salting and slow hashing.

argon2 — the right tool

Argon2 is the winner of the Password Hashing Competition (2015). It's deliberately slow (prevents brute-force) and uses lots of memory (prevents GPU attacks):

npm install argon2
import argon2 from 'argon2';

// Hash a password (during registration)
const hash = await argon2.hash(password);
// Result: $argon2id$v=19$m=65536,t=3,p=4$randomsalt$longhashvalue

// Verify a password (during login)
const isValid = await argon2.verify(storedHash, attemptedPassword);
// Returns true or false

The hash string contains everything needed to verify: the algorithm, parameters, salt, and hash value. You store the entire string in the database.

Why argon2 and not bcrypt?

Both are good. Argon2 is newer and has memory-hardness (resists GPU attacks better). bcrypt is battle-tested and also fine. For Token, we use argon2 because it's the current recommendation.

The users table (updated for auth)

-- Add password_hash column (migration)
ALTER TABLE users ADD COLUMN password_hash TEXT NOT NULL;
ALTER TABLE users ADD COLUMN email TEXT NOT NULL UNIQUE;

The schema now stores email (for login) and password_hash (the argon2 output). Never name it password — that implies plaintext.

Registration flow

// api/src/routes/auth.ts
import { Router } from 'express';
import argon2 from 'argon2';
import { z } from 'zod';
import { pool } from '../db/pool.js';
import { ApiError } from '../utils/api-error.js';

const router = Router();

const registerSchema = z.object({
  email: z.string().email('Invalid email'),
  password: z.string().min(8, 'Password must be at least 8 characters'),
  displayName: z.string().min(1).max(100),
});

router.post('/register', async (req, res, next) => {
  try {
    const { email, password, displayName } = registerSchema.parse(req.body);

    // Check if email already exists
    const existing = await pool.query(
      'SELECT id FROM users WHERE email = $1', [email]
    );
    if (existing.rows[0]) {
      throw ApiError.conflict('Email already registered');
    }

    // Hash the password (this is deliberately slow — ~200ms)
    const passwordHash = await argon2.hash(password);

    // Insert the user
    const { rows } = await pool.query(
      `INSERT INTO users (email, password_hash, display_name)
       VALUES ($1, $2, $3) RETURNING id, email, display_name, created_at`,
      [email, passwordHash, displayName]
    );

    res.status(201).json({
      data: rows[0],
      success: true,
    });
  } catch (err) { next(err); }
});

export default router;

Login flow

const loginSchema = z.object({
  email: z.string().email(),
  password: z.string().min(1),
});

router.post('/login', async (req, res, next) => {
  try {
    const { email, password } = loginSchema.parse(req.body);

    // Find user by email
    const { rows } = await pool.query(
      'SELECT id, email, display_name, password_hash FROM users WHERE email = $1',
      [email]
    );
    const user = rows[0];

    // Constant-time response: don't reveal whether email exists
    if (!user) {
      throw ApiError.unauthorized('Invalid email or password');
    }

    // Verify password against stored hash
    const valid = await argon2.verify(user.password_hash, password);
    if (!valid) {
      throw ApiError.unauthorized('Invalid email or password');
    }

    // Success — issue tokens (next lesson)
    res.json({
      data: {
        user: { id: user.id, email: user.email, displayName: user.display_name },
        // accessToken and refreshToken will be added in the next lesson
      },
      success: true,
    });
  } catch (err) { next(err); }
});
Security: same error message

The login error always says "Invalid email or password" — never "Email not found" or "Wrong password" separately. If you told an attacker which part was wrong, they could enumerate valid emails (check which ones return "wrong password" vs "not found") and then focus on brute-forcing passwords for known accounts.

Password requirements

Token requires at least 8 characters. Beyond that, avoid complex rules (uppercase + number + symbol) — they don't meaningfully increase security and frustrate users. Long passwords (passphrases) are more secure than short complex ones.

const passwordSchema = z.string()
  .min(8, 'Password must be at least 8 characters')
  .max(128, 'Password too long');  // cap at 128 to prevent DoS via hashing huge strings

The max limit matters: argon2 is deliberately slow. A 10MB password would take minutes to hash, tying up your server. Cap it at 128 characters.

Timing attacks

argon2.verify already handles this, but the concept matters: when comparing secrets, you must use constant-time comparison. If you compared character-by-character and returned early on mismatch, an attacker could time the response and figure out how many characters are correct.

// DON'T compare secrets like this:
if (attempt === secret) { ... }  // returns faster when first chars differ

// argon2.verify does constant-time comparison internally — safe.

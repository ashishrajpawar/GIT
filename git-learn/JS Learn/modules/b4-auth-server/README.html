Auth (Server)

3 lessons Phase 2 — Backend Core
Module goal

Build Token's authentication system from scratch. There are no passwords: you sign in with your phone number and a one-time code, and the device stays signed in until it is revoked. So this module is about hashing an identifier that is small enough to enumerate, issuing and verifying one-time codes without telling strangers who has an account, running sessions that end by revocation rather than by clock, and rate limiting an endpoint where every request spends real money.

Lessons

  1. Phone Sign-up & One-Time Codes — phone_hash with a pepper, OTP issue and verify, the denial oracle, DLT
  2. JWT & Refresh Rotation — access/refresh tokens, rotation, requireAuth middleware, logout
  3. Rate Limiting — three OTP layers, why the per-IP one bounds your SMS bill, trust proxy, CGNAT, IPv6

After this module

You'll have:

  • Phone sign-up with a peppered phone_hash — no email, no password, anywhere
  • One-time codes that are hashed at rest, single-use, expiring, and attempt-capped
  • A sign-in endpoint that answers identically whether or not the number is registered — in body and in timing
  • Sessions that never expire, with rotation, reuse detection, a retry grace window, and a per-device revocation list
  • A requireAuth middleware protecting all token routes
  • Three-layer rate limiting on code requests, and no account lockout — deliberately, because there is no password to brute-force

Phase 2 (Backend Core) is now complete.

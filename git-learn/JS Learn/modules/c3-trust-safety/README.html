Trust, Safety & Abuse

Track C

Phase 3 — 3 lessons  |  after A5, because you cannot moderate a token you have not built yet

Module goal

Token's premise is that strangers can reach you. That is the product, and it is also its largest abuse surface — spam, harassment and token farming are the expected failure mode rather than edge cases.

The usual answer is unavailable. ADR-0002 means the server holds ciphertext, so it cannot scan content, cannot run a classifier, and cannot show a moderator what was reported. This module is how you handle abuse anyway: reports assembled on the one device that can read the message, signals that survive not being able to read anything, and a protective action that does not wait for someone to be awake.

Lessons

  1. Reporting Without Reading — the report is packaged by the reporter's device, and the signature is what turns a claimed author into a known one
  2. The Signals You Have Without the Content — what metadata catches, what it cannot distinguish, and why a 99%-accurate detector still produces a queue that is 99% wrong
  3. Suspension, Reversal, and the Lever the User Already Has — automatic interim suspension, why its reversal rate is published, and revocation as the control that needs no operator at all
The one thing this module will not do

Client-side scanning was considered and rejected — the design where every device checks outgoing content against a policy list before encrypting it. It is surveillance infrastructure running on the user's own hardware, it is trivially bypassed by a modified client, and it inverts the promise the product is sold on.

The cost of rejecting it is stated plainly in ADR-0006 and is not hedged: abuse in message content can never be detected proactively. Only what somebody reports is ever visible. Every design in this module starts from that.

What you'll build

  • screenReport(report, directory, config) — what a submitted report can actually be acted on, given that the author of every message in it is a claim until a signature makes it a fact
  • assessSender(activity, now, policy) — where a sender goes in the review queue and nothing else, with a window that excludes its own boundary and a count of the events a dishonest clock tried to add

Where the rest of this subject lives

This module is the engineering. The policy half — the threat model, the triage matrix, the 24-hour SLA both stores audit, the published contact and the transparency report — is F1/0006, and the decisions behind both are ADR-0006 and ADR-0011 in token/docs/adr/. When they disagree, the ADRs win.

Prerequisites

  • A5 — Core Token Features — revocation is the strongest abuse control the product has, and it has to exist
  • C5 — End-to-End Encryption — the key directory and the signature both come from there

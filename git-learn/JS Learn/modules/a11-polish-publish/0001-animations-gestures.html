Animations & Gestures

A11 — Lesson 1 of 5  |  ~50 min

Why this matters for Token: The user swipes a token card to revoke it. They drag a bottom sheet up to reveal token details. They long-press a conversation to archive it. None of this works without gesture handling, and none of it feels right without running animations on the UI thread at 60 fps. React Native's built-in Animated API runs on the JS thread — one heavy render and the animation stutters. Reanimated runs animations on the native UI thread, completely decoupled from JS.

The Animation Problem in React Native

React Native has two threads that matter for UI:

  • JS thread — runs your component logic, state updates, API calls
  • UI thread — renders native views, handles touch events, paints frames

The built-in Animated API sends animation frame updates from JS → UI via the bridge. If the JS thread is busy (parsing a large JSON response, re-rendering a list), frames get dropped and the animation stutters.

Reanimated compiles animation logic into worklets — small functions that execute directly on the UI thread. The JS thread can be completely blocked and your animations still run at 60 fps.

Installing the Libraries

# In your app/ directory
npx expo install react-native-reanimated react-native-gesture-handler

Add the Reanimated Babel plugin to babel.config.js:

// app/babel.config.js
module.exports = function (api) {
  api.cache(true);
  return {
    presets: ['babel-preset-expo'],
    plugins: ['react-native-reanimated/plugin'], // must be last
  };
};

Wrap your app entry with GestureHandlerRootView:

// app/App.tsx
import { GestureHandlerRootView } from 'react-native-gesture-handler';

export default function App() {
  return (
    <GestureHandlerRootView style={{ flex: 1 }}>
      {/* your navigation and screens */}
    </GestureHandlerRootView>
  );
}

Core Concepts: Shared Values & Animated Styles

Reanimated introduces two key primitives:

useSharedValue

A value that lives on the UI thread. Changing it does not trigger a React re-render.

import { useSharedValue } from 'react-native-reanimated';

const offset = useSharedValue(0);

// On the UI thread, set it directly:
offset.value = 100;

useAnimatedStyle

A hook that returns a style object recalculated on the UI thread whenever a shared value changes:

import Animated, { useAnimatedStyle, useSharedValue } from 'react-native-reanimated';

function FadeBox() {
  const opacity = useSharedValue(1);

  const animatedStyle = useAnimatedStyle(() => ({
    opacity: opacity.value,
  }));

  return <Animated.View style={[styles.box, animatedStyle]} />;
}

Animated.View here is from Reanimated (not the built-in Animated). It knows how to read animated styles from the UI thread.

Timing & Spring Animations

To animate a shared value over time, use withTiming or withSpring:

import { withTiming, withSpring, Easing } from 'react-native-reanimated';

// Timing: fixed duration, specific easing curve
offset.value = withTiming(200, {
  duration: 300,
  easing: Easing.bezier(0.25, 0.1, 0.25, 1),
});

// Spring: physics-based, feels natural for UI interactions
offset.value = withSpring(200, {
  damping: 15,
  stiffness: 120,
});

When to use which:

  • withTiming — fades, colour transitions, progress bars (predictable duration)
  • withSpring — drags, swipes, snapping (physics feel)

Gesture Handler: Pan, Tap, Long Press

The react-native-gesture-handler library replaces React Native's built-in touch system with native-level gesture recognizers.

Gesture object API (v2)

import { Gesture, GestureDetector } from 'react-native-gesture-handler';
import Animated, { useSharedValue, useAnimatedStyle, withSpring } from 'react-native-reanimated';

function DraggableCard() {
  const translateX = useSharedValue(0);
  const translateY = useSharedValue(0);
  const startX = useSharedValue(0);
  const startY = useSharedValue(0);

  const pan = Gesture.Pan()
    .onStart(() => {
      startX.value = translateX.value;
      startY.value = translateY.value;
    })
    .onUpdate((event) => {
      translateX.value = startX.value + event.translationX;
      translateY.value = startY.value + event.translationY;
    })
    .onEnd(() => {
      // Snap back to origin
      translateX.value = withSpring(0);
      translateY.value = withSpring(0);
    });

  const animatedStyle = useAnimatedStyle(() => ({
    transform: [
      { translateX: translateX.value },
      { translateY: translateY.value },
    ],
  }));

  return (
    <GestureDetector gesture={pan}>
      <Animated.View style={[styles.card, animatedStyle]}>
        {/* card content */}
      </Animated.View>
    </GestureDetector>
  );
}

Building: Swipe-to-Revoke

The user swipes a token card left to reveal a revoke action. Swiping past the threshold asks to revoke — read the callout under this block before you decide it should just do it.

// app/src/components/SwipeableTokenCard.tsx
import { Gesture, GestureDetector } from 'react-native-gesture-handler';
import Animated, {
  useSharedValue,
  useAnimatedStyle,
  withSpring,
  withTiming,
  runOnJS,
  interpolate,
  Extrapolation,
} from 'react-native-reanimated';
import { View, Text, StyleSheet, Dimensions } from 'react-native';

const SCREEN_WIDTH = Dimensions.get('window').width;

// A FRACTION of the width, not a pixel count: 137px is 35% of a phone and
// 17% of a tablet, and a swipe control that means different things on
// different devices is a swipe control you cannot tune.
const THRESHOLD = SCREEN_WIDTH * 0.35;
const MIN_FLING_VELOCITY = 800;   // px/s — a flick that never travels far

interface Props {
  tokenId: number;         // NOT the code. GET /tokens returns none (ADR-0007)
  label: string;
  issuedTo?: string;
  onAskRevoke: (tokenId: number) => void;   // ASK, not do -- see the callout
}

export function SwipeableTokenCard({ tokenId, label, issuedTo, onAskRevoke }: Props) {
  const translateX = useSharedValue(0);

  const pan = Gesture.Pan()
    .activeOffsetX([-10, 10])
    .onUpdate((event) => {
      // Only allow left swipe
      translateX.value = Math.min(0, event.translationX);
    })
    .onEnd((event) => {
      // Distance OR a fast flick commits -- but a flick back at the moment
      // of release vetoes either. See swipeOutcome() in the exercise below;
      // this is the same decision, written where it can be tested.
      const travelled = -translateX.value;
      const flickingBack = event.velocityX > MIN_FLING_VELOCITY;
      const flickingAway = -event.velocityX >= MIN_FLING_VELOCITY;
      const commit = !flickingBack && (travelled >= THRESHOLD || flickingAway);

      // The card always returns to rest. It does NOT fly off-screen:
      // nothing has been revoked yet, and a row that has already left the
      // list cannot come back if the user says no -- or if the API fails.
      translateX.value = withSpring(0);

      if (commit) runOnJS(onAskRevoke)(tokenId);
    });

  const cardStyle = useAnimatedStyle(() => ({
    transform: [{ translateX: translateX.value }],
  }));

  const revokeStyle = useAnimatedStyle(() => ({
    // Reanimated requires the INPUT range to be non-decreasing. Writing it
    // as [0, -THRESHOLD] descends, and the result is undefined -- it is not
    // "reversed for you". Put the smaller number first and flip the OUTPUT.
    opacity: interpolate(
      translateX.value,
      [-THRESHOLD, 0],
      [1, 0],
      Extrapolation.CLAMP
    ),
  }));

  return (
    <View style={styles.container}>
      {/* Background revoke action */}
      <Animated.View style={[styles.revokeAction, revokeStyle]}>
        <Text style={styles.revokeText}>Revoke</Text>
      </Animated.View>

      {/* Foreground card */}
      <GestureDetector gesture={pan}>
        <Animated.View style={[styles.card, cardStyle]}>
          <Text style={styles.label}>{label}</Text>
          {issuedTo ? (
            <Text style={styles.issuedTo}>Issued to: {issuedTo}</Text>
          ) : null}
        </Animated.View>
      </GestureDetector>
    </View>
  );
}

// Colours come from useTheme() in the real component -- see 0002, which is
// the next lesson and says nothing visual may be hardcoded. They are
// literals here only so this file reads on its own. In particular
// '#e74c3c' was the old danger red, and it is 3.82:1 against white.
const styles = StyleSheet.create({
  container: {
    marginVertical: 8,
    marginHorizontal: 16,
  },
  revokeAction: {
    ...StyleSheet.absoluteFillObject,
    backgroundColor: '#C0392B',   // colors.danger
    borderRadius: 12,
    justifyContent: 'center',
    alignItems: 'flex-end',
    paddingRight: 24,
  },
  revokeText: {
    color: '#FFFFFF',             // colors.onDanger
    fontWeight: '700',
    fontSize: 16,
  },
  card: {
    backgroundColor: '#FFFFFF',   // colors.cardBackground
    borderRadius: 12,
    padding: 16,
    elevation: 3,
    shadowColor: '#000',
    shadowOffset: { width: 0, height: 2 },
    shadowOpacity: 0.1,
    shadowRadius: 4,
  },
  label: {
    fontSize: 18,
    fontWeight: '600',
  },
  issuedTo: {
    fontSize: 14,
    color: '#5A6268',             // colors.textSecondary
    marginTop: 4,
  },
});

Key details:

  • activeOffsetX([-10, 10]) — prevents accidental swipes; the gesture only activates after 10px of horizontal movement
  • runOnJS(onAskRevoke)(tokenId) — bridges back from the UI thread to the JS thread. Note it carries the id: owner endpoints take :id and the code is never in a URL (ADR-0007)
  • interpolate — maps one range to another (swipe distance → opacity), and its input range must be non-decreasing
  • Extrapolation.CLAMP — prevents values from exceeding the output range
A gesture is not consent, and revoke cannot be undone

This section used to say the token is "revoked immediately with a satisfying animation", and the code fired onRevoke from the end of a pan. Two separate problems, and both matter more here than they would in a mail app.

Revocation is terminal. b2/0001's column comment is revoked_at — "set once, never cleared", and b7/0003 makes revoked a state nothing transitions out of. There is no un-revoke, by design. So an accidental swipe permanently destroys a capability, and on the other end of it a delivery driver's channel goes dead with no way for either party to recover it. An irreversible action reached by a gesture needs a confirmation step, and the reason is not timidity — it is that there is no undo to fall back on. Compare a swipe that archives a conversation, which is why the long-press section further down does not ask.

It also destroyed the row before the work succeeded. The old code animated the card to -SCREEN_WIDTH and called onRevoke from the completion callback. If that request then fails — offline, 500, expired session — the card is gone from the list and the token is still live. The user has been shown the one outcome a security feature must never fake.

Optimistic UI is fine when being wrong is cheap. Here the two failure directions are not symmetric: showing "revoking…" briefly when it succeeded costs a moment, and showing "revoked" when it did not costs the user the thing they came to the app to do. So the card springs back, the screen asks, and the row changes only when the server says it did.

// In the screen, not the card.
const askRevoke = (tokenId: number) => {
  Alert.alert(
    'Revoke this token?',
    'Anyone holding it loses access immediately. This cannot be undone.',
    [
      { text: 'Cancel', style: 'cancel' },
      {
        text: 'Revoke',
        style: 'destructive',
        onPress: async () => {
          try {
            await api.post(`/tokens/${tokenId}/revoke`);
            refresh();                     // the list re-reads the real state
          } catch (err) {
            showError('Could not revoke — the token is still active.');
          }
        },
      },
    ]
  );
};

Note the error message says what is true of the token, not what went wrong with the request. "Network error" leaves the user wondering; "the token is still active" tells them the thing they need to act on.

Bottom Sheet: Token Detail Panel

A bottom sheet is a panel that slides up from the bottom. The user drags it to different snap points. We'll use @gorhom/bottom-sheet which is built on Reanimated and gesture-handler:

# Install
npx expo install @gorhom/bottom-sheet
// app/src/components/TokenDetailSheet.tsx
import BottomSheet, { BottomSheetView } from '@gorhom/bottom-sheet';
import { useCallback, useMemo, useRef } from 'react';
import { Text, View, StyleSheet } from 'react-native';

interface Props {
  tokenId: number;
  label: string;
  issuedTo?: string;
  createdAt: string;
  expiresAt: string | null;
  status: 'active' | 'paused' | 'revoked';
}

export function TokenDetailSheet(props: Props) {
  const sheetRef = useRef<BottomSheet>(null);
  const snapPoints = useMemo(() => ['25%', '60%', '90%'], []);

  // The code is NOT a prop -- the list it came from does not have one.
  // This is the one screen allowed to show it, and only on request, one
  // token at a time, through an endpoint that logs the disclosure.
  const [code, setCode] = useState<string | null>(null);
  const revealCode = async () => {
    const res = await api.post(`/tokens/${props.tokenId}/reveal`);
    setCode(res.data.code);
  };

  const handleSheetChange = useCallback((index: number) => {
    console.log('Sheet snapped to index:', index);
  }, []);

  return (
    <BottomSheet
      ref={sheetRef}
      index={0}
      snapPoints={snapPoints}
      onChange={handleSheetChange}
      enablePanDownToClose
      backgroundStyle={styles.sheetBackground}
      handleIndicatorStyle={styles.indicator}
    >
      <BottomSheetView style={styles.content}>
        <Text style={styles.heading}>{props.label}</Text>
        {code ? (
          <Text style={styles.code}>{code}</Text>
        ) : (
          <Pressable onPress={revealCode}>
            <Text style={styles.reveal}>Show code</Text>
          </Pressable>
        )}
        <View style={styles.row}>
          <Text style={styles.label}>Issued to</Text>
          <Text style={styles.value}>{props.issuedTo ?? '—'}</Text>
        </View>
        <View style={styles.row}>
          <Text style={styles.label}>Status</Text>
          <Text style={[styles.value, styles[props.status]]}>
            {props.status.toUpperCase()}
          </Text>
        </View>
        <View style={styles.row}>
          <Text style={styles.label}>Created</Text>
          <Text style={styles.value}>{props.createdAt}</Text>
        </View>
        <View style={styles.row}>
          <Text style={styles.label}>Expires</Text>
          <Text style={styles.value}>{props.expiresAt ?? 'Never'}</Text>
        </View>
      </BottomSheetView>
    </BottomSheet>
  );
}

Layout Animations: Entering & Exiting

When a token gets revoked, the card should animate out and the remaining cards should smoothly fill the gap. Reanimated provides layout animations for this:

import Animated, { FadeOut, Layout, SlideInRight } from 'react-native-reanimated';

function TokenList({ tokens, onRevoke }) {
  return (
    <View>
      {tokens.map((token) => (
        <Animated.View
          // token.id, not token.code. GET /tokens has no code field, so
          // keying on it gives every row key={undefined} -- React falls
          // back to the array index and the layout animations below stop
          // working: rows get reused across positions, so removing the
          // first item animates the wrong card out.
          key={token.id}
          entering={SlideInRight.duration(300)}
          exiting={FadeOut.duration(200)}
          layout={Layout.springify()}
        >
          <SwipeableTokenCard
            tokenId={token.id}
            label={token.label}
            issuedTo={token.issuedTo}
            onAskRevoke={onAskRevoke}
          />
        </Animated.View>
      ))}
    </View>
  );
}

Layout.springify() animates position changes when items above are removed — the remaining cards spring upward to fill the gap.

An exit animation is a claim. exiting={FadeOut} runs when the item leaves the array, so it fires when the list re-reads from the server and the token is genuinely gone — not when the swipe ends. That ordering is the whole point of the callout above: the row animating away is the app telling the user something happened, and it should not be able to say that before it is true.

Long-press to Archive a Conversation

Combine a long-press gesture with a scale animation for haptic-like feedback:

import { Gesture, GestureDetector } from 'react-native-gesture-handler';
import Animated, { useSharedValue, useAnimatedStyle, withSpring, runOnJS } from 'react-native-reanimated';
import * as Haptics from 'expo-haptics';

function ConversationItem({ conversation, onArchive }) {
  const scale = useSharedValue(1);

  const longPress = Gesture.LongPress()
    .minDuration(500)
    .onStart(() => {
      scale.value = withSpring(0.95);
      runOnJS(Haptics.impactAsync)(Haptics.ImpactFeedbackStyle.Medium);
    })
    .onEnd((_event, success) => {
      scale.value = withSpring(1);
      if (success) {
        runOnJS(onArchive)(conversation.id);
      }
    });

  const animatedStyle = useAnimatedStyle(() => ({
    transform: [{ scale: scale.value }],
  }));

  return (
    <GestureDetector gesture={longPress}>
      <Animated.View style={[styles.conversationCard, animatedStyle]}>
        {/* conversation content */}
      </Animated.View>
    </GestureDetector>
  );
}

Performance Rules

  1. Never read .value in a component body — it bypasses React and won't re-render. Only read inside useAnimatedStyle or worklets.
  2. Keep worklets pure — no API calls, no console.log, no accessing JS-thread closures. Use runOnJS to bridge back.
  3. Avoid useAnimatedStyle in lists of 100+ items — each instance has a UI-thread listener. Use entering/exiting props for list item animations.
  4. Combine gestures with Gesture.Simultaneous() or Gesture.Exclusive() — don't nest GestureDetector components.

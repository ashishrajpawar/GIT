Store Submission

A11 — Lesson 5 of 5  |  ~45 min

Why this matters for Token: This is the finish line. Token is built, tested, deployed. But users can't install it until it's on the Play Store and App Store. The submission process has specific requirements — screenshots, privacy policy, content rating, age declaration — and any mistake means a rejection that costs days. EAS Submit automates the binary upload, but the metadata, compliance, and policy work is on you.

Apple Developer Account Setup

Requirements:

  • Apple Developer Program membership ($99/year)
  • App Store Connect access
  • A registered App ID (created automatically by EAS if you use --auto-submit)

Creating the App in App Store Connect

  1. Go to App Store Connect → My Apps → + New App
  2. Platform: iOS
  3. Name: Token
  4. Primary language: English (India)
  5. Bundle ID: app.tokn.token (must match app.config.js)
  6. SKU: token-ios-v1 (any unique string)

Google Play Console Setup

Requirements:

  • Google Play Developer account ($25 one-time)
  • App created in Google Play Console
  • Upload key configured (EAS manages this for you)

Creating the App in Play Console

  1. Go to Play Console → All apps → Create app
  2. App name: Token
  3. Default language: English (India)
  4. App or game: App
  5. Free or paid: Free
  6. Accept declarations

Building for Production with EAS

# Build both platforms
eas build --profile production --platform all

# Or build separately
eas build --profile production --platform ios
eas build --profile production --platform android

EAS Build:

  • Resolves APP_ENV=production from eas.json
  • Injects EAS Secrets as env vars
  • Compiles native code (WebRTC, secure-store, etc.)
  • Signs the binary (iOS: provisioning profile + certificate; Android: upload key)
  • Returns a download URL for the .ipa / .aab

For iOS, EAS manages certificates and provisioning profiles automatically. On first build, it will prompt you to log in with your Apple Developer credentials.

Submitting with EAS Submit

# Submit the latest production build to both stores
eas submit --platform all --latest

# Or submit a specific build
eas submit --platform ios --id BUILD_ID
eas submit --platform android --id BUILD_ID

For iOS, EAS Submit uses App Store Connect API keys. Set them up once:

# Generate an API key in App Store Connect → Users and Access → Keys
# Download the .p8 file, then:
eas credentials  # follow prompts to add ASC API key

For Android, EAS Submit needs a service account key:

# In Google Cloud Console:
# 1. Create a service account with "Service Account User" role
# 2. Download the JSON key
# 3. In Play Console → Setup → API access → link the service account
# 4. Grant "Release manager" permission

eas credentials  # follow prompts to add the service account JSON

Privacy Policy

Both stores require a privacy policy URL. For Token, it must cover:

  • What data is collected (account email, token metadata, messages)
  • What is NOT collected (contacts, location, browsing history)
  • How messages are stored (encrypted at rest, deleted on token revocation)
  • Third-party services (FCM for push notifications — disclose this)
  • Data retention (messages deleted X days after token revocation)
  • User rights (delete account, export data)
  • DPDP Act 2023 compliance (India's data protection law)

Host at https://tokn.app/privacy — the redemption web app already runs on this domain, so add a /privacy route.

Content Rating & Declarations

Google Play — Content Rating Questionnaire

Answer honestly. For Token:

  • Violence: No
  • Sexual content: No
  • Language: Users can type anything → "Users can exchange unfiltered content"
  • Controlled substances: No
  • Interactive elements: "Users interact" + "Shares location: No" + "Digital purchases: No"

Result: likely PEGI 12 or equivalent (due to unfiltered user communication).

Apple — Age Rating

Similar questionnaire in App Store Connect. Token will likely get 12+ for "Infrequent/Mild Mature/Suggestive Themes" (because users can message freely).

Data Safety (Google Play)

Declare what Token collects:

  • Email address → Account management → Required
  • Messages → App functionality → Required → Encrypted
  • Crash logs → Analytics → Optional
  • Device identifiers (FCM token) → Push notifications → Required

App Privacy (iOS)

Similar to Google's Data Safety. Declare:

  • Contact Info (email) → linked to identity
  • Identifiers (FCM token) → not linked to identity
  • Usage Data (crash logs) → not linked to identity

Post-submission: Updates with EAS Update

Once the app is live, bug fixes don't always need a full store review. EAS Update sends JavaScript-only changes over-the-air (OTA):

# Push a JS-only fix to production users
eas update --branch production --message "Fix token list refresh bug"

What OTA can update: JS code, images, JSON — anything in the JS bundle.

What requires a new build: Native code changes (new native modules, updated native dependencies, changes to app.config.js that affect the binary).

For Token, adding a new chat feature (JS only) → OTA update. Adding a new native payment module → new build + store submission.

The Full Release Flow

1. Code complete → merge to main
2. eas build --profile production --platform all
3. Test the production build on real devices
4. eas submit --platform all --latest
5. Fill metadata in App Store Connect / Play Console
6. Submit for review
7. Wait (Apple: 24–48h, Google: a few hours to 7 days)
8. Approved → goes live
9. Subsequent JS fixes → eas update --branch production

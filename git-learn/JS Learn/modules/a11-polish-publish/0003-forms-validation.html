Forms & Validation

A11 — Lesson 3 of 5  |  ~45 min

Why this matters for Token: Token has forms everywhere — registration, login, creating a token (label, rules, expiry), editing access rules, settings. Right now each form manages its own state with useState, validates inline, and has no connection to the backend's validation. If the server rejects a field the client already accepted, the user sees a confusing "400 Bad Request". By sharing zod schemas between shared/, api/, and app/, validation runs identically on both sides — the client catches the same errors the server would, before the request even fires.

Why Not Just useState for Forms?

A login form with 2 fields is manageable. But Token's "Create Token" form has:

  • Label (required, 3–50 chars)
  • Issued-to name (optional, max 100 chars)
  • Expiry (optional date, must be in the future)
  • Max uses (optional number, 1–1000)
  • Access rules (array of rule objects)
  • Channels allowed (multi-select: chat, voice, video)

With raw useState, you'd have 6+ state variables, 6+ error states, validation logic scattered across handlers, and no way to show errors on blur vs submit. react-hook-form solves all of this with a single hook.

Shared Zod Schemas

// shared/src/schemas/token.ts
import { z } from 'zod';

// A text input that the user left alone gives you '', not undefined.
// Turn it into "absent" ONCE, here, rather than in every consumer.
const optionalText = z
  .string()
  .transform((s) => s.trim())
  .transform((s) => (s === '' ? undefined : s));

export const createTokenSchema = z.object({
  // Trim BEFORE measuring: '   ab   ' is a 2-character label, not an 8.
  label: z
    .string()
    .transform((s) => s.trim())
    .pipe(
      z
        .string()
        .min(3, 'Label must be at least 3 characters')
        .max(50, 'Label must be at most 50 characters')
    ),

  issuedTo: optionalText.pipe(
    z.string().max(100, 'Name too long').optional()
  ),

  // undefined = never expires. NOT '' -- see the callout below.
  expiresAt: optionalText.pipe(
    z
      .string()
      .datetime({ message: 'Pick a date' })
      .refine((d) => new Date(d) > new Date(), 'Expiry must be in the future')
      .optional()
  ),

  // undefined = unlimited. 0 = no uses at all. Both are meaningful and
  // they are opposites, which is why .min(1) was wrong here.
  maxUses: z
    .number()
    .int()
    .min(0, 'Cannot be negative')
    .max(1000, 'Maximum 1000 uses')
    .optional(),

  channels: z
    .array(z.enum(['chat', 'voice', 'video']))
    .min(1, 'Select at least one channel'),
});

export type CreateTokenInput = z.infer<typeof createTokenSchema>;
Three things this schema got wrong, and they are all the same mistake

Until 2026-08-22 the block above said .optional().or(z.literal('')) on two fields and .min(1) on maxUses. Each is a small thing; together they are one habit — treating "the user did not fill this in" as a value rather than as an absence.

  • '' is not a date. .or(z.literal('')) makes the empty string valid, so it passes validation, goes into the request body, and arrives at a TIMESTAMPTZ column. new Date('') is Invalid Date. The field the user deliberately left blank is the one that breaks the insert.
  • '' is not a name either. Same transform on issuedTo stored an empty string where the rest of the system expects null, so issuedTo ?? 'Unnamed' renders nothing rather than the fallback — ?? only catches null and undefined.
  • maxUses: 0 was unreachable. .min(1, 'Must allow at least 1 use') means the form can never produce it. But CLAUDE.md and the CHECK (max_uses >= 0) constraint both say null is unlimited and 0 permits no uses at all — opposite meanings. A schema shared by app/ and api/ that rejects 0 makes half of that convention undefined behaviour: the column allows a state nothing can create, and the day something else writes one, no form can edit it back.

The reason it matters more here than in a component: this schema is imported by the API too. A validation bug in a screen is a bad screen. The same bug in shared/ is the API's definition of a valid token.

This schema is imported by:

  • api/ — validates the request body before inserting into Postgres
  • app/ — validates the form before sending the request

react-hook-form Basics

import { useForm, Controller } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { createTokenSchema, CreateTokenInput } from '@token/shared/schemas/token';

function CreateTokenForm() {
  const {
    control,       // connects inputs to the form
    handleSubmit,  // wraps your submit fn with validation
    formState: { errors, isSubmitting },
  } = useForm<CreateTokenInput>({
    resolver: zodResolver(createTokenSchema),
    defaultValues: {
      label: '',
      issuedTo: '',
      channels: ['chat'],
    },
  });

  const onSubmit = async (data: CreateTokenInput) => {
    // data is already validated — safe to send
    const res = await api.post('/tokens', data);
    // handle response...
  };

  return (/* form JSX */);
}

Key concepts:

  • control — the brain of the form. You pass it to Controller components.
  • resolver — plugs zod (or yup, joi, etc.) into the validation pipeline.
  • errors — an object like { label: { message: "Label must be..." } }
  • handleSubmit — only calls your function if validation passes.

Controller: Connecting React Native Inputs

React Native inputs aren't HTML inputs — they don't have name or onChange. The Controller component bridges the gap:

import { Controller } from 'react-hook-form';
import { View, Text, TextInput } from 'react-native';
import { useTheme } from '../theme/ThemeContext';

interface FormFieldProps {
  control: any;
  name: string;
  label: string;
  placeholder?: string;
  multiline?: boolean;
  keyboardType?: 'default' | 'numeric' | 'email-address';
  error?: { message?: string };
}

export function FormField({ control, name, label, placeholder, multiline, keyboardType, error }: FormFieldProps) {
  const { colors, spacing } = useTheme();

  return (
    <View style={{ marginBottom: spacing.md }}>
      <Text style={{ color: colors.text, fontSize: 14, fontWeight: '600', marginBottom: spacing.xs }}>
        {label}
      </Text>
      <Controller
        control={control}
        name={name}
        render={({ field: { onChange, onBlur, value } }) => (
          <TextInput
            value={value}
            onChangeText={onChange}
            onBlur={onBlur}
            placeholder={placeholder}
            placeholderTextColor={colors.textMuted}
            multiline={multiline}
            keyboardType={keyboardType}
            style={{
              backgroundColor: colors.inputBackground,
              borderWidth: 1,
              borderColor: error ? colors.danger : colors.border,
              borderRadius: 8,
              padding: spacing.sm + 4,
              color: colors.text,
              fontSize: 16,
            }}
          />
        )}
      />
      {error?.message && (
        <Text style={{ color: colors.danger, fontSize: 12, marginTop: spacing.xs }}>
          {error.message}
        </Text>
      )}
    </View>
  );
}

The Complete Create Token Form

// app/src/screens/CreateTokenScreen.tsx
import { View, Text, Pressable, ScrollView, Switch } from 'react-native';
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { createTokenSchema, CreateTokenInput } from '@token/shared/schemas/token';
import { FormField } from '../components/FormField';
import { useTheme } from '../theme/ThemeContext';
import { useAuth } from '../auth/AuthContext';
import { api } from '../api/client';

const CHANNEL_OPTIONS = ['chat', 'voice', 'video'] as const;

export function CreateTokenScreen({ navigation }) {
  const { colors, spacing } = useTheme();
  const { token: authToken } = useAuth();

  const {
    control,
    handleSubmit,
    setValue,
    watch,
    formState: { errors, isSubmitting },
  } = useForm<CreateTokenInput>({
    resolver: zodResolver(createTokenSchema),
    defaultValues: {
      label: '',
      issuedTo: '',
      channels: ['chat'],
    },
  });

  const selectedChannels = watch('channels');

  const toggleChannel = (channel: typeof CHANNEL_OPTIONS[number]) => {
    const current = selectedChannels || [];
    if (current.includes(channel)) {
      setValue('channels', current.filter((c) => c !== channel), { shouldValidate: true });
    } else {
      setValue('channels', [...current, channel], { shouldValidate: true });
    }
  };

  const onSubmit = async (data: CreateTokenInput) => {
    try {
      const res = await api.post('/tokens', data, {
        headers: { Authorization: \`Bearer \${authToken}\` },
      });
      navigation.navigate('TokenDetail', { tokenCode: res.data.code });
    } catch (err: any) {
      // Server-side validation error (shouldn't happen if schemas match)
      alert(err.response?.data?.message || 'Failed to create token');
    }
  };

  return (
    <ScrollView style={{ flex: 1, backgroundColor: colors.background }}>
      <View style={{ padding: spacing.lg }}>
        <FormField
          control={control}
          name="label"
          label="Token Label"
          placeholder="e.g. Delivery driver, Job application"
          error={errors.label}
        />

        <FormField
          control={control}
          name="issuedTo"
          label="Issued To (optional)"
          placeholder="e.g. Swiggy, HR person"
          error={errors.issuedTo}
        />

        <FormField
          control={control}
          name="maxUses"
          label="Max Uses (optional)"
          placeholder="Leave blank for unlimited"
          keyboardType="numeric"
          error={errors.maxUses}
        />

        {/* Channel multi-select */}
        <Text style={{ color: colors.text, fontSize: 14, fontWeight: '600', marginBottom: spacing.xs }}>
          Allowed Channels
        </Text>
        <View style={{ flexDirection: 'row', gap: spacing.sm, marginBottom: spacing.md }}>
          {CHANNEL_OPTIONS.map((ch) => {
            const active = selectedChannels?.includes(ch);
            return (
              <Pressable
                key={ch}
                onPress={() => toggleChannel(ch)}
                style={{
                  paddingVertical: spacing.sm,
                  paddingHorizontal: spacing.md,
                  borderRadius: 20,
                  backgroundColor: active ? colors.primary : colors.surface,
                  borderWidth: 1,
                  borderColor: active ? colors.primary : colors.border,
                }}
              >
                <Text style={{ color: active ? '#fff' : colors.text, fontWeight: '600' }}>
                  {ch.charAt(0).toUpperCase() + ch.slice(1)}
                </Text>
              </Pressable>
            );
          })}
        </View>
        {errors.channels && (
          <Text style={{ color: colors.danger, fontSize: 12, marginBottom: spacing.md }}>
            {errors.channels.message}
          </Text>
        )}

        {/* Submit */}
        <Pressable
          onPress={handleSubmit(onSubmit)}
          disabled={isSubmitting}
          style={{
            backgroundColor: isSubmitting ? colors.textMuted : colors.primary,
            padding: spacing.md,
            borderRadius: 12,
            alignItems: 'center',
            marginTop: spacing.lg,
          }}
        >
          <Text style={{ color: '#fff', fontSize: 16, fontWeight: '700' }}>
            {isSubmitting ? 'Creating...' : 'Create Token'}
          </Text>
        </Pressable>
      </View>
    </ScrollView>
  );
}

Handling Server-Side Errors

Even with shared schemas, the server might reject for reasons the client can't know (duplicate label, rate limit). Map server errors back to the form:

import { useForm } from 'react-hook-form';

const { setError } = useForm(/* ... */);

const onSubmit = async (data: CreateTokenInput) => {
  try {
    await api.post('/tokens', data);
  } catch (err: any) {
    const serverErrors = err.response?.data?.errors;
    if (serverErrors) {
      // serverErrors: { label: "Already exists", ... }
      Object.entries(serverErrors).forEach(([field, message]) => {
        setError(field as keyof CreateTokenInput, {
          type: 'server',
          message: message as string,
        });
      });
    }
  }
};

Validation Timing: When Errors Appear

react-hook-form supports multiple validation modes:

onTouchedFirst blur, then onChangeBest UX for most forms

  mode: 'onTouched', // recommended for Token forms
});

Reusable Form Patterns

Number fields (maxUses)

TextInput always gives you a string. Transform it — but read the callout under this block before copying the obvious version.

<Controller
  control={control}
  name="maxUses"
  render={({ field: { onChange, value } }) => (
    <TextInput
      keyboardType="numeric"
      // value === 0 must render as "0", so ?? and not ||
      value={value?.toString() ?? ''}
      onChangeText={(text) => {
        const trimmed = text.trim();

        // Blank means "unlimited" -- an absence, deliberately chosen.
        if (trimmed === '') return onChange(undefined);

        // Number(), not parseInt(): parseInt('7x') is 7 and parseInt('1e3')
        // is 1. It reads a PREFIX and discards the rest, silently.
        const num = Number(trimmed);

        // Anything that is not a clean number stays as the raw string, so
        // the resolver reports "Expected number" and the user sees an
        // error. Do NOT map it to undefined -- see below.
        onChange(Number.isInteger(num) ? num : trimmed);
      }}
    />
  )}
/>
A typo must not become an unlimited token

The version this lesson shipped was:

const num = parseInt(text, 10);
onChange(isNaN(num) ? undefined : num);

It looks like careful defensive coding, and it hands the form's most dangerous value to anyone who fumbles a keystroke. undefined is not "invalid" — on an .optional() field it means absent, and absent on maxUses means unlimited. So typing 3 and then hitting a letter clears the field to undefined, validation passes cleanly, and the user issues a token with no use limit believing they set one.

Nothing anywhere reports this. The form is valid, the request is valid, the row is valid. The only trace is a token that keeps working after the third use.

And parseInt is the quieter half: it parses a prefix. parseInt('7x') is 7 and parseInt('1e3') is 1, both without complaint. Number() refuses the whole string, which is what you want from something guarding a limit.

The general rule, and it has now come up in four lessons: when a value cannot be understood, refuse it — do not substitute a default. The substituted default is always the permissive one, because the permissive one is what "no opinion" looks like. Same shape as b7/0002's unknown rule type falling through to allowed.

Date fields (expiresAt)

import DateTimePicker from '@react-native-community/datetimepicker';

<Controller
  control={control}
  name="expiresAt"
  render={({ field: { onChange, value } }) => (
    <DateTimePicker
      value={value ? new Date(value) : new Date()}
      mode="datetime"
      minimumDate={new Date()}
      onChange={(_, date) => {
        if (date) onChange(date.toISOString());
      }}
    />
  )}
/>

Try it yourself — this one is broken on purpose

The parseInt handler the lesson used to ship, run over what a user actually types. Every line prints what would reach the API. Read the output before you read the callout above again, and fix the handler so that a typo is an error rather than a limit.

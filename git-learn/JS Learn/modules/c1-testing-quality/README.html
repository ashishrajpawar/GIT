Testing & Quality

Track C

Phase 3 — 5 lessons  |  after B3, because you test the API as it is built

Module goal

Token has a set of promises that cannot be checked by looking at the screen. A revoked token and a token that never existed must produce identical responses. A redemption must be counted exactly once even when two requests arrive together. A rule the engine does not recognise must be refused rather than permitted. A paused token at its use limit must report the state the user can actually clear.

Every one of those is a sentence, and every one of them is one assertion. This module is about writing them down — and about the much harder second question, which is knowing which sentences are worth writing.

Lessons

  1. What a Test Is — arrange, act, assert; node:test and why assert/strict; and the runner you build, whose first requirement is surviving a test that explodes
  2. Time, Randomness and Fakes — the clock, the byte source and the network; and how owning the randomness is what makes the modulo bias in the code generator testable at all
  3. Testing an HTTP Handler — without a network, a port or a running server; the five denials that must be one denial; and which differences are safe to expose
  4. Testing Against Real Postgres — why a mock cannot see the LEFT JOIN bug, the transaction that makes every test start from the same place, and fixtures that share an array
  5. What to Test — the coverage number that lies, and the invariants this course has already had to fight

What you'll build

  • runTests(tests) — a test runner that reports names and reasons, keeps its order, and cannot be silenced by one exploding test
  • isExpired(token, now) — four lines, one of which is the guard that stops a token which never expires from reporting as expired in 1970
  • makeCodeGenerator(nextByte) — the real token generator, with rejection sampling, and a test that proves the modulo bias is gone by asserting the distribution exactly rather than statistically
  • handleRedeem(req, deps) — the endpoint a stranger reaches, as a plain function, with the five ways of being dead collapsed into one indistinguishable answer in both the response and the log
  • rowsToToken(rows) — the half of a query that needs no database, and the place the LEFT JOIN decision is finally interpreted: no rows means no token, one null row means a token with no rules, and those are not the same answer
Why this module comes after B3 and not at the end

“Write the tests afterwards” fails for a reason that has nothing to do with discipline: code written without tests is usually shaped so that testing it is expensive. A handler that reads the clock, opens its own database connection and calls the SMS vendor cannot be tested without a clock, a database and an SMS vendor.

The same handler, written to receive those three things, is a function you can call with whatever you like. That shape is not a testing technique — it is a design that testing forces on you early and cannot retrofit later.

Prerequisites

  • Module 01 — JavaScript Fundamentals — the exercises are plain functions, objects and early returns
  • B3 — Node & HTTP Server — there has to be an API before there is anything to test

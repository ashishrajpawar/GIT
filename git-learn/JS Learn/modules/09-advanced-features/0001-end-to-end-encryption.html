Advanced Features · Lesson 1

End-to-End Encryption

Key exchange · Encrypt/decrypt · Secure storage · Verification UI ~75 min Hands-on
Why this matters for your WhatsApp clone

When Priya sends "I love you" to Rahul, that message passes through Firebase servers. Without encryption, anyone at Google (or any hacker who breaches Firebase) can read it. End-to-end encryption (E2E) means the message is scrambled before it leaves Priya's phone and only Rahul's phone can unscramble it. Not even you — the app developer — can read it. This is exactly how real WhatsApp works, and it's what users expect from a messaging app in 2026.

1. How end-to-end encryption works (the big picture)

Here's the flow in plain English:

  1. Key generation: When Priya installs the app, her phone generates a key pair — a public key (she shares with everyone) and a private key (never leaves her phone).
  2. Key exchange: When Priya wants to message Rahul, her app fetches Rahul's public key from Firebase.
  3. Shared secret: Priya's phone combines her private key + Rahul's public key to produce a shared secret (a password only they know). Rahul's phone does the same math: his private key + Priya's public key = the same shared secret. This is called Diffie-Hellman key exchange.
  4. Encrypt: Priya's app uses the shared secret to scramble the message text into unreadable gibberish (ciphertext).
  5. Send: The ciphertext goes to Firebase. Firebase stores garbage — it can't read the message.
  6. Decrypt: Rahul's app uses the same shared secret to unscramble the ciphertext back into "I love you".
// Simplified flow:
// Priya's phone:
//   privateKeyPriya + publicKeyRahul → sharedSecret
//   encrypt("I love you", sharedSecret) → "a7f2c9b1e3..."
//
// Firebase stores: "a7f2c9b1e3..." (meaningless)
//
// Rahul's phone:
//   privateKeyRahul + publicKeyPriya → sharedSecret (same!)
//   decrypt("a7f2c9b1e3...", sharedSecret) → "I love you"

Key terminology

TermWhat it means

3. Generating and storing keys

When a user signs up (or installs the app fresh), we generate their key pair and store the private key securely.

// crypto/keys.js — Key generation and secure storage

import * as SecureStore from 'expo-secure-store';
import * as Crypto from 'expo-crypto';
import { x25519 } from '@noble/curves/ed25519';
import { bytesToHex, hexToBytes } from '@noble/curves/abstract/utils';

// Generate a new key pair for this user
export async function generateKeyPair() {
  // 1. Generate 32 random bytes as the private key
  const randomBytes = await Crypto.getRandomBytesAsync(32);
  const privateKey = new Uint8Array(randomBytes);

  // 2. Derive the public key from the private key (math — not reversible)
  const publicKey = x25519.getPublicKey(privateKey);

  // 3. Store the private key in secure hardware
  await SecureStore.setItemAsync(
    'e2e_private_key',
    bytesToHex(privateKey)
  );

  // 4. Return the public key (to upload to Firebase)
  return bytesToHex(publicKey);
}

// Retrieve the private key from secure storage
export async function getPrivateKey() {
  const hex = await SecureStore.getItemAsync('e2e_private_key');
  if (!hex) return null;
  return hexToBytes(hex);
}

// Check if we already have a key pair
export async function hasKeyPair() {
  const key = await SecureStore.getItemAsync('e2e_private_key');
  return key !== null;
}

Why expo-secure-store?

  • iOS: Stores in the Keychain — backed by the Secure Enclave (hardware chip). Even if someone jailbreaks the phone, they can't extract it.
  • Android: Stores in the Android Keystore — hardware-backed on modern phones. Protected by the device lock screen.
  • Not AsyncStorage! AsyncStorage is plain text on disk. Anyone with USB access could read it.

4. Publishing your public key to Firebase

After generating keys, upload the public key so other users can encrypt messages to you.

// crypto/publishKey.js — Upload public key to Firestore

import { doc, setDoc } from 'firebase/firestore';
import { db, auth } from '../firebaseConfig';
import { generateKeyPair, hasKeyPair } from './keys';

// Call this once after registration or first app launch
export async function ensureKeysExist() {
  // Don't regenerate if keys already exist
  if (await hasKeyPair()) {
    console.log('Key pair already exists');
    return;
  }

  // Generate new key pair
  const publicKeyHex = await generateKeyPair();

  // Store public key in Firestore (anyone can read this)
  const userId = auth.currentUser.uid;
  await setDoc(doc(db, 'publicKeys', userId), {
    publicKey: publicKeyHex,
    createdAt: new Date().toISOString(),
    // Device identifier — useful if user has multiple devices later
    deviceId: `${userId}-primary`,
  });

  console.log('E2E keys generated and published');
}

5. Deriving the shared secret

When Priya wants to message Rahul, her app computes a shared secret from her private key and Rahul's public key.

// crypto/sharedSecret.js — Derive shared secrets for conversations

import { doc, getDoc } from 'firebase/firestore';
import { x25519 } from '@noble/curves/ed25519';
import { hexToBytes, bytesToHex } from '@noble/curves/abstract/utils';
import { db } from '../firebaseConfig';
import { getPrivateKey } from './keys';

// Cache shared secrets in memory (they don't change per conversation)
const secretCache = new Map();

// Get the shared secret for a conversation with another user
export async function getSharedSecret(otherUserId) {
  // Check cache first (avoid re-computing)
  if (secretCache.has(otherUserId)) {
    return secretCache.get(otherUserId);
  }

  // 1. Get my private key from secure storage
  const myPrivateKey = await getPrivateKey();
  if (!myPrivateKey) {
    throw new Error('No private key found — call ensureKeysExist() first');
  }

  // 2. Fetch the other user's public key from Firestore
  const keyDoc = await getDoc(doc(db, 'publicKeys', otherUserId));
  if (!keyDoc.exists()) {
    throw new Error(`No public key found for user ${otherUserId}`);
  }
  const otherPublicKey = hexToBytes(keyDoc.data().publicKey);

  // 3. Compute the shared secret using ECDH
  //    myPrivate + theirPublic = sharedSecret
  //    theirPrivate + myPublic = same sharedSecret!
  const sharedSecret = x25519.getSharedSecret(myPrivateKey, otherPublicKey);

  // 4. Cache it for this session
  secretCache.set(otherUserId, sharedSecret);

  return sharedSecret;
}
The magic of Diffie-Hellman

The shared secret is never sent over the network. Priya computes it locally. Rahul computes the exact same value locally. Firebase never sees it. Even if someone intercepts both public keys, they still can't compute the shared secret without one of the private keys. This is the mathematical foundation that makes E2E encryption possible.

6. Encrypting and decrypting messages

Now we use the shared secret to encrypt (before sending) and decrypt (after receiving) message text.

// crypto/messageCrypto.js — Encrypt and decrypt message text

import { gcm } from '@noble/ciphers/aes';
import { randomBytes } from '@noble/ciphers/webcrypto';
import { bytesToHex, hexToBytes } from '@noble/curves/abstract/utils';
import { getSharedSecret } from './sharedSecret';

// Encrypt a message before sending to Firebase
export async function encryptMessage(plaintext, otherUserId) {
  // 1. Get the shared secret for this conversation
  const sharedSecret = await getSharedSecret(otherUserId);

  // 2. Generate a random 12-byte nonce (IV) — unique per message
  //    This ensures the same message text produces different ciphertext each time
  const nonce = randomBytes(12);

  // 3. Encrypt using AES-256-GCM
  //    GCM provides both encryption AND authentication
  //    (tampered ciphertext will fail to decrypt)
  const textBytes = new TextEncoder().encode(plaintext);
  const cipher = gcm(sharedSecret, nonce);
  const ciphertext = cipher.encrypt(textBytes);

  // 4. Return nonce + ciphertext as a single hex string
  //    We need the nonce to decrypt later, so we prepend it
  const combined = new Uint8Array(nonce.length + ciphertext.length);
  combined.set(nonce);
  combined.set(ciphertext, nonce.length);

  return bytesToHex(combined);
}

// Decrypt a message received from Firebase
export async function decryptMessage(encryptedHex, otherUserId) {
  // 1. Get the shared secret for this conversation
  const sharedSecret = await getSharedSecret(otherUserId);

  // 2. Split the hex string back into nonce + ciphertext
  const combined = hexToBytes(encryptedHex);
  const nonce = combined.slice(0, 12);
  const ciphertext = combined.slice(12);

  // 3. Decrypt using AES-256-GCM
  const cipher = gcm(sharedSecret, nonce);
  const plainBytes = cipher.decrypt(ciphertext);

  // 4. Convert bytes back to text
  return new TextDecoder().decode(plainBytes);
}

Why AES-GCM?

  • AES-256 — the same encryption used by governments and banks. Unbreakable with current technology.
  • GCM mode — provides authenticated encryption. If anyone tampers with the ciphertext in Firebase, decryption will throw an error instead of returning garbage. You'll know someone messed with the data.
  • Random nonce — ensures "Hello" encrypted twice produces completely different ciphertext. Without this, an attacker could detect repeated messages.

7. Integrating encryption into your message sending flow

Now we modify the existing sendMessage function to encrypt before storing in Firebase, and decrypt when reading.

// Updated sendMessage — now with encryption
import { writeBatch, doc, collection, serverTimestamp }
  from 'firebase/firestore';
import { db, auth } from '../firebaseConfig';
import { encryptMessage } from '../crypto/messageCrypto';

export async function sendEncryptedMessage(chatId, plaintext, recipientUserId) {
  const userId = auth.currentUser.uid;
  const trimmed = plaintext.trim();

  if (trimmed.length === 0 || trimmed.length > 4096) {
    throw new Error('Message must be 1–4096 characters');
  }

  // Encrypt the message text BEFORE sending to Firebase
  const encryptedText = await encryptMessage(trimmed, recipientUserId);

  const batch = writeBatch(db);

  const msgRef = doc(collection(db, 'chats', chatId, 'messages'));
  batch.set(msgRef, {
    senderId: userId,
    // Store encrypted text instead of plaintext!
    text: encryptedText,
    // Flag so the app knows to decrypt
    encrypted: true,
    createdAt: serverTimestamp(),
  });

  // Update rate limit
  const rateLimitRef = doc(db, 'rateLimits', userId);
  batch.set(rateLimitRef, { lastWrite: serverTimestamp() });

  // Update chat preview (store first few chars of PLAIN text for sender's preview)
  // Note: the preview is NOT encrypted — acceptable trade-off for UX
  // WhatsApp does the same: notification previews are decrypted on-device
  const chatRef = doc(db, 'chats', chatId);
  batch.update(chatRef, {
    lastMessage: trimmed.substring(0, 50),
    lastMessageAt: serverTimestamp(),
  });

  await batch.commit();
}
// Decrypting messages when they arrive from the real-time listener
import { decryptMessage } from '../crypto/messageCrypto';

// Inside your useEffect listener:
const processMessages = async (snapshot) => {
  const msgs = await Promise.all(
    snapshot.docs.map(async (msgDoc) => {
      const data = msgDoc.data();
      let displayText = data.text;

      // If the message is encrypted, decrypt it
      if (data.encrypted) {
        try {
          // The "other user" is whoever DIDN'T send the message
          const otherUserId = data.senderId === auth.currentUser.uid
            ? recipientUserId  // I sent it — decrypt with recipient's key
            : data.senderId;   // They sent it — decrypt with sender's key

          displayText = await decryptMessage(data.text, otherUserId);
        } catch (err) {
          displayText = '🔒 Unable to decrypt message';
          console.error('Decryption failed:', err);
        }
      }

      return {
        id: msgDoc.id,
        ...data,
        text: displayText,
      };
    })
  );

  setMessages(msgs);
};

Important detail: who do I derive the key with?

Whether you're the sender or the receiver, you always derive the shared secret with the other person in the chat. The shared secret is the same both ways:

  • Priya sending to Rahul: getSharedSecret('rahul456')
  • Rahul receiving from Priya: getSharedSecret('priya123')
  • Both produce the same shared secret — so both can encrypt and decrypt.

9. Key verification between users

How does Rahul know the public key in Firebase really belongs to Priya? What if an attacker replaced it? WhatsApp solves this with a security code — a number that both users can compare in person or over a phone call.

// crypto/verification.js — Generate a security code for two users

import { sha256 } from '@noble/hashes/sha256';
import { bytesToHex, hexToBytes } from '@noble/curves/abstract/utils';
import { doc, getDoc } from 'firebase/firestore';
import { db, auth } from '../firebaseConfig';

// Generate a 60-digit security code for a conversation
// Both users will see the same code (it's symmetric)
export async function getSecurityCode(otherUserId) {
  const myUserId = auth.currentUser.uid;

  // Fetch both public keys
  const myKeyDoc = await getDoc(doc(db, 'publicKeys', myUserId));
  const otherKeyDoc = await getDoc(doc(db, 'publicKeys', otherUserId));

  if (!myKeyDoc.exists() || !otherKeyDoc.exists()) {
    throw new Error('Both users must have public keys');
  }

  const myKey = myKeyDoc.data().publicKey;
  const otherKey = otherKeyDoc.data().publicKey;

  // Sort keys so both users produce the same hash
  // (Priya+Rahul and Rahul+Priya must give same result)
  const sorted = [myKey, otherKey].sort();
  const combined = sorted[0] + sorted[1];

  // Hash the combined keys to produce the security code
  const hash = sha256(new TextEncoder().encode(combined));
  const hashHex = bytesToHex(hash);

  // Convert to 60 digits (groups of 5 for readability)
  const digits = hashHex
    .replace(/[a-f]/g, '')    // Keep only digits
    .padEnd(60, '0')          // Ensure 60 chars
    .substring(0, 60);

  // Format as 12 groups of 5: "12345 67890 12345..."
  return digits.match(/.{5}/g).join(' ');
}

async function generateKeyPair() {

// ─── Crypto: Shared Secret ───────────────────────────

const secretCache = new Map();

async function getSharedSecret(otherUserId) {

// ─── Crypto: Encrypt / Decrypt ───────────────────────

async function encryptText(plaintext, otherUserId) {
  const secret = await getSharedSecret(otherUserId);
  const nonce = randomBytes(12);
  const textBytes = new TextEncoder().encode(plaintext);
  const cipher = gcm(secret, nonce);
  const ciphertext = cipher.encrypt(textBytes);

  const combined = new Uint8Array(12 + ciphertext.length);
  combined.set(nonce);
  combined.set(ciphertext, 12);
  return bytesToHex(combined);
}

async function decryptText(encryptedHex, otherUserId) {
  const secret = await getSharedSecret(otherUserId);
  const combined = hexToBytes(encryptedHex);
  const nonce = combined.slice(0, 12);
  const ciphertext = combined.slice(12);
  const cipher = gcm(secret, nonce);
  const plainBytes = cipher.decrypt(ciphertext);
  return new TextDecoder().decode(plainBytes);
}

// ─── Crypto: Security Code ───────────────────────────

        createdAt: serverTimestamp(),
      });

      const rateLimitRef = doc(db, 'rateLimits', auth.currentUser.uid);
      batch.set(rateLimitRef, { lastWrite: serverTimestamp() });

      await batch.commit();
      setInput('');
    } catch (error) {
      Alert.alert('Send failed', error.message);
    } finally {
      setSending(false);
    }
  };

  const userId = auth.currentUser?.uid;

  const renderMessage = ({ item }) => {
    const isMine = item.senderId === userId;
    return (
      <View style={[styles.bubble, isMine ? styles.myBubble : styles.theirBubble]}>
        <Text style={styles.messageText}>{item.text}</Text>
        <Text style={styles.timeText}>
          {item.createdAt?.toDate?.()
            ? item.createdAt.toDate().toLocaleTimeString([], {
                hour: '2-digit', minute: '2-digit',
              })
            : 'Sending...'}
        </Text>
      </View>
    );
  };

  return (
    <KeyboardAvoidingView
      style={styles.container}
      behavior={Platform.OS === 'ios' ? 'padding' : 'height'}
    >
      {/* Header */}
      <View style={styles.header}>
        <Text style={styles.headerTitle}>{recipientName}</Text>
        <Text style={styles.headerSubtitle}>online</Text>
      </View>

      {/* Encryption banner */}
      <EncryptionBanner />

      {/* Messages */}
      <FlatList
        data={messages}
        renderItem={renderMessage}
        keyExtractor={(item) => item.id}
        inverted
        style={styles.messageList}
        contentContainerStyle={{ paddingVertical: 10 }}
      />

      {/* Input bar */}
      <View style={styles.inputBar}>
        <TextInput
          style={styles.input}
          value={input}
          onChangeText={setInput}
          placeholder="Type a message"
          maxLength={4096}
          multiline
        />
        <Pressable
          style={[styles.sendBtn, sending && { opacity: 0.5 }]}
          onPress={handleSend}
          disabled={sending}
        >
          {sending
            ? <ActivityIndicator color={COLORS.white} size="small" />
            : <Text style={styles.sendText}>Send</Text>
          }
        </Pressable>
      </View>

      {/* Security code (tap header to see it in a real app) */}
      {securityCode ? (
        <View style={styles.securityCodeBar}>
          <Text style={styles.securityLabel}>Security code:</Text>
          <Text style={styles.securityCode}>{securityCode}</Text>
        </View>
      ) : null}
    </KeyboardAvoidingView>
  );
}

11. Key takeaways

  • Private keys never leave the device — stored in iOS Keychain / Android Keystore via expo-secure-store
  • Public keys are published to Firestore — anyone logged in can fetch them
  • ECDH (x25519) produces a shared secret — without either private key ever being sent over the network
  • AES-256-GCM encrypts each message — with a unique random nonce so repeated texts look different
  • Firebase only stores ciphertext — even a database breach reveals nothing readable
  • Security codes let users verify keys — protects against man-in-the-middle attacks
  • GCM authentication detects tampering — if anyone modifies the ciphertext, decryption fails rather than returning garbage
  • @noble/curves works in Expo Go — pure JS, no native code, audited library
What about group chats?

Group E2E encryption is significantly harder — you'd need to encrypt the message separately for each participant, or implement the Signal Protocol's "Sender Keys" scheme. For now, this lesson covers 1:1 chats. Real WhatsApp uses Sender Keys for groups to avoid encrypting each message N times.

Advanced Features · Lesson 3

Deep Linking & OTA Updates

expo-linking · Universal links · App links · expo-updates · Rollback ~65 min Hands-on
Why this matters for your WhatsApp clone

When Priya gets a push notification "Rahul sent you a message", tapping it should open that exact chat — not the home screen. That's a deep link. And when you fix a bug at 2 AM, you don't want users waiting 3 days for Apple to review a new build — OTA (Over-The-Air) updates push your JavaScript fix instantly to every phone, without going through the app stores. Real WhatsApp uses both of these heavily.

1. What are deep links?

A deep link is a URL that opens a specific screen inside your app instead of just launching the app's home screen.

TypeFormatExampleWorks when
Custom scheme chatapp:// chatapp://chat/rahul456 App is installed
Universal link (iOS) https://yourapp.com/ https://yourapp.com/chat/rahul456 App installed → opens app; not installed → opens website
App link (Android) https://yourapp.com/ https://yourapp.com/chat/rahul456 Same as universal links but for Android

Where deep links come from

  • Push notifications — tap a notification → open the chat it's about
  • Shared links — someone texts you https://yourapp.com/invite/group123
  • QR codes — scan to join a group
  • Email — "Click here to verify your account"
  • Other apps — a contact app shares a profile link

2. Setting up expo-linking

expo-linking handles deep links in Expo apps. It's already included — you just need to configure it.

Step 1: Define your URL scheme in app.config.js

// app.config.js
export default {
  name: 'ChatApp',
  slug: 'chatapp',
  scheme: 'chatapp',    // ← This registers chatapp:// as your custom scheme
  ios: {
    bundleIdentifier: 'com.yourname.chatapp',
    associatedDomains: ['applinks:yourapp.com'],  // For universal links
  },
  android: {
    package: 'com.yourname.chatapp',
    intentFilters: [
      {
        action: 'VIEW',
        autoVerify: true,   // For app links (verified ownership)
        data: [
          { scheme: 'https', host: 'yourapp.com', pathPrefix: '/chat' },
          { scheme: 'https', host: 'yourapp.com', pathPrefix: '/invite' },
        ],
        category: ['BROWSABLE', 'DEFAULT'],
      },
    ],
  },
  // ... rest of config
};

Step 2: Handle incoming links

// navigation/linking.js — Deep link configuration for React Navigation

import * as Linking from 'expo-linking';

// The prefix tells React Navigation which URLs belong to your app
const prefix = Linking.createURL('/');
// This gives: "chatapp://" in dev, or "https://yourapp.com" in production

export const linkingConfig = {
  prefixes: [prefix, 'https://yourapp.com', 'chatapp://'],
  config: {
    screens: {
      // Map URL paths to screen names in your navigator
      Main: {
        screens: {
          Chats: {
            screens: {
              ChatList: 'chats',
              // chatapp://chat/rahul456 → opens MessageThread with recipientId="rahul456"
              MessageThread: 'chat/:recipientId',
            },
          },
          Calls: 'calls',
          Status: 'status',
          Settings: 'settings',
        },
      },
      Login: 'login',
      // chatapp://invite/group123 → opens group invite screen
      GroupInvite: 'invite/:groupId',
    },
  },
};

Step 3: Pass linking config to NavigationContainer

// App.js — Connect deep links to your navigation
import { NavigationContainer } from '@react-navigation/native';
import { linkingConfig } from './navigation/linking';

export default function App() {
  return (
    <NavigationContainer linking={linkingConfig}>
      {/* Your navigators go here */}
    </NavigationContainer>
  );
}

That's it! Now when someone opens chatapp://chat/rahul456, React Navigation automatically navigates to the MessageThread screen with route.params.recipientId === 'rahul456'.

3. Handling links when the app is already open

Deep links arrive in two scenarios:

  • Cold start — app was closed, link opens it fresh → React Navigation handles this automatically via the linking prop
  • Already open — app is running in the background, user taps a link → you need to listen for the event
// hooks/useDeepLink.js — Listen for links while app is open
import { useEffect } from 'react';
import * as Linking from 'expo-linking';
import { useNavigation } from '@react-navigation/native';

export function useDeepLink() {
  const navigation = useNavigation();

  useEffect(() => {
    // Handle link that opened the app (cold start)
    const handleInitialLink = async () => {
      const url = await Linking.getInitialURL();
      if (url) {
        handleUrl(url);
      }
    };

    // Handle link while app is already running
    const subscription = Linking.addEventListener('url', (event) => {
      handleUrl(event.url);
    });

    handleInitialLink();

    return () => subscription.remove();
  }, []);

  function handleUrl(url) {
    // Parse the URL to extract the path
    const parsed = Linking.parse(url);
    console.log('Deep link received:', parsed);

    // Example: chatapp://chat/rahul456
    // parsed = { path: 'chat/rahul456', queryParams: {} }

    if (parsed.path?.startsWith('chat/')) {
      const recipientId = parsed.path.replace('chat/', '');
      navigation.navigate('Main', {
        screen: 'Chats',
        params: {
          screen: 'MessageThread',
          params: { recipientId },
        },
      });
    }

    if (parsed.path?.startsWith('invite/')) {
      const groupId = parsed.path.replace('invite/', '');
      navigation.navigate('GroupInvite', { groupId });
    }
  }
}

4. Deep links from push notifications

The most common source of deep links in a chat app: tapping a notification should open that specific conversation.

// When sending push notifications (from your Cloud Function),
// include the deep link data in the notification payload:

// Cloud Function — send notification with deep link data
const message = {
  notification: {
    title: 'Rahul',
    body: 'Hey, are you coming tonight?',
  },
  data: {
    // This data is passed to the app when the notification is tapped
    type: 'new_message',
    chatId: 'chat_priya_rahul',
    senderId: 'rahul456',
    senderName: 'Rahul',
  },
  token: recipientFCMToken,
};

await admin.messaging().send(message);
// In your React Native app — handle notification tap
import * as Notifications from 'expo-notifications';
import { useNavigation } from '@react-navigation/native';

export function useNotificationNavigation() {
  const navigation = useNavigation();

  useEffect(() => {
    // When user taps a notification
    const subscription = Notifications.addNotificationResponseReceivedListener(
      (response) => {
        const data = response.notification.request.content.data;

        if (data.type === 'new_message') {
          // Navigate directly to the chat
          navigation.navigate('Main', {
            screen: 'Chats',
            params: {
              screen: 'MessageThread',
              params: {
                chatId: data.chatId,
                recipientId: data.senderId,
                recipientName: data.senderName,
              },
            },
          });
        }

        if (data.type === 'incoming_call') {
          navigation.navigate('IncomingCall', {
            callerId: data.callerId,
            callerName: data.callerName,
          });
        }
      }
    );

    return () => subscription.remove();
  }, [navigation]);
}

5. Universal links (iOS) and app links (Android)

Custom schemes (chatapp://) only work if the app is installed. Universal links use your website domain — if the app isn't installed, the browser opens your website instead (where you can show a "Download the app" page).

iOS: Universal links setup

You need a file on your web server that proves you own the domain:

// Host this at: https://yourapp.com/.well-known/apple-app-site-association
// (No file extension! Just this exact filename)
{
  "applinks": {
    "apps": [],
    "details": [
      {
        "appID": "ABC123XYZ.com.yourname.chatapp",
        "paths": ["/chat/*", "/invite/*", "/verify/*"]
      }
    ]
  }
}

// ABC123XYZ = your Apple Team ID
// com.yourname.chatapp = your bundle identifier

Android: App links setup

// Host this at: https://yourapp.com/.well-known/assetlinks.json
[
  {
    "relation": ["delegate_permission/common.handle_all_urls"],
    "target": {
      "namespace": "android_app",
      "package_name": "com.yourname.chatapp",
      "sha256_cert_fingerprints": [
        "AA:BB:CC:DD:EE:FF:00:11:22:33:44:55:66:77:88:99:AA:BB:CC:DD:EE:FF:00:11:22:33:44:55:66:77:88:99"
      ]
    }
  }
]

// Get your SHA-256 fingerprint:
// eas credentials --platform android

Where to host these files

  • Firebase Hosting — free, already in your stack. Run firebase init hosting and put the files in the public/.well-known/ folder
  • Any web server — Vercel, Netlify, or your own server. The file just needs to be accessible at the exact URL path
Important: HTTPS is required

Both Apple and Google require these files to be served over HTTPS from your verified domain. HTTP will not work. Firebase Hosting provides free SSL automatically.

6. OTA Updates with expo-updates

OTA updates let you push JavaScript changes to users' phones without going through the app stores. The user just opens the app and it silently downloads the new code.

What can be updated OTA

Can update OTACannot update OTA (needs new build)
JavaScript code (all your screens, logic)Native modules (new library with native code)
Images, fonts, assets in JS bundleApp icon, splash screen
Bug fixes in any JS fileiOS/Android permissions changes
New screens, UI changesNew Expo SDK version
Updated API calls, business logicChanges to app.json native settings

Setup

# Install expo-updates
npx expo install expo-updates
// app.config.js — add updates configuration
export default {
  // ... existing config
  updates: {
    enabled: true,
    // Check for updates every time the app launches
    checkAutomatically: 'ON_LAUNCH',
    // Fallback to the embedded bundle if the update download fails
    fallbackToCacheTimeout: 5000,  // Wait max 5 seconds
  },
  runtimeVersion: {
    // Policy: auto-generate version from native code changes
    policy: 'appVersion',
  },
};

Publishing an OTA update

# From your terminal (or CI pipeline):
# This bundles your JS and uploads it to EAS Update servers
eas update --branch production --message "Fix crash in message thread"

# For preview testers:
eas update --branch preview --message "New group chat UI"

7. Update strategies

Different situations call for different update behaviors. Here are the four strategies:

Strategy 1: Silent update (default)

Download the update in the background. Apply it next time the app launches. The user never notices.

// This is the default behavior with checkAutomatically: 'ON_LAUNCH'
// No extra code needed — expo-updates does this automatically

// The flow:
// 1. User opens app → sees current version immediately
// 2. expo-updates checks for a new version in the background
// 3. If found, downloads it silently
// 4. Next time the user opens the app, they get the new version

Strategy 2: Soft prompt ("Update available")

Show a non-blocking banner asking the user to restart for the update.

// components/UpdateBanner.js
import React, { useState, useEffect } from 'react';
import { View, Text, Pressable, StyleSheet } from 'react-native';
import * as Updates from 'expo-updates';

export function UpdateBanner() {
  const [updateAvailable, setUpdateAvailable] = useState(false);

  useEffect(() => {
    async function checkForUpdate() {
      try {
        const update = await Updates.checkForUpdateAsync();
        if (update.isAvailable) {
          // Download it in the background
          await Updates.fetchUpdateAsync();
          setUpdateAvailable(true);
        }
      } catch (err) {
        // Silently fail — don't disrupt the user
        console.log('Update check failed:', err);
      }
    }

    // Only check in production (not in development)
    if (!__DEV__) {
      checkForUpdate();
    }
  }, []);

  if (!updateAvailable) return null;

  const handleRestart = async () => {
    await Updates.reloadAsync();  // Restarts the app with the new code
  };

  return (
    <View style={styles.banner}>
      <Text style={styles.bannerText}>A new version is available</Text>
      <Pressable style={styles.btn} onPress={handleRestart}>
        <Text style={styles.btnText}>Restart</Text>
      </Pressable>
    </View>
  );
}

const styles = StyleSheet.create({
  banner: {
    flexDirection: 'row',
    alignItems: 'center',
    justifyContent: 'space-between',
    backgroundColor: '#075E54',
    padding: 12,
    paddingTop: 48, // account for status bar
  },
  bannerText: { color: '#fff', fontSize: 14, flex: 1 },
  btn: {
    backgroundColor: '#25D366',
    paddingHorizontal: 14,
    paddingVertical: 6,
    borderRadius: 4,
  },
  btnText: { color: '#fff', fontWeight: '700', fontSize: 13 },
});

Strategy 3: Force update (critical fix)

Block the entire app until the user updates. Use this only for critical security or crash fixes.

// components/ForceUpdateScreen.js
import React, { useState, useEffect } from 'react';
import { View, Text, ActivityIndicator, StyleSheet } from 'react-native';
import * as Updates from 'expo-updates';

export function ForceUpdateScreen() {
  const [status, setStatus] = useState('Checking for updates...');

  useEffect(() => {
    async function forceUpdate() {
      try {
        const update = await Updates.checkForUpdateAsync();

        if (update.isAvailable) {
          setStatus('Downloading update...');
          await Updates.fetchUpdateAsync();
          setStatus('Restarting...');
          await Updates.reloadAsync();
        } else {
          setStatus('App is up to date');
        }
      } catch (err) {
        setStatus('Update failed. Please check your internet connection.');
      }
    }

    forceUpdate();
  }, []);

  return (
    <View style={styles.container}>
      <ActivityIndicator size="large" color="#075E54" />
      <Text style={styles.text}>{status}</Text>
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: 'center', alignItems: 'center', padding: 24 },
  text: { marginTop: 16, fontSize: 16, color: '#333', textAlign: 'center' },
});

Strategy 4: Version check (app too old)

When your backend changes in a way that breaks old app versions, force users to update via the store.

// hooks/useMinVersionCheck.js
import { useEffect, useState } from 'react';
import { Linking, Platform } from 'react-native';
import Constants from 'expo-constants';
import { doc, getDoc } from 'firebase/firestore';
import { db } from '../firebaseConfig';

export function useMinVersionCheck() {
  const [blocked, setBlocked] = useState(false);

  useEffect(() => {
    async function checkVersion() {
      // Read minimum required version from Firestore (you control this)
      const configDoc = await getDoc(doc(db, 'appConfig', 'versions'));
      if (!configDoc.exists()) return;

      const minVersion = configDoc.data().minVersion; // e.g., "1.3.0"
      const currentVersion = Constants.expoConfig.version; // e.g., "1.2.0"

      if (isVersionLower(currentVersion, minVersion)) {
        setBlocked(true);
      }
    }

    checkVersion();
  }, []);

  const openStore = () => {
    const url = Platform.OS === 'ios'
      ? 'https://apps.apple.com/app/id1234567890'
      : 'https://play.google.com/store/apps/details?id=com.yourname.chatapp';
    Linking.openURL(url);
  };

  return { blocked, openStore };
}

function isVersionLower(current, minimum) {
  const c = current.split('.').map(Number);
  const m = minimum.split('.').map(Number);
  for (let i = 0; i < 3; i++) {
    if (c[i] < m[i]) return true;
    if (c[i] > m[i]) return false;
  }
  return false;
}

8. Rollback on crash

What if you push a bad OTA update that crashes the app? expo-updates has built-in rollback protection.

// How automatic rollback works:
//
// 1. You push an OTA update with a bug
// 2. User's app downloads and applies the update
// 3. App crashes on launch
// 4. expo-updates detects the crash (app didn't stay open for 10+ seconds)
// 5. On next launch, it rolls back to the previous working version
//
// This is AUTOMATIC — no code needed!

// You can also manually roll back from the terminal:
// eas update:rollback --branch production

// Or point the branch back to a specific update:
// eas update:republish --group UPDATE_GROUP_ID --branch production

Testing rollback locally

// You can test the rollback behavior with this pattern:
import * as Updates from 'expo-updates';

// In your root component:
useEffect(() => {
  if (!__DEV__) {
    // Log which update is running
    console.log('Running update ID:', Updates.updateId);
    console.log('Is embedded (not OTA):', Updates.isEmbeddedLaunch);
    console.log('Created at:', Updates.createdAt);
  }
}, []);
EAS Update channels = build profiles

Remember the build profiles from Lesson 2? Each profile has a channel field. OTA updates target a channel — so updates pushed to the "preview" channel only reach preview builds, and "production" updates only reach production builds. You can't accidentally push a dev update to all users.

          eas-version: latest

      .catch((err) => Alert.alert('Login failed', err.message))
      .finally(() => setLoading(false));
  }, []);

  if (loading) {
    return (
      <View style={styles.center}>
        <ActivityIndicator size="large" color={COLORS.darkGreen} />
      </View>
    );
  }

  if (!user) {
    return (
      <View style={styles.center}>
        <Text>Not logged in</Text>
      </View>
    );
  }

  return (
    <NavigationContainer linking={linking}>
      <Stack.Navigator screenOptions={{ headerShown: false }}>
        <Stack.Screen name="ChatList" component={ChatListScreen} />
        <Stack.Screen name="MessageThread" component={MessageThreadScreen} />
      </Stack.Navigator>
    </NavigationContainer>
  );
}

11. Key takeaways

  • Deep links open specific screens — chatapp://chat/rahul456 goes straight to that conversation
  • React Navigation's linking prop — maps URL paths to screens automatically
  • Universal links (iOS) + app links (Android) — use your real domain; work even if app isn't installed
  • Push notification taps → deep link — include route data in the notification payload
  • OTA updates push JS changes instantly — no store review wait time
  • Four update strategies: silent, soft prompt, force update, version gate
  • eas update --branch production — publishes OTA update from terminal or CI
  • Automatic rollback on crash — bad updates revert to the previous working version
  • Channels match build profiles — preview updates can't reach production users
  • OTA can't change native code — new libraries or permissions still need a store build
Apple's rules on OTA

Apple allows OTA updates for JavaScript code (this is explicitly permitted in their guidelines for React Native and similar frameworks). What they don't allow is using OTA to bypass their review by shipping entirely new functionality that changes the app's core purpose. Bug fixes, UI tweaks, and feature polish are all fine.

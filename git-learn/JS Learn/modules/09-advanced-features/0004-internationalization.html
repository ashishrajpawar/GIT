Advanced Features · Lesson 4

Internationalization (i18n)

expo-localization · i18next · Translation files · RTL · Plurals · Date/number formatting ~65 min Hands-on
Why this matters for your WhatsApp clone

WhatsApp is available in 60+ languages — that's how it reached 2 billion users worldwide. If your app only speaks English, you're locking out millions of potential users in India alone (Hindi, Tamil, Marathi, Bengali...). Internationalization means building your app so that every piece of text can be translated without changing any code. Add Hindi today, Arabic tomorrow, Japanese next week — all by adding a single translation file.

1. The i18n approach

Instead of hardcoding text like "Send message" directly in your components, you replace every visible string with a key that looks up the correct translation at runtime.

// ❌ Before: hardcoded English
<Text>Send message</Text>
<Text>{unread} unread messages</Text>

// ✅ After: translation key
<Text>{t('chat.send')}</Text>
<Text>{t('chat.unread', { count: unread })}</Text>

// The actual text comes from a JSON file:
// en.json: { "chat": { "send": "Send message", "unread": "{{count}} unread messages" } }
// hi.json: { "chat": { "send": "संदेश भेजें", "unread": "{{count}} अपठित संदेश" } }

Libraries we'll use

LibraryPurpose
expo-localizationDetect the user's device language and region
i18nextThe translation engine — loads the right language file, handles plurals, interpolation
react-i18nextReact hooks (useTranslation) to use translations in components

Step 2: Initialize i18next

// i18n/index.js — Initialize the translation system

import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import * as Localization from 'expo-localization';

// Import translation files
import en from '../locales/en.json';
import hi from '../locales/hi.json';
import ar from '../locales/ar.json';

// Detect the user's device language
const deviceLanguage = Localization.getLocales()[0]?.languageCode || 'en';

i18n
  .use(initReactI18next)   // Connect i18next to React
  .init({
    resources: {
      en: { translation: en },
      hi: { translation: hi },
      ar: { translation: ar },
    },
    lng: deviceLanguage,       // Use device language by default
    fallbackLng: 'en',        // If translation missing, fall back to English
    interpolation: {
      escapeValue: false,      // React already escapes values
    },
    // Pluralization
    pluralSeparator: '_',
    compatibilityJSON: 'v4',  // Use modern plural rules
  });

export default i18n;

3. Using translations in components

The useTranslation hook gives you the t() function that looks up translations.

// screens/ChatListScreen.js
import React from 'react';
import { View, Text, FlatList, StyleSheet } from 'react-native';
import { useTranslation } from 'react-i18next';

export function ChatListScreen() {
  const { t } = useTranslation();

  const chats = [
    { id: '1', name: 'Rahul', lastMsg: 'Hey!', unread: 3 },
    { id: '2', name: 'Priya', lastMsg: 'Photo', unread: 0 },
  ];

  return (
    <View style={styles.container}>
      {/* Tab title uses translation key */}
      <Text style={styles.title}>{t('tabs.chats')}</Text>

      {chats.length === 0 ? (
        <View style={styles.empty}>
          <Text>{t('chat.noChats')}</Text>
          <Text>{t('chat.startChat')}</Text>
        </View>
      ) : (
        <FlatList
          data={chats}
          keyExtractor={(item) => item.id}
          renderItem={({ item }) => (
            <View style={styles.row}>
              <Text style={styles.name}>{item.name}</Text>
              {item.unread > 0 && (
                <Text style={styles.unread}>
                  {/* Pluralization: "1 unread message" vs "3 unread messages" */}
                  {t('chat.unread', { count: item.unread })}
                </Text>
              )}
            </View>
          )}
        />
      )}
    </View>
  );
}

Interpolation — inserting dynamic values

// Translation key: "lastSeen": "last seen {{time}}"
// Usage:
<Text>{t('chat.lastSeen', { time: '10:30 AM' })}</Text>
// Output (English): "last seen 10:30 AM"
// Output (Hindi): "अंतिम बार 10:30 AM पर देखा"

Pluralization — different text for 1 vs many

// Translation keys (English):
// "unread_one": "{{count}} unread message"
// "unread_other": "{{count}} unread messages"

// Usage:
t('chat.unread', { count: 1 })  // → "1 unread message"
t('chat.unread', { count: 5 })  // → "5 unread messages"

// i18next automatically picks _one or _other based on count!
// Some languages (like Arabic) have more forms: _zero, _one, _two, _few, _many, _other

4. Switching languages at runtime

Let users choose their preferred language in Settings — it overrides the device default.

// screens/LanguageSettingsScreen.js
import React from 'react';
import { View, Text, Pressable, FlatList, StyleSheet } from 'react-native';
import { useTranslation } from 'react-i18next';
import AsyncStorage from '@react-native-async-storage/async-storage';

const LANGUAGES = [
  { code: 'en', name: 'English', nativeName: 'English' },
  { code: 'hi', name: 'Hindi', nativeName: 'हिन्दी' },
  { code: 'ar', name: 'Arabic', nativeName: 'العربية' },
  { code: 'ta', name: 'Tamil', nativeName: 'தமிழ்' },
  { code: 'mr', name: 'Marathi', nativeName: 'मराठी' },
  { code: 'bn', name: 'Bengali', nativeName: 'বাংলা' },
];

export function LanguageSettingsScreen() {
  const { t, i18n } = useTranslation();

  const changeLanguage = async (langCode) => {
    // 1. Change the active language
    await i18n.changeLanguage(langCode);

    // 2. Save preference (so it persists after app restart)
    await AsyncStorage.setItem('userLanguage', langCode);
  };

  return (
    <View style={styles.container}>
      <Text style={styles.title}>{t('settings.language')}</Text>

      <FlatList
        data={LANGUAGES}
        keyExtractor={(item) => item.code}
        renderItem={({ item }) => {
          const isActive = i18n.language === item.code;
          return (
            <Pressable
              style={[styles.langRow, isActive && styles.activeRow]}
              onPress={() => changeLanguage(item.code)}
            >
              <View>
                <Text style={styles.langName}>{item.nativeName}</Text>
                <Text style={styles.langSubname}>{item.name}</Text>
              </View>
              {isActive && <Text style={styles.check}>✓</Text>}
            </Pressable>
          );
        }}
      />
    </View>
  );
}
// In your i18n/index.js — load saved preference on startup
import AsyncStorage from '@react-native-async-storage/async-storage';

// After i18n.init(), restore saved language:
async function loadSavedLanguage() {
  const saved = await AsyncStorage.getItem('userLanguage');
  if (saved && saved !== i18n.language) {
    await i18n.changeLanguage(saved);
  }
}

loadSavedLanguage();

5. RTL (Right-to-Left) layout support

Arabic, Hebrew, Urdu, and Persian are read right-to-left. When a user switches to Arabic, your entire layout should mirror — send button on the left, messages aligned differently, text aligned right.

// i18n/rtl.js — Handle RTL layout changes
import { I18nManager } from 'react-native';
import * as Updates from 'expo-updates';

// List of RTL languages
const RTL_LANGUAGES = ['ar', 'he', 'ur', 'fa'];

export function applyRTL(languageCode) {
  const shouldBeRTL = RTL_LANGUAGES.includes(languageCode);
  const isCurrentlyRTL = I18nManager.isRTL;

  if (shouldBeRTL !== isCurrentlyRTL) {
    // Force RTL or LTR
    I18nManager.allowRTL(shouldBeRTL);
    I18nManager.forceRTL(shouldBeRTL);

    // Restart the app for layout changes to take effect
    // (RTL changes require a restart in React Native)
    Updates.reloadAsync();
  }
}
// Call applyRTL when language changes:
const changeLanguage = async (langCode) => {
  await i18n.changeLanguage(langCode);
  await AsyncStorage.setItem('userLanguage', langCode);
  applyRTL(langCode);  // Restart if RTL state changed
};

RTL-aware styles

// Use 'start'/'end' instead of 'left'/'right' for RTL compatibility
const styles = StyleSheet.create({
  chatRow: {
    flexDirection: 'row',  // Automatically flips in RTL!
    paddingHorizontal: 16,
  },
  avatar: {
    // ❌ Don't use marginRight — it won't flip
    // marginRight: 12,

    // ✅ Use marginEnd — flips based on RTL setting
    marginEnd: 12,
  },
  messageText: {
    // ❌ Don't use textAlign: 'left'
    // textAlign: 'left',

    // ✅ Use 'auto' — follows the language direction
    textAlign: 'auto',
  },
  sendButton: {
    // ❌ position + right won't flip
    // position: 'absolute', right: 12,

    // ✅ Use 'end' — works in both LTR and RTL
    position: 'absolute',
    end: 12,
  },
});

// React Native RTL rules:
// - flexDirection: 'row' automatically reverses in RTL
// - marginStart/marginEnd replace marginLeft/marginRight
// - paddingStart/paddingEnd replace paddingLeft/paddingRight
// - 'start'/'end' replace 'left'/'right' in position
// - textAlign: 'auto' follows language direction
RTL requires a restart

Unlike language changes (which are instant), switching between LTR and RTL requires an app restart because React Native's layout engine needs to recalculate all Flexbox positions. That's why we call Updates.reloadAsync(). Users switching between Hindi (LTR) and Arabic (RTL) will see a brief restart.

6. Number and date formatting per locale

Numbers and dates look different in different regions: "1,234.56" in the US vs "1.234,56" in Germany vs "١٬٢٣٤٫٥٦" in Arabic.

// utils/formatters.js — Locale-aware formatting
import * as Localization from 'expo-localization';

// Get the user's locale (e.g., 'en-IN', 'hi-IN', 'ar-SA')
const userLocale = Localization.getLocales()[0]?.languageTag || 'en-US';

// Format numbers according to locale
export function formatNumber(num) {
  return new Intl.NumberFormat(userLocale).format(num);
}
// formatNumber(1234567)
// English: "1,234,567"
// Hindi:   "12,34,567" (Indian numbering uses lakhs/crores!)
// Arabic:  "١٬٢٣٤٬٥٦٧"

// Format dates according to locale
export function formatDate(date) {
  return new Intl.DateTimeFormat(userLocale, {
    day: 'numeric',
    month: 'short',
    year: 'numeric',
  }).format(date);
}
// formatDate(new Date('2026-08-05'))
// English (US): "Aug 5, 2026"
// English (IN): "5 Aug 2026"
// Hindi:        "5 अग॰ 2026"
// Arabic:       "٥ أغسطس ٢٠٢٦"

// Format time (for message timestamps)
export function formatTime(date) {
  return new Intl.DateTimeFormat(userLocale, {
    hour: '2-digit',
    minute: '2-digit',
  }).format(date);
}
// formatTime(new Date())
// English: "10:30 AM"
// Hindi:   "10:30 am"
// Arabic:  "١٠:٣٠ ص"

// Relative time ("2 minutes ago", "yesterday")
export function formatRelativeTime(date) {
  const now = new Date();
  const diffMs = now - date;
  const diffMins = Math.floor(diffMs / 60000);
  const diffHours = Math.floor(diffMs / 3600000);
  const diffDays = Math.floor(diffMs / 86400000);

  const rtf = new Intl.RelativeTimeFormat(userLocale, { numeric: 'auto' });

  if (diffMins < 1) return rtf.format(0, 'minute');      // "just now" / "अभी"
  if (diffMins < 60) return rtf.format(-diffMins, 'minute'); // "5 minutes ago"
  if (diffHours < 24) return rtf.format(-diffHours, 'hour'); // "2 hours ago"
  if (diffDays < 7) return rtf.format(-diffDays, 'day');     // "yesterday" / "2 days ago"

  return formatDate(date);
}
// Using in a component:
import { formatRelativeTime } from '../utils/formatters';

function MessageBubble({ message }) {
  const timeDisplay = message.createdAt
    ? formatRelativeTime(message.createdAt.toDate())
    : '';

  return (
    <View style={styles.bubble}>
      <Text>{message.text}</Text>
      <Text style={styles.time}>{timeDisplay}</Text>
    </View>
  );
}

8. Server-side: translating push notifications

Push notifications are sent from your Cloud Function — they also need to be translated. Store the user's language in their Firestore profile.

// Firestore user document:
{
  "name": "Priya",
  "language": "hi",   // ← save when user picks a language
  ...
}

// Cloud Function — send translated notification
const translations = {
  en: { newMessage: '{{name}} sent you a message' },
  hi: { newMessage: '{{name}} ने आपको संदेश भेजा' },
  ar: { newMessage: '{{name}} أرسل لك رسالة' },
};

async function sendNotification(recipientId, senderName) {
  // 1. Get recipient's language preference
  const userDoc = await admin.firestore().doc(`users/${recipientId}`).get();
  const lang = userDoc.data().language || 'en';

  // 2. Get the translation
  const template = translations[lang]?.newMessage
    || translations.en.newMessage;
  const body = template.replace('{{name}}', senderName);

  // 3. Send the notification in their language
  await admin.messaging().send({
    notification: { title: senderName, body },
    token: userDoc.data().fcmToken,
  });
}

Getting translations done

For a real app, don't use Google Translate — it's often wrong for UI text. Options: (1) Ask native speakers on your team, (2) Use a service like Crowdin or Lokalise where native speakers contribute translations, (3) Hire professional translators for your primary markets. Start with 3–5 languages where you have the most users.

// ─── Chat Screen ─────────────────────────────────────
function ChatScreen() {
  const { t } = useTranslation();
  const [messages, setMessages] = useState([
    { id: '1', senderId: 'rahul456', text: 'Hey, how are you?', time: '10:30' },
    { id: '2', senderId: 'me', text: 'Good! Working on the app.', time: '10:31' },
    { id: '3', senderId: 'rahul456', text: 'Awesome! Let me know when done.', time: '10:32' },
  ]);
  const [input, setInput] = useState('');

  const handleSend = () => {
    if (!input.trim()) return;
    setMessages(prev => [
      { id: String(Date.now()), senderId: 'me', text: input.trim(), time: 'Now' },
      ...prev,
    ]);
    setInput('');
  };

  return (
    <KeyboardAvoidingView
      style={styles.container}
      behavior={Platform.OS === 'ios' ? 'padding' : 'height'}
    >
      {/* Header — all text uses t() */}
      <View style={styles.header}>
        <Text style={styles.headerTitle}>Rahul</Text>
        <Text style={styles.headerSubtitle}>{t('chat.online')}</Text>
      </View>

      {/* Encryption banner — translated */}
      <View style={styles.encBanner}>
        <Text style={styles.encText}>🔒 {t('chat.encrypted')}</Text>
      </View>

      {/* Language picker (for demo — normally in Settings) */}
      <LanguagePicker />

      {/* Messages */}
      <FlatList
        data={messages}
        keyExtractor={(item) => item.id}
        inverted
        style={styles.messageList}
        renderItem={({ item }) => {
          const isMine = item.senderId === 'me';
          return (
            <View style={[styles.bubble, isMine ? styles.myBubble : styles.theirBubble]}>
              <Text style={styles.messageText}>{item.text}</Text>
              <Text style={styles.timeText}>{item.time}</Text>
            </View>
          );
        }}
      />

      {/* Input bar — placeholder is translated */}
      <View style={styles.inputBar}>
        <TextInput
          style={styles.input}
          value={input}
          onChangeText={setInput}
          placeholder={t('chat.typeMessage')}
          multiline
        />
        <Pressable style={styles.sendBtn} onPress={handleSend}>
          <Text style={styles.sendText}>{t('chat.send')}</Text>
        </Pressable>
      </View>
    </KeyboardAvoidingView>
  );
}

11. Key takeaways

  • Never hardcode visible text — every string goes through t('key')
  • expo-localization detects device language — use as the default, let users override
  • i18next handles interpolation and plurals — t('key', { count: n }) picks the right form automatically
  • Translation files are just JSON — easy to hand off to translators
  • RTL requires special attention: use marginStart/End, textAlign: 'auto', and test with Arabic
  • Numbers and dates differ per locale — use Intl.NumberFormat and Intl.DateTimeFormat
  • Save language preference in AsyncStorage — so it persists across launches
  • Push notifications need server-side translation — store user language in Firestore
  • Adding a new language = new JSON file + 2 lines of code — then push via OTA
  • Use eslint-plugin-i18next — catches hardcoded strings you missed

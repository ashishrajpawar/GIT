Advanced Features · Lesson 5

Accessibility

accessibilityLabel · Roles · Font scaling · Touch targets · Contrast · Screen readers · Live regions ~70 min Hands-on
Why this matters for your WhatsApp clone

Over 1 billion people worldwide have some form of disability — visual, motor, hearing, or cognitive. In India alone, 26 million people are visually impaired and use screen readers (VoiceOver on iOS, TalkBack on Android) to navigate their phones. If your app isn't accessible, these users simply cannot use it. Apple and Google both prioritise accessibility in their store reviews, and in many countries it's a legal requirement. Making your app accessible isn't optional — it's the right thing to do, and it makes your app better for everyone.

1. How screen readers work

A screen reader reads your app out loud, element by element. When a blind user swipes right, the screen reader moves to the next element and announces what it is.

// What a screen reader announces for each element:
// 1. The LABEL — what is this? ("Send button", "Rahul's chat", "Message text field")
// 2. The ROLE — what type of element? ("button", "text", "image", "link")
// 3. The STATE — is it disabled? selected? expanded?
// 4. The HINT — what happens if I tap? ("double tap to send message")

// Example announcement:
// "Send, button, double tap to send your message"

Testing with screen readers

PlatformScreen readerHow to enable
iOS VoiceOver Settings → Accessibility → VoiceOver → ON (or triple-click side button)
Android TalkBack Settings → Accessibility → TalkBack → ON (or hold both volume buttons 3 seconds)
You MUST test with a real screen reader

Accessibility props in code don't guarantee a good experience. You need to actually turn on VoiceOver/TalkBack and navigate your app by swiping. You'll immediately find confusing labels, missing announcements, and unreachable buttons. Budget 30 minutes to test after implementing this lesson.

2. accessibilityLabel — naming every element

Every interactive element needs a label that the screen reader announces. Without it, a button might just say "button" with no context.

// ❌ Bad: screen reader says "button" — useless
<Pressable onPress={handleSend}>
  <Image source={sendIcon} />
</Pressable>

// ✅ Good: screen reader says "Send message, button"
<Pressable
  onPress={handleSend}
  accessibilityLabel="Send message"
  accessibilityRole="button"
>
  <Image source={sendIcon} />
</Pressable>

Rules for good labels

  • Describe the action, not the appearance — "Send message" not "Green arrow icon"
  • Keep it short — 2–4 words is ideal. Screen reader users are impatient.
  • Don't include the role — saying "Send button" is redundant because accessibilityRole="button" already says "button"
  • Include context when needed — "Rahul's chat" not just "Chat" (if there are multiple chats on screen)

3. accessibilityRole — telling the screen reader what type of element

Roles tell the screen reader what kind of element it's announcing. This changes how the element is described and sometimes how it behaves.

"link"Navigating to another screen/URL"Rahul's profile, link"
"image"Images and icons"Profile photo, image"
"header"Section headers"Chats, heading"

"switch"Toggle switches"Notifications, switch, on"

4. Grouping elements for better navigation

Without grouping, a screen reader user has to swipe through every individual element. A chat row with an avatar, name, last message, and timestamp would take 4 swipes. Grouping combines them into one swipe.

// ❌ Bad: 4 separate swipes to get through one chat row
<View>
  <Image source={avatar} />
  <Text>Rahul</Text>
  <Text>Hey, are you coming?</Text>
  <Text>10:30 AM</Text>
</View>

// ✅ Good: 1 swipe — everything is announced together
<Pressable
  accessible={true}
  accessibilityLabel={`Rahul. Hey, are you coming? 10:30 AM. 2 unread messages`}
  accessibilityRole="button"
  accessibilityHint="Double tap to open chat"
  onPress={() => openChat('rahul456')}
>
  <Image source={avatar} accessibilityElementsHidden={true} />
  <Text importantForAccessibility="no">Rahul</Text>
  <Text importantForAccessibility="no">Hey, are you coming?</Text>
  <Text importantForAccessibility="no">10:30 AM</Text>
</Pressable>

Key props for grouping

PropPlatformEffect
accessible={true}BothMakes the container a single accessibility element
accessibilityElementsHidden={true}iOSHides children from VoiceOver
importantForAccessibility="no"AndroidHides element from TalkBack
importantForAccessibility="no-hide-descendants"AndroidHides element AND all its children

5. Dynamic font scaling

Many users (especially older adults) set their phone's font size to "Large" or "Extra Large". Your app must respect this setting — text should grow larger without breaking the layout.

// React Native respects system font scaling BY DEFAULT.
// A <Text> with fontSize: 16 will appear larger if the user's font scale is 1.5x.

// The problems come when you PREVENT scaling or don't account for it:

// ❌ Bad: disabling font scaling
<Text allowFontScaling={false}>Hello</Text>
// This locks text at its coded size — visually impaired users can't enlarge it

// ✅ Good: allow scaling (this is the default — just don't override it)
<Text>Hello</Text>

// ❌ Bad: fixed height container that clips enlarged text
<View style={{ height: 40 }}>
  <Text style={{ fontSize: 16 }}>This might get clipped at 2x font scale</Text>
</View>

// ✅ Good: flexible height that grows with text
<View style={{ minHeight: 40, paddingVertical: 8 }}>
  <Text style={{ fontSize: 16 }}>This grows as needed</Text>
</View>

Setting a maximum scale factor

Sometimes unlimited scaling breaks your layout (e.g., a tab bar). You can cap scaling without disabling it entirely:

// Allow scaling up to 1.5x (150%), but not beyond
<Text maxFontSizeMultiplier={1.5}>Tab Label</Text>

// For the message input, allow up to 1.3x
<TextInput maxFontSizeMultiplier={1.3} style={styles.input} />

// For message bubbles — allow full scaling (no cap)
<Text>{message.text}</Text>

Testing font scaling

// Android: Settings → Display → Font size (drag slider to max)

// In Expo, you can also test via the Accessibility Inspector:
// iOS Simulator → Xcode → Open Developer Tool → Accessibility Inspector

6. Minimum touch target size (44x44 points)

Apple's Human Interface Guidelines and Google's Material Design both require interactive elements to be at least 44x44 points (iOS) or 48x48 dp (Android). Small buttons are impossible for users with motor impairments to tap accurately.

// ❌ Bad: tiny 24x24 icon button — impossible to tap accurately
<Pressable onPress={handleCall} style={{ width: 24, height: 24 }}>
  <Text>📞</Text>
</Pressable>

// ✅ Good: visual icon is 24px but tap target is 44px
<Pressable
  onPress={handleCall}
  accessibilityLabel="Voice call"
  accessibilityRole="button"
  style={styles.iconButton}
  hitSlop={{ top: 10, bottom: 10, left: 10, right: 10 }}
>
  <Text style={{ fontSize: 24 }}>📞</Text>
</Pressable>

const styles = StyleSheet.create({
  iconButton: {
    // Visual: centered 24px icon
    width: 44,       // But the tap area is 44x44!
    height: 44,
    justifyContent: 'center',
    alignItems: 'center',
  },
});

hitSlop — expand tap area without expanding visual size

// hitSlop adds invisible padding to the tap target
// Great when you can't make the visual element bigger

<Pressable
  hitSlop={{ top: 12, bottom: 12, left: 12, right: 12 }}
  onPress={handleAction}
>
  <Text style={{ fontSize: 12 }}>Small text link</Text>
</Pressable>
// Visual size: tiny
// Tap target: tiny + 12px in all directions = much easier to tap

Common offenders in a chat app

  • Emoji reaction buttons — often 20x20px. Make them at least 44x44.
  • Header action icons (video call, search, menu) — use hitSlop if they're smaller than 44px.
  • Message timestamp — if tappable, needs a proper target size.
  • Close/X buttons on modals — notoriously small. Use 44x44 minimum.

7. Colour contrast (WCAG AA compliance)

Text must have enough contrast against its background for users with low vision to read it. The standard is WCAG AA: at least 4.5:1 ratio for normal text, 3:1 for large text.

ExampleRatioPasses?
Black (#000) on White (#FFF)21:1✅ Excellent
Dark green (#075E54) on White (#FFF)7.4:1✅ Good
White (#FFF) on Light green (#25D366)2.1:1❌ Fails!
Gray (#999) on White (#FFF)2.8:1❌ Fails!
Dark gray (#555) on Light gray (#ECE5DD)4.6:1✅ Passes
 
// Fixing contrast issues in our WhatsApp colours:

// ❌ Fails: white text on lightGreen (#25D366) = 2.1:1 ratio
<View style={{ backgroundColor: '#25D366' }}>
  <Text style={{ color: '#FFFFFF' }}>Send</Text>
</View>

// ✅ Passes: white text on darkGreen (#075E54) = 7.4:1 ratio
<View style={{ backgroundColor: '#075E54' }}>
  <Text style={{ color: '#FFFFFF' }}>Send</Text>
</View>

// ✅ Alternative: dark text on lightGreen
<View style={{ backgroundColor: '#25D366' }}>
  <Text style={{ color: '#0a3d2a' }}>Send</Text>  {/* Dark green text = 5.3:1 */}
</View>

// Timestamp text — often too light:
// ❌ #999 on #DCF8C6 (bubbleGreen) = 2.5:1
// ✅ #555 on #DCF8C6 = 4.8:1

Tools for checking contrast

  • WebAIM Contrast Checker — paste two colours, see the ratio instantly
  • Expo Accessibility Inspector — highlights contrast violations
  • iOS: Settings → Accessibility → Display → Increase Contrast — see how your app looks

8. accessibilityLiveRegion — announcing new messages

When a new message arrives, screen reader users need to be told — otherwise they won't know. accessibilityLiveRegion makes the screen reader automatically announce dynamic content changes.

// ❌ Bad: new message arrives silently — blind user doesn't know
<FlatList
  data={messages}
  renderItem={renderMessage}
/>

// ✅ Good: announce new messages as they arrive
function MessageThread({ messages }) {
  const [latestMessage, setLatestMessage] = useState('');

  useEffect(() => {
    if (messages.length > 0) {
      const newest = messages[0]; // First item (inverted list)
      setLatestMessage(`New message from ${newest.senderName}: ${newest.text}`);
    }
  }, [messages]);

  return (
    <View style={{ flex: 1 }}>
      {/* Hidden element that announces new messages */}
      <View
        accessibilityLiveRegion="polite"
        accessibilityRole="alert"
        style={{ position: 'absolute', width: 1, height: 1, opacity: 0 }}
      >
        <Text>{latestMessage}</Text>
      </View>

      <FlatList
        data={messages}
        renderItem={renderMessage}
        inverted
      />
    </View>
  );
}

Live region types

ValueBehaviourUse for
"polite"Waits for the current announcement to finish, then speaksNew messages, status updates
"assertive"Interrupts whatever is being spokenUrgent alerts, errors, incoming calls
"none"Don't announce changes (default)Decorative or frequently-changing content (timers)
 
// Incoming call alert — interrupt immediately
<View accessibilityLiveRegion="assertive" accessibilityRole="alert">
  <Text>Incoming call from {callerName}</Text>
</View>

// Typing indicator — polite (non-urgent)
<View accessibilityLiveRegion="polite">
  <Text>{typingUser} is typing...</Text>
</View>

// Message send status — polite
<View accessibilityLiveRegion="polite">
  <Text>Message sent</Text>
</View>

10. Full working example — accessible chat app

Here's a complete App.js with full accessibility: labelled elements, proper roles, grouped chat rows, live region for new messages, contrast-safe colours, and scalable text.

// App.js — Fully Accessible Chat App Demo

import React, { useState, useEffect } from 'react';
import {
  View, Text, TextInput, FlatList, Pressable,
  StyleSheet, Platform, KeyboardAvoidingView,
  AccessibilityInfo, Switch,
} from 'react-native';

// ─── WhatsApp colours (contrast-checked) ─────────────
const COLORS = {
  darkGreen: '#075E54',   // 7.4:1 on white ✓
  lightGreen: '#25D366',
  bubbleGreen: '#DCF8C6',
  chatBg: '#ECE5DD',
  white: '#FFFFFF',
  // Accessible text colours:
  textPrimary: '#1a1a1a', // 17:1 on white ✓
  textSecondary: '#4a4a4a', // 9.7:1 on white ✓
  textOnGreen: '#0a3d2a',   // 5.3:1 on lightGreen ✓

// ─── Accessible Chat Row ─────────────────────────────
function ChatRow({ chat, onPress }) {
  const unreadLabel = chat.unread > 0
    ? `, ${chat.unread} unread messages`
    : '';

  return (
    <Pressable
      accessible={true}
      accessibilityLabel={`Chat with ${chat.name}. Last message: ${chat.lastMsg}. ${chat.time}${unreadLabel}`}
      accessibilityRole="button"
      accessibilityHint="Double tap to open this conversation"
      onPress={onPress}
      style={styles.chatRow}
    >
      {/* Avatar — hidden from screen reader (info is in the parent label) */}
      <View
        style={styles.avatar}
        accessibilityElementsHidden={true}
        importantForAccessibility="no-hide-descendants"
      >
        <Text style={styles.avatarText}>{chat.name[0]}</Text>
      </View>

      {/* Text content — hidden individually, parent label covers it */}
      <View style={styles.chatInfo} importantForAccessibility="no">
        <View style={styles.chatHeader}>
          <Text style={styles.chatName}>{chat.name}</Text>
          <Text style={styles.chatTime}>{chat.time}</Text>
        </View>
        <View style={styles.chatPreviewRow}>
          <Text style={styles.chatPreview} numberOfLines={1}>{chat.lastMsg}</Text>
          {chat.unread > 0 && (
            <View style={styles.badge}>
              <Text style={styles.badgeText}>{chat.unread}</Text>
            </View>
          )}
        </View>
      </View>
    </Pressable>
  );
}

// ─── Accessible Message Bubble ───────────────────────
function MessageBubble({ message, isMe }) {
  const timeStr = message.time;
  const senderStr = isMe ? 'You' : message.senderName;

  return (
    <View
      accessible={true}
      accessibilityLabel={`${senderStr}: ${message.text}. ${timeStr}`}
      accessibilityRole="text"
      style={[styles.bubble, isMe ? styles.myBubble : styles.theirBubble]}
    >
      <Text style={styles.messageText}>{message.text}</Text>
      <Text style={styles.timeText}>{timeStr}</Text>
    </View>
  );
}

// ─── Message Thread Screen ───────────────────────────
function MessageThreadScreen({ chat, onBack }) {
  const [messages, setMessages] = useState([
    { id: '1', senderId: chat.id, senderName: chat.name, text: 'Hey! How are you?', time: '10:30 AM' },
    { id: '2', senderId: 'me', senderName: 'You', text: 'Good! Working on accessibility.', time: '10:31 AM' },
    { id: '3', senderId: chat.id, senderName: chat.name, text: 'That is great!', time: '10:32 AM' },
  ]);
  const [input, setInput] = useState('');
  const [latestAnnouncement, setLatestAnnouncement] = useState('');

  const handleSend = () => {
    if (!input.trim()) return;
    const newMsg = {
      id: String(Date.now()),
      senderId: 'me',
      senderName: 'You',
      text: input.trim(),
      time: 'Now',
    };
    setMessages(prev => [newMsg, ...prev]);
    setLatestAnnouncement(`Message sent: ${input.trim()}`);
    setInput('');
  };

  // Simulate incoming message (for demo)
  useEffect(() => {
    const timer = setTimeout(() => {
      const incoming = {
        id: 'incoming1',
        senderId: chat.id,
        senderName: chat.name,
        text: 'By the way, is the app working with TalkBack now?',
        time: 'Just now',
      };
      setMessages(prev => [incoming, ...prev]);
      setLatestAnnouncement(`New message from ${chat.name}: ${incoming.text}`);
    }, 5000);
    return () => clearTimeout(timer);
  }, []);

  return (
    <KeyboardAvoidingView
      style={styles.container}
      behavior={Platform.OS === 'ios' ? 'padding' : 'height'}
    >
      {/* Header */}
      <View style={styles.header}>
        <Pressable
          accessibilityLabel="Go back"
          accessibilityRole="button"
          onPress={onBack}
          hitSlop={{ top: 12, bottom: 12, left: 12, right: 12 }}
          style={styles.backBtn}
        >
          <Text style={styles.backText}>←</Text>
        </Pressable>
        <View>
          <Text style={styles.headerTitle} accessibilityRole="header">
            {chat.name}
          </Text>
          <Text style={styles.headerSubtitle}>online</Text>
        </View>

        {/* Call buttons with proper targets */}
        <View style={styles.headerActions}>
          <Pressable
            accessibilityLabel={`Voice call ${chat.name}`}
            accessibilityRole="button"
            hitSlop={{ top: 10, bottom: 10, left: 10, right: 10 }}
            style={styles.headerIcon}
          >
            <Text style={{ fontSize: 20 }}>📞</Text>
          </Pressable>
          <Pressable
            accessibilityLabel={`Video call ${chat.name}`}
            accessibilityRole="button"
            hitSlop={{ top: 10, bottom: 10, left: 10, right: 10 }}
            style={styles.headerIcon}
          >
            <Text style={{ fontSize: 20 }}>📹</Text>
          </Pressable>
        </View>
      </View>

      {/* Live region — announces new messages to screen reader */}
      <View
        accessibilityLiveRegion="polite"
        accessibilityRole="alert"
        style={styles.srOnly}
      >
        <Text>{latestAnnouncement}</Text>
      </View>

      {/* Messages */}
      <FlatList
        data={messages}
        keyExtractor={(item) => item.id}
        inverted
        style={styles.messageList}
        contentContainerStyle={{ paddingVertical: 10 }}
        renderItem={({ item }) => (
          <MessageBubble
            message={item}
            isMe={item.senderId === 'me'}
          />
        )}
      />

      {/* Input bar */}
      <View style={styles.inputBar}>
        <TextInput
          style={styles.input}
          value={input}
          onChangeText={setInput}
          placeholder="Type a message"
          accessibilityLabel="Message text field"
          accessibilityHint="Type your message and press send"
          multiline
          maxLength={4096}
        />
        <Pressable
          style={[styles.sendBtn, !input.trim() && styles.sendBtnDisabled]}
          onPress={handleSend}
          disabled={!input.trim()}
          accessibilityLabel="Send message"
          accessibilityRole="button"
          accessibilityState={{ disabled: !input.trim() }}
          accessibilityHint={input.trim() ? 'Double tap to send' : 'Type a message first'}
        >
          <Text style={styles.sendText}>Send</Text>
        </Pressable>
      </View>
    </KeyboardAvoidingView>
  );
}

// ─── Main App ────────────────────────────────────────
export default function App() {
  const [currentChat, setCurrentChat] = useState(null);
  const [screenReaderEnabled, setScreenReaderEnabled] = useState(false);

  // Detect if screen reader is active
  useEffect(() => {
    AccessibilityInfo.isScreenReaderEnabled().then(setScreenReaderEnabled);
    const subscription = AccessibilityInfo.addEventListener(
      'screenReaderChanged',
      setScreenReaderEnabled
    );
    return () => subscription.remove();
  }, []);

  if (currentChat) {
    return (
      <MessageThreadScreen
        chat={currentChat}
        onBack={() => setCurrentChat(null)}
      />
    );
  }

  return (
    <View style={{ flex: 1 }}>
      <ChatListScreen onOpenChat={setCurrentChat} />

      {/* Accessibility status (for demo purposes) */}
      <View style={styles.a11yStatus}>
        <Text style={styles.a11yText}>
          Screen reader: {screenReaderEnabled ? 'ON' : 'OFF'}
        </Text>
        <Text style={styles.a11yHint}>
          Turn on VoiceOver/TalkBack to test accessibility
        </Text>
      </View>
    </View>
  );
}

11. Key takeaways

  • Every interactive element needs accessibilityLabel — describe the action, not the appearance
  • accessibilityRole tells the screen reader the element type — button, link, header, image, etc.
  • Group related elements — accessible={true} on a container with a combined label
  • Minimum 44x44 tap targets — use hitSlop if the visual element is smaller
  • Allow font scaling — never set allowFontScaling={false}; use minHeight instead of fixed height
  • Contrast ratio ≥ 4.5:1 — check timestamps, subtitles, and placeholder text
  • accessibilityLiveRegion="polite" — announces new messages to screen reader users
  • Hide decorative elements — accessibilityElementsHidden (iOS) and importantForAccessibility="no" (Android)
  • Test with a real screen reader — VoiceOver on iOS, TalkBack on Android, at least 30 minutes
  • AccessibilityInfo.isScreenReaderEnabled() — detect if a screen reader is active (show extra help)
Accessibility helps everyone

Accessibility improvements help ALL users: larger tap targets reduce mis-taps for everyone, better contrast helps in sunlight, grouped elements speed up navigation, and live regions help users who look away from their screen. Accessibility isn't a checkbox — it makes your app better for the 100%, not just the 15% with disabilities.

Logs, Backups & Monitoring

B9 — Lesson 3 of 3  |  ~45 min

Why this matters for Token: Your app is live. Users are issuing tokens, redeeming them, and chatting through your WebSocket server. When something breaks at 2 AM, you need three things: logs that tell you what went wrong, backups so you don't lose data, and alerts so you know it happened without users telling you. This lesson sets up all three.

Structured Logging

Console.log is for development. In production, you need structured logs — JSON objects with consistent fields that can be searched, filtered, and aggregated.

Why JSON Logs?

// ❌ Unstructured — hard to parse, impossible to filter
console.log("User 42 redeemed token MERC-8GH2 at 2024-03-15T10:30:00Z");

// ✓ Structured — machine-readable, searchable
{
  "level": "info",
  "msg": "token redeemed",
  "userId": 42,
  "tokenCode": "MERC-8GH2",
  "timestamp": "2024-03-15T10:30:00.123Z",
  "requestId": "req-abc-123",
  "duration_ms": 45
}

Building a Logger with pino

pino is the fastest Node.js JSON logger — 10x faster than winston because it writes JSON directly without formatting overhead.

# Install
npm install pino pino-http
// api/src/logger.ts
import pino from 'pino';

export const logger = pino({
  level: process.env.LOG_LEVEL || 'info',
  // In production, output raw JSON (for log aggregators)
  // In development, use pino-pretty for readable output
  transport: process.env.NODE_ENV !== 'production'
    ? { target: 'pino-pretty', options: { colorize: true } }
    : undefined,
  // Base fields included in every log line
  base: {
    service: 'token-api',
    version: process.env.npm_package_version,
  },
});

// Child loggers inherit parent fields and add their own
export function createChildLogger(context: Record<string, unknown>) {
  return logger.child(context);
}

Request Logging with Correlation IDs

Every HTTP request gets a unique ID. All log lines during that request include it — so you can trace a single request across your entire system.

// api/src/middleware/requestLogger.ts
import { randomUUID } from 'crypto';
import pinoHttp from 'pino-http';
import { logger } from '../logger';

export const requestLogger = pinoHttp({
  logger,
  genReqId: (req) => {
    // Use client-provided ID if present, otherwise generate one
    return (req.headers['x-request-id'] as string) || randomUUID();
  },
  customProps: (req) => ({
    requestId: req.id,
  }),
  // Don't log health check spam
  autoLogging: {
    ignore: (req) => req.url === '/health',
  },
  // What to include in the request log
  serializers: {
    req: (req) => ({
      method: req.method,
      url: req.url,
      // Don't log authorization header (contains JWT)
      headers: { 'user-agent': req.headers['user-agent'] },
    }),
    res: (res) => ({
      statusCode: res.statusCode,
    }),
  },
});

// Usage in Express
// app.use(requestLogger);
// Now every request logs: method, url, statusCode, duration, requestId

Application-Level Logging

// In your route handlers, use the request's logger
// (it already has requestId attached)

import { Request, Response } from 'express';

export async function redeemToken(req: Request, res: Response) {
  const { code } = req.params;

  // req.log is added by pino-http — it includes requestId automatically
  req.log.info({ tokenCode: code }, 'token redemption attempt');

  try {
    const token = await findTokenByCode(code);

    if (!token) {
      req.log.warn({ tokenCode: code }, 'token not found');
      return res.status(404).json({ error: 'token not found' });
    }

    if (token.revoked_at) {
      req.log.warn({ tokenCode: code, revokedAt: token.revoked_at }, 'revoked token redemption attempt');
      return res.status(410).json({ error: 'token revoked' });
    }

    const event = await createRedemptionEvent(token.id, req.ip);
    req.log.info({ tokenId: token.id, eventId: event.id }, 'token redeemed successfully');

    res.json({ success: true, conversationId: event.conversation_id });
  } catch (err) {
    req.log.error({ err, tokenCode: code }, 'token redemption failed');
    res.status(500).json({ error: 'internal error' });
  }
}

Log Levels

LevelWhen to useToken example
fatalApp is crashing, cannot continueDatabase connection lost permanently
errorSomething failed that shouldn'tFailed to send push notification after retries
warnUnusual but handledRevoked token redemption attempt
infoNormal business eventsToken issued, token redeemed, user registered

traceEverything (noisy, dev only)Every SQL query, every function entry

In production, set LOG_LEVEL=info. Switch to debug when investigating an issue. Never run trace in production — the volume will fill your disk.

Viewing Logs

Coolify shows container logs in its dashboard. You can also SSH in and use Docker directly:

# View live logs (follow mode)
docker logs -f token-api --since 1h

# Search logs for a specific request
docker logs token-api 2>&1 | grep "req-abc-123"

# View logs with timestamps
docker logs -t token-api --since "2024-03-15T10:00:00"

# Pipe through pino-pretty for readability (install globally on server)
docker logs token-api | npx pino-pretty

Database Backups

Your users' tokens, messages, and access rules live in Postgres. If the database is lost, everything is lost. Automated backups are non-negotiable.

pg_dump — The Standard Backup Tool

# Full database dump (custom compressed format)
pg_dump -U token -d token_prod -Fc > backup_2024-03-15.dump

# Restore from backup
pg_restore -U token -d token_prod --clean backup_2024-03-15.dump

# SQL-format dump (readable, larger)
pg_dump -U token -d token_prod > backup_2024-03-15.sql

Automated Backup Script

#!/bin/bash
# api/scripts/backup.sh
# Runs daily via cron — dumps Postgres and keeps 7 days of backups

set -euo pipefail

BACKUP_DIR="/backups/postgres"
RETENTION_DAYS=7
TIMESTAMP=$(date +%Y-%m-%d_%H-%M-%S)
FILENAME="token_prod_${TIMESTAMP}.dump"

# Create backup directory if it doesn't exist
mkdir -p "$BACKUP_DIR"

# Dump the database (using Docker exec into the Postgres container)
docker exec token-postgres pg_dump \
  -U token \
  -d token_prod \
  -Fc \
  > "${BACKUP_DIR}/${FILENAME}"

# Verify the backup is non-empty
if [ ! -s "${BACKUP_DIR}/${FILENAME}" ]; then
  echo "ERROR: Backup file is empty!" >&2
  exit 1
fi

# Report size
BACKUP_SIZE=$(du -h "${BACKUP_DIR}/${FILENAME}" | cut -f1)
echo "Backup created: ${FILENAME} (${BACKUP_SIZE})"

# Delete backups older than retention period
find "$BACKUP_DIR" -name "*.dump" -mtime +${RETENTION_DAYS} -delete
echo "Cleaned up backups older than ${RETENTION_DAYS} days"

Scheduling with cron

# SSH into your VPS, then:
crontab -e

# Add this line — runs backup at 3:00 AM daily

# Verify it's scheduled
crontab -l

Off-Site Backups

A backup on the same server as the database doesn't protect against disk failure or a compromised server. Copy backups off-site:

# Option 1: rsync to a second VPS or NAS
rsync -az /backups/postgres/ backup-user@other-server:/backups/token/

# Option 2: Upload to S3-compatible storage (Backblaze B2, ~$0.005/GB)
# Install rclone, configure a remote, then:
rclone copy /backups/postgres/ b2:token-backups/postgres/

# Option 3: Coolify's built-in backup feature (if using managed Postgres)
# Configure in Coolify → Database → Backups → Enable S3

Testing Restores

A backup you've never restored from is not a backup. Test quarterly:

# Restore to a temporary database (not production!)
createdb -U token token_restore_test
pg_restore -U token -d token_restore_test /backups/postgres/latest.dump

# Verify data is intact
psql -U token -d token_restore_test -c "SELECT COUNT(*) FROM users;"
psql -U token -d token_restore_test -c "SELECT COUNT(*) FROM tokens;"

# Clean up
dropdb -U token token_restore_test

Health Checks & Uptime Monitoring

You need to know when your app is down before your users tell you.

Internal Health Checks

You already wrote /health in the previous lesson. Extend it to check all dependencies:

// api/src/routes/health.ts
import { Router } from 'express';
import { db } from '../db';
import { redisClient } from '../redis';

const router = Router();

// Simple liveness check — is the process running?
router.get('/health/live', (req, res) => {
  res.json({ status: 'ok' });
});

// Readiness check — can the app serve traffic?
router.get('/health/ready', async (req, res) => {
  const checks: Record<string, 'ok' | 'fail'> = {};

  try {
    await db.query('SELECT 1');
    checks.database = 'ok';
  } catch {
    checks.database = 'fail';
  }

  try {
    await redisClient.ping();
    checks.redis = 'ok';
  } catch {
    checks.redis = 'fail';
  }

  const allOk = Object.values(checks).every(v => v === 'ok');
  const statusCode = allOk ? 200 : 503;

  res.status(statusCode).json({
    status: allOk ? 'healthy' : 'degraded',
    checks,
    timestamp: new Date().toISOString(),
    uptime: process.uptime(),
  });
});

export default router;

External Uptime Monitoring

An external service pings your health endpoint every minute. If it fails, you get an alert. Free options:

  • UptimeRobot — 50 free monitors, 5-min intervals, email/SMS/Slack alerts
  • Uptime Kuma — self-hosted (run it on your VPS), 1-min intervals
  • Betterstack (formerly Better Uptime) — free tier with status pages

Configure two monitors:

  1. https://api.tokn.app/health/ready — full health (DB + Redis)
  2. https://tokn.app/health — web page is serving (nginx responds)

Basic Alerting Pattern

For a solo developer, the simplest alerting is a webhook that sends to your phone:

// api/src/services/alerting.ts
import { logger } from '../logger';

const ALERT_WEBHOOK = process.env.ALERT_WEBHOOK_URL; // Slack, Discord, or Telegram

interface Alert {
  severity: 'warning' | 'critical';
  title: string;
  detail: string;
}

export async function sendAlert(alert: Alert): Promise<void> {
  if (!ALERT_WEBHOOK) {
    logger.warn(alert, 'alert triggered but no webhook configured');
    return;
  }

  try {
    await fetch(ALERT_WEBHOOK, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        text: `[${alert.severity.toUpperCase()}] ${alert.title}\n${alert.detail}`,
      }),
    });
  } catch (err) {
    // Don't throw — alerting failure shouldn't crash the app
    logger.error({ err, alert }, 'failed to send alert');
  }
}

// Usage examples:
// sendAlert({ severity: 'critical', title: 'Database unreachable', detail: 'SELECT 1 timed out after 5s' });
// sendAlert({ severity: 'warning', title: 'High memory usage', detail: 'RSS: 450MB / 512MB limit' });

Monitoring Key Metrics

Even without a full monitoring stack (Prometheus/Grafana), you can track essential metrics in your logs:

// api/src/middleware/metrics.ts
import { logger } from '../logger';

// Log slow requests
export function slowRequestLogger(thresholdMs = 1000) {
  return (req: any, res: any, next: any) => {
    const start = Date.now();

    res.on('finish', () => {
      const duration = Date.now() - start;
      if (duration > thresholdMs) {
        req.log.warn({
          duration_ms: duration,
          threshold_ms: thresholdMs,
          method: req.method,
          url: req.url,
        }, 'slow request detected');
      }
    });

    next();
  };
}

// Periodic health report (every 5 minutes)
setInterval(async () => {
  const memUsage = process.memoryUsage();
  logger.info({
    memory: {
      rss_mb: Math.round(memUsage.rss / 1024 / 1024),
      heap_used_mb: Math.round(memUsage.heapUsed / 1024 / 1024),
      heap_total_mb: Math.round(memUsage.heapTotal / 1024 / 1024),
    },
    uptime_hours: Math.round(process.uptime() / 3600 * 10) / 10,
  }, 'periodic health report');
}, 5 * 60 * 1000);

Docker Log Rotation

Without rotation, container logs grow forever and fill your disk. Configure Docker's log driver to auto-rotate:

// /etc/docker/daemon.json (on your VPS)
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "50m",
    "max-file": "5"
  }
}

// Each container keeps at most 5 log files of 50MB each = 250MB max per container
// Restart Docker after changing: sudo systemctl restart docker

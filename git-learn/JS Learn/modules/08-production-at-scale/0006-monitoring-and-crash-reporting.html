Production at Scale · Lesson 6

Monitoring & Crash Reporting

Crashlytics · Sentry · Logging strategy · Performance monitoring · Alerts ~55 min Hands-on
Why this matters for your WhatsApp clone

Right now, if your app crashes on a user's phone, you have no idea. The user just silently stops using it. With crash reporting, you get an alert within minutes: "5 users crashed on the MessageThread screen on Android 12 when they tap a voice message." You know exactly what broke, on which device, and can fix it before 500 more users hit it. Every serious app — WhatsApp, Instagram, Spotify — uses crash reporting and performance monitoring. It's how they ship fixes within hours of a problem appearing.

1. Two options: Firebase Crashlytics vs. Sentry

Both are excellent crash reporting tools. Here's how they compare for a React Native + Expo app:

Firebase CrashlyticsSentry
PriceFree (unlimited)Free tier: 5K events/month; paid plans after
Expo supportRequires EAS Build + config pluginFirst-class Expo support (sentry-expo)
JavaScript errorsLimited — better for native crashesExcellent — full JS stack traces with source maps
Native crashesExcellent (ObjC/Java/C++)Good
Performance monitoringYes (Firebase Performance)Yes (built-in)
Already in your stackYes (you use Firebase)Extra service to set up
Best forNative crashes + Firebase-heavy appsJS errors + detailed debugging

Recommendation for your app: Use Sentry for JavaScript crash reporting (easier setup with Expo, better JS stack traces) and Firebase Performance for performance monitoring (already in your stack). This gives you the best of both.

2. Setting up Sentry with Expo

Step 1: Install

npx expo install @sentry/react-native

Step 2: Create a Sentry project

  1. Sign up at sentry.io (free tier is enough to start)
  2. Create a new project → choose "React Native"
  3. Copy your DSN (a URL that identifies your project)

Step 3: Initialize in your app

// App.js — at the very top, before all other imports
import * as Sentry from '@sentry/react-native';

Sentry.init({
  dsn: 'https://abc123@o123456.ingest.sentry.io/789',
  // Only send errors in production (not during development)
  enabled: !__DEV__,
  // Capture 20% of transactions for performance monitoring
  tracesSampleRate: 0.2,
  // Attach user info to crash reports
  beforeSend(event) {
    // Strip any sensitive data before sending
    if (event.user) {
      delete event.user.email; // don't send emails to Sentry
    }
    return event;
  },
});

// Wrap your root component with Sentry's error boundary
export default Sentry.wrap(function App() {
  // your app code...
});

Step 4: Add the Expo config plugin

// app.json (or app.config.js)
{
  "expo": {
    "plugins": [
      [
        "@sentry/react-native/expo",
        {
          "organization": "your-org",
          "project": "your-whatsapp-clone"
        }
      ]
    ]
  }
}

Step 5: Upload source maps (for readable stack traces)

// In eas.json, add the Sentry upload step
{
  "build": {
    "production": {
      "env": {
        "SENTRY_AUTH_TOKEN": "your-sentry-auth-token"
      }
    }
  }
}

// Source maps upload automatically during EAS Build with the plugin configured

3. What to log (and what NOT to log)

Logging everything fills your crash dashboard with noise. Log strategically:

DO log (as breadcrumbs)

import * as Sentry from '@sentry/react-native';

// Navigation events — "user was on this screen when it crashed"
Sentry.addBreadcrumb({
  category: 'navigation',
  message: 'Opened MessageThread for chat: group-family',
  level: 'info',
});

// Key user actions — "what did they do before the crash?"
Sentry.addBreadcrumb({
  category: 'user-action',
  message: 'Tapped send button',
  level: 'info',
});

// Network status changes — "were they offline?"
Sentry.addBreadcrumb({
  category: 'network',
  message: 'Network changed: wifi → none',
  level: 'warning',
});

// Firebase errors that you handle (but want to track frequency)
Sentry.addBreadcrumb({
  category: 'firebase',
  message: 'Firestore write failed: unavailable (will retry)',
  level: 'warning',
});

DO NOT log

  • Message content — private; never send to a third party
  • Passwords or tokens — obvious security risk
  • Every state update — too noisy, fills up your event quota
  • Successful operations — you only need to know when things go wrong
  • Phone numbers or emails — PII that you don't need for debugging

Setting user context (without PII)

// After login, attach the user ID (NOT email/phone)
import * as Sentry from '@sentry/react-native';

function onLoginSuccess(user) {
  Sentry.setUser({
    id: user.uid,  // enough to look up the user if needed
    // Do NOT include: email, phone, name
  });
}

function onLogout() {
  Sentry.setUser(null); // clear user context
}

4. Capturing errors at different levels

import * as Sentry from '@sentry/react-native';

// Level 1: Automatic crash capture (unhandled exceptions)
// → Sentry.wrap() handles this automatically. No extra code needed.

// Level 2: Caught errors you want to track
async function sendMessage(chatId, text) {
  try {
    await addDoc(collection(db, 'chats', chatId, 'messages'), { ... });
  } catch (error) {
    if (!isRetryableError(error)) {
      // Permanent error — report to Sentry
      Sentry.captureException(error, {
        tags: { screen: 'MessageThread', action: 'send_message' },
        extra: { chatId, textLength: text.length },
      });
    }
    throw error; // re-throw so the UI handles it
  }
}

// Level 3: Warnings (things that shouldn't happen but aren't crashes)
function loadUserProfile(userId) {
  const doc = await getDoc(userRef);
  if (!doc.exists()) {
    // User exists in Auth but not in Firestore — data inconsistency
    Sentry.captureMessage('User profile missing in Firestore', {
      level: 'warning',
      extra: { userId },
    });
    return defaultProfile;
  }
  return doc.data();
}

// Level 4: Custom events for business metrics
function trackCallDropped(callId, duration, reason) {
  Sentry.captureMessage('Call dropped', {
    level: 'info',
    tags: { reason }, // 'network', 'timeout', 'user_hangup'
    extra: { callId, durationSeconds: duration },
  });
}

5. Firebase Performance Monitoring

Performance monitoring tells you how long things take in production — not on your fast WiFi, but on your users' real devices and connections.

Setup

npx expo install @react-native-firebase/perf

// app.json
{
  "expo": {
    "plugins": [
      "@react-native-firebase/perf"
    ]
  }
}

Automatic monitoring (free with setup)

  • App start time — how long from tap to first screen
  • HTTP request latency — all fetch/XHR requests automatically tracked
  • Screen rendering — slow/frozen frames detected automatically

Custom traces (measure what you care about)

import perf from '@react-native-firebase/perf';

// Measure how long it takes to load a chat
async function loadChatWithTrace(chatId) {
  const trace = await perf().startTrace('load_chat_messages');
  trace.putAttribute('chatId', chatId);

  const messages = await getDocs(
    query(collection(db, 'chats', chatId, 'messages'),
      orderBy('createdAt', 'desc'),
      limit(30))
  );

  trace.putMetric('message_count', messages.size);
  await trace.stop(); // records duration automatically

  return messages;
}

// Measure image upload time
async function uploadImageWithTrace(uri, path) {
  const trace = await perf().startTrace('upload_image');

  const response = await fetch(uri);
  const blob = await response.blob();
  trace.putMetric('file_size_bytes', blob.size);

  await uploadBytes(ref(storage, path), blob);
  await trace.stop();
}

// Measure time-to-interactive for the chat list screen
function ChatListScreen() {
  const traceRef = useRef(null);

  useEffect(() => {
    async function startTrace() {
      traceRef.current = await perf().startTrace('chat_list_tti');
    }
    startTrace();
  }, []);

  // Call when the first data appears
  function onDataLoaded(chatCount) {
    if (traceRef.current) {
      traceRef.current.putMetric('chat_count', chatCount);
      traceRef.current.stop();
      traceRef.current = null;
    }
  }

  // ...
}

6. Basic analytics: DAU and messages/day

You don't need a full analytics suite to start. Track two numbers that tell you if your app is healthy:

import { getAnalytics, logEvent } from 'firebase/analytics';

const analytics = getAnalytics(app);

// Track daily active users (DAU)
// Firebase Analytics tracks this automatically via session events.
// But you can add custom events for deeper insight:

// When the app opens
function onAppOpen() {
  logEvent(analytics, 'app_open', {
    platform: Platform.OS,
  });
}

// When a message is sent (tells you engagement)
function onMessageSent(chatId, messageType) {
  logEvent(analytics, 'message_sent', {
    message_type: messageType, // 'text', 'image', 'voice'
    is_group: chatId.startsWith('group_'),
  });
}

// When a call is made
function onCallStarted(callType) {
  logEvent(analytics, 'call_started', {
    call_type: callType, // 'voice', 'video'
  });
}

// When a user signs up (funnel tracking)
function onSignupComplete() {
  logEvent(analytics, 'sign_up_complete');
}

What to track (and what not to)

Track ✅Don't track ❌
App opens per dayMessage content
Messages sent (count + type)Who is messaging whom
Calls started/durationCall audio/video content
Signup/login eventsPasswords or tokens
Feature usage (status views, group creates)Exact user location
Error frequency by typePersonal identifiers (email, phone)

7. Setting up alerts for error spikes

In Sentry

  1. Go to Alerts → Create Alert
  2. Choose "When number of errors exceeds a threshold"
  3. Set: "If more than 10 events in 1 hour → send email"
  4. Add a second alert: "If a new issue is seen for the first time → send immediately"

In Firebase Console

  1. Crashlytics → Alerts: auto-alerts when crash-free rate drops below 99%
  2. Performance → Alerts: alert when app start time exceeds 5 seconds

Recommended alert thresholds for your app

MetricAlert if...Severity
Crash-free rateBelow 99%🔴 Critical
New crash typeFirst occurrence🟡 Warning
Error spike10+ errors in 1 hour🟡 Warning
App start timeAbove 5 seconds (p95)🟡 Warning
Message send failure rateAbove 5%🔴 Critical

8. Reading crash reports — what to look for

When a crash comes in, here's how to read the report:

// Example Sentry crash report:

// 1. TITLE — what threw
// "TypeError: Cannot read property 'toDate' of null"

// 2. WHERE — stack trace (most important line is the top of YOUR code)
// at MessageBubble (MessageThread.js:142)
// at FlatList (node_modules/react-native/...)

// 3. BREADCRUMBS — what happened before the crash
// [info] navigation: Opened MessageThread for chat: group-family
// [info] user-action: Scrolled to older messages
// [warning] firebase: onSnapshot received doc with null createdAt
// [error] CRASH: TypeError: Cannot read property 'toDate' of null

// 4. DEVICE INFO
// Device: Samsung Galaxy A12, Android 12
// App version: 1.2.3
// Free RAM: 180MB

// 5. DIAGNOSIS
// The crash happens because a message document has createdAt: null
// (probably written while offline and not yet synced).
// Fix: add a null check before calling .toDate()
// Before: message.createdAt.toDate()
// After:  message.createdAt?.toDate?.() || new Date()

Triage checklist

  1. How many users affected? — 1 user = low priority; 500 = fix now
  2. Is it reproducible? — check if the same device/OS version keeps crashing
  3. Is it in critical path? — login screen crash > settings screen crash
  4. Can you reproduce locally? — use the breadcrumbs to replay the steps
  5. Is there a quick workaround? — null check, try/catch, or feature flag

9. Full working example — app with monitoring

// App.js — Monitoring & Crash Reporting Demo
// Shows: Sentry initialization, breadcrumbs, error capture,
// performance traces, and user context

import React, { useState, useEffect, useRef } from 'react';
import {
  View, Text, TextInput, FlatList, Pressable,
  StyleSheet, Alert, ActivityIndicator, Platform,
  KeyboardAvoidingView,
} from 'react-native';
import * as Sentry from '@sentry/react-native';
import { initializeApp } from 'firebase/app';
import { getAuth, signInWithEmailAndPassword } from 'firebase/auth';
import {
  getFirestore, collection, doc, query, orderBy,
  limit, onSnapshot, addDoc, serverTimestamp, writeBatch,
} from 'firebase/firestore';

// ─── Initialize Sentry FIRST ──────────────────
Sentry.init({
  dsn: 'https://your-dsn@sentry.io/your-project-id',
  enabled: !__DEV__,
  tracesSampleRate: 0.2,
  beforeSend(event) {
    if (event.user) delete event.user.email;
    return event;
  },
});

// ─── Firebase config ───────────────────────────
const firebaseConfig = {
  apiKey: 'YOUR_API_KEY',
  authDomain: 'your-app.firebaseapp.com',
  projectId: 'your-app',
  storageBucket: 'your-app.appspot.com',
  messagingSenderId: '123456789',
  appId: '1:123456789:web:abc123',
};

const app = initializeApp(firebaseConfig);
const auth = getAuth(app);
const db = getFirestore(app);

const COLORS = {
  darkGreen: '#075E54',
  lightGreen: '#25D366',
  bubbleGreen: '#DCF8C6',
  chatBg: '#ECE5DD',
  white: '#FFFFFF',
};

// ─── Logging helpers ───────────────────────────
function logNavigation(screen, params = {}) {
  Sentry.addBreadcrumb({
    category: 'navigation',
    message: `Opened ${screen}`,
    data: params,
    level: 'info',
  });
}

function logUserAction(action, details = {}) {
  Sentry.addBreadcrumb({
    category: 'user-action',
    message: action,
    data: details,
    level: 'info',
  });
}

function logFirebaseError(operation, error) {
  Sentry.addBreadcrumb({
    category: 'firebase',
    message: `${operation} failed: ${error.code || error.message}`,
    level: 'warning',
  });
}

// ─── Chat Screen with monitoring ───────────────
function ChatScreen({ chatId }) {
  const [messages, setMessages] = useState([]);
  const [input, setInput] = useState('');
  const [sending, setSending] = useState(false);
  const loadStartTime = useRef(Date.now());

  const userId = auth.currentUser?.uid;

  useEffect(() => {
    logNavigation('ChatScreen', { chatId });
    loadStartTime.current = Date.now();

    const q = query(
      collection(db, 'chats', chatId, 'messages'),
      orderBy('createdAt', 'desc'),
      limit(50)
    );

    const unsubscribe = onSnapshot(q, (snapshot) => {
      const msgs = snapshot.docs.map(d => ({ id: d.id, ...d.data() }));
      setMessages(msgs);

      // Track time-to-first-data
      if (loadStartTime.current) {
        const loadTime = Date.now() - loadStartTime.current;
        Sentry.addBreadcrumb({
          category: 'performance',
          message: `Chat loaded in ${loadTime}ms (${msgs.length} messages)`,
          level: 'info',
        });
        loadStartTime.current = null; // only track once
      }
    }, (error) => {
      // Listener error — log and report
      logFirebaseError('messages_listener', error);
      Sentry.captureException(error, {
        tags: { screen: 'ChatScreen', operation: 'onSnapshot' },
        extra: { chatId },
      });
    });

    return unsubscribe;
  }, [chatId]);

  const handleSend = async () => {
    const trimmed = input.trim();
    if (!trimmed) return;

    logUserAction('send_message', { chatId, textLength: trimmed.length });
    setSending(true);
    setInput('');

    try {
      const batch = writeBatch(db);
      const msgRef = doc(collection(db, 'chats', chatId, 'messages'));
      batch.set(msgRef, {
        senderId: userId,
        text: trimmed,
        createdAt: serverTimestamp(),
      });
      const chatRef = doc(db, 'chats', chatId);
      batch.update(chatRef, {
        lastMessage: trimmed.substring(0, 100),
        lastMessageAt: serverTimestamp(),
      });
      await batch.commit();
    } catch (error) {
      logFirebaseError('send_message', error);

      // Report non-retryable errors to Sentry
      if (error.code !== 'unavailable') {
        Sentry.captureException(error, {
          tags: { screen: 'ChatScreen', action: 'send_message' },
          extra: { chatId, textLength: trimmed.length },
        });
      }

      Alert.alert('Send failed', error.message);
      setInput(trimmed); // restore the text so they don't lose it
    } finally {
      setSending(false);
    }
  };

  const renderMessage = ({ item }) => {
    const isMine = item.senderId === userId;
    const isPending = !item.createdAt;

    return (
      <View style={[styles.bubble, isMine ? styles.myBubble : styles.theirBubble]}>
        <Text style={styles.messageText}>{item.text}</Text>
        <View style={styles.metaRow}>
          <Text style={styles.timeText}>
            {isPending
              ? 'Sending...'
              : item.createdAt?.toDate?.()
                ? item.createdAt.toDate().toLocaleTimeString([], {
                    hour: '2-digit', minute: '2-digit',
                  })
                : ''}
          </Text>
          {isMine && (
            <Text style={styles.tick}>{isPending ? '🕐' : '✓✓'}</Text>
          )}
        </View>
      </View>
    );
  };

  return (
    <KeyboardAvoidingView
      style={styles.container}
      behavior={Platform.OS === 'ios' ? 'padding' : 'height'}
    >
      <View style={styles.header}>
        <Text style={styles.headerTitle}>Priya</Text>
        <Text style={styles.headerSubtitle}>online</Text>
      </View>

      <FlatList
        data={messages}
        renderItem={renderMessage}
        keyExtractor={(item) => item.id}
        inverted
        style={styles.messageList}
        contentContainerStyle={{ paddingVertical: 10 }}
      />

      <View style={styles.inputBar}>
        <TextInput
          style={styles.input}
          value={input}
          onChangeText={setInput}
          placeholder="Type a message"
          maxLength={4096}
          multiline
        />
        <Pressable
          style={[styles.sendBtn, sending && { opacity: 0.5 }]}
          onPress={handleSend}
          disabled={sending}
        >
          {sending
            ? <ActivityIndicator color={COLORS.white} size="small" />
            : <Text style={styles.sendText}>Send</Text>
          }
        </Pressable>
      </View>
    </KeyboardAvoidingView>
  );
}

// ─── Main App (wrapped with Sentry) ───────────
function MainApp() {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    signInWithEmailAndPassword(auth, 'reviewer@yourapp.com', 'ReviewTest2026!')
      .then((cred) => {
        setUser(cred.user);
        // Set user context for crash reports (ID only, no PII)
        Sentry.setUser({ id: cred.user.uid });
      })
      .catch((err) => {
        Sentry.captureException(err, { tags: { screen: 'Login' } });
        Alert.alert('Login failed', err.message);
      })
      .finally(() => setLoading(false));
  }, []);

  if (loading) {
    return (
      <View style={styles.center}>
        <ActivityIndicator size="large" color={COLORS.darkGreen} />
      </View>
    );
  }

  if (!user) {
    return (
      <View style={styles.center}>
        <Text>Not logged in</Text>
      </View>
    );
  }

  return <ChatScreen chatId="chat1" />;
}

// Export wrapped with Sentry error boundary
export default Sentry.wrap(MainApp);

10. Key takeaways

  • Use Sentry for JS errors — first-class Expo support, readable stack traces with source maps
  • Use Firebase Performance — automatic app start, HTTP, and frame tracking
  • Log breadcrumbs, not content — navigation, actions, and errors; never message text or PII
  • Sentry.captureException() — for caught errors you want to track
  • Custom performance traces — measure load_chat, upload_image, time-to-interactive
  • Set user ID (not email) — enough to investigate but respects privacy
  • Set up alerts — crash-free rate < 99%, error spikes, new issue types
  • Read crash reports — stack trace + breadcrumbs + device info = fast diagnosis

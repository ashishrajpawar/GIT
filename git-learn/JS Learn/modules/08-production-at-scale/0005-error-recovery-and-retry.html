Production at Scale · Lesson 5

Error Recovery & Retry Logic

Exponential backoff · Retry queue · Graceful degradation · ErrorBoundary · User-facing errors ~55 min Hands-on
Why this matters for your WhatsApp clone

In the real world, things fail: Firebase has outages, the user's connection drops mid-upload, a server returns a 500 error. If your app just shows "Something went wrong" and gives up, users lose messages. WhatsApp never loses a message — if a send fails, it retries automatically in the background until it succeeds. This lesson teaches you to build that same resilience: retry transient failures, show helpful errors for permanent ones, and isolate crashes so one broken screen doesn't take down the whole app.

1. Transient vs. permanent errors

The first rule of error handling: not all errors deserve a retry. You need to tell them apart.

TypeExamplesWhat to do
Transient (temporary) Network timeout, Firestore unavailable (503), rate limited (429) Retry with backoff — it'll probably work in a few seconds
Permanent (won't fix itself) Permission denied (403), document not found (404), invalid data, auth expired Don't retry — show the user a helpful message 
// Helper: is this error worth retrying?
function isRetryableError(error) {
  // Network errors (no response at all)
  if (error.code === 'unavailable') return true;        // Firestore offline
  if (error.code === 'resource-exhausted') return true; // rate limited
  if (error.code === 'deadline-exceeded') return true;  // timeout
  if (error.code === 'aborted') return true;            // transaction conflict
  if (error.message?.includes('network')) return true;  // generic network error

  // NOT retryable
  if (error.code === 'permission-denied') return false;
  if (error.code === 'not-found') return false;
  if (error.code === 'already-exists') return false;
  if (error.code === 'invalid-argument') return false;
  if (error.code === 'unauthenticated') return false;

  // Unknown errors — retry once, then give up
  return true;
}

2. Exponential backoff

When a request fails, don't retry immediately — you'll just hit the same overloaded server again. Wait a little, then try again. If it fails again, wait longer. This is exponential backoff.

// Exponential backoff: wait 1s, 2s, 4s, 8s, 16s... (with jitter)
async function withRetry(fn, maxRetries = 5) {
  let attempt = 0;

  while (true) {
    try {
      return await fn();
    } catch (error) {
      attempt++;

      // Don't retry permanent errors
      if (!isRetryableError(error)) {
        throw error;
      }

      // Give up after max retries
      if (attempt >= maxRetries) {
        throw error;
      }

      // Calculate wait time: 2^attempt * 1000ms, with random jitter
      const baseDelay = Math.pow(2, attempt) * 1000; // 2s, 4s, 8s, 16s...
      const jitter = Math.random() * 1000;           // 0–1000ms random
      const delay = baseDelay + jitter;

      console.log(`Retry ${attempt}/${maxRetries} in ${Math.round(delay)}ms`);
      await new Promise(resolve => setTimeout(resolve, delay));
    }
  }
}

// Usage:
async function sendMessageWithRetry(chatId, text) {
  return withRetry(async () => {
    await addDoc(collection(db, 'chats', chatId, 'messages'), {
      senderId: auth.currentUser.uid,
      text: text,
      createdAt: serverTimestamp(),
    });
  });
}

Why jitter matters

If 1,000 users all get an error at the same time (server hiccup), without jitter they'd all retry at exactly 2 seconds, flooding the server again. Random jitter spreads retries across time so the server can recover.

Backoff timeline example

AttemptWait timeTotal elapsed
1 (first try)0s0s
2 (retry 1)~2s~2s
3 (retry 2)~4s~6s
4 (retry 3)~8s~14s
5 (retry 4)~16s~30s
Give up—~30s total

3. Retry queue for unsent messages

Exponential backoff works for individual requests, but what if the user sends 5 messages while offline? You need a queue that retries all pending messages in order.

import AsyncStorage from '@react-native-async-storage/async-storage';
import NetInfo from '@react-native-community/netinfo';

const QUEUE_KEY = 'message_retry_queue';

// Add a failed message to the queue
async function queueMessage(chatId, text, senderId) {
  const existing = await AsyncStorage.getItem(QUEUE_KEY);
  const queue = existing ? JSON.parse(existing) : [];

  queue.push({
    id: `msg_${Date.now()}_${Math.random().toString(36).slice(2)}`,
    chatId,
    text,
    senderId,
    queuedAt: Date.now(),
    attempts: 0,
  });

  await AsyncStorage.setItem(QUEUE_KEY, JSON.stringify(queue));
}

// Process the queue (called when network returns)
async function processRetryQueue() {
  const existing = await AsyncStorage.getItem(QUEUE_KEY);
  if (!existing) return;

  const queue = JSON.parse(existing);
  const remaining = [];

  for (const item of queue) {
    try {
      await addDoc(collection(db, 'chats', item.chatId, 'messages'), {
        senderId: item.senderId,
        text: item.text,
        createdAt: serverTimestamp(),
      });
      // Success — don't keep in queue
    } catch (error) {
      item.attempts += 1;

      if (item.attempts < 10 && isRetryableError(error)) {
        remaining.push(item); // Keep for next retry cycle
      } else {
        // Permanent failure or too many attempts — notify user
        console.warn('Message permanently failed:', item.text.substring(0, 50));
      }
    }
  }

  await AsyncStorage.setItem(QUEUE_KEY, JSON.stringify(remaining));
}

// Auto-process when connectivity returns
function useRetryQueueProcessor() {
  useEffect(() => {
    const unsubscribe = NetInfo.addEventListener((state) => {
      if (state.isConnected) {
        processRetryQueue();
      }
    });
    return unsubscribe;
  }, []);
}

Showing pending messages in the UI

function usePendingMessages() {
  const [pending, setPending] = useState([]);

  useEffect(() => {
    loadPending();
    // Re-check every 5 seconds
    const interval = setInterval(loadPending, 5000);
    return () => clearInterval(interval);
  }, []);

  async function loadPending() {
    const existing = await AsyncStorage.getItem(QUEUE_KEY);
    setPending(existing ? JSON.parse(existing) : []);
  }

  return pending;
}

function MessageThread({ chatId }) {

      attempts: p.attempts,
    }));

}

4. Graceful degradation when Firebase is unreachable

Sometimes Firebase has a full outage. Your app shouldn't crash — it should degrade gracefully, showing cached data and limiting features.

function useFirebaseHealth() {
  const [status, setStatus] = useState('healthy'); // 'healthy' | 'degraded' | 'offline'
  const failCount = useRef(0);

  function reportSuccess() {
    failCount.current = 0;
    setStatus('healthy');
  }

  function reportFailure(error) {
    if (isRetryableError(error)) {
      failCount.current += 1;

      if (failCount.current >= 5) {
        setStatus('offline');     // Firebase is probably down
      } else if (failCount.current >= 2) {
        setStatus('degraded');   // Having issues
      }
    }
  }

  return { status, reportSuccess, reportFailure };
}

// Use in your app's top level
function App() {
  const { status } = useFirebaseHealth();

  return (
    <View style={{ flex: 1 }}>
      {status === 'degraded' && (
        <View style={styles.degradedBar}>
          <Text style={styles.degradedText}>
            Some features may be slow right now
          </Text>
        </View>
      )}
      {status === 'offline' && (
        <View style={styles.offlineBar}>
          <Text style={styles.offlineText}>
            Viewing cached messages — new messages will sync when service resumes
          </Text>
        </View>
      )}
      {/* rest of app */}
    </View>
  );
}

5. ErrorBoundary — isolating crashes

In React Native, if one component throws an unhandled error, the entire app crashes with a white screen. An ErrorBoundary catches the error and shows a fallback UI instead — only the broken section is affected.

import React from 'react';
import { View, Text, Pressable, StyleSheet } from 'react-native';

class ErrorBoundary extends React.Component {
  constructor(props) {
    super(props);
    this.state = { hasError: false, error: null };
  }

  static getDerivedStateFromError(error) {
    return { hasError: true, error };
  }

  componentDidCatch(error, info) {
    // Log to your crash reporting service (Crashlytics, Sentry, etc.)
    console.error('ErrorBoundary caught:', error, info.componentStack);
  }

  handleRetry = () => {
    this.setState({ hasError: false, error: null });
  };

  render() {
    if (this.state.hasError) {
      return (
        <View style={boundaryStyles.container}>
          <Text style={boundaryStyles.emoji}>😕</Text>
          <Text style={boundaryStyles.title}>
            {this.props.fallbackTitle || 'Something went wrong'}
          </Text>
          <Text style={boundaryStyles.message}>
            {this.props.fallbackMessage || 'This section had a problem loading.'}
          </Text>
          <Pressable style={boundaryStyles.retryBtn} onPress={this.handleRetry}>
            <Text style={boundaryStyles.retryText}>Try Again</Text>
          </Pressable>
        </View>
      );
    }

    return this.props.children;
  }
}

const boundaryStyles = StyleSheet.create({
  container: {
    flex: 1, justifyContent: 'center', alignItems: 'center', padding: 24,
  },
  emoji: { fontSize: 48, marginBottom: 12 },
  title: { fontSize: 18, fontWeight: '700', color: '#333', marginBottom: 8 },
  message: { fontSize: 14, color: '#666', textAlign: 'center', marginBottom: 20 },
  retryBtn: {
    backgroundColor: '#075E54', borderRadius: 8,
    paddingHorizontal: 24, paddingVertical: 12,
  },
  retryText: { color: '#fff', fontWeight: '600', fontSize: 15 },
});

6. User-facing error messages that help

Never show raw error codes to users. Map technical errors to friendly messages with clear actions.

function getUserFriendlyError(error) {
  const code = error.code || '';
  const message = error.message || '';

  // Auth errors
  if (code === 'auth/wrong-password' || code === 'auth/user-not-found') {
    return {
      title: 'Login failed',
      message: 'Email or password is incorrect. Try again or tap "Forgot password".',
      action: 'retry',
    };
  }
  if (code === 'auth/too-many-requests') {
    return {
      title: 'Too many attempts',
      message: 'Account temporarily locked. Wait 5 minutes and try again.',
      action: 'wait',
    };
  }
  if (code === 'auth/network-request-failed') {
    return {
      title: 'No internet',
      message: 'Check your connection and try again.',
      action: 'retry',
    };
  }

  // Firestore errors
  if (code === 'permission-denied') {
    return {
      title: 'Access denied',
      message: 'You don\'t have permission for this action. Try logging out and back in.',
      action: 'reauth',
    };
  }
  if (code === 'unavailable') {
    return {
      title: 'Service temporarily unavailable',
      message: 'We\'re having trouble connecting. Your message will be sent automatically when service resumes.',
      action: 'auto_retry',
    };
  }
  if (code === 'resource-exhausted') {
    return {
      title: 'Slow down',
      message: 'You\'re sending messages too fast. Wait a moment and try again.',
      action: 'wait',
    };
  }

  // Storage errors
  if (message.includes('storage/unauthorized')) {
    return {
      title: 'Upload failed',
      message: 'You don\'t have permission to upload this file.',
      action: 'none',
    };
  }
  if (message.includes('storage/canceled')) {
    return {
      title: 'Upload cancelled',
      message: 'The upload was cancelled. Tap to try again.',
      action: 'retry',
    };
  }

  // Fallback for unknown errors
  return {
    title: 'Something went wrong',
    message: 'Please try again. If the problem continues, restart the app.',
    action: 'retry',
  };
}

// Usage:
async function handleSend(chatId, text) {
  try {
    await sendMessageWithRetry(chatId, text);
  } catch (error) {
    const friendly = getUserFriendlyError(error);

    if (friendly.action === 'auto_retry') {
      // Queue for later, show subtle toast
      await queueMessage(chatId, text, auth.currentUser.uid);
      showToast('Message queued — will send when connected');
    } else {
      // Show alert with the friendly message
      Alert.alert(friendly.title, friendly.message);
    }
  }
}

7. Timeout wrapper for slow requests

Sometimes a request hangs forever (server is alive but not responding). Set a timeout so your UI doesn't wait indefinitely.

// Wrap any async function with a timeout
function withTimeout(fn, timeoutMs = 15000) {
  return Promise.race([
    fn(),
    new Promise((_, reject) =>
      setTimeout(() => reject(new Error('Request timed out')), timeoutMs)
    ),
  ]);
}

// Usage: fail after 10 seconds
async function loadChat(chatId) {
  try {
    const chatDoc = await withTimeout(
      () => getDoc(doc(db, 'chats', chatId)),
      10000 // 10 second timeout
    );
    return chatDoc.data();
  } catch (error) {
    if (error.message === 'Request timed out') {
      // Show cached data instead
      return getCachedChat(chatId);
    }
    throw error;
  }
}

// Combine with retry: timeout per attempt, backoff between attempts
async function robustFetch(chatId) {
  return withRetry(async () => {
    return withTimeout(
      () => getDoc(doc(db, 'chats', chatId)),
      10000
    );
  }, 3); // max 3 attempts, each with 10s timeout
}

// ─── Retry utilities ───────────────────────────
function isRetryableError(error) {
  const code = error.code || '';
  if (code === 'unavailable') return true;
  if (code === 'resource-exhausted') return true;
  if (code === 'deadline-exceeded') return true;
  if (code === 'aborted') return true;
  if (error.message?.includes('network')) return true;
  if (code === 'permission-denied') return false;
  if (code === 'not-found') return false;
  if (code === 'unauthenticated') return false;
  return true;
}

async function withRetry(fn, maxRetries = 4) {
  let attempt = 0;
  while (true) {
    try {
      return await fn();
    } catch (error) {
      attempt++;
      if (!isRetryableError(error) || attempt >= maxRetries) throw error;
      const delay = Math.pow(2, attempt) * 1000 + Math.random() * 1000;
      await new Promise(resolve => setTimeout(resolve, delay));
    }
  }
}

function getUserFriendlyError(error) {
  const code = error.code || '';
  if (code === 'unavailable') {

}

// ─── Chat Screen with retry logic ──────────────
function ChatScreen({ chatId }) {
  const [messages, setMessages] = useState([]);
  const [input, setInput] = useState('');
  const [sending, setSending] = useState(false);
  const [pendingMessages, setPendingMessages] = useState([]);
  const retryTimerRef = useRef(null);

  const userId = auth.currentUser?.uid;

  // Listen to messages
  useEffect(() => {
    const q = query(
      collection(db, 'chats', chatId, 'messages'),
      orderBy('createdAt', 'desc'),
      limit(50)
    );
    const unsubscribe = onSnapshot(q, (snapshot) => {
      const msgs = snapshot.docs.map(d => ({ id: d.id, ...d.data() }));
      setMessages(msgs);

      // Remove from pending if they appear in Firestore
      setPendingMessages(prev =>
        prev.filter(p => !msgs.some(m => m.text === p.text && m.senderId === p.senderId))
      );
    });
    return unsubscribe;
  }, [chatId]);

  // Retry pending messages periodically
  useEffect(() => {
    retryTimerRef.current = setInterval(() => {
      retryPendingMessages();
    }, 10000); // every 10 seconds

    return () => clearInterval(retryTimerRef.current);
  }, []);

  async function retryPendingMessages() {
    setPendingMessages(prev => {
      const updated = [...prev];
      updated.forEach(async (msg) => {
        if (msg.attempts < 5) {
          try {
            await addDoc(collection(db, 'chats', chatId, 'messages'), {
              senderId: msg.senderId,
              text: msg.text,
              createdAt: serverTimestamp(),
            });
            // Success — will be removed when onSnapshot fires
          } catch (error) {
            msg.attempts += 1;
          }
        }
      });
      return updated.filter(m => m.attempts < 5);
    });
  }

  const handleSend = async () => {
    const trimmed = input.trim();
    if (!trimmed) return;
    setInput('');
    setSending(true);

    try {
      await withRetry(async () => {
        const batch = writeBatch(db);
        const msgRef = doc(collection(db, 'chats', chatId, 'messages'));
        batch.set(msgRef, {
          senderId: userId,
          text: trimmed,
          createdAt: serverTimestamp(),
        });
        const chatRef = doc(db, 'chats', chatId);
        batch.update(chatRef, {
          lastMessage: trimmed.substring(0, 100),
          lastMessageAt: serverTimestamp(),
        });
        await batch.commit();
      });
    } catch (error) {
      const friendly = getUserFriendlyError(error);

      // Add to pending queue
      setPendingMessages(prev => [...prev, {
        id: `pending_${Date.now()}`,
        text: trimmed,
        senderId: userId,
        attempts: 0,
        queuedAt: Date.now(),
      }]);

      Alert.alert(friendly.title, friendly.message);
    } finally {
      setSending(false);
    }
  };

  // Merge pending + real messages for display
  const displayMessages = [
    ...pendingMessages.map(p => ({
      ...p,
      createdAt: null,
      status: p.attempts > 0 ? 'retrying' : 'pending',
    })),
    ...messages,
  ];

  const renderMessage = ({ item }) => {
    const isMine = item.senderId === userId;
    const isPending = !item.createdAt;
    const isRetrying = item.status === 'retrying';

    return (
      <View style={[styles.bubble, isMine ? styles.myBubble : styles.theirBubble,
        isPending && styles.pendingBubble]}>
        <Text style={styles.messageText}>{item.text}</Text>
        <View style={styles.metaRow}>
          <Text style={styles.timeText}>
            {isPending
              ? (isRetrying ? `Retrying (${item.attempts})...` : 'Sending...')
              : item.createdAt?.toDate?.()?.toLocaleTimeString([], {
                  hour: '2-digit', minute: '2-digit',
                }) || ''}
          </Text>
          {isMine && (
            <Text style={styles.tick}>
              {isPending ? '🕐' : '✓✓'}
            </Text>
          )}
        </View>
      </View>
    );
  };

  return (
    <KeyboardAvoidingView
      style={styles.container}
      behavior={Platform.OS === 'ios' ? 'padding' : 'height'}
    >
      <View style={styles.header}>
        <Text style={styles.headerTitle}>Priya</Text>
        <Text style={styles.headerSubtitle}>
          {pendingMessages.length > 0
            ? `${pendingMessages.length} message(s) pending`
            : 'online'}
        </Text>
      </View>

      <FlatList
        data={displayMessages}
        renderItem={renderMessage}
        keyExtractor={(item) => item.id}
        inverted
        style={styles.messageList}
        contentContainerStyle={{ paddingVertical: 10 }}
      />

      <View style={styles.inputBar}>
        <TextInput
          style={styles.input}
          value={input}
          onChangeText={setInput}
          placeholder="Type a message"
          maxLength={4096}
          multiline
        />
        <Pressable
          style={[styles.sendBtn, sending && { opacity: 0.5 }]}
          onPress={handleSend}
          disabled={sending}
        >
          {sending
            ? <ActivityIndicator color={COLORS.white} size="small" />
            : <Text style={styles.sendText}>Send</Text>
          }
        </Pressable>
      </View>
    </KeyboardAvoidingView>
  );
}

9. Key takeaways

  • Classify errors first — transient (retry) vs. permanent (show message)
  • Exponential backoff with jitter — 2s, 4s, 8s, 16s... plus randomness
  • Retry queue with AsyncStorage — survives app restart, processes on reconnect
  • Graceful degradation — show cached data, queue writes, disable impossible features
  • ErrorBoundary per section — one crash doesn't take down the whole app
  • Friendly error messages — never show raw error codes; tell the user what to do
  • Timeout wrapper — don't hang forever on slow requests
  • Pending indicators — show clock/retry count so users know their message isn't lost

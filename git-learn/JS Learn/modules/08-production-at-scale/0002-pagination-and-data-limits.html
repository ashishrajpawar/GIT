Production at Scale · Lesson 2

Pagination & Data Limits

Cursor pagination · startAfter · Infinite scroll · Real-time tail · Read costs ~55 min Hands-on
Why this matters for your WhatsApp clone

Right now your chat loads every single message at once. That's fine for 20 messages during testing — but a real conversation has 10,000+ messages. Loading all of them means: the app freezes for 5 seconds on open, uses 50MB of RAM, and costs you money (Firestore charges per document read). WhatsApp loads only the latest ~30 messages and fetches older ones when you scroll up. That's pagination — and it's what makes the app feel instant even in year-old group chats.

1. The problem: loading everything at once

Here's what you might have now — a query with no limit:

// ❌ BAD — loads ALL messages in the chat
const q = query(
  collection(db, 'chats', chatId, 'messages'),
  orderBy('createdAt', 'desc')
);

onSnapshot(q, (snapshot) => {
  // If there are 15,000 messages, this reads 15,000 documents
  // Cost: 15,000 reads × $0.06 per 100K = $0.009 per chat open
  // With 1,000 daily users opening 10 chats each = $90/day!
  const msgs = snapshot.docs.map(doc => ({ id: doc.id, ...doc.data() }));
  setMessages(msgs);
});

2. Cursor-based pagination with startAfter

Instead of loading everything, load one page at a time (e.g. 30 messages). When the user scrolls up, load the next 30 — using a cursor to remember where you left off.

import {
  collection, query, orderBy, limit, startAfter,
  getDocs,
} from 'firebase/firestore';

const PAGE_SIZE = 30;

// Load the first page
async function loadFirstPage(chatId) {
  const q = query(
    collection(db, 'chats', chatId, 'messages'),
    orderBy('createdAt', 'desc'),  // newest first
    limit(PAGE_SIZE)
  );

  const snapshot = await getDocs(q);
  const messages = snapshot.docs.map(doc => ({ id: doc.id, ...doc.data() }));

  // The cursor is the LAST document in this page
  const lastDoc = snapshot.docs[snapshot.docs.length - 1];

  return { messages, lastDoc };
}

// Load the next page (older messages)
async function loadNextPage(chatId, lastDoc) {
  const q = query(
    collection(db, 'chats', chatId, 'messages'),
    orderBy('createdAt', 'desc'),
    startAfter(lastDoc),  // Start after the cursor
    limit(PAGE_SIZE)
  );

  const snapshot = await getDocs(q);
  const messages = snapshot.docs.map(doc => ({ id: doc.id, ...doc.data() }));
  const newLastDoc = snapshot.docs[snapshot.docs.length - 1] || null;

  return { messages, lastDoc: newLastDoc };
}

How the cursor works

  1. First page: get the 30 newest messages. Save the last document as a "cursor"
  2. Second page: startAfter(cursor) tells Firestore "give me 30 messages older than this one"
  3. Third page: same thing, with the new cursor from page 2
  4. When a page returns fewer than 30 results — you've reached the beginning of the chat
Why cursor > offset

Some databases use OFFSET 30 to skip pages. Firestore doesn't support offset — and even if it did, offsets are slow (the database still reads and discards the skipped rows). Cursors jump directly to the right spot. WhatsApp, Signal, and Telegram all use cursor-based pagination.

3. Infinite scroll with FlatList

Connect pagination to the UI: when the user scrolls near the top (older messages), fetch the next page automatically.

import React, { useState, useEffect, useCallback } from 'react';
import { FlatList, ActivityIndicator, View, Text } from 'react-native';

function MessageList({ chatId }) {
  const [messages, setMessages] = useState([]);
  const [cursor, setCursor] = useState(null);    // last document for pagination
  const [loading, setLoading] = useState(false);
  const [hasMore, setHasMore] = useState(true);  // are there older messages?

  const PAGE_SIZE = 30;

  // Load initial page on mount
  useEffect(() => {
    loadInitial();
  }, [chatId]);

  async function loadInitial() {
    setLoading(true);
    const { messages: msgs, lastDoc } = await loadFirstPage(chatId);
    setMessages(msgs);
    setCursor(lastDoc);
    setHasMore(msgs.length === PAGE_SIZE);
    setLoading(false);
  }

  // Load more when user scrolls to the top
  const loadMore = useCallback(async () => {
    if (loading || !hasMore || !cursor) return;

    setLoading(true);
    const { messages: older, lastDoc } = await loadNextPage(chatId, cursor);

    setMessages(prev => [...prev, ...older]); // Append older messages at the end
    setCursor(lastDoc);
    setHasMore(older.length === PAGE_SIZE);
    setLoading(false);
  }, [loading, hasMore, cursor, chatId]);

  return (
    <FlatList
      data={messages}
      renderItem={({ item }) => <MessageBubble message={item} />}
      keyExtractor={(item) => item.id}
      inverted                          // newest at the bottom
      onEndReached={loadMore}           // fires when scrolling UP (because inverted)
      onEndReachedThreshold={0.3}       // trigger when 30% from the top
      ListFooterComponent={
        loading ? <ActivityIndicator style={{ padding: 20 }} /> : null
      }
    />
  );
}

Why inverted + onEndReached works

When a FlatList is inverted, the "end" of the list is visually at the top of the screen. So onEndReached fires when the user scrolls up — exactly when you want to load older messages.

4. Real-time tail + pagination (the WhatsApp pattern)

There's a problem with pure pagination: if Priya sends you a message while you're scrolling up, you won't see it until you scroll back down and refresh. The solution: use a real-time listener for new messages combined with pagination for old messages.

import {
  collection, query, orderBy, limit, startAfter,
  getDocs, onSnapshot, where, Timestamp,
} from 'firebase/firestore';

function useMessages(chatId) {
  const [messages, setMessages] = useState([]);
  const [cursor, setCursor] = useState(null);
  const [hasMore, setHasMore] = useState(true);
  const [loading, setLoading] = useState(false);

  const PAGE_SIZE = 30;

  useEffect(() => {
    let unsubscribe = null;

    async function init() {
      // 1. Load the first page (one-time fetch)
      const q = query(
        collection(db, 'chats', chatId, 'messages'),
        orderBy('createdAt', 'desc'),
        limit(PAGE_SIZE)
      );
      const snapshot = await getDocs(q);
      const initial = snapshot.docs.map(doc => ({ id: doc.id, ...doc.data() }));

      setMessages(initial);
      setCursor(snapshot.docs[snapshot.docs.length - 1] || null);
      setHasMore(initial.length === PAGE_SIZE);

      // 2. Start real-time listener for NEW messages only
      //    (messages created after our initial fetch)
      const newestTimestamp = initial.length > 0
        ? initial[0].createdAt
        : Timestamp.now();

      const realtimeQuery = query(
        collection(db, 'chats', chatId, 'messages'),
        orderBy('createdAt', 'asc'),
        startAfter(newestTimestamp)
      );

      unsubscribe = onSnapshot(realtimeQuery, (snap) => {
        const newMsgs = snap.docChanges()
          .filter(change => change.type === 'added')
          .map(change => ({ id: change.doc.id, ...change.doc.data() }));

        if (newMsgs.length > 0) {
          // Prepend new messages at the start (they're newer)
          setMessages(prev => [...newMsgs.reverse(), ...prev]);
        }
      });
    }

    init();
    return () => { if (unsubscribe) unsubscribe(); };
  }, [chatId]);

  // Load older messages (called by onEndReached)
  const loadOlder = useCallback(async () => {
    if (loading || !hasMore || !cursor) return;
    setLoading(true);

    const q = query(
      collection(db, 'chats', chatId, 'messages'),
      orderBy('createdAt', 'desc'),
      startAfter(cursor),
      limit(PAGE_SIZE)
    );

    const snapshot = await getDocs(q);
    const older = snapshot.docs.map(doc => ({ id: doc.id, ...doc.data() }));

    setMessages(prev => [...prev, ...older]);
    setCursor(snapshot.docs[snapshot.docs.length - 1] || null);
    setHasMore(older.length === PAGE_SIZE);
    setLoading(false);
  }, [loading, hasMore, cursor, chatId]);

  return { messages, loadOlder, loading, hasMore };
}

How this works

PartWhat it doesType
Initial fetchLoads latest 30 messagesOne-time getDocs
Real-time tailListens for messages newer than the initial batchonSnapshot (live)
Load olderFetches 30 more messages when user scrolls upOne-time getDocs

This is exactly how WhatsApp works: new messages pop in instantly (real-time), scrolling up loads history on demand (pagination).

5. Paginating the chat list

The chat list also needs pagination. If a user has 500 conversations, loading all of them wastes reads and slows down the home screen.

function useChatList(userId) {
  const [chats, setChats] = useState([]);
  const [cursor, setCursor] = useState(null);
  const [hasMore, setHasMore] = useState(true);

  const PAGE_SIZE = 20;

  useEffect(() => {
    // Real-time listener for the first page (most recent chats)
    const q = query(
      collection(db, 'chats'),
      where('participants', 'array-contains', userId),
      orderBy('lastMessageAt', 'desc'),
      limit(PAGE_SIZE)
    );

    const unsubscribe = onSnapshot(q, (snapshot) => {
      const chatList = snapshot.docs.map(doc => ({ id: doc.id, ...doc.data() }));
      setChats(chatList);
      setCursor(snapshot.docs[snapshot.docs.length - 1] || null);
      setHasMore(chatList.length === PAGE_SIZE);
    });

    return unsubscribe;
  }, [userId]);

  const loadMoreChats = useCallback(async () => {
    if (!hasMore || !cursor) return;

    const q = query(
      collection(db, 'chats'),
      where('participants', 'array-contains', userId),
      orderBy('lastMessageAt', 'desc'),
      startAfter(cursor),
      limit(PAGE_SIZE)
    );

    const snapshot = await getDocs(q);
    const older = snapshot.docs.map(doc => ({ id: doc.id, ...doc.data() }));

    setChats(prev => [...prev, ...older]);
    setCursor(snapshot.docs[snapshot.docs.length - 1] || null);
    setHasMore(older.length === PAGE_SIZE);
  }, [hasMore, cursor, userId]);

  return { chats, loadMoreChats, hasMore };
}

6. Firestore read cost awareness

Firestore charges per document read. Understanding costs helps you make pagination decisions.

Cost examples for your WhatsApp clone

ScenarioWithout paginationWith pagination (30/page)
User opens a 5,000-message chat 5,000 reads 30 reads
1,000 users each open 5 chats/day 25,000,000 reads/day = $15/day 150,000 reads/day = $0.09/day
User scrolls up 3 pages Already loaded everything 90 additional reads
⚠️ Real-time listeners also count as reads

Each document delivered by onSnapshot counts as a read. If you listen to 30 messages and one changes, that's 1 read (just the changed doc). But the initial snapshot counts as 30 reads. This is why we limit the real-time listener to only new messages (the "tail") rather than re-listening to the full history.

7. Document count limits and guards

Beyond pagination, you should enforce limits on how much data exists:

// In your security rules — limit group chat participants
match /chats/{chatId} {
  allow create: if request.resource.data.participants.size() <= 256;
  allow update: if request.resource.data.participants.size() <= 256;
}

// In your client code — enforce message length before sending
function validateMessage(text) {
  const trimmed = text.trim();
  if (trimmed.length === 0) return { valid: false, error: 'Message is empty' };
  if (trimmed.length > 4096) return { valid: false, error: 'Message too long (max 4096 chars)' };
  return { valid: true, text: trimmed };
}

// Limit status updates per user (prevent spam)
async function postStatus(userId, content) {
  // Check how many statuses the user has in the last 24 hours
  const oneDayAgo = new Date(Date.now() - 24 * 60 * 60 * 1000);
  const q = query(
    collection(db, 'statuses'),
    where('userId', '==', userId),
    where('createdAt', '>', Timestamp.fromDate(oneDayAgo))
  );

  const snapshot = await getDocs(q);
  if (snapshot.size >= 30) {
    throw new Error('Maximum 30 status updates per 24 hours');
  }

  // Proceed with posting...
}

8. Full working example — paginated message thread

Here's a complete App.js demonstrating the real-time tail + infinite scroll pattern. Paste this into your project to see pagination in action.

// ─── Custom hook: paginated messages + real-time tail ──
function useMessages(chatId) {
  const [messages, setMessages] = useState([]);
  const [cursor, setCursor] = useState(null);
  const [hasMore, setHasMore] = useState(true);
  const [loading, setLoading] = useState(false);
  const [initialLoading, setInitialLoading] = useState(true);

  useEffect(() => {
    let unsubscribe = null;

    async function init() {
      try {
        // Step 1: Fetch the latest PAGE_SIZE messages (one-time)
        const initialQuery = query(
          collection(db, 'chats', chatId, 'messages'),
          orderBy('createdAt', 'desc'),
          limit(PAGE_SIZE)
        );

        const snapshot = await getDocs(initialQuery);
        const initial = snapshot.docs.map(doc => ({
          id: doc.id,
          ...doc.data(),
        }));

        setMessages(initial);
        setCursor(snapshot.docs[snapshot.docs.length - 1] || null);
        setHasMore(initial.length === PAGE_SIZE);
        setInitialLoading(false);

        // Step 2: Real-time listener for messages NEWER than our fetch
        const newestTimestamp = initial.length > 0 && initial[0].createdAt
          ? initial[0].createdAt
          : Timestamp.now();

        const tailQuery = query(
          collection(db, 'chats', chatId, 'messages'),
          orderBy('createdAt', 'asc'),
          startAfter(newestTimestamp)
        );

        unsubscribe = onSnapshot(tailQuery, (snap) => {
          const newMsgs = snap.docChanges()
            .filter(change => change.type === 'added')
            .map(change => ({ id: change.doc.id, ...change.doc.data() }));

          if (newMsgs.length > 0) {
            setMessages(prev => [...newMsgs.reverse(), ...prev]);
          }
        });
      } catch (error) {
        Alert.alert('Error loading messages', error.message);
        setInitialLoading(false);
      }
    }

    init();
    return () => { if (unsubscribe) unsubscribe(); };
  }, [chatId]);

  // Load older messages when user scrolls up
  const loadOlder = useCallback(async () => {
    if (loading || !hasMore || !cursor) return;
    setLoading(true);

    try {
      const olderQuery = query(
        collection(db, 'chats', chatId, 'messages'),
        orderBy('createdAt', 'desc'),
        startAfter(cursor),
        limit(PAGE_SIZE)
      );

      const snapshot = await getDocs(olderQuery);
      const older = snapshot.docs.map(doc => ({
        id: doc.id,
        ...doc.data(),
      }));

      setMessages(prev => [...prev, ...older]);
      setCursor(snapshot.docs[snapshot.docs.length - 1] || null);
      setHasMore(older.length === PAGE_SIZE);
    } catch (error) {
      Alert.alert('Error loading older messages', error.message);
    } finally {
      setLoading(false);
    }
  }, [loading, hasMore, cursor, chatId]);

  return { messages, loadOlder, loading, hasMore, initialLoading };
}

// ─── Send message ──────────────────────────────
async function sendMessage(chatId, text) {
  const trimmed = text.trim();
  if (trimmed.length === 0 || trimmed.length > 4096) {
    throw new Error('Message must be 1–4096 characters');
  }

  const userId = auth.currentUser.uid;
  const batch = writeBatch(db);

  const msgRef = doc(collection(db, 'chats', chatId, 'messages'));
  batch.set(msgRef, {
    senderId: userId,
    text: trimmed,
    createdAt: serverTimestamp(),
  });

  const chatRef = doc(db, 'chats', chatId);
  batch.update(chatRef, {
    lastMessage: trimmed.substring(0, 100),
    lastMessageAt: serverTimestamp(),
  });

  await batch.commit();
}

// ─── Chat Screen ───────────────────────────────
function ChatScreen({ chatId }) {
  const { messages, loadOlder, loading, hasMore, initialLoading } = useMessages(chatId);
  const [input, setInput] = useState('');
  const [sending, setSending] = useState(false);

    if (!input.trim()) return;
    setSending(true);
    try {
      await sendMessage(chatId, input);
      setInput('');
    } catch (error) {
      Alert.alert('Send failed', error.message);
    } finally {
      setSending(false);
    }
  };

  const renderMessage = ({ item }) => {
    const isMine = item.senderId === userId;
    return (
      <View style={[styles.bubble, isMine ? styles.myBubble : styles.theirBubble]}>
        <Text style={styles.messageText}>{item.text}</Text>
        <Text style={styles.timeText}>
          {item.createdAt?.toDate?.()
            ? item.createdAt.toDate().toLocaleTimeString([], {
                hour: '2-digit', minute: '2-digit',
              })
            : 'Sending...'}
        </Text>
      </View>
    );
  };

  const renderFooter = () => {
    if (loading) {
      return (
        <View style={styles.footerLoader}>
          <ActivityIndicator size="small" color={COLORS.darkGreen} />
          <Text style={styles.footerText}>Loading older messages...</Text>
        </View>

      return (
        <View style={styles.footerLoader}>
          <Text style={styles.footerText}>— Beginning of conversation —</Text>
        </View>
      );

    return null;
  };

  if (initialLoading) {
    return (

        <ActivityIndicator size="large" color={COLORS.darkGreen} />
        <Text style={{ marginTop: 10, color: '#666' }}>Loading chat...</Text>

    );
  }

  return (
    <KeyboardAvoidingView
      style={styles.container}
      behavior={Platform.OS === 'ios' ? 'padding' : 'height'}
    >
      {/* Header */}
      <View style={styles.header}>
        <Text style={styles.headerTitle}>Priya</Text>

        <TextInput
          style={styles.input}
          value={input}
          onChangeText={setInput}
          placeholder="Type a message"
          maxLength={4096}
          multiline

          style={[styles.sendBtn, sending && { opacity: 0.5 }]}
          onPress={handleSend}
          disabled={sending}
        >
          {sending
            ? <ActivityIndicator color={COLORS.white} size="small" />
            : <Text style={styles.sendText}>Send</Text>
          }
        </Pressable>
      </View>
    </KeyboardAvoidingView>
  );
}

9. Key takeaways

  • Never load all documents — always use limit()
  • Cursor pagination with startAfter — fast and Firestore-native
  • Real-time tail + pagination — new messages appear live, old messages load on demand
  • inverted FlatList + onEndReached — triggers when scrolling UP
  • Track hasMore — stop fetching when you reach the beginning
  • Firestore charges per read — pagination saves real money at scale
  • Set hard limits everywhere — message length, page size, group size, uploads

Production at Scale · Lesson 4

Cloud Functions — Server-Side Logic

Firebase Functions · Triggers · Push notifications · Scheduled cleanup · Validation ~60 min Hands-on
Why this matters for your WhatsApp clone

Right now all your logic runs on the user's phone. That's a problem: when Priya sends Rahul a message, Priya's phone is responsible for sending Rahul a push notification. But what if Priya's phone has poor signal? Or the app is force-closed mid-send? The notification never arrives. Cloud Functions move critical logic to Google's servers — they run automatically when data changes, regardless of what any phone is doing. WhatsApp's servers handle notifications, group membership validation, and cleanup — yours should too.

1. What are Cloud Functions?

Cloud Functions are small pieces of JavaScript (Node.js) that run on Firebase's servers. They trigger automatically when something happens — a document is created, a user signs up, or a timer fires.

Types of triggers

Trigger typeWhen it firesUse case in your app
onDocumentCreatedA new document is addedSend push notification when new message arrives
onDocumentUpdatedA document changesUpdate group metadata when members change
onDocumentDeletedA document is removedClean up related data when a chat is deleted
onCallClient explicitly calls the functionValidate group creation with complex rules
onScheduleRuns on a timer (cron)Delete expired statuses every hour
onUserCreatedA new user signs upCreate their profile document automatically
⚠️ Requires Firebase Blaze plan

Cloud Functions require the Blaze (pay-as-you-go) plan. The free tier includes 2 million invocations/month — more than enough for a new app. You only pay if you exceed that.

3. Push notifications on new message

This is the most important Cloud Function for a messaging app. When a new message is created, send a push notification to all other participants.

// functions/index.js

exports.sendMessageNotification = onDocumentCreated(
  'chats/{chatId}/messages/{messageId}',
  async (event) => {
    const message = event.data.data();    // the new message document
    const chatId = event.params.chatId;
    const senderId = message.senderId;

    // 1. Get the chat to find all participants
    const chatDoc = await db.doc(`chats/${chatId}`).get();
    if (!chatDoc.exists) return;

    const participants = chatDoc.data().participants;

    // 2. Get all participants EXCEPT the sender
    const recipients = participants.filter(uid => uid !== senderId);

    // 3. Get the sender's name (for the notification title)
    const senderDoc = await db.doc(`users/${senderId}`).get();
    const senderName = senderDoc.exists ? senderDoc.data().name : 'Someone';

    // 4. Get push tokens for each recipient
    const tokens = [];
    for (const uid of recipients) {
      const userDoc = await db.doc(`users/${uid}`).get();
      if (userDoc.exists && userDoc.data().pushToken) {
        tokens.push(userDoc.data().pushToken);
      }
    }

    if (tokens.length === 0) return; // no one to notify

    // 5. Send the push notification
    const notification = {
      notification: {
        title: senderName,
        body: message.text.substring(0, 100), // truncate long messages
      },
      data: {
        chatId: chatId,
        senderId: senderId,
        type: 'new_message',
      },
      tokens: tokens, // send to multiple devices at once
    };

    const response = await messaging.sendEachForMulticast(notification);

    // 6. Clean up invalid tokens (device uninstalled the app)
    const failedTokens = [];
    response.responses.forEach((resp, idx) => {
      if (!resp.success && resp.error?.code === 'messaging/registration-token-not-registered') {
        failedTokens.push(tokens[idx]);
      }
    });

    // Remove invalid tokens from Firestore
    if (failedTokens.length > 0) {
      const batch = db.batch();
      for (const uid of recipients) {
        const userDoc = await db.doc(`users/${uid}`).get();
        if (userDoc.exists && failedTokens.includes(userDoc.data().pushToken)) {
          batch.update(db.doc(`users/${uid}`), { pushToken: null });
        }
      }
      await batch.commit();
    }
  }
);

Why this is better than sending from the client

Client-side notificationsCloud Function notifications
Fails if sender's phone loses signalRuns on Google's servers — always reliable
Sender needs recipients' push tokensTokens stay server-side (more secure)
Sender can fake notificationsServer validates everything

4. Server-side group membership validation

Some operations need complex validation that's hard to do in security rules alone. For example: only group admins can add members, and the group can't exceed 256 people.

// functions/index.js

exports.addGroupMember = onCall(async (request) => {
  // request.auth contains the caller's identity
  if (!request.auth) {
    throw new HttpsError('unauthenticated', 'Must be logged in');
  }

  const { chatId, newMemberId } = request.data;
  const callerId = request.auth.uid;

  // 1. Get the chat document
  const chatDoc = await db.doc(`chats/${chatId}`).get();
  if (!chatDoc.exists) {
    throw new HttpsError('not-found', 'Chat not found');
  }

  const chatData = chatDoc.data();

  // 2. Verify it's a group chat
  if (!chatData.isGroup) {
    throw new HttpsError('failed-precondition', 'Not a group chat');
  }

  // 3. Verify the caller is an admin
  if (!chatData.admins || !chatData.admins.includes(callerId)) {
    throw new HttpsError('permission-denied', 'Only admins can add members');
  }

  // 4. Check group size limit
  if (chatData.participants.length >= 256) {
    throw new HttpsError('resource-exhausted', 'Group is full (max 256 members)');
  }

  // 5. Check if user is already a member
  if (chatData.participants.includes(newMemberId)) {
    throw new HttpsError('already-exists', 'User is already a member');
  }

  // 6. Verify the new member exists
  const memberDoc = await db.doc(`users/${newMemberId}`).get();
  if (!memberDoc.exists) {
    throw new HttpsError('not-found', 'User not found');
  }

  // 7. All checks passed — add the member
  await db.doc(`chats/${chatId}`).update({
    participants: [...chatData.participants, newMemberId],
  });

  // 8. Send a system message to the group
  await db.collection(`chats/${chatId}/messages`).add({
    senderId: 'system',
    text: `${memberDoc.data().name} was added by ${(await db.doc(`users/${callerId}`).get()).data().name}`,
    createdAt: new Date(),
    type: 'system',
  });

  return { success: true, memberName: memberDoc.data().name };
});

    Alert.alert('Cannot add member', error.message);
  }
}

5. Scheduled cleanup — expired statuses

WhatsApp statuses disappear after 24 hours. Instead of checking expiry on the client, run a scheduled function that deletes old statuses automatically.

// functions/index.js

exports.cleanupExpiredStatuses = onSchedule('every 1 hours', async (event) => {
  // Find statuses older than 24 hours
  const cutoff = new Date(Date.now() - 24 * 60 * 60 * 1000);

  const expiredQuery = db.collection('statuses')
    .where('createdAt', '<', cutoff);

  const snapshot = await expiredQuery.get();

  if (snapshot.empty) {
    console.log('No expired statuses to clean up');
    return;
  }

  // Delete in batches (Firestore limits batch size to 500)
  const batchSize = 500;
  let deleted = 0;

  while (deleted < snapshot.docs.length) {
    const batch = db.batch();
    const chunk = snapshot.docs.slice(deleted, deleted + batchSize);

    chunk.forEach(doc => {
      batch.delete(doc.ref);
    });

    await batch.commit();
    deleted += chunk.length;
  }

  console.log(`Cleaned up ${deleted} expired statuses`);
});

Other scheduled cleanups for your app

// Clean up stale push tokens (users who uninstalled > 30 days ago)
exports.cleanupStalePushTokens = onSchedule('every 24 hours', async (event) => {
  const thirtyDaysAgo = new Date(Date.now() - 30 * 24 * 60 * 60 * 1000);

  const staleUsers = await db.collection('users')
    .where('lastActive', '<', thirtyDaysAgo)
    .where('pushToken', '!=', null)
    .get();

  const batch = db.batch();
  staleUsers.docs.forEach(doc => {
    batch.update(doc.ref, { pushToken: null });
  });

  await batch.commit();
  console.log(`Cleared ${staleUsers.size} stale push tokens`);
});

// Clean up old moderation reports that have been resolved
exports.cleanupOldReports = onSchedule('every 7 days', async (event) => {
  const ninetyDaysAgo = new Date(Date.now() - 90 * 24 * 60 * 60 * 1000);

  const oldReports = await db.collection('reports')
    .where('status', '==', 'resolved')
    .where('resolvedAt', '<', ninetyDaysAgo)
    .get();

  const batch = db.batch();
  oldReports.docs.forEach(doc => {
    batch.delete(doc.ref);
  });

  await batch.commit();
  console.log(`Cleaned up ${oldReports.size} old resolved reports`);
});

6. Auto-create user profile on sign-up

// functions/index.js
const { onUserCreated } = require('firebase-functions/v2/identity');

exports.createUserProfile = onUserCreated(async (event) => {
  const user = event.data;

  // Create a profile document automatically when someone signs up
  await db.doc(`users/${user.uid}`).set({
    uid: user.uid,
    name: user.displayName || 'New User',
    email: user.email || null,
    photoURL: user.photoURL || null,
    createdAt: new Date(),
    lastActive: new Date(),
    pushToken: null,
  });

  console.log(`Profile created for ${user.uid}`);
});

Monitoring in production

In the Firebase Console → Functions, you can see:

  • Invocations — how often each function runs
  • Errors — which functions are failing and why
  • Execution time — how long each function takes
  • Logs — your console.log() output
⚠️ Cold starts

The first time a function runs (or after ~15 minutes of inactivity), it has a "cold start" delay of 1–3 seconds. After that, it stays warm and responds in ~100ms. For push notifications this is fine — a 2-second delay before a notification is unnoticeable. For callable functions (like addGroupMember), the user might notice. To reduce cold starts, set minInstances: 1 in the function config (costs a few cents/month).

8. Common patterns summary

PatternClient-side?Cloud Function?Why
Send message✅Must be instant; Firestore handles it
Push notification✅Reliability; tokens stay server-side
Read messages✅Real-time listener on the client
Add group member✅Complex validation, system messages
Delete expired data✅Must happen even if no one opens the app
Block/report user✅ (write)✅ (process)Client writes report; function handles logic
Update typing indicator✅Ephemeral, low-stakes, needs to be instant
Image thumbnail✅CPU-intensive; don't drain user's battery

Rule of thumb: If it must happen reliably (even if the user closes the app), or it requires privileged access (other users' tokens, admin operations), put it in a Cloud Function.

// and saving push tokens for server-side notifications

  appId: '1:123456789:web:abc123',

const app = initializeApp(firebaseConfig);
const auth = getAuth(app);
const db = getFirestore(app);

// ─── Save push token to Firestore ──────────────
// (Called on app start so the Cloud Function knows where to send notifications)
async function savePushToken(userId) {
  // In a real app, get this from expo-notifications:
  // const { data: token } = await Notifications.getExpoPushTokenAsync();
  const token = 'ExponentPushToken[xxxxxx]'; // placeholder

  await setDoc(doc(db, 'users', userId), {
    pushToken: token,
    lastActive: serverTimestamp(),
  }, { merge: true }); // merge: true = don't overwrite other fields
}

// ─── Callable function wrappers ────────────────
const addGroupMemberFn = httpsCallable(functions, 'addGroupMember');
const removeGroupMemberFn = httpsCallable(functions, 'removeGroupMember');

async function addMemberToGroup(chatId, newMemberId) {
  try {
    const result = await addGroupMemberFn({ chatId, newMemberId });
    return { success: true, data: result.data };
  } catch (error) {
    // Cloud Function errors have a .code and .message
    return { success: false, error: error.message };
  }
}

// ─── Group Management Screen ───────────────────
function GroupManageScreen({ chatId }) {
  const [members, setMembers] = useState([]);
  const [newMemberEmail, setNewMemberEmail] = useState('');
  const [loading, setLoading] = useState(false);

  useEffect(() => {
    loadMembers();
  }, []);

  async function loadMembers() {
    const chatDoc = await getDoc(doc(db, 'chats', chatId));
    if (chatDoc.exists()) {
      const participants = chatDoc.data().participants || [];
      const memberData = [];
      for (const uid of participants) {
        const userDoc = await getDoc(doc(db, 'users', uid));
        if (userDoc.exists()) {
          memberData.push({ id: uid, ...userDoc.data() });
        }
      }
      setMembers(memberData);
    }
  }

  async function handleAddMember() {
    if (!newMemberEmail.trim()) return;
    setLoading(true);

    const result = await addMemberToGroup(chatId, newMemberEmail.trim());

    if (result.success) {
      Alert.alert('Done', `${result.data.memberName} added to the group`);
      setNewMemberEmail('');
      loadMembers(); // refresh the list
    } else {
      Alert.alert('Cannot add member', result.error);
    }

    setLoading(false);
  }

  return (
    <View style={styles.container}>
      {/* Header */}
      <View style={styles.header}>
        <Text style={styles.headerTitle}>Group Members</Text>
        <Text style={styles.headerSubtitle}>
          {members.length} / 256 members
        </Text>
      </View>

      {/* Member list */}
      <FlatList
        data={members}
        renderItem={({ item }) => (
          <View style={styles.memberRow}>
            <View style={styles.avatar}>
              <Text style={styles.avatarText}>
                {item.name?.[0]?.toUpperCase() || '?'}
              </Text>
            </View>
            <View>
              <Text style={styles.memberName}>{item.name}</Text>
              <Text style={styles.memberEmail}>{item.email}</Text>
            </View>
          </View>
        )}
        keyExtractor={(item) => item.id}
        style={styles.list}
      />

      {/* Add member */}
      <View style={styles.addBar}>
        <TextInput
          style={styles.input}
          value={newMemberEmail}
          onChangeText={setNewMemberEmail}
          placeholder="Enter user ID to add"
          autoCapitalize="none"
        />
        <Pressable
          style={[styles.addBtn, loading && { opacity: 0.5 }]}
          onPress={handleAddMember}
          disabled={loading}
        >
          {loading
            ? <ActivityIndicator color={COLORS.white} size="small" />
            : <Text style={styles.addBtnText}>Add</Text>
          }
        </Pressable>
      </View>
    </View>
  );
}

// ─── Main App ─────────────────────────────────
export default function App() {

10. Key takeaways

  • Cloud Functions run on Google's servers — no dependency on any user's phone
  • Push notifications belong on the server — reliability + security
  • onDocumentCreated — triggers when new data is written (perfect for notifications)
  • onCall — client-invoked functions with auth + error handling built in
  • onSchedule — cron jobs for cleanup (expired statuses, stale tokens, old reports)
  • Clean up invalid push tokens — removes tokens for uninstalled apps
  • Cold starts — first invocation is slow (~2s); use minInstances: 1 for critical paths
  • Test locally — firebase emulators:start runs everything on your machine

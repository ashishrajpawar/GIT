Production at Scale · Lesson 8

Media Compression & Storage Optimization

Image compression · Video strategies · Thumbnails · Storage costs · Cleanup ~55 min Hands-on
Why this matters for your WhatsApp clone

A single photo from a modern phone is 5–12 MB. If 100 users each send 10 photos a day, that's 5–12 GB uploaded daily. Firebase Storage charges $0.026/GB/month — in one month your bill would be $4–10 just for storage, and growing every day. Plus, recipients on slow connections wait 10+ seconds to see a full-size image. WhatsApp compresses images down to ~100–200 KB before sending — they load instantly and cost almost nothing to store. This lesson teaches you to do the same.

2. Compressing images before upload

Use expo-image-manipulator to resize and compress images on the device before uploading to Firebase Storage.

Install

npx expo install expo-image-manipulator

Compression function

import * as ImageManipulator from 'expo-image-manipulator';

async function compressImage(uri, options = {}) {
  const {
    maxWidth = 1200,    // max width in pixels
    maxHeight = 1200,   // max height in pixels
    quality = 0.7,      // JPEG quality (0–1). 0.7 = great quality, ~80% size reduction
  } = options;

  const result = await ImageManipulator.manipulateAsync(
    uri,
    [{ resize: { width: maxWidth, height: maxHeight } }], // resize if larger
    {
      compress: quality,
      format: ImageManipulator.SaveFormat.JPEG,
    }
  );

  // result.uri = path to the compressed file on device
  // result.width, result.height = new dimensions
  return result;
}

// Usage after picking an image:
import * as ImagePicker from 'expo-image-picker';

async function pickAndCompressImage() {
  const picked = await ImagePicker.launchImageLibraryAsync({
    mediaTypes: ImagePicker.MediaTypeOptions.Images,
    quality: 1, // pick at full quality — we'll compress ourselves
  });

  if (picked.canceled) return null;

  const original = picked.assets[0];
  console.log('Original size:', original.fileSize); // e.g. 8,500,000 bytes (8.5 MB)

  const compressed = await compressImage(original.uri);
  // Compressed is typically 100–300 KB

  return compressed.uri;
}

WhatsApp's approach

WhatsApp resizes images to max 1600×1200, compresses to JPEG quality ~0.65, and strips all EXIF metadata. The result is typically 100–200 KB — small enough to send instantly on 3G. We'll use similar settings.

3. Generating thumbnails

When the chat list shows a preview of the last image sent, you don't need the full 1200px image — a tiny thumbnail (100px) loads 10× faster and uses 50× less bandwidth.

async function generateThumbnail(uri) {
  const thumbnail = await ImageManipulator.manipulateAsync(
    uri,
    [{ resize: { width: 100 } }], // 100px wide, height auto-calculated
    {
      compress: 0.5,
      format: ImageManipulator.SaveFormat.JPEG,
    }
  );

  // Thumbnail is typically 5–15 KB
  return thumbnail.uri;
}

// When sending an image message:
async function sendImageMessage(chatId, imageUri) {
  // 1. Compress the full image
  const compressed = await compressImage(imageUri);

  // 2. Generate a tiny thumbnail
  const thumbnail = await generateThumbnail(imageUri);

  // 3. Upload both to Firebase Storage
  const userId = auth.currentUser.uid;
  const timestamp = Date.now();

  const fullRef = ref(storage, `chatImages/${chatId}/${timestamp}_full.jpg`);
  const thumbRef = ref(storage, `chatImages/${chatId}/${timestamp}_thumb.jpg`);

  const [fullUrl, thumbUrl] = await Promise.all([
    uploadFile(fullRef, compressed.uri),
    uploadFile(thumbRef, thumbnail.uri),
  ]);

  // 4. Save message with both URLs
  await addDoc(collection(db, 'chats', chatId, 'messages'), {
    senderId: userId,
    type: 'image',
    imageUrl: fullUrl,        // full image (loaded when user taps)
    thumbnailUrl: thumbUrl,   // tiny preview (loaded immediately in chat)
    createdAt: serverTimestamp(),
  });

  // 5. Update chat preview with thumbnail
  await updateDoc(doc(db, 'chats', chatId), {
    lastMessage: '📷 Photo',
    lastMessageAt: serverTimestamp(),
  });
}

// Helper to upload a file and return its download URL
async function uploadFile(storageRef, localUri) {
  const response = await fetch(localUri);
  const blob = await response.blob();
  await uploadBytes(storageRef, blob);
  return await getDownloadURL(storageRef);
}

4. Video compression strategies

Videos are the biggest storage cost. A 30-second phone video can be 50–100 MB. You need aggressive compression.

Option 1: Use expo-video-thumbnails + limit duration

npx expo install expo-video-thumbnails
import * as VideoThumbnails from 'expo-video-thumbnails';

// Generate a thumbnail for the video preview
async function getVideoThumbnail(videoUri) {
  const { uri } = await VideoThumbnails.getThumbnailAsync(videoUri, {
    time: 1000, // thumbnail at 1 second
    quality: 0.5,
  });
  return uri;
}

// Limit video duration at the picker level
async function pickVideo() {
  const result = await ImagePicker.launchImageLibraryAsync({
    mediaTypes: ImagePicker.MediaTypeOptions.Videos,
    videoMaxDuration: 60, // max 60 seconds (like WhatsApp status)
    quality: 0.5,         // ImagePicker's built-in compression
  });

  if (result.canceled) return null;
  return result.assets[0];
}

Option 2: ffmpeg for advanced compression (with expo-av)

// For production-grade video compression, use a Cloud Function
// that runs ffmpeg on the server after upload:

// functions/index.js
const { onObjectFinalized } = require('firebase-functions/v2/storage');
const { execSync } = require('child_process');
const path = require('path');
const os = require('os');

exports.compressVideo = onObjectFinalized(
  { bucket: 'your-app.appspot.com' },
  async (event) => {
    const filePath = event.data.name;

    // Only process videos in the chatVideos folder
    if (!filePath.startsWith('chatVideos/') || filePath.includes('_compressed')) {
      return;
    }

    // Download, compress with ffmpeg, re-upload
    // (ffmpeg is available in Cloud Functions runtime)
    const tempInput = path.join(os.tmpdir(), 'input.mp4');
    const tempOutput = path.join(os.tmpdir(), 'output.mp4');

    // Download the original
    await bucket.file(filePath).download({ destination: tempInput });

    // Compress: 720p, 1Mbps bitrate, fast preset
    execSync(`ffmpeg -i ${tempInput} -vf scale=-2:720 -b:v 1M -preset fast ${tempOutput}`);

    // Upload compressed version
    const compressedPath = filePath.replace('.mp4', '_compressed.mp4');
    await bucket.upload(tempOutput, { destination: compressedPath });

    // Optionally delete the original to save storage
    await bucket.file(filePath).delete();
  }
);

5. Firebase Storage cost management

Storage lifecycle rules

Firebase Storage (backed by Google Cloud Storage) supports lifecycle rules to automatically delete old files:

6. CDN caching headers

When you set Cache-Control headers on uploaded files, browsers and the CDN cache them — so the same image isn't downloaded from Firebase Storage repeatedly.

import { ref, uploadBytes, getDownloadURL } from 'firebase/storage';

async function uploadWithCaching(storageRef, localUri, cacheSeconds = 86400) {
  const response = await fetch(localUri);
  const blob = await response.blob();

  // Set metadata with caching headers
  const metadata = {
    contentType: 'image/jpeg',
    cacheControl: `public, max-age=${cacheSeconds}`, // cache for 24 hours
  };

  await uploadBytes(storageRef, blob, metadata);
  return await getDownloadURL(storageRef);
}

// Profile photos: cache for 1 hour (might change)
const profileUrl = await uploadWithCaching(
  ref(storage, `profilePhotos/${userId}/avatar.jpg`),
  compressedUri,
  3600 // 1 hour
);

// Chat images: cache for 30 days (never change once sent)
const chatImageUrl = await uploadWithCaching(
  ref(storage, `chatImages/${chatId}/${timestamp}.jpg`),
  compressedUri,
  2592000 // 30 days
);

Why this matters

  • Without caching: every time a user scrolls past an image → new download → you pay $0.12/GB
  • With caching: the CDN serves it from memory → free after the first load
  • Chat images never change, so 30-day cache is safe
  • Profile photos might change, so use shorter cache (1 hour)

7. Cleaning up orphaned files

When a user deletes a message that had an image, the Firestore document is gone — but the file in Storage remains, costing you money forever. Clean it up with a Cloud Function:

// functions/index.js
const { onDocumentDeleted } = require('firebase-functions/v2/firestore');
const { getStorage } = require('firebase-admin/storage');

const bucket = getStorage().bucket();

exports.cleanupDeletedMessageMedia = onDocumentDeleted(
  'chats/{chatId}/messages/{messageId}',
  async (event) => {
    const message = event.data.data();

    // Only process image/voice/video messages
    if (!message.imageUrl && !message.voiceUrl && !message.videoUrl) {
      return;
    }

    const filesToDelete = [];

    if (message.imageUrl) {
      filesToDelete.push(extractPathFromUrl(message.imageUrl));
    }
    if (message.thumbnailUrl) {
      filesToDelete.push(extractPathFromUrl(message.thumbnailUrl));
    }
    if (message.voiceUrl) {
      filesToDelete.push(extractPathFromUrl(message.voiceUrl));
    }
    if (message.videoUrl) {
      filesToDelete.push(extractPathFromUrl(message.videoUrl));
    }

    // Delete all associated files
    await Promise.all(
      filesToDelete.map(async (path) => {
        try {
          await bucket.file(path).delete();
          console.log(`Deleted: ${path}`);
        } catch (error) {
          // File might already be gone — that's fine
          if (error.code !== 404) {
            console.error(`Failed to delete ${path}:`, error);
          }
        }
      })
    );
  }
);

// Helper: extract Storage path from a download URL
function extractPathFromUrl(url) {
  // Firebase download URLs contain the path encoded between /o/ and ?
  const match = url.match(/\/o\/(.+?)\?/);
  if (match) {
    return decodeURIComponent(match[1]);
  }
  return null;
}

Periodic orphan scan (safety net)

// Run weekly to find files in Storage with no matching Firestore document
exports.findOrphanedFiles = onSchedule('every 7 days', async (event) => {
  const [files] = await bucket.getFiles({ prefix: 'chatImages/' });

  let orphaned = 0;
  for (const file of files) {
    // Extract chatId and timestamp from path
    const parts = file.name.split('/');
    const chatId = parts[1];

    // Check if any message references this file
    const messages = await db.collection(`chats/${chatId}/messages`)
      .where('imageUrl', '==', await getDownloadURL(file))
      .limit(1)
      .get();

    if (messages.empty) {
      await file.delete();
      orphaned++;
    }
  }

  console.log(`Cleaned up ${orphaned} orphaned files`);
});

8. Progressive image loading (blur-up pattern)

WhatsApp shows a blurry placeholder that sharpens into the full image. This makes image loading feel instant even on slow connections.

import { useState } from 'react';
import { Image, View, StyleSheet, Animated } from 'react-native';

function ProgressiveImage({ thumbnailUrl, fullUrl, style }) {
  const [fullLoaded, setFullLoaded] = useState(false);
  const opacity = useState(new Animated.Value(0))[0];

  const onFullLoad = () => {
    setFullLoaded(true);
    Animated.timing(opacity, {
      toValue: 1,
      duration: 300,
      useNativeDriver: true,
    }).start();
  };

  return (
    <View style={style}>
      {/* Blurry thumbnail (always visible first) */}
      <Image
        source={{ uri: thumbnailUrl }}
        style={[StyleSheet.absoluteFill, style]}
        blurRadius={2}
      />

      {/* Full image (fades in on top when loaded) */}
      <Animated.Image
        source={{ uri: fullUrl }}
        style={[StyleSheet.absoluteFill, style, { opacity }]}
        onLoad={onFullLoad}
      />
    </View>
  );
}

// Usage in a message bubble:
function ImageMessageBubble({ message }) {
  return (
    <View style={styles.imageBubble}>
      <ProgressiveImage
        thumbnailUrl={message.thumbnailUrl}
        fullUrl={message.imageUrl}
        style={styles.chatImage}
      />
    </View>
  );
}

10. Key takeaways

  • Compress images before upload — expo-image-manipulator, quality 0.7, max 1200px → ~150 KB
  • Generate thumbnails — 100px wide, quality 0.5 → ~10 KB for chat list previews
  • Upload both full + thumbnail — show thumbnail immediately, load full on tap
  • Set Cache-Control headers — prevents repeated downloads; 30 days for chat images
  • Limit video duration — videoMaxDuration: 60 at the picker level
  • Server-side video compression — Cloud Function with ffmpeg for 720p/1Mbps
  • Delete files when messages are deleted — Cloud Function on document delete

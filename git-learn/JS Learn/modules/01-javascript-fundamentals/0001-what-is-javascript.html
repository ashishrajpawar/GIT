Lesson 1

What Is JavaScript?

Foundations ~15 min read Beginner
Your goal, right now

You want to build a WhatsApp clone — real-time chat, voice and video calls, group messaging. That app will be written in JavaScript. Every button tap, every message that pops up on screen, every notification — all of that is JavaScript running on a phone. This lesson is your starting point.

So what is JavaScript?

JavaScript is a programming language — a set of instructions you write that a computer (or phone) can follow.

Think of it like this: when you use WhatsApp and type a message and hit Send, something has to make that happen. Something has to grab the text you typed, package it up, send it to the other person, and show their reply on your screen. That "something" is code — and for mobile apps built with React Native, that code is JavaScript.

JavaScript started as a language for web browsers (it's what makes websites interactive — buttons that do things, forms that validate, menus that open and close). But over time it grew far beyond that. Today you can use JavaScript to:

  • Build mobile apps (React Native — what you're learning)
  • Build web apps (React, Vue, etc.)
  • Build servers and backends (Node.js)
  • Build desktop apps (Electron)

One language. Phones, browsers, servers, desktops. That's a big reason it's worth learning.

Common confusion

JavaScript and Java are completely different languages. They share part of a name for historical marketing reasons, but they are as different as "car" and "carpet". You're learning JavaScript.

Your first line of JavaScript

Before anything else, here is the single most important tool you'll use while learning: console.log(). It prints output so you can see what your code is doing.

Here is a complete, valid JavaScript program:

console.log("Hello, Ashish!");

When this runs, it prints the text Hello, Ashish! to the developer console. That's it. One line. That is a program.

Let's break it apart:

  • console — a built-in object that gives you access to developer tools
  • .log() — a function on that object that prints ("logs") whatever you put inside the parentheses
  • "Hello, Ashish!" — the text you want to print (the quotes mark it as text, not code)
  • ; — a semicolon marks the end of a statement (like a period at the end of a sentence)
Try it yourself

Open your browser, press F12 (or right-click any page → Inspect → Console tab). Type console.log("Hello!") and press Enter. You'll see your message appear. You just ran JavaScript.

Variables — storing information

Almost everything in programming comes down to this: you have some piece of information, and you need to store it so you can use it later.

In JavaScript, you use a variable to store a value and give it a name.

A real-world analogy

Think about your phone's Contacts app. When you save someone's number, you give it a name: "Mum", "Office", "Delivery". Later, when WhatsApp needs to show who called you, it looks up that name and shows it on screen.

A variable works exactly like that — it's a named slot that holds a piece of information. You give the slot a name, and you can look it up any time you need it.

let username = "Ashish";

This creates a variable called username and stores the value "Ashish" inside it. Now anywhere in your code you can write username and JavaScript knows you mean "Ashish".

let username = "Ashish";
console.log("Welcome back, " + username); // Welcome back, Ashish

Two ways to create a variable: let and const

JavaScript gives you two main keywords for creating variables:

let — for values that can change

let messageCount = 0;
messageCount = 5;    // Changed it — this is fine
messageCount = 12;   // Changed it again — also fine

Use let when the value will be updated over time. Your unread message count, for example, changes constantly.

const — for values that stay fixed

const appName = "ChatApp";
// appName = "Other"; // This would cause an ERROR

const is short for "constant" — the value is set once and cannot be replaced. Use it for things that are fixed: your app's name, a URL, a configuration value.

A simple rule of thumb

Start with const. If you find yourself needing to change the value, switch to let. This habit makes your code easier to understand — when you see const, you immediately know that value never changes.

Seeing them together

const appName = "ChatApp";       // Fixed — the app name never changes
let currentUser = "Ashish";      // Could change when someone logs out / in
let unreadCount = 0;             // Changes every time a new message arrives

console.log(appName);            // ChatApp
console.log(currentUser);        // Ashish
console.log(unreadCount);        // 0

unreadCount = 3;                 // A new message came in
console.log(unreadCount);        // 3
In your WhatsApp clone

You'll use variables to store things like:

  • const APP_NAME = "ChatApp" — fixed name used throughout the app
  • let currentUser = { name: "Ashish", photo: "..." } — the logged-in user's profile
  • let messages = [] — the list of messages in a chat (grows as messages arrive)
  • let isTyping = false — whether the other person is typing right now

Every single piece of information your app handles will live in a variable like one of these.

What about var?

You may come across a third keyword: var. It's the original way to declare variables in JavaScript, but it has some confusing behaviour that tripped up many programmers. Modern JavaScript replaced it with let and const.

When you see var in old tutorials or StackOverflow answers, just mentally replace it with let or const. Never use var in new code you write.

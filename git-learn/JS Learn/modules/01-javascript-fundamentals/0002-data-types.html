Lesson 2

Data Types

Foundations ~20 min read Beginner
Why this matters for your app

Your WhatsApp clone will handle many kinds of information — a message (text), a count of unread messages (a number), whether someone is online (yes or no), a list of contacts (a collection). JavaScript has a different data type for each of these. Knowing which type to use, and what each one can do, is the foundation of everything.

The six types you'll use every day

JavaScript has a handful of built-in types. Here are the six you'll encounter constantly:

Type What it holds Example
String Text "Hello Ashish"
Number Any number 42, 3.14
Boolean True or false only true, false
Array An ordered list of values ["Ali", "Sara", "Ravi"]
Object A collection of named values { name: "Ashish", age: 25 }
null / undefined No value / not set yet null, undefined

Let's go through each one properly.

String — text

A string is any piece of text. You wrap it in quotes — either single quotes '...', double quotes "...", or backticks `...`.

const senderName = "Ashish";
const greeting   = 'Good morning!';
const lastMessage = `See you soon`;

All three produce strings. Most developers pick double quotes and stick with them.

Joining strings together

You can combine strings using +:

const first = "Good";
const second = "morning";
console.log(first + " " + second + "!"); // Good morning!

Template literals — the modern way

Backtick strings (called template literals) let you embed variables directly inside the text using ${ }. This is much cleaner than using +:

const username = "Ashish";
const unread   = 5;

// Old way (messy with +)
console.log("Welcome back, " + username + ". You have " + unread + " messages.");

// Modern way (template literal)
console.log(`Welcome back, ${username}. You have ${unread} messages.`);

Both print the same thing, but the template literal version is far easier to read. You'll use this pattern constantly in React Native — for example, building a notification text like `${senderName} sent you a message`.

In your WhatsApp clone

Strings everywhere: the message text, the user's name, a contact's phone number, the chat room title. Almost every piece of text on screen will live in a string variable.

Number — any numeric value

JavaScript has just one number type for both whole numbers and decimals:

const unreadCount = 12;
const callDuration = 3.5;       // minutes
const negativeBalance = -50;

You can do arithmetic with numbers:

const a = 10;
const b = 3;

console.log(a + b);   // 13  (addition)
console.log(a - b);   // 7   (subtraction)
console.log(a * b);   // 30  (multiplication)
console.log(a / b);   // 3.333...  (division)
console.log(a % b);   // 1   (remainder — "10 divided by 3 leaves 1 left over")
Watch out: strings that look like numbers

If you wrap a number in quotes, it becomes a string, not a number. "5" and 5 are different. Mixing them with + gives a surprising result:

console.log(5 + 5);       // 10  ✓  (number + number)
console.log("5" + 5);     // "55" ✗  (string + number = joined text!)

This is a very common beginner mistake. Always make sure numeric values are stored without quotes.

Boolean — true or false

A boolean has only two possible values: true or false. No quotes, no capitals — just the literal words true and false.

const isOnline   = true;
const isTyping   = false;
const isMuted    = true;
const isBlocked  = false;

Booleans are how your app makes decisions. "Is this user online? Show a green dot. Otherwise, show nothing." You'll get to that in the next lesson when you learn about if statements. For now, just know that booleans are the values those decisions are based on.

In your WhatsApp clone
  • isOnline — show green dot or not
  • isTyping — show "typing..." indicator
  • isRead — show blue ticks or grey ticks
  • isMuted — suppress notifications for this chat

Array — an ordered list

An array holds multiple values in a single variable, in a specific order. You write them inside square brackets [ ], separated by commas.

const contacts = ["Ali", "Sara", "Ravi", "Priya"];
const messages = ["Hey!", "How are you?", "See you at 6"];

Getting items out of an array

Each item has a position number called an index. Counting starts at 0, not 1. This trips up beginners, so remember it: first item is index 0.

const contacts = ["Ali", "Sara", "Ravi"];

console.log(contacts[0]);   // "Ali"   ← first item
console.log(contacts[1]);   // "Sara"  ← second item
console.log(contacts[2]);   // "Ravi"  ← third item

Finding out how many items are in an array

console.log(contacts.length);   // 3

Adding items to an array

const messages = ["Hey!", "How are you?"];
messages.push("On my way!");           // Adds to the end
console.log(messages.length);          // 3
In your WhatsApp clone

Arrays are everywhere. Your chat screen has an array of messages. Your home screen has an array of conversations. Your contacts list is an array of users. Every time a new message arrives, you'll push() it onto the messages array.

Object — a bundle of related information

An object groups related pieces of information together under one name. Each piece has a key (a name) and a value.

const user = {
  name: "Ashish",
  phone: "+91 98765 43210",
  isOnline: true,
  unreadCount: 4
};

Think of it like a contact card — one object that holds everything about one person.

Reading values from an object

Use a dot . followed by the key name:

console.log(user.name);         // "Ashish"
console.log(user.isOnline);     // true
console.log(user.unreadCount);  // 4

Updating a value inside an object

user.unreadCount = 7;           // A new message arrived
console.log(user.unreadCount);  // 7

Objects inside arrays

This is the pattern you'll use most — a list of objects. Think of a chat list: each chat is an object, and the whole list is an array of those objects.

const chats = [
  { name: "Ali",   lastMessage: "See you soon!",  unread: 2 },
  { name: "Sara",  lastMessage: "Thanks!",         unread: 0 },
  { name: "Ravi",  lastMessage: "On my way",        unread: 5 }
];

console.log(chats[0].name);          // "Ali"
console.log(chats[2].unread);        // 5
console.log(chats[1].lastMessage);   // "Thanks!"
In your WhatsApp clone

Every message in your app will be an object: { sender: "Ali", text: "Hey!", time: "10:32", isRead: false }. Your chat list will be an array of those message objects. This exact pattern is what Firebase will store and send back to your app.

null and undefined — the "nothing" values

Sometimes a variable intentionally has no value, or hasn't been given one yet. JavaScript uses two special values for this:

undefined — not set yet

If you declare a variable but don't give it a value, it is automatically undefined:

let profilePhoto;
console.log(profilePhoto);   // undefined

null — intentionally empty

null is something you set deliberately to mean "this has no value right now". It's a signal you write yourself:

let currentCall = null;   // No active call right now
// ... later, when a call starts:
// currentCall = { caller: "Ali", startTime: "10:45" };
Simple rule

You'll see undefined when something hasn't been set. You'll write null yourself when you want to say "empty on purpose". Don't worry too much about the difference right now — just know both exist and mean "no value".

Checking the type of a value

JavaScript has a built-in tool called typeof that tells you what type a value is. Very useful when debugging:

console.log(typeof "Hello");        // "string"
console.log(typeof 42);             // "number"
console.log(typeof true);           // "boolean"
console.log(typeof ["a", "b"]);     // "object"   ← arrays report as "object" (a quirk)
console.log(typeof { name: "A" });  // "object"
console.log(typeof undefined);      // "undefined"
console.log(typeof null);           // "object"   ← another famous JS quirk, just accept it
Two famous quirks

typeof [] returns "object" instead of "array", and typeof null also returns "object". These are well-known JavaScript oddities — don't let them confuse you. You'll learn better ways to check for arrays later.

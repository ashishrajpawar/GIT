Lesson 7

DOM & Browser APIs

Browser JS ~25 min read Beginner
Why this matters for your WhatsApp clone

Before you write a single line of React Native, you need to understand a fundamental idea: how does JavaScript talk to a user interface?

In a browser, JavaScript talks to the UI through something called the DOM — the Document Object Model. It's the browser's internal representation of everything you see on screen: every button, every text box, every message bubble. JavaScript can read it, change it, add to it, and remove from it.

React Native does something very similar on mobile — but instead of a DOM, it has a tree of native components (Views, Texts, TextInputs). The mental model is identical. Learning the DOM now gives you the foundation for understanding React Native's component tree later. Every time you see something like document.getElementById() in the browser, you'll recognise the parallel when React Native says <TextInput />.

What is the DOM?

When a browser loads an HTML page, it reads all the HTML tags and builds a tree structure in memory. This tree is called the Document Object Model — the DOM.

Every HTML element — a heading, a paragraph, a button, an input field — becomes a node in that tree. Each node has a parent, may have children, and may have siblings. The whole page is one big tree, with document at the root.

Here is a tiny HTML page and the tree it creates:

<!-- The HTML -->
<div id="chat-screen">
  <h2>Ashish & Priya</h2>
  <div id="message-list"></div>
  <input id="message-input" type="text" />
  <button id="send-btn">Send</button>
</div>

/* The tree that the browser builds:
   document
     └── <div id="chat-screen">
           ├── <h2> "Ashish & Priya"
           ├── <div id="message-list">
           ├── <input id="message-input">
           └── <button id="send-btn"> "Send"
*/

JavaScript can reach into this tree at any point and do things with any node — read its text, change its colour, add new children, or remove it entirely. That is the power of the DOM.

The React Native parallel

In React Native, your component tree looks almost identical:

<View>               {/* like <div> */}
  <Text>Ashish & Priya</Text>   {/* like <h2> */}
  <ScrollView>...</ScrollView>   {/* like #message-list */}
  <TextInput />       {/* like <input> */}
  <TouchableOpacity> {/* like <button> */}
    <Text>Send</Text>
  </TouchableOpacity>
</View>

Same tree shape, different names. The DOM gives you the mental model.

Selecting elements

Before you can read or change anything in the DOM, you have to select the element you want to work with. JavaScript gives you several ways to do this.

document.getElementById()

The most direct method. If an element has an id attribute, you can grab it instantly:

// Get the message input field
const inputField = document.getElementById("message-input");

// Get the send button
const sendButton = document.getElementById("send-btn");

// Get the list where messages appear
const messageList = document.getElementById("message-list");

console.log(inputField);   // <input id="message-input" type="text">
console.log(sendButton);   // <button id="send-btn">Send</button>

document.querySelector()

A more flexible method. It accepts any CSS selector and returns the first matching element:

// Select by id (same as getElementById, but with a # prefix)
const sendButton = document.querySelector("#send-btn");

// Select by class name (using a dot prefix)
const firstMessage = document.querySelector(".message-bubble");

// Select by element type
const firstInput = document.querySelector("input");

// Select by attribute
const textInput = document.querySelector("input[type='text']");

document.querySelectorAll()

Like querySelector(), but returns all matching elements as a NodeList (similar to an array):

// Get all message bubbles in the chat
const allMessages = document.querySelectorAll(".message-bubble");

// Loop through them
allMessages.forEach(function(messageEl) {
  console.log(messageEl.textContent);
});

// In a WhatsApp-style app — count unread messages
const unreadMessages = document.querySelectorAll(".message-bubble.unread");
console.log("Unread count:", unreadMessages.length);
Tip: prefer querySelector

In modern code you'll mostly use querySelector and querySelectorAll — they're flexible and use the CSS syntax you already know. Use getElementById when you just need one specific element quickly and you know its id.

querySelector can return null

If no element matches your selector, querySelector() returns null — not an element. If you then try to call a method on null, you'll get a TypeError crash.

const el = document.querySelector("#typo-in-id");
// el is null if the id doesn't exist

// This will crash with "Cannot read properties of null":
el.textContent = "Hello";  // TypeError!

// Safe approach — check first:
if (el !== null) {
  el.textContent = "Hello";
}

Always double-check your selector strings match your actual HTML ids and class names.

Reading and changing content

Once you have a reference to an element, you can read or change what it contains.

.textContent — plain text

The safest and most common property. It reads or sets the plain text inside an element — no HTML, just characters.

// Read the current text of a message
const statusEl = document.querySelector("#online-status");
console.log(statusEl.textContent);  // "Online"

// Change the text — Priya just went offline
statusEl.textContent = "Last seen today at 10:35 AM";

// Show the user's name in the chat header
const headerName = document.querySelector("#chat-header-name");
const currentContact = "Priya Sharma";
headerName.textContent = currentContact;

.innerHTML — HTML content

innerHTML reads or sets the full HTML inside an element, including tags. This lets you insert formatted content:

// Insert a message with bold sender name
const messageList = document.querySelector("#message-list");
messageList.innerHTML = "<strong>Priya:</strong> On my way!";
XSS risk — never use innerHTML with user input

innerHTML is dangerous when the content comes from a user. If someone types <script>stealYourData()</script> into a message field and you insert it with innerHTML, that script executes. This is called a Cross-Site Scripting (XSS) attack.

// DANGEROUS — never do this with user-supplied text:
messageEl.innerHTML = userTypedMessage;

// SAFE — always use textContent for user input:
messageEl.textContent = userTypedMessage;

Rule: use textContent for anything a user typed. Only use innerHTML for static, trusted content you control.

.value — reading input fields

Text inputs, search boxes, and textareas don't use textContent. Their current text lives in the .value property:

// The message the user has typed so far
const inputField = document.querySelector("#message-input");
const typedText = inputField.value;
console.log("User typed:", typedText);

// Clear the input after sending (like WhatsApp does)
inputField.value = "";
In your WhatsApp clone

Every time the user taps Send in your app, the logic will be: read inputField.value to get their message text, do something with it (send to server / add to list), then set inputField.value = "" to clear the box. That's the core loop of every chat input in the world.

Changing styles and classes

JavaScript can change how elements look — either by directly setting CSS properties, or by adding and removing CSS class names.

Direct style with .style.property

Every element has a .style object. Set any CSS property on it (in camelCase) to override the element's appearance:

const bubble = document.querySelector(".message-bubble");

// Change background colour of a message bubble
bubble.style.backgroundColor = "#DCF8C6";  // WhatsApp green

// Make the typing indicator visible
const typingEl = document.querySelector("#typing-indicator");
typingEl.style.display = "block";    // show it
typingEl.style.display = "none";     // hide it

// Dim a sent message while it's being delivered
bubble.style.opacity = "0.6";

Classes with .classList

A cleaner approach is to keep your styles in CSS and just toggle class names with JavaScript. The .classList API gives you three key methods:

const bubble = document.querySelector(".message-bubble");

// Add a class
bubble.classList.add("delivered");    // now has class "message-bubble delivered"

// Remove a class
bubble.classList.remove("sending");   // gone

// Toggle — add if absent, remove if present
bubble.classList.toggle("selected");  // tap to select a message

// Check if a class is present
if (bubble.classList.contains("unread")) {
  console.log("This message hasn't been read yet");
}

Here is a realistic example — changing a message tick from sent to delivered:

// When the server confirms delivery:
function markDelivered(messageId) {
  const msgEl = document.querySelector("#msg-" + messageId);
  if (msgEl !== null) {
    msgEl.classList.remove("status-sent");
    msgEl.classList.add("status-delivered");
    // Your CSS shows one tick for "sent", two ticks for "delivered"
  }
}
classList vs style

Prefer classList over .style wherever possible. When styles live in CSS classes, designers can change the look without touching JS. When they live in .style calls scattered across your JS, they're hard to find and change.

Creating and removing elements

Adding a new message to a chat doesn't just mean changing text — it means creating a brand-new element and inserting it into the DOM. You do this with createElement() and appendChild().

document.createElement()

Creates a new element in memory. It's not on the page yet — you still have to insert it:

// Create a new div for a message bubble
const newBubble = document.createElement("div");

// Set its text (safe — uses textContent, not innerHTML)
newBubble.textContent = "Hey! Are you free tonight?";

// Give it a class for styling
newBubble.classList.add("message-bubble");
newBubble.classList.add("received");  // it's an incoming message

appendChild()

Inserts the new element as the last child of a parent element — so new messages appear at the bottom of the list:

const messageList = document.querySelector("#message-list");
messageList.appendChild(newBubble);
// The bubble is now visible on the page!

element.remove()

Removes an element from the DOM entirely — useful for deleting messages:

// User long-presses a message and taps "Delete"
function deleteMessage(messageId) {
  const msgEl = document.querySelector("#msg-" + messageId);
  if (msgEl !== null) {
    msgEl.remove();   // Gone from the page
  }
}

Here is the full create-and-add pattern in one place:

function addMessageToUI(text, isOutgoing) {
  // 1. Create the element
  const bubble = document.createElement("div");

  // 2. Set safe text content
  bubble.textContent = text;

  // 3. Style it based on direction
  bubble.classList.add("message-bubble");
  bubble.classList.add(isOutgoing ? "sent" : "received");

  // 4. Add to the message list
  const messageList = document.querySelector("#message-list");
  messageList.appendChild(bubble);

  // 5. Scroll to the newest message (like WhatsApp does)
  bubble.scrollIntoView({ behavior: "smooth" });
}
This is the core of every chat UI

That addMessageToUI function above is the heart of a chat interface. When a new message arrives (from the server, or sent by the user), you call it and the message appears. In React Native the mechanism is different (you update state and React re-renders), but the idea — "take this text, wrap it in a styled element, add it to the list" — is identical.

Mini-project: a working chat message display

Let's put everything together. Below is a complete, self-contained HTML file you can copy into a new file (call it chat-demo.html), open in your browser, and use immediately. It has a text input, a Send button, and a message list. Clicking Send (or pressing Enter) adds your message to the list and clears the input — exactly like a real chat app.

<!DOCTYPE html>
<html lang="en">
<head>

  <title>Chat Demo</title>
  <style>

      flex: 1;
      padding: 0.6rem 0.75rem;

      border-radius: 20px;

    }
    #send-btn {
      background: #25D366;
      color: #fff;

      width: 44px;

      font-size: 1.2rem;
      cursor: pointer;
    }
    #send-btn:hover {
      background: #128C7E;
    }
  </style>
</head>
<body>

  <div id="chat-screen">
    <div id="chat-header">Priya Sharma</div>
    <div id="message-list"></div>
    <div id="input-row">
      <input id="message-input" type="text" placeholder="Type a message" />
      <button id="send-btn">➤</button>
    </div>
  </div>

  <script>
    // Grab the elements we need
    const messageList = document.getElementById("message-list");
    const messageInput = document.getElementById("message-input");
    const sendButton = document.getElementById("send-btn");

    // A helper to get the current time as "HH:MM"
    function getCurrentTime() {
      const now = new Date();
      const h = String(now.getHours()).padStart(2, "0");
      const m = String(now.getMinutes()).padStart(2, "0");
      return h + ":" + m;
    }

    // Create and add a message bubble to the list
    function addMessage(text, isOutgoing) {
      // 1. Create the outer bubble div
      const bubble = document.createElement("div");
      bubble.classList.add("message-bubble");
      bubble.classList.add(isOutgoing ? "sent" : "received");

      // 2. Set text safely using textContent (never innerHTML for user input)
      const messageText = document.createElement("div");
      messageText.textContent = text;

      // 3. Add a timestamp
      const timeEl = document.createElement("div");
      timeEl.classList.add("message-time");
      timeEl.textContent = getCurrentTime();

      // 4. Assemble and insert
      bubble.appendChild(messageText);
      bubble.appendChild(timeEl);
      messageList.appendChild(bubble);

      // 5. Scroll to the latest message
      bubble.scrollIntoView({ behavior: "smooth" });
    }

    // Handle the send button click
    function handleSend() {
      const text = messageInput.value.trim();

      // Don't send empty messages
      if (text === "") {
        return;
      }

      // Add the outgoing message (isOutgoing = true)
      addMessage(text, true);

      // Clear the input field
      messageInput.value = "";

      // Simulate a reply after 1.5 seconds
      setTimeout(function() {
        addMessage("Got it! See you there.", false);
      }, 1500);
    }

    // Listen for button click
    sendButton.addEventListener("click", handleSend);

    // Also allow pressing Enter to send
    messageInput.addEventListener("keydown", function(event) {
      if (event.key === "Enter") {
        handleSend();
      }
    });

    // Seed a couple of messages so the screen isn't empty on load
    addMessage("Hey Ashish! Are you coming to the meeting?", false);
    addMessage("Yes, I'll be there in 10 minutes", true);
  </script>

</body>
</html>

Save that as chat-demo.html and open it in your browser. Type a message and click the arrow button (or press Enter). You'll see your message appear on the right, and a simulated reply pop up 1.5 seconds later on the left — exactly like a real WhatsApp conversation.

What you just built

This demo uses every DOM concept from this lesson:

  • getElementById and querySelector to select elements
  • .value to read and clear the text input
  • createElement and appendChild to build and insert message bubbles
  • classList.add to apply sent/received styles
  • .textContent (not .innerHTML) to safely insert user text
  • scrollIntoView to keep the latest message visible
  • addEventListener to respond to clicks and keypresses (full detail in Lesson 8)

This is a real chat UI pattern. The React Native version you'll build later replaces the DOM calls with component state, but every step in the logic is the same.

Bridge to React Native: the same idea, different words

Everything you learned in this lesson — selecting elements, changing their content, adding and removing nodes — is called imperative DOM manipulation. You tell JavaScript exactly what to do, step by step: "find this element, change its text, add this child."

React and React Native use a declarative approach instead. You describe what the UI should look like based on your data, and React figures out which DOM nodes (or native views) to create, update, or remove. You never write appendChild in React code.

Here is the same "add a message" logic in React Native:

// In React Native you keep messages in state:
const [messages, setMessages] = React.useState([
  { id: 1, text: "Hey Ashish! Are you coming?", outgoing: false },
  { id: 2, text: "Yes, 10 minutes away", outgoing: true }
]);

// To add a new message, you update state:
function handleSend() {
  const text = inputValue.trim();
  if (text === "") return;

  setMessages(function(prev) {
    return [...prev, { id: Date.now(), text: text, outgoing: true }];
  });

  setInputValue("");  // clear the input
}

// React automatically re-renders the list with the new message.
// You never manually call createElement or appendChild.

The underlying difference is this:

  • DOM (browser): you mutate the tree yourself — "add this node here, remove that one there"
  • React / React Native: you update data (state), and React updates the tree for you — you just declare what the UI should look like for any given state

Learning the DOM gives you two things:

  1. A mental model of what React is doing for you under the hood — it's still manipulating a tree, just automatically
  2. The ability to understand and work on web projects, which you will likely encounter alongside your React Native work
The payoff

When you write your first React Native chat screen and see that messages just appear when you call setMessages(), you'll know exactly what React is doing — it's running the same createElement and appendChild logic you wrote by hand in this lesson, just automatically and efficiently. That understanding will make you a far better React Native developer.

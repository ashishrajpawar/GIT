Lesson 8

Events

Browser JS ~20 min read Beginner
Why this matters for your WhatsApp clone

Every single interaction in your app is an event. When Ashish taps the Send button — that's an event. When he starts typing and the other person sees "Ashish is typing..." — that's triggered by an input event. When he long-presses a message to get the delete/copy menu — that's a long-press event. When he swipes right to reply to a message — swipe event. Without understanding events, your app would just be a static picture on a screen. Events are how your app listens to the user and responds.

What is an event?

The browser (or, in React Native, the mobile runtime) constantly watches everything that happens — mouse movements, key presses, button taps, form submissions, network responses, timers going off. When something happens that your code cares about, the browser fires an event: a signal that says "hey, this just happened."

Your job as a developer is to tell the browser: "when that event fires, run this function." That function is called an event handler (or event listener). The browser will call it automatically the moment the event fires.

Think of it like a waiter in a restaurant. The waiter (the browser) watches every table. When a customer (the user) raises their hand (fires an event), the waiter comes over and does whatever the customer needs (runs your handler function). You don't have to keep checking — the waiter just shows up.

In your WhatsApp clone

React Native has its own event system (onPress, onChangeText, etc.) built on the same concept. Once you understand browser events here, React Native events will feel completely natural — they're the same idea with slightly different names.

addEventListener — attaching a handler

The main way to listen for events in browser JavaScript is addEventListener. You call it on any DOM element:

element.addEventListener(eventType, handlerFunction);

Let's break that down with a real messaging example. Imagine a Send button in your chat UI:

// Grab the Send button from the page
const sendButton = document.getElementById("send-btn");

// Define what happens when it's clicked
function handleSendClick() {
  console.log("Send button was tapped!");
}

// Attach the handler — now the button is "listening"
sendButton.addEventListener("click", handleSendClick);

The three parts of addEventListener:

  • eventType — a string naming the event: "click", "input", "keydown", "submit"
  • handlerFunction — the function to call when the event fires (notice: no parentheses — you pass the function itself, not its return value)

Common event types you'll use constantly:

  • "click" — button tapped / mouse clicked
  • "input" — text field content changed (fires on every keystroke)
  • "keydown" — a key was pressed (fires before the character appears)
  • "submit" — a form was submitted
  • "focus" / "blur" — an input gained / lost focus
In your WhatsApp clone

In React Native you'll write <TouchableOpacity onPress={handleSendClick}> instead of addEventListener("click", ...). Same pattern: give it a function, it calls that function when the user interacts. Learning the browser version makes the React Native version immediately obvious.

The event object

When the browser calls your handler function, it automatically passes one argument: the event object. This object is packed with information about what just happened — what element was interacted with, which key was pressed, where the mouse was, and much more.

const sendButton = document.getElementById("send-btn");

sendButton.addEventListener("click", function(event) {
  // `event` is the event object — the browser passes it automatically
  console.log(event.type);    // "click"
  console.log(event.target);  // the actual DOM element that was clicked
});

The three event object properties you'll use most often:

event.target

The element that triggered the event. Useful when one handler covers many elements (more on this in the delegation section).

// In a message list, find out which message bubble was tapped
const messageList = document.getElementById("message-list");

messageList.addEventListener("click", function(event) {
  const tappedElement = event.target;
  console.log("Tapped message text:", tappedElement.textContent);
});

event.key

On keyboard events, this tells you which key was pressed — "Enter", "Backspace", "a", etc.

const messageInput = document.getElementById("message-input");

messageInput.addEventListener("keydown", function(event) {
  console.log("Key pressed:", event.key); // "Enter", "a", "Backspace", etc.
});

event.preventDefault()

Stops the browser's default behaviour for that event. The classic use case: a form's default behaviour when submitted is to reload the page. In a chat app you never want that.

const chatForm = document.getElementById("chat-form");

chatForm.addEventListener("submit", function(event) {
  event.preventDefault(); // Stop the page from reloading!
  // Now handle the submission yourself
  console.log("Form submitted without page reload");
});
Forgetting preventDefault on a form

If your chat input is inside a <form> element and you forget to call event.preventDefault(), pressing Enter or clicking Send will reload the entire page — wiping out all your messages. Always call it first thing in your submit handler.

Input events — reacting to typing in real time

The "input" event fires on a text field every single time its value changes — every keystroke, every paste, every delete. This is exactly what powers the "Ashish is typing..." indicator in WhatsApp.

const messageInput = document.getElementById("message-input");

messageInput.addEventListener("input", function(event) {
  const currentText = event.target.value;
  console.log("Current input:", currentText);

  if (currentText.length > 0) {
    // Tell the server the user is typing
    // In your WhatsApp clone: socket.emit("typing", { chatId, userId })
    console.log("User is typing — show the typing indicator to others");
  } else {
    // Input was cleared — stop the typing indicator
    console.log("User stopped typing");
  }
});

Notice we're reading event.target.value — event.target is the input element, and .value is its current text content.

In your WhatsApp clone

In React Native the equivalent is the onChangeText prop on a TextInput component: <TextInput onChangeText={(text) => handleTyping(text)} />. The text parameter is the new value — same idea as event.target.value, just passed directly as an argument.

Keyboard events — sending with Enter

In almost every chat app, pressing Enter sends the message. You detect this with a "keydown" listener that checks event.key:

const messageInput = document.getElementById("message-input");

messageInput.addEventListener("keydown", function(event) {
  // Check if the key pressed was Enter
  if (event.key === "Enter") {
    event.preventDefault(); // Don't insert a newline in the input

    const messageText = messageInput.value.trim();

    if (messageText !== "") {
      sendMessage(messageText);
      messageInput.value = ""; // Clear the input after sending
    }
  }
});

function sendMessage(text) {
  console.log("Sending message:", text);
  // In your WhatsApp clone: add to messages array, call API, etc.
}

The .trim() call removes any leading or trailing spaces — so pressing Enter on an empty input (or one with only spaces) doesn't send a blank message.

What about Shift+Enter to add a new line without sending? Check event.shiftKey:

messageInput.addEventListener("keydown", function(event) {
  if (event.key === "Enter" && !event.shiftKey) {
    // Enter alone = send message
    event.preventDefault();
    sendMessage(messageInput.value.trim());
    messageInput.value = "";
  }
  // Shift+Enter falls through — default behaviour inserts a newline
});
In your WhatsApp clone

React Native's TextInput has a onSubmitEditing prop that fires when the user taps the keyboard's "return/send" key — same concept as detecting Enter in a browser. You'll also use blurOnSubmit={false} to keep the keyboard open after sending.

Event delegation — one listener for many elements

Imagine your chat screen has 200 messages. If you attached a click listener to each message bubble individually, you'd have 200 event listeners consuming memory. Worse: when new messages arrive dynamically, you'd have to manually attach a listener to each new one.

Event delegation solves this elegantly. Instead of listening on each child, you attach one listener to the parent container. When a child is clicked, the event "bubbles up" through the DOM to the parent, where your single listener catches it. You then use event.target to find out which child was actually clicked.

// ONE listener on the message list container — not one per message
const messageList = document.getElementById("message-list");

messageList.addEventListener("click", function(event) {
  // event.target is the specific element that was clicked
  const clickedMessage = event.target.closest(".message-bubble");

  if (clickedMessage) {
    const messageId = clickedMessage.dataset.messageId;
    console.log("Message tapped:", messageId);
    // Show options: Reply, Copy, Delete, React
  }
});

// When a new message arrives, just add it to the DOM —
// the existing listener on the parent automatically covers it
function addMessageToList(message) {
  const bubble = document.createElement("div");
  bubble.classList.add("message-bubble");
  bubble.dataset.messageId = message.id;
  bubble.textContent = message.text;
  messageList.appendChild(bubble);
  // No need to attach a new listener — the parent already handles it
}

closest(".message-bubble") walks up the DOM from the clicked element and returns the first ancestor (or the element itself) matching that selector. This handles the case where the user clicked on something inside the bubble (like a timestamp span) rather than the bubble itself.

In your WhatsApp clone

React Native handles this differently — each component has its own onPress — but the concept of delegation shows up in React as lifting state up and passing callbacks down. One handler at the top, children call it with their identity. Same mental model.

Removing event listeners — preventing memory leaks

Event listeners don't automatically disappear when you're done with them. If you navigate away from a chat screen but the listener is still attached, it keeps running — wasting memory and potentially causing bugs (a listener firing on a component that no longer exists). You remove a listener with removeEventListener.

const messageInput = document.getElementById("message-input");

function handleKeydown(event) {
  if (event.key === "Enter") {
    sendMessage(messageInput.value.trim());
    messageInput.value = "";
  }
}

// Attach the listener when entering the chat screen
messageInput.addEventListener("keydown", handleKeydown);

// Remove it when leaving the chat screen
function onLeaveChatScreen() {
  messageInput.removeEventListener("keydown", handleKeydown);
  console.log("Listener removed — no memory leak");
}

You must pass the exact same function reference to removeEventListener that you passed to addEventListener. That's why handleKeydown is a named function stored in a variable — so you have a reference to give back.

Anonymous functions cannot be removed

If you use an anonymous function (written inline) with addEventListener, you can never remove that listener — every call to addEventListener with an anonymous function creates a brand-new function object, so removeEventListener has nothing to match against. Always use a named function when you plan to remove the listener later.

// BAD — this listener can never be removed:
input.addEventListener("keydown", function(event) { /* ... */ });

// GOOD — you can call removeEventListener later:
function handleKeydown(event) { /* ... */ }
input.addEventListener("keydown", handleKeydown);
input.removeEventListener("keydown", handleKeydown); // Works!
In your WhatsApp clone — React Native useEffect cleanup

In React Native with React hooks, you clean up event listeners (and subscriptions, timers, socket connections) in the cleanup function returned from useEffect:

useEffect(() => {
  // Set up — runs when component mounts
  const subscription = socket.on("message", handleNewMessage);

  // Cleanup — runs when component unmounts (navigating away)
  return () => {
    socket.off("message", handleNewMessage);
  };
}, []);

This is the React Native equivalent of removeEventListener. Same idea: clean up after yourself when you're done.

Putting it all together — a working chat input bar

Here is a complete, self-contained example of a chat input bar. Type a message, press Enter or click Send, the message appears in the list, and the input clears. All the concepts from this lesson in one place.

<!-- HTML structure for the chat screen -->
<div id="message-list"></div>

<form id="chat-form">
  <input
    type="text"
    id="message-input"
    placeholder="Type a message..."
    autocomplete="off"
  />
  <button type="submit" id="send-btn">Send</button>
</form>

<p id="typing-indicator" style="display:none;">You are typing...</p>
// ── Chat input bar — complete implementation ──────────────────────

const chatForm = document.getElementById("chat-form");
const messageInput = document.getElementById("message-input");
const messageList = document.getElementById("message-list");
const typingIndicator = document.getElementById("typing-indicator");

let typingTimer = null; // Used to hide the indicator after pausing

// ── 1. Show/hide typing indicator as the user types ──────────────
messageInput.addEventListener("input", function(event) {
  const text = event.target.value;

  if (text.length > 0) {
    typingIndicator.style.display = "block";

    // Clear any previous timer so it doesn't hide too soon
    clearTimeout(typingTimer);

    // Hide the indicator 1.5 s after the user stops typing
    typingTimer = setTimeout(function() {
      typingIndicator.style.display = "none";
    }, 1500);
  } else {
    typingIndicator.style.display = "none";
  }
});

// ── 2. Send on Enter key (Shift+Enter inserts a newline) ──────────
messageInput.addEventListener("keydown", function(event) {
  if (event.key === "Enter" && !event.shiftKey) {
    event.preventDefault(); // Don't let Enter submit the form twice
    submitMessage();
  }
});

// ── 3. Send on clicking the Send button (form submit) ─────────────
chatForm.addEventListener("submit", function(event) {
  event.preventDefault(); // Stop page reload
  submitMessage();
});

// ── 4. Shared send logic ──────────────────────────────────────────
function submitMessage() {
  const text = messageInput.value.trim();
  if (text === "") return; // Don't send empty messages

  appendMessage(text, "me");

  messageInput.value = "";               // Clear the input
  typingIndicator.style.display = "none"; // Hide the typing indicator
  clearTimeout(typingTimer);
  messageInput.focus();                  // Keep focus so user can keep typing
}

// ── 5. Add a message bubble to the list (event delegation target) ─
function appendMessage(text, sender) {
  const bubble = document.createElement("div");
  bubble.classList.add("message-bubble", sender === "me" ? "outgoing" : "incoming");
  bubble.dataset.sender = sender;
  bubble.textContent = text;
  messageList.appendChild(bubble);

  // Scroll to the latest message
  messageList.scrollTop = messageList.scrollHeight;
}

// ── 6. Event delegation — one listener handles all message taps ───
messageList.addEventListener("click", function(event) {
  const bubble = event.target.closest(".message-bubble");
  if (!bubble) return; // Clicked somewhere in the list but not on a bubble

  console.log("Message tapped:", bubble.textContent);
  // In your WhatsApp clone: show a context menu (Reply, Copy, Delete, React)
});

// ── Simulate an incoming reply after 2 seconds (for demo) ─────────
setTimeout(function() {
  appendMessage("Hey! Got your message.", "them");
}, 2000);

This single file demonstrates every concept from this lesson:

  • addEventListener with "input", "keydown", and "submit"
  • event.target.value to read the input
  • event.key === "Enter" and event.shiftKey for keyboard handling
  • event.preventDefault() to stop form reload
  • Event delegation on the message list
  • Named functions so listeners could be removed later with removeEventListener
You just built the core of WhatsApp's chat input

The logic above — type, detect Enter, append bubble, clear input, delegate taps — is the exact same logic React Native's WhatsApp-style chat input uses. The API names change (onChangeText, onSubmitEditing, onPress) but the structure is identical. You understand the fundamentals.

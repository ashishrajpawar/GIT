Lesson 11

Modern JavaScript (ES6+)

Core JS ~30 min read Beginner
Why this matters for Token

Most of "modern JavaScript" you have already been writing for nine lessons without anyone naming it. This lesson names it, and then spends its real time on the three things you have not met.

Two of them — ?. and ?? — are the direct answer to a problem this course has been building up deliberately. querySelector returns null (lesson 7). find returns undefined (lesson 10). A property that was never set returns undefined (lesson 10 again). Every one of those crashes on the next line, pointing nowhere near the cause. ?. and ?? are how you stop writing that bug.

The third is modules. Token is one repo with four folders — app/, web/, api/, shared/ — and shared/ exists so the phone, the browser and the server all agree on what a token is. That sharing is import and export, and nothing else.

2. Template literals, properly

Backticks instead of quotes, with ${...} holes you can put any expression into.

const token = { code: "MERC-8GH2-KP4X", issuedTo: "Corner Store", uses: 3 };

// Concatenation - fine, but you have to think about every space
const oldWay = token.issuedTo + " (" + token.code + ") - " + token.uses + " uses";

// Template literal - the spaces are just there
const newWay = `${token.issuedTo} (${token.code}) — ${token.uses} uses`;

Two things concatenation cannot do at all:

// 1. Real line breaks, written as line breaks
const summary = `Token ${token.code}
Issued to: ${token.issuedTo}
Uses: ${token.uses}`;

// 2. Any expression inside the hole, not just a variable
const line = `${token.uses === 1 ? "1 use" : `${token.uses} uses`}`;
A template literal is still just a string

Which means it is not safe to put into innerHTML simply because it looks tidier. `<b>${label}</b>` where label came from a person is exactly the XSS hole from lesson 7, in nicer clothing. The rule has not changed: textContent for anything a person typed.

Try it yourself

3. Optional chaining ?.

Reading a property of something that turned out to be undefined throws. That is the crash behind most of the traps in this module — and until now the only fix has been to check first, at every level.

const token = { code: "MERC-8GH2-KP4X", rule: { maxUses: 5 } };
const bare  = { code: "CAFE-2BN7-4KQ9" };            // no rule yet

console.log(token.rule.maxUses);    // 5
console.log(bare.rule.maxUses);     // TypeError: Cannot read properties of undefined

// The old way - true, tedious, and easy to get one level wrong
const max = bare && bare.rule && bare.rule.maxUses;

// Optional chaining: stop and give undefined, rather than throwing
console.log(bare.rule?.maxUses);    // undefined
console.log(bare?.rule?.maxUses);   // undefined - safe even if `bare` is null

a?.b means: if a is null or undefined, stop and produce undefined; otherwise carry on. It short-circuits, so nothing to the right of the failure runs.

// It works on function calls and array indexes too
token.onRevoke?.();          // only calls it if it exists
tokens?.[0]?.code;           // safe even if tokens is undefined or empty
It is not a licence to stop thinking about missing data

?. turns a crash into an undefined. That is usually what you want — but an undefined that silently reaches the screen as the word "undefined" is not better than a crash, it is just quieter. Pair it with ??, which is the next section, and decide what the fallback should be.

Try it yourself

4. Nullish coalescing ??

a ?? b gives you a, unless a is null or undefined, in which case it gives you b. It is how you supply a default.

const label   = token.issuedTo ?? "(unlabelled)";
const maxUses = token.rule?.maxUses ?? "unlimited";

You may have seen || used for the same job. It is not the same job.

  • || falls back on any falsy value: null, undefined, 0, "", false, NaN
  • ?? falls back only on null and undefined

That difference is invisible until a legitimate value happens to be 0 or "" — and then it is a bug that looks like the data is wrong rather than the code.

Try it yourself — this one is broken on purpose

An access rule that says maxUses: 0 means a token that cannot be used at all — paused, or issued but not yet activated. Watch what || does to it.

Why this one matters more than a display bug

Token is a capability system. maxUses is not a preference, it is the limit that decides whether a holder gets in. A || that quietly turns "zero uses allowed" into "five uses allowed" is not a formatting mistake — it is the system granting access nobody authorised, with no error and nothing in the logs.

Use ?? for defaults on anything that could legitimately be 0, "" or false. That is most numbers, every text field, and every flag.

5. Modules — import and export

Everything so far has lived in one file. Real projects do not. Modules are how a file says what it offers and what it needs.

// ── shared/tokens.js ─────────────────────────────────────────────────

// Named exports: as many per file as you like
export const ALPHABET = "23456789ABCDEFGHJKMNPQRSTUVWXYZ";

export function isValidCode(code) {
  return /^[23456789ABCDEFGHJKMNPQRSTUVWXYZ]{4}(-[23456789ABCDEFGHJKMNPQRSTUVWXYZ]{4}){2}$/
    .test(code);
}

export function formatCode(raw) {
  const clean = raw.toUpperCase().replace(/[^0-9A-Z]/g, "");
  return [clean.slice(0, 4), clean.slice(4, 8), clean.slice(8, 12)].join("-");
}

// Default export: at most one per file, for the file's main thing
export default function describeToken(token) {
  return `${token.code} — ${token.issuedTo}`;
}
// ── app/screens/TokenList.js ─────────────────────────────────────────

// Named imports go in braces, and the names must match
import { isValidCode, formatCode } from "../../shared/tokens";

// The default import has no braces, and you may call it whatever you like
import describeToken from "../../shared/tokens";

// Both at once
import describeToken, { ALPHABET } from "../../shared/tokens";

// Rename on the way in, when two files export the same name
import { formatCode as formatTokenCode } from "../../shared/tokens";
This is what shared/ is for

Token is one repo with four folders: app/ (React Native), web/ (the redemption page), api/ (the server) and shared/.

isValidCode has to give the same answer in all three places. If the phone, the browser and the server each carry their own copy, they will disagree eventually — and the failure will be a code that one accepts and another rejects, which is close to impossible to debug from a support ticket.

One definition in shared/, imported three times, cannot drift. That is the whole argument for the folder.

No playground for this one, and that is the honest reason

import resolves real files. The playgrounds on this page run a single snippet of code with no file system and no bundler behind them, so an import line has nothing to resolve and cannot work. You will use modules for real from Module A2 onward, once the repo has more than one file.

6. Mini-project: a token card that survives incomplete data

The realistic version of the token detail screen. The API is mid-migration, so some tokens have a rule, some do not, some have partial rules, and one is missing entirely. Save it as token-card-demo.html and click through them — nothing crashes, and every missing value has a deliberate fallback.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8" />
  <title>Token Card Demo</title>
  <style>
    body { font-family: sans-serif; max-width: 520px; margin: 2rem auto;
           background: #F3F4F6; color: #111827; }
    #card { background: #fff; border-radius: 10px; padding: 1.1rem;

             background: #2563EB; color: #fff; cursor: pointer; font-size: 0.82rem; }
  </style>
</head>
<body>

  <div id="card"></div>
  <div id="controls"></div>

  <script>
    // Exactly the mess a real API in mid-migration returns
    const samples = [
      {
        name: "complete",
        token: {
          code: "MERC-8GH2-KP4X", issuedTo: "Corner Store", revoked: false,
          rule: { maxUses: 5, expiresOn: "2026-09-01" }
        }
      },
      {
        name: "no rule",
        token: { code: "CAFE-2BN7-4KQ9", issuedTo: "Cafe", revoked: false }
      },
      {
        name: "paused (maxUses 0)",
        token: {
          code: "RENT-2WX7-JP8N", issuedTo: "Landlord", revoked: false,
          rule: { maxUses: 0 }
        }
      },
      {
        name: "no label",
        token: { code: "GYM4-7TXQ-3RBV", revoked: false, rule: { maxUses: 2 } }
      },
      {
        name: "revoked",
        token: {
          code: "MART-9KM3-8VZR", issuedTo: "Supermarket", revoked: true,
          rule: { maxUses: 9, expiresOn: "2026-01-14" }
        }
      },
      { name: "nothing at all", token: undefined }
    ];

    const cardEl = document.getElementById("card");

    // Every read is guarded, and every fallback is chosen on purpose.
    function describeToken(token) {
      return {
        code:      token?.code ?? "(no code)",
        label:     token?.issuedTo ?? "(unlabelled)",
        // ?? not || - a rule of 0 uses is a real rule, not a missing one
        maxUses:   token?.rule?.maxUses ?? "unlimited",
        expiresOn: token?.rule?.expiresOn ?? "never",
        status:    token?.revoked ? "revoked" : "active"
      };
    }

    function render(token) {
      const view = describeToken(token);

      cardEl.innerHTML = "";
      cardEl.className = view.status === "revoked" ? "revoked" : "";

      const code = document.createElement("div");
      code.className = "code";
      code.textContent = view.code;

      const label = document.createElement("div");
      label.className = "label";
      label.textContent = view.label;      // text, never innerHTML

      const list = document.createElement("dl");
      const rows = [
        ["Status", view.status],
        ["Max uses", view.maxUses],
        ["Expires", view.expiresOn]
      ];

      for (const [name, value] of rows) {
        const dt = document.createElement("dt");
        dt.textContent = name;

        const dd = document.createElement("dd");
        dd.textContent = value;
        // Mark the defaults visually so a fallback never masquerades as data
        if (value === "unlimited" || value === "never") {
          dd.className = "missing";
        }

        list.appendChild(dt);
        list.appendChild(dd);
      }

      cardEl.appendChild(code);
      cardEl.appendChild(label);
      cardEl.appendChild(list);
    }

    const controlsEl = document.getElementById("controls");
    for (const sample of samples) {
      const btn = document.createElement("button");
      btn.textContent = sample.name;
      btn.addEventListener("click", function () { render(sample.token); });
      controlsEl.appendChild(btn);
    }

    render(samples[0].token);
  </script>

</body>
</html>
What to notice
  • Click paused (maxUses 0) and it reads 0, not "unlimited". Swap the ?? for || and it reads "unlimited" — the bug from section 4, on screen.
  • Click nothing at all. token is undefined and the card still renders, because every read starts with token?..
  • The defaults are styled differently from real values. A fallback that looks identical to data is a fallback you will eventually mistake for data.
  • describeToken does all the guarding, and render does none. Deciding what missing means in one place is what keeps the rest of the screen simple — and it is exactly this lesson's exercise.

Bridge to React Native: why this shows up immediately

A React screen renders before its data arrives. That is not an edge case, it is the first thing that happens every time:

function TokenDetail({ code }) {
  const [token, setToken] = React.useState(null);   // null on the first render

  React.useEffect(() => {
    api.fetchDetail(code).then(setToken);
  }, [code]);

  // Runs with token === null, before the request has finished
  return (
    <View>
      <Text>{token?.code ?? "Loading…"}</Text>
      <Text>{token?.rule?.maxUses ?? "unlimited"}</Text>
    </View>
  );
}

Without the ?. that first render throws, and the screen never appears at all — including the spinner that was supposed to cover the wait. This is the single most common crash in a new React Native app, and it is why ?. is worth the section it just got.

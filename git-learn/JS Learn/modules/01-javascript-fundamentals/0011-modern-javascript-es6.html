Lesson 11

Modern JavaScript (ES6+)

Core JavaScript ~25 min read Beginner–Intermediate
Why this matters for your WhatsApp clone

Every React Native tutorial, every Firebase snippet, and every Stack Overflow answer you'll read uses modern JavaScript syntax. If you don't know it, the code will look like a foreign language. This lesson covers the features you will see every single day: arrow functions, destructuring, the spread operator, template literals, and modules. After this lesson, React Native code will start to feel readable.

1. let and const — the modern way to declare variables

You've used let and const already in previous lessons, but here's the full picture. Before 2015, JavaScript only had var. Modern code uses let and const instead — they fix subtle scoping bugs that var had.

// const — for values that won't be reassigned
const userId = "user-ashish-01";
const MAX_MESSAGE_LENGTH = 4096;

// let — for values that WILL be reassigned
let unreadCount = 0;
unreadCount = unreadCount + 3; // allowed

// var — old, avoid in new code
var oldStyle = "don't use this";

// The key rule: default to const. Use let only when you know the value will change.
// Never use var in new code.
const doesn't mean "frozen"

const means you can't reassign the variable — you can't do const x = 1; x = 2;. But if const holds an object or array, you can still modify the object's properties or push items to the array. The binding is constant, not the content.

const user = { name: "Ashish" };
user.name = "Priya"; // allowed — modifying a property
user = { name: "Rahul" }; // ERROR — can't reassign the variable itself

2. Arrow functions — shorter function syntax

Arrow functions are a shorter way to write functions. You'll see them everywhere in React Native — in event handlers, array methods, and component definitions.

// Traditional function
function greet(name) {
  return "Hello, " + name;
}

// Arrow function — same thing, shorter
const greet = (name) => {
  return "Hello, " + name;
};

// Even shorter: if the body is just a return, drop the braces and 'return'
const greet = (name) => "Hello, " + name;

// One parameter: you can drop the parentheses too
const greet = name => "Hello, " + name;

// No parameters: keep empty parentheses
const sayHello = () => "Hello!";

Arrow functions with array methods

This is where they shine. Compare the old and new style:

const messages = [
  { sender: "Priya",  text: "Ready?",     read: true  },
  { sender: "Ashish", text: "Yes!",       read: false },
  { sender: "Priya",  text: "On my way!", read: false }
];

// Old style — verbose
const unread = messages.filter(function(msg) {
  return msg.read === false;
});

// Modern arrow function style — much cleaner
const unread = messages.filter(msg => msg.read === false);

// map with arrow function
const senders = messages.map(msg => msg.sender);
console.log(senders); // ["Priya", "Ashish", "Priya"]

// find with arrow function
const first = messages.find(msg => !msg.read);
console.log(first.text); // "Yes!"
Arrow functions and 'this'

Arrow functions do not have their own this — they inherit it from the surrounding code. This matters in class-based code, but in React Native (which uses hooks, not classes), you'll rarely hit this issue. Just know it exists.

3. Destructuring — unpacking values cleanly

Destructuring lets you pull values out of an object or array into separate variables in one line. It sounds small, but it makes React Native code dramatically cleaner.

Object destructuring

const message = {
  id:        "msg-001",
  sender:    "Priya",
  text:      "Hey! Coming tonight?",
  timestamp: 1700000000000,
  read:      false
};

// Without destructuring — repetitive
const sender    = message.sender;
const text      = message.text;
const read      = message.read;

// WITH destructuring — one line
const { sender, text, read } = message;

console.log(sender); // "Priya"
console.log(text);   // "Hey! Coming tonight?"
console.log(read);   // false

Destructuring with renaming

const user = { id: "user-001", name: "Priya" };

// Rename 'id' to 'userId' as you destructure
const { id: userId, name } = user;

console.log(userId); // "user-001"
console.log(name);   // "Priya"

Destructuring with default values

const message = { sender: "Priya", text: "Hello!" };
// 'read' doesn't exist on this object

const { sender, text, read = false } = message;
console.log(read); // false — uses the default

Array destructuring

// From Lesson 9 — Promise.all returns an array
const [messages, userProfile] = await Promise.all([
  fetchMessages(chatId),
  fetchUserProfile(userId)
]);

// useState in React Native (coming soon) also uses array destructuring
const [count, setCount] = useState(0);
// count is the current value, setCount is the function to update it

Destructuring in function parameters

This is extremely common in React Native components — instead of writing props.name, props.text, etc., you destructure props right in the function signature:

// Without destructuring
function MessageItem(props) {
  return props.sender + ": " + props.text;
}

// With destructuring in the parameter
function MessageItem({ sender, text, read }) {
  const status = read ? "✓✓" : "✓";
  return sender + ": " + text + " " + status;
}

// Call it the same way either way
console.log(MessageItem({ sender: "Priya", text: "Hey!", read: true }));
// "Priya: Hey! ✓✓"
In your WhatsApp clone

Every React Native component you write will destructure its props in the function signature. Every time you read data from Firebase, you'll destructure the fields you need. This is the single most-used ES6 feature in day-to-day React Native code.

4. The spread operator — ...

You saw ... briefly in Lesson 10 for copying objects. It does more than that — it "spreads" the contents of an array or object into another one.

Spreading arrays

const existingMessages = ["msg-001", "msg-002"];
const newMessage = "msg-003";

// Add a new message to the list (without mutating the original)
const updatedMessages = [...existingMessages, newMessage];
console.log(updatedMessages); // ["msg-001", "msg-002", "msg-003"]
console.log(existingMessages); // ["msg-001", "msg-002"] — untouched

// Merge two arrays
const groupA = ["Priya", "Rahul"];
const groupB = ["Mom", "Dad"];
const everyone = [...groupA, ...groupB];
console.log(everyone); // ["Priya", "Rahul", "Mom", "Dad"]

Spreading objects — copying and updating

const message = {
  id:     "msg-001",
  sender: "Priya",
  text:   "Hey!",
  read:   false
};

// Mark it as read — create a new object with read changed
const readMessage = { ...message, read: true };

console.log(message.read);     // false — original untouched
console.log(readMessage.read); // true  — new object has updated value

// This pattern is everywhere in React Native state updates:
// "give me a copy of this object, but with this one field changed"

Merging objects

const defaults = {
  notifications: true,
  darkMode:      false,
  fontSize:      16
};

const userPrefs = {
  darkMode: true  // user turned on dark mode
};

// Merge: start with defaults, override with userPrefs
const settings = { ...defaults, ...userPrefs };
console.log(settings);
// { notifications: true, darkMode: true, fontSize: 16 }
// userPrefs.darkMode overrode defaults.darkMode
React Native state updates use spread constantly

In React Native, you never mutate state directly — you create a new copy with the change applied. The spread operator is how you do that: setUser({ ...user, status: 'busy' }). You'll write this dozens of times per screen.

5. Template literals — cleaner string building

Template literals use backtick characters (`) instead of quotes and let you embed expressions directly inside strings with ${}. No more string concatenation with +.

const name    = "Priya";
const unread  = 3;
const chatId  = "chat-001";

// Old way — concatenation
const title = name + " (" + unread + " unread)";

// Modern — template literal
const title = `${name} (${unread} unread)`;
console.log(title); // "Priya (3 unread)"

// Any expression works inside ${}
const status = `Last seen ${unread > 0 ? "recently" : "a while ago"}`;

// Multi-line strings — no more \n
const notification = `
New message from ${name}:
Open the app to read it.
`.trim();
console.log(notification);

// Useful for building Firebase paths
const messagePath = `chats/${chatId}/messages`;
console.log(messagePath); // "chats/chat-001/messages"

6. Optional chaining ?. and nullish coalescing ??

Two more modern features you'll use constantly when dealing with data that might not exist yet — like user data that's still loading from Firebase.

Optional chaining ?.

const user = {
  name:    "Priya",
  profile: {
    avatar: "priya.jpg"
  }
};

// Without optional chaining — crashes if profile is null/undefined
console.log(user.profile.avatar); // "priya.jpg" — fine here

// But what if the user hasn't set a profile yet?
const newUser = { name: "Rahul" }; // no profile object
console.log(newUser.profile.avatar); // TypeError: Cannot read properties of undefined

// WITH optional chaining — returns undefined instead of crashing
console.log(newUser.profile?.avatar); // undefined — safe

// Chain as deeply as you need
console.log(user?.profile?.settings?.theme); // undefined — no crash

Nullish coalescing ??

// ?? returns the RIGHT side if the LEFT side is null or undefined
const avatar = user.profile?.avatar ?? "default-avatar.jpg";
console.log(avatar); // "priya.jpg" if it exists, "default-avatar.jpg" if not

const unreadCount = chat.unread ?? 0;
// If unread is null or undefined, use 0

// Difference from || (or):
// || triggers on any falsy value: 0, "", false, null, undefined
// ?? triggers ONLY on null and undefined

const count = 0;
console.log(count || 5);  // 5  — 0 is falsy, so || replaces it
console.log(count ?? 5);  // 0  — 0 is not null/undefined, so ?? keeps it
These prevent most "cannot read property of undefined" crashes

In your WhatsApp clone, data from Firebase might not have arrived yet when a component first renders. Using ?. and ?? everywhere on incoming data means your app shows empty/default states instead of crashing while it loads.

7. Modules — import and export

As your app grows, you'll split your code into multiple files. ES6 modules let each file export what it wants to share and import what it needs from other files. React Native uses this system for everything.

// ── File: utils/messages.js ──────────────────────────────────────────────

// Named export — export multiple things by name
export function formatTimestamp(timestamp) {
  const date = new Date(timestamp);
  return date.toLocaleTimeString([], { hour: "2-digit", minute: "2-digit" });
}

export function getUnreadCount(messages) {
  return messages.filter(msg => !msg.read).length;
}

// Default export — one main thing per file
export default function buildChatPreview(chat) {
  const last = chat.messages[chat.messages.length - 1];
  return {
    name:    chat.participant.name,
    preview: last.text,
    unread:  getUnreadCount(chat.messages)
  };
}


// ── File: screens/ChatList.js ────────────────────────────────────────────

// Import named exports with { }
import { formatTimestamp, getUnreadCount } from "./utils/messages";

// Import the default export (no curly braces)
import buildChatPreview from "./utils/messages";

// Import both at once
import buildChatPreview, { formatTimestamp } from "./utils/messages";

// Use them
const preview = buildChatPreview(chat);
const time    = formatTimestamp(1700000000000);
What you'll see in React Native

Every screen, component, and utility in your app will use imports and exports. React Native components are default exports. Helper functions and constants are usually named exports. You'll write import React from 'react' and import { View, Text } from 'react-native' at the top of every component file.

8. Everything together — a complete example

Here's a realistic slice of code using all seven features from this lesson at once. This is very close to what real React Native code looks like.

// ─── Data from Firebase ───────────────────────────────────────────────────
const rawChat = {
  id: "chat-001",
  participant: {
    id:     "user-priya-02",
    name:   "Priya Sharma",
    profile: {
      avatar: "priya.jpg",
      status: "online"
    }
  },
  messages: [
    { id: "m1", sender: "Priya",  text: "Hey! Good game last night!", read: true,  timestamp: 1700000000000 },
    { id: "m2", sender: "Ashish", text: "Yeah! That final over!",     read: true,  timestamp: 1700000060000 },
    { id: "m3", sender: "Priya",  text: "Heart attack material lol",  read: false, timestamp: 1700000120000 }
  ]
};

// ─── Helper functions (arrow functions + template literals) ───────────────

const formatTime = timestamp =>
  new Date(timestamp).toLocaleTimeString([], { hour: "2-digit", minute: "2-digit" });

const getUnread = messages => messages.filter(m => !m.read).length;

// ─── Build the chat header data (destructuring + optional chaining + ??) ──

function buildChatHeader(chat) {
  // Destructure what we need
  const { participant, messages } = chat;
  const { name, profile } = participant;

  // Optional chaining + nullish coalescing for safe property access
  const avatar = profile?.avatar ?? "default-avatar.jpg";
  const status = profile?.status ?? "offline";

  const lastMsg  = messages[messages.length - 1];
  const unread   = getUnread(messages);

  return {
    name,
    avatar,
    status,
    preview:     lastMsg.text,
    previewTime: formatTime(lastMsg.timestamp),
    unread
  };
}

// ─── Display (spread to add a computed field) ─────────────────────────────

const header = buildChatHeader(rawChat);

// Add a display-ready badge string using spread
const displayHeader = {
  ...header,
  badge: header.unread > 0 ? `${header.unread} new` : ""
};

// ─── Render ───────────────────────────────────────────────────────────────

const { name, status, preview, previewTime, badge } = displayHeader;

console.log(`${name} — ${status}`);                  // "Priya Sharma — online"
console.log(`${preview} · ${previewTime}`);           // "Heart attack material lol · 12:02 AM"
if (badge) console.log(`Badge: ${badge}`);            // "Badge: 1 new"

Every line of that uses features from this lesson. Paste it into your browser console and read through it until it all makes sense.

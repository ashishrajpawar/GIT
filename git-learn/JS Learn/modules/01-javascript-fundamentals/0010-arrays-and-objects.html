Lesson 10

Arrays & Objects

Core JS ~35 min read Beginner
Why this matters for Token

Token's home screen is a list of tokens. That list is an array of objects — and so is almost every other screen: redemptions, messages, access rules, devices.

Everything the app does is a transformation of that array. Filtering to the active ones. Searching by label. Sorting by most recently used. Counting how many uses are left. None of those are new concepts — they are all array methods, applied to your own data.

One idea in this lesson outranks the rest: objects and arrays are handled by reference. Copy one carelessly and you change the original without meaning to. In plain JavaScript that is a confusing bug. In React it is worse — it is a screen that does not update, with no error to explain why. That is why this lesson's exercise is about producing a new array rather than editing the one you were given.

1. Arrays — ordered lists

An array holds values in order, each reachable by a numeric index starting at 0.

const codes = ["MERC-8GH2-KP4X", "CAFE-2BN7-4KQ9", "RENT-2WX7-JP8N"];

console.log(codes[0]);        // "MERC-8GH2-KP4X"
console.log(codes.length);    // 3
console.log(codes[codes.length - 1]);   // the last one

codes.push("GYM4-7TXQ-3RBV");           // add to the end
const removed = codes.pop();            // take the last one off
Reading past the end gives undefined, not an error

codes[99] on a three-item array returns undefined. It does not throw. So the crash arrives later, when something tries to read a property off that undefined — the same delayed-blame pattern as querySelector returning null in lesson 7.

2. Array methods — the ones you will use every day

You will rarely write a manual for loop over app data. These five cover almost everything, and each one returns something new rather than changing the array it was given.

MethodReturnsUsed for
mapa new array, same lengthtransform every item
filtera new array, shorter or equalkeep the ones that match
findone item, or undefinedlocate a single item
reduceone value of any shapecombine everything into a total
some / everya booleanask a yes/no question of the list
 
const tokens = [
  { code: "MERC-8GH2-KP4X", issuedTo: "Corner Store", uses: 3, revoked: false },
  { code: "CAFE-2BN7-4KQ9", issuedTo: "Cafe",         uses: 0, revoked: false },
  { code: "RENT-2WX7-JP8N", issuedTo: "Landlord",     uses: 7, revoked: true  }
];

// Just the live ones
const active = tokens.filter(function (t) { return !t.revoked; });

// Just the codes, for display
const codes = tokens.map(function (t) { return t.code; });

// One specific token
const one = tokens.find(function (t) { return t.code === "CAFE-2BN7-4KQ9"; });

// Total uses across every token
const totalUses = tokens.reduce(function (sum, t) { return sum + t.uses; }, 0);

// Questions about the whole list
const anyRevoked  = tokens.some(function (t) { return t.revoked; });
const allUsed     = tokens.every(function (t) { return t.uses > 0; });
find returns undefined when nothing matches

Same trap as before, one level along. tokens.find(...) with no match gives undefined, and undefined.code throws. Check before you read.

Try it yourself

3. Objects — data with named properties

An array is indexed by position. An object is indexed by name, which is what you want the moment a thing has more than one attribute.

const token = {
  code: "MERC-8GH2-KP4X",
  issuedTo: "Corner Store",
  revoked: false,
  uses: 3,
  rule: { maxUses: 5, expiresOn: "2026-09-01" }    // objects nest
};

console.log(token.code);              // dot notation
console.log(token["code"]);           // bracket notation - same thing
console.log(token.rule.maxUses);      // 5

const field = "issuedTo";
console.log(token[field]);            // bracket is required when the name is in a variable

token.revoked = true;                 // change a property
token.lastUsedAt = "10:02";           // add a new one
delete token.uses;                    // remove one

Destructuring — pulling properties out by name

const { code, issuedTo, revoked } = token;
console.log(code, issuedTo, revoked);

// Rename as you go, and supply a default for a missing property
const { issuedTo: label, uses = 0 } = token;

// It works on function parameters too, which is where you will meet it most
function describe({ code, revoked }) {
  return code + (revoked ? " (revoked)" : " (active)");
}

Try it yourself

4. Arrays of objects — the shape of every screen

Put the two together and you have the shape almost all app data arrives in.

const tokens = [
  { code: "MERC-8GH2-KP4X", issuedTo: "Corner Store", uses: 3, revoked: false },
  { code: "BANK-4FJ7-6TWD", issuedTo: "Bank",         uses: 1, revoked: false },
  { code: "MART-9KM3-8VZR", issuedTo: "Supermarket",  uses: 9, revoked: true  }
];

// The three questions a list screen always asks:
const visible = tokens.filter(function (t) { return !t.revoked; });
const sorted  = [...visible].sort(function (a, b) { return b.uses - a.uses; });
const labels  = sorted.map(function (t) { return t.issuedTo; });
sort() changes the array it is called on

map and filter return new arrays. sort and reverse do not — they reorder in place and return the same array. That is why the example above spreads into a copy first. Sorting a list you were handed is one of the most common accidental mutations there is.

Try it yourself

5. Reference vs value — the one that causes real bugs

Numbers and strings are copied by value. Objects and arrays are handled by reference: the variable holds a pointer to the thing, not the thing itself. Assigning it somewhere else copies the pointer, and now two names refer to one object.

Try it yourself — this one is broken on purpose

Run it and watch the original change underneath you. Then fix it with a spread, as described underneath.

// The fix: spread builds a NEW object with the same values
const copy = { ...original };
copy.revoked = true;          // original is untouched

// Same for arrays
const listCopy = [...tokens];
listCopy.push(newToken);      // tokens still has its original length
Spread copies one level deep, and no further

This is the part that catches people after they think they have understood it. { ...token } gives you a new outer object, but any nested object inside is still the same one, shared with the original.

So changing copy.rule.maxUses also changes original.rule.maxUses. To copy a nested piece you have to spread that level too.

Try it yourself

Why this matters more in React than in plain JavaScript

React decides whether to re-render by asking "is this a different object than last time?" — not by inspecting what changed inside it. Mutate an object in place and the answer is no, so the screen keeps showing stale data. No error, no warning; the app just quietly stops updating.

This is the reasoning behind the project rule: never mutate state arrays or objects directly — always spread into new ones. This lesson's exercise is that rule, written out by hand.

  <script>
    // The single source of truth. Never edited — only read from.
    const tokens = [
      { code: "MERC-8GH2-KP4X", issuedTo: "Corner Store", uses: 3, revoked: false },
      { code: "CAFE-2BN7-4KQ9", issuedTo: "Cafe",         uses: 0, revoked: false },
      { code: "RENT-2WX7-JP8N", issuedTo: "Landlord",     uses: 7, revoked: true  },
      { code: "BANK-4FJ7-6TWD", issuedTo: "Bank",         uses: 1, revoked: false },
      { code: "MART-9KM3-8VZR", issuedTo: "Supermarket",  uses: 9, revoked: true  },
      { code: "GYM4-7TXQ-3RBV", issuedTo: "Gym",          uses: 2, revoked: false }

    const searchEl  = document.getElementById("search");
    const statusEl  = document.getElementById("status");
    const sortEl    = document.getElementById("sort");
    const listEl    = document.getElementById("token-list");
    const summaryEl = document.getElementById("summary");

    // Derive what to show. Note it never touches `tokens` itself.
    function visibleTokens() {
      const term = searchEl.value.trim().toLowerCase();
      const status = statusEl.value;

      const matching = tokens.filter(function (t) {
        const matchesTerm = term === "" ||
          t.issuedTo.toLowerCase().includes(term) ||
          t.code.toLowerCase().includes(term);

        const matchesStatus =
          status === "all" ||
          (status === "active"  && !t.revoked) ||
          (status === "revoked" &&  t.revoked);

        return matchesTerm && matchesStatus;
      });

      // Copy before sorting - sort() reorders in place
      return [...matching].sort(function (a, b) {
        if (sortEl.value === "label") {
          return a.issuedTo.localeCompare(b.issuedTo);
        }
        return b.uses - a.uses;
      });
    }

    function render() {
      const shown = visibleTokens();

      // The summary is computed from the data, never tracked separately
      const totalUses = tokens.reduce(function (sum, t) { return sum + t.uses; }, 0);
      const activeCount = tokens.filter(function (t) { return !t.revoked; }).length;

      summaryEl.textContent =
        "Showing " + shown.length + " of " + tokens.length + " · " +
        activeCount + " active · " + totalUses + " uses in total";

      listEl.innerHTML = "";

      if (shown.length === 0) {
        const empty = document.createElement("li");
        empty.className = "empty";
        empty.textContent = "No tokens match.";
        listEl.appendChild(empty);
        return;
      }

      for (const token of shown) {
        const row = document.createElement("li");
        if (token.revoked) row.classList.add("revoked");

        const code = document.createElement("span");
        code.className = "code";
        code.textContent = token.code;

        const who = document.createElement("span");
        who.className = "who";
        who.textContent = token.issuedTo;      // text, never innerHTML

        const uses = document.createElement("span");
        uses.className = "uses";
        uses.textContent = token.uses === 1 ? "1 use" : token.uses + " uses";

        row.appendChild(code);
        row.appendChild(who);
        row.appendChild(uses);
        listEl.appendChild(row);
      }
    }

    searchEl.addEventListener("input", render);
    statusEl.addEventListener("change", render);
    sortEl.addEventListener("change", render);

    render();
  </script>

</body>

What to notice
  • tokens is never modified. Every view of it is derived with filter, sort and map, so there is exactly one source of truth and no way for a filtered copy to drift out of sync with it.
  • The summary counts are computed on every render rather than stored. A separate activeCount variable is a bug waiting to happen — it is one missed update away from lying.
  • [...matching].sort(...) — the copy is deliberate. Sorting matching directly would work here too, but the habit is what saves you when the array is not yours.
  • This is the same render() shape as lesson 7's mini-project, and it is what React automates.

Bridge to React: derived values and immutable updates

Two habits from this lesson carry straight into the app, and they are the two the project's state rules are built on.

Derive, do not store. The count of active tokens is not state — it is a fact about the token list. Computing it inline means it cannot go stale:

const [tokens, setTokens] = React.useState(initialTokens);

// Derived on every render. Not useState, not useEffect.
const active = tokens.filter(t => !t.revoked);
const totalUses = tokens.reduce((sum, t) => sum + t.uses, 0);

Update by replacing, not editing. This is exactly the exercise below:

function revoke(code) {
  setTokens(function (prev) {
    return prev.map(function (t) {
      return t.code === code ? { ...t, revoked: true } : t;
    });
  });
}

Read that map carefully. It returns a new array; the one token that matched is a new object with revoked flipped; every other token is the same object as before. That last part is not laziness — React uses it to skip re-rendering the rows that did not change.

The version that looks equivalent and is not:

// BROKEN - mutates the existing object, so React sees no change
const token = tokens.find(t => t.code === code);
token.revoked = true;
setTokens(tokens);        // same array reference - often no re-render at all

Now build it yourself

Revoking a token is the app's most common write, and it is the one where a mutation bug hides best: the data really is correct, so a console log looks right, and only the screen is wrong.

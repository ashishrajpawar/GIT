India's DPDP Act

B10 — Lesson 2 of 2  |  ~50 min

Why this matters for Token: The Digital Personal Data Protection Act (2023) is India's equivalent of GDPR. Token is a privacy product by definition — its entire value proposition is controlling who can contact you. The DPDP Act isn't an obstacle; it's the legal framework that validates your product's design. Token already does most of what the law requires. This lesson maps the legal requirements to your implementation.

DPDP Act — The Key Concepts

The Act was passed in August 2023. Its rules are being notified in phases. Here's what matters for Token:

Legal termPlain EnglishToken equivalent
Data PrincipalThe person whose data it isYour user (the token issuer)
Data FiduciaryThe entity that decides how data is usedYou (the app developer/company)
Data ProcessorEntity that processes data on behalf of fiduciaryYour VPS provider, Expo (for push)
ConsentPermission to process data, for a stated purposeThe user signing up and issuing tokens
Purpose limitationData used only for the stated purposeMessages only for communication, not ads/profiling
Data minimisationCollect only what you needNo phone number or email required (the whole point!)

The Seven Obligations

The DPDP Act imposes these obligations on Data Fiduciaries (you). Here's how Token implements each:

1. Lawful Purpose & Consent

You must have a lawful basis for processing personal data, and consent must be:

  • Free — not coerced
  • Specific — for a stated purpose
  • Informed — the user knows what they're consenting to
  • Unconditional — not bundled with other terms
// Implementation: clear consent screen during registration
// NOT a 50-page terms of service with a single "I agree" checkbox

2. Right to Withdraw Consent

The user can withdraw consent at any time, and withdrawal must be as easy as granting it.

// api/src/routes/consent.ts
router.delete('/consent/:purpose', authenticateJWT, async (req, res) => {
  const { purpose } = req.params;
  const userId = req.user.id;

  // Record withdrawal
  await db.query(
    'UPDATE consent_records SET withdrawn_at = NOW() WHERE user_id = $1 AND purpose = $2',
    [userId, purpose]
  );

  // Act on withdrawal immediately
  if (purpose === 'push_notifications') {
    // Delete push token — stop sending notifications
    await db.query('UPDATE users SET push_token = NULL WHERE id = $1', [userId]);
  }

  if (purpose === 'data_processing') {
    // This is withdrawing ALL consent — equivalent to account deletion request
    // Queue account deletion (must complete within 72 hours per DPDP)
    await db.query(
      'INSERT INTO deletion_queue (user_id, requested_at, deadline) VALUES ($1, NOW(), NOW() + interval \'72 hours\')',
      [userId]
    );
  }

  req.log.info({ userId, purpose }, 'consent withdrawn');
  res.json({ withdrawn: true, effectiveImmediately: true });
});

3. Right to Access (Data Portability)

The user can request a copy of all their personal data in a machine-readable format.

// api/src/routes/dataExport.ts
router.get('/me/data-export', authenticateJWT, async (req, res) => {
  const userId = req.user.id;

  // Gather all user data
  const [user, tokens, messages, consents, redemptions] = await Promise.all([
    db.query('SELECT id, username, created_at FROM users WHERE id = $1', [userId]),
    db.query('SELECT id, code, label, created_at, revoked_at FROM tokens WHERE user_id = $1', [userId]),
    db.query('SELECT id, conversation_id, content, created_at FROM messages WHERE sender_id = $1', [userId]),
    db.query('SELECT purpose, granted, granted_at, withdrawn_at FROM consent_records WHERE user_id = $1', [userId]),
    db.query('SELECT id, token_id, redeemed_at, ip_address FROM redemption_events WHERE token_id IN (SELECT id FROM tokens WHERE user_id = $1)', [userId]),
  ]);

  const exportData = {
    exportedAt: new Date().toISOString(),
    format: 'DPDP-compliant-export-v1',
    user: user.rows[0],
    tokens: tokens.rows,
    messages: messages.rows,
    consentRecords: consents.rows,
    redemptionEvents: redemptions.rows,
  };

  // Return as downloadable JSON
  res.setHeader('Content-Type', 'application/json');
  res.setHeader('Content-Disposition', 'attachment; filename="token-data-export.json"');
  res.json(exportData);
});

5. Right to Erasure (Account Deletion)

The user can request complete deletion of their data. This must be actual deletion, not soft-delete.

// api/src/routes/account.ts
router.delete('/me', authenticateJWT, async (req, res) => {
  const userId = req.user.id;

  req.log.info({ userId }, 'account deletion requested');

  // Start deletion in a transaction
  await db.query('BEGIN');

  try {
    // Delete in dependency order (foreign keys)
    await db.query('DELETE FROM consent_records WHERE user_id = $1', [userId]);
    await db.query('DELETE FROM redemption_events WHERE token_id IN (SELECT id FROM tokens WHERE user_id = $1)', [userId]);
    await db.query('DELETE FROM access_rules WHERE token_id IN (SELECT id FROM tokens WHERE user_id = $1)', [userId]);
    await db.query('DELETE FROM messages WHERE sender_id = $1', [userId]);
    await db.query('DELETE FROM participants WHERE user_id = $1', [userId]);
    await db.query('DELETE FROM tokens WHERE user_id = $1', [userId]);
    await db.query('DELETE FROM users WHERE id = $1', [userId]);

    await db.query('COMMIT');

    req.log.info({ userId }, 'account deleted completely');
    res.json({ deleted: true });
  } catch (err) {
    await db.query('ROLLBACK');
    req.log.error({ err, userId }, 'account deletion failed');
    res.status(500).json({ error: 'deletion failed — please contact support' });
  }
});

// IMPORTANT: This is HARD deletion. Once done, the data is gone.
// The only thing you may retain is an anonymised record that an account
// existed (for audit purposes) — but NO personal data.

6. Grievance Redressal

You must provide a mechanism for users to raise data-related complaints and get a response.

// Minimum requirement: a contact email or in-app form
// that reaches a human within a reasonable timeframe.

// For a solo developer, this can be:
// - An email address displayed in the app's settings: privacy@tokn.app
// - A simple form that creates a ticket in your issue tracker
// - The app's "Contact" screen that sends a message to your admin account

// The law requires you to respond within a "reasonable time"
// (specific timelines will be in the rules, expected 15-30 days)

7. Data Breach Notification

If personal data is breached, you must notify the Data Protection Board of India (DPBI) and affected users.

// What counts as a breach:
// - Database dump leaked
// - Unauthorised access to user accounts
// - Backup stolen or exposed
// - Server compromised with data exfiltration

// What to do:
// 1. Contain the breach (revoke compromised credentials, patch the vulnerability)
// 2. Assess what data was affected
// 3. Notify DPBI "without unreasonable delay"
// 4. Notify affected Data Principals (your users)
// 5. Document everything (what happened, when, what you did)

// Preparation (do this NOW, not during a breach):
// - Incident response plan documented
// - Contact details for DPBI ready
// - Notification template drafted
// - Logging comprehensive enough to determine breach scope

Token's Natural Compliance Advantage

Token's privacy-first design means you're already mostly compliant:

DPDP requirementToken already does this
Data minimisationNo phone number, no email, no real name required
Purpose limitationData used only for communication (no ads, no profiling)
ConsentEvery token is an explicit consent grant from the user
Right to withdrawToken revocation IS consent withdrawal
Security safeguardsEnd-to-end encrypted (planned), encrypted at rest

The product IS the compliance mechanism. A token is a consent artifact — it represents the user's decision to allow contact, with specific rules, revocable at any time. This is exactly what the DPDP Act envisions.

Privacy Policy — What to Include

Your privacy policy must be in clear language (not legalese) and state:

// Required sections for Token's privacy policy:

// 1. What data you collect
//    - Username (chosen by user, need not be real name)
//    - Password (hashed, never stored in plaintext)
//    - Messages (content of conversations)
//    - Token metadata (when created, rules, redemption events)
//    - Device push tokens (for notifications)
//    - IP addresses (in server logs, retained 30 days)

// 2. Why you collect it (purpose)
//    - Account management
//    - Delivering messages between token issuers and holders
//    - Push notifications for new messages and calls
//    - Security (rate limiting, abuse prevention)

// 3. Who you share it with
//    - No third parties (no ads, no analytics services, no data brokers)
//    - Expo (only push tokens, for notification delivery)
//    - VPS provider (data at rest on their hardware)

// 4. How long you retain it
//    - Account data: until account deletion
//    - Messages: until account deletion
//    - Server logs: 30 days
//    - Backups: 7 days (then overwritten)

// 5. How to exercise your rights
//    - Export: Settings → Download My Data
//    - Delete: Settings → Delete Account
//    - Withdraw consent: Settings → Privacy → toggle each purpose
//    - Grievance: privacy@tokn.app

// 6. Contact details
//    - Name of Data Fiduciary
//    - Email for privacy queries

Children's Data

The DPDP Act has strict rules about processing children's data (under 18 in India). Token's approach:

// Option 1 (simplest): Declare the app is for 18+ users
// - Add to terms of service
// - No age verification needed for general-purpose apps (yet)
// - If you KNOW a user is under 18, you need verifiable parental consent

// Option 2: If you want users under 18:
// - Implement verifiable parental consent mechanism
// - Don't serve behavioural tracking or targeted content to them
// - Don't process their data for any purpose beyond the service itself

// For Token v1: Option 1 is appropriate.
// A communication privacy app for adults is the simplest path.

Cross-Border Data Transfer

If your server is outside India (e.g., Singapore VPS), you're transferring data cross-border. The DPDP Act allows this to countries not blacklisted by the government. Singapore is fine. If the government blacklists a country, you'd need to move your data.

// Best practice: document where data lives
// - Primary database: Hetzner Singapore
// - Backups: [your backup location]
// - Push notification relay: Expo (US-based)
// - No other third parties

// If you choose a VPS in India (e.g., Mumbai region on AWS/DigitalOcean),
// cross-border transfer isn't an issue at all.

Security Hardening

B10 — Lesson 1 of 2  |  ~55 min

Why this matters for Token: Token's core promise is privacy. If your server is compromised, every user's contact graph, messages, and tokens are exposed. A single SQL injection or leaked secret undoes everything the product stands for. This lesson covers the defences that prevent that from happening.

SQL Injection — The #1 Rule

Never concatenate user input into SQL strings. Always use parameterised queries.

// ❌ VULNERABLE — string concatenation
async function getToken(code: string) {
  // An attacker sends: code = "'; DROP TABLE tokens; --"
  const result = await db.query(
    `SELECT * FROM tokens WHERE code = '${code}'`
  );
  return result.rows[0];
}

// ✓ SAFE — parameterised query
async function getToken(code: string) {
  // The $1 placeholder is never interpreted as SQL
  const result = await db.query(
    'SELECT * FROM tokens WHERE code = $1',
    [code]
  );
  return result.rows[0];
}

Why Parameterised Queries Are Safe

The database driver sends the query template and values separately. The database compiles the template first, then binds the values as data — never as SQL syntax. Even if the value contains '; DROP TABLE, it's treated as a literal string, not a command.

// What the database sees with parameterised queries:
// Template: "SELECT * FROM tokens WHERE code = $1"
// Values:   ["'; DROP TABLE tokens; --"]
// Result:   looks for a token with code literally "'; DROP TABLE tokens; --"
//           (finds nothing, attacks nothing)

Auditing Your Codebase

// Search for potential injection vulnerabilities:
// grep for template literals or string concatenation in .query() calls

// Red flags:
db.query(`SELECT * FROM ${table} WHERE id = ${id}`)     // ❌
db.query("SELECT * FROM " + table + " WHERE id = " + id) // ❌
db.query(\`UPDATE tokens SET name = '\${name}'\`)          // ❌

// Safe patterns:
db.query('SELECT * FROM tokens WHERE id = $1', [id])     // ✓
db.query('SELECT * FROM tokens WHERE code = $1 AND user_id = $2', [code, userId]) // ✓

Secrets Management

What Counts as a Secret

  • JWT_SECRET and JWT_REFRESH_SECRET
  • DATABASE_URL (contains password)
  • Expo push notification tokens
  • Any API key for external services

Rules

// 1. NEVER commit secrets to git
//    Use .env files locally (add to .gitignore)
//    Use Coolify's encrypted environment variables in production

// .gitignore — these must be here
.env
.env.local
.env.production
*.pem
*.key

// 2. NEVER log secrets
logger.info({ dbUrl: process.env.DATABASE_URL }); // ❌ NEVER
logger.info({ dbHost: 'postgres-internal' });      // ✓ OK to log host, not credentials

// 3. Use strong random values (64+ hex chars)
// node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

// 4. Different secrets per environment
// Dev JWT_SECRET ≠ Staging JWT_SECRET ≠ Production JWT_SECRET

Secret Rotation

// If a secret is compromised, you need to rotate it without downtime.
// Strategy: support TWO secrets simultaneously during rotation.

// api/src/auth/verifyToken.ts
import jwt from 'jsonwebtoken';

const JWT_SECRETS = [
  process.env.JWT_SECRET,           // Current secret
  process.env.JWT_SECRET_PREVIOUS,  // Previous secret (during rotation)
].filter(Boolean) as string[];

export function verifyAccessToken(token: string): JwtPayload | null {
  for (const secret of JWT_SECRETS) {
    try {
      return jwt.verify(token, secret) as JwtPayload;
    } catch {
      continue; // Try next secret
    }
  }
  return null; // None worked — token is invalid
}

// Rotation process:
// 1. Generate new secret
// 2. Set JWT_SECRET = new, JWT_SECRET_PREVIOUS = old
// 3. Deploy — new tokens signed with new secret, old tokens still verify
// 4. Wait for all old tokens to expire (access tokens: 15 min)
// 5. Remove JWT_SECRET_PREVIOUS

CORS — Cross-Origin Resource Sharing

CORS controls which websites can make requests to your API. Without it, any website could make requests to api.tokn.app using a logged-in user's cookies/credentials.

// api/src/middleware/cors.ts
import cors from 'cors';

const ALLOWED_ORIGINS = [
  'https://tokn.app',              // Production web client
  'http://localhost:5173',         // Local Vite dev server
  'http://localhost:19006',        // Expo web (development only)
];

export const corsMiddleware = cors({
  origin: (origin, callback) => {
    // Allow requests with no origin (mobile apps, server-to-server)
    if (!origin) return callback(null, true);

    if (ALLOWED_ORIGINS.includes(origin)) {
      callback(null, true);
    } else {
      callback(new Error(`Origin ${origin} not allowed by CORS`));
    }
  },
  credentials: true, // Allow cookies/auth headers
  methods: ['GET', 'POST', 'PUT', 'DELETE', 'PATCH'],
  allowedHeaders: ['Content-Type', 'Authorization', 'X-Request-ID'],
  maxAge: 86400, // Cache preflight for 24 hours
});

Why Mobile Apps Don't Need CORS

CORS is a browser security mechanism. React Native apps make HTTP requests directly (like a server would) — they don't send an Origin header. That's why we allow requests with no origin.

Security Headers

HTTP headers that instruct browsers to enable security features:

# Install helmet (sets security headers automatically)
npm install helmet
// api/src/app.ts
import helmet from 'helmet';

app.use(helmet({
  // Content Security Policy — controls what resources the page can load
  contentSecurityPolicy: {
    directives: {
      defaultSrc: ["'self'"],
      scriptSrc: ["'self'"],
      styleSrc: ["'self'", "'unsafe-inline'"],  // Needed for some UI frameworks
      imgSrc: ["'self'", "data:", "https:"],
      connectSrc: ["'self'", "wss://api.tokn.app"],
    },
  },
  // Strict Transport Security — force HTTPS for 1 year
  hsts: {
    maxAge: 31536000,
    includeSubDomains: true,
    preload: true,
  },
  // Prevent clickjacking (embedding in iframes)
  frameguard: { action: 'deny' },
  // Don't reveal server software
  hidePoweredBy: true,
  // Prevent MIME type sniffing
  noSniff: true,
  // Referrer Policy — don't leak URLs to third parties
  referrerPolicy: { policy: 'strict-origin-when-cross-origin' },
}));

What Each Header Does

HeaderThreat it prevents
Strict-Transport-SecurityDowngrade attacks (forcing HTTP instead of HTTPS)
Content-Security-PolicyXSS (injecting malicious scripts)
X-Frame-Options: DENYClickjacking (embedding your page in a hidden iframe)
X-Content-Type-Options: nosniffMIME confusion attacks
Referrer-PolicyLeaking sensitive URLs to third-party sites

Input Validation at the Boundary

You already use zod for validation (from B3). Here's the security perspective — validate everything at the API boundary, even if the client already validated it:

// api/src/routes/tokens.ts
import { z } from 'zod';

const createTokenSchema = z.object({
  label: z.string()
    .min(1)
    .max(100)
    .trim(),
  rules: z.object({
    maxRedemptions: z.number().int().positive().max(1000).optional(),
    expiresAt: z.string().datetime().optional(),
    allowedCategories: z.array(z.string().max(50)).max(20).optional(),
  }).optional(),
});

// In the route handler:
export async function createToken(req: Request, res: Response) {
  const parsed = createTokenSchema.safeParse(req.body);

  if (!parsed.success) {
    return res.status(400).json({
      error: 'validation_error',
      details: parsed.error.flatten(),
    });
  }

  // parsed.data is now typed AND validated — safe to use
  const { label, rules } = parsed.data;
  // ...
}

Output Encoding

When storing user-generated content (token labels, messages), encode it before rendering in HTML contexts to prevent stored XSS:

// The redemption web page displays the token holder's name.
// If that name contains <script>alert('xss')</script>, you have a problem.

// React handles this automatically for JSX content:
// <p>{holderName}</p>  ← React escapes this by default ✓

// BUT: dangerouslySetInnerHTML bypasses it:
// <div dangerouslySetInnerHTML={{ __html: holderName }} /> ← ❌ NEVER with user data

// On the server side, if you ever generate HTML:
import { encode } from 'html-entities';
const safeName = encode(holderName); // "<script>" becomes "&lt;script&gt;"

Broken Access Control

The most critical check: does this user own this resource?

// ❌ VULNERABLE — no ownership check
router.get('/tokens/:id', async (req, res) => {
  const token = await db.query('SELECT * FROM tokens WHERE id = $1', [req.params.id]);
  res.json(token.rows[0]); // Any logged-in user can read ANY token
});

// ✓ SAFE — ownership enforced
router.get('/tokens/:id', authenticateJWT, async (req, res) => {
  const token = await db.query(
    'SELECT * FROM tokens WHERE id = $1 AND user_id = $2',
    [req.params.id, req.user.id]  // Only returns if user owns it
  );

  if (!token.rows[0]) {
    return res.status(404).json({ error: 'not found' });
  }

  res.json(token.rows[0]);
});

The Pattern: Always Include user_id in Queries

// Every query that reads or modifies user data should include the ownership clause:

// Read user's tokens
'SELECT * FROM tokens WHERE user_id = $1'

// Update a specific token (owned by user)
'UPDATE tokens SET label = $2 WHERE id = $1 AND user_id = $3'

// Delete (revoke) a token (owned by user)
'UPDATE tokens SET revoked_at = NOW() WHERE id = $1 AND user_id = $2'

// Read messages in a conversation the user participates in
'SELECT m.* FROM messages m JOIN participants p ON p.conversation_id = m.conversation_id WHERE m.conversation_id = $1 AND p.user_id = $2'

Preventing Common Attacks

Timing Attacks on Token Lookup

// When checking if a token code is valid, use constant-time comparison
// to prevent attackers from guessing codes character by character.

import { timingSafeEqual } from 'crypto';

function safeCompare(a: string, b: string): boolean {
  if (a.length !== b.length) return false;
  return timingSafeEqual(Buffer.from(a), Buffer.from(b));
}

// For database lookups, this is less relevant (the DB handles comparison),
// but for API key validation or HMAC verification, always use timingSafeEqual.

Request Size Limits

// Prevent denial of service via oversized payloads
import express from 'express';

app.use(express.json({ limit: '1mb' }));  // Reject bodies > 1MB
app.use(express.urlencoded({ limit: '1mb', extended: true }));

// For file uploads (if you ever add them), use streaming with size limits
// Never buffer an entire upload in memory
